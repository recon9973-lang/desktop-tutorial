## 2. A 원천 실측 세부 — 서울 행정동 생활인구

- **받는 법** (열쇠 없음): 페이지 `https://data.seoul.go.kr/dataList/OA-14991/S/1/datasetView.do` 의 파일 목록 →
  `POST https://datafile.seoul.go.kr/bigfile/iot/inf/nio_download.do?&useCache=false` ·
  폼 `infId=OA-14991&seqNo=2607&seq=2607&infSeq=3` (seq = YYMM · infSeq 는 폼 hidden 값 3 · 1 로 보내면
  «잘못된 접근»). Referer 필요.
- **파일**: `LOCAL_PEOPLE_DONG_YYYYMM.zip` → CSV (UTF-8 BOM) · 열 = 기준일ID · 시간대구분(00~23) · 행정동코드 ·
  총생활인구수 · 남자 0~9 / 10~14 / … / 65~69 / 70세이상 (14구간) · 여자 같은 14구간. 값은 소수(추정치).
- **행정동 코드**: 통계청 2016 기준 **8자리** (예 11680640 = 역삼1동). 우리 행안부 10자리 코드의 앞 8자리와
  **415 / 424 일치** (나머지 9 = 2016 이후 분동·개편 · 서울시 안내: 「데이터 일관성을 위해 2016 집계 영역 유지 · 항동 없음」).
  → 붙일 때 8자리 접두 + 못 붙는 9곳은 «—».
- **크기**: 월 112MB CSV 를 저장소에 넣지 않는다 (ERP 방식). 빌드 스크립트가 **행정동 × 시간대 × 평일/주말** 로
  평균내 컬럼형 gzip JSON (424 × 24 × 2 × 30값 ≈ 600K 값 → 약 1MB gz) 만 커밋. 최근 3개월 평균이면 계절성도 눌린다.
- **값의 성격**: KT 기지국 기반 추정 + 서울시 공공데이터 보정. «추정» 을 화면에 적는다 (제1 원칙).

## 3. 추천 — 판 셋

### 판 A (다음 판 · 사장님 손 zero) — 「반경 안 시간대별 생활인구 (서울)」
- 원천 A + v0.3.513 의 행정동 표본점 비율 → **반경 안 시간대(24h) 생활인구 곡선** · 평일/주말 · 낮 최고 / 밤 최저 ·
  주간 유입 배율 (낮/밤) · 성·연령 구성 (14구간). 병원 마케팅의 핵심 물음 «이 자리에 낮에 누가 오나» 에 직접 답.
- 서울 밖 거래처는 «서울만 잽니다 (통신 생활인구 원천이 서울시만 공개)» — 0 이 아니라 «—» + 사유.
- 조달 경로는 이미 있다: 샌드박스 다운로드 → 집계 → Higgsfield → fetch-file → veo 데이터 폴더.

### 판 B — 「인구 이동 (전입·전출)」 전국 · 행정동
- 원천 B. 사장님이 공공데이터포털에서 **활용신청 1회** (자동승인) 하고, 콘솔 「외부 연결 열쇠」의
  공공데이터포털 열쇠 자리에 열쇠를 넣으면 (심평원과 같은 열쇠) 이 방이 붙인다. 월별 전입·전출·순이동 · 연령대별.
- 「이 시군구·행정동에 젊은 층이 들어오나 나가나」 — 개원 입지의 추세 신호.

### 판 C — 전국 유동인구 (사장님 결정)
- SKT 지오비전 퍼즐 (월 220만) 또는 KT PLIP 견적. SaaS 안에서 재배포 허용 조건이 계약의 핵심 (s17 §2).
- 결정 전까지 서울 밖은 판 A 의 «—» 로 정직하게.
