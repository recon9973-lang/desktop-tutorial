## 0. 한 줄 요약

거래처(병원·업체) **주소 하나를 좌표로 바꾸고**, 그 점을 중심으로 **500m·1km·3km·5km·10km 다섯 고리**에서
① 같은 진료과 경쟁 기관 ② 지하철역·버스정류장 ③ 연령·성별 인구를 **공공데이터로 자동 집계**해
거래처 상세에 **「입지」 탭**으로 그리고, 그 결과를 이미 있는 **키워드·AEO 질문·경쟁사 식별·리포트·이슈**에 공급한다.

```
주소 ──지오코딩──▶ 좌표·행정동코드
                      │
                      ▼
        ┌──── 반경 고리 5단 (500m / 1km / 3km / 5km / 10km) ────┐
        │  ① 경쟁     심평원 병원정보 API(좌표·반경·진료과목)        │
        │  ② 교통     국토부 지하철역·버스정류장 좌표 + TAGO 노선   │
        │  ③ 인구     행안부 주민등록(행정동×연령×성별) × SGIS 경계 │
        └──────────────────────────┬──────────────────────────────┘
                                   ▼
                      입지 스냅샷(기준일 판) ──▶ 「입지」 탭 그림
                                   │
        ┌──────────┬───────────────┼───────────────┬──────────────┐
        ▼          ▼               ▼               ▼              ▼
     키워드     AEO 질문 프리필   경쟁사 후보     리포트 §입지    이슈 규칙
   (역·동+과)  (regionLadder)   (/competitors)  (발행 불변)    (밀도·공백)
```

### 0.1 이미 있는 자산 — 베놈 ERP `/market` 상권분석 (2026-09-03 실측)
`marketing-agency-erp`(erp-v1, 운영 erp.seokorea.org v1.4.0 = 86c68cc)에 같은 4축의 **구 단위** 모듈이 이미 돌아간다.
이 기획안은 그것을 **좌표·반경 5단·거래처 기준**으로 확장하는 것이며, 아래 자산을 그대로 가져온다.

| ERP 자산 | 내용 | 이 기획안에서 |
|---|---|---|
| `src/server/data/region/hospital-points.json.gz` | 심평원 병원정보(2026.6) **79,764곳 좌표**, `radiusDensity()` 하버사인 반경 계산 | §3.2 미러 테이블의 초기 적재본 |
| `population-by-sgg.json` 외 10종 | 행안부 인구(시군구 255)·개폐업·진료과 수요·다빈도·상병 성연령 | §3.4 시군구 단위 보조 지표 |
| `scripts/build-region-data.py` | 원자료(`data/`) → 압축 데이터셋 빌드 | 월간 미러 갱신 스크립트의 출발점 |
| `analyzeRegion / analyzeRadius / searchCompetitors` 서버 액션 | 구 분석·시설명 기준 반경(1km 기본)·네이버 경쟁 검색 | API 설계(§4.2)의 참고 구현 |
| SGIS(연령·성별)·네이버 지역검색·공공데이터(상가) 키 스위치 | 키 없으면 해당 축만 «미수집» 강등 | §5.7 부분 실패 문법과 동일 |

**ERP 모듈이 못 하는 것 = 이 기획안이 채우는 것**: ① 반경 경쟁이 **종별(의원·치과의원…) 기준**이라 같은 진료과를 못 가른다
② 교통은 시군구 오디널 등급(0~3)뿐, 역·정류장 좌표가 없다 ③ 인구 연령은 SGIS 키가 있어야 하고 행정동·격자 단위가 아니다
④ 반경이 1km 단일이고 거래처와 연결되지 않는다(시설명 검색).

## 1. 왜 지금 이것인가 (현황과 공백)

| 현재 | 공백 |
|---|---|
| 거래처 폼에 **주소**가 있다(«동명 타업체를 가르는 기준»으로만 씀) | 좌표·행정동이 없어 **공간 계산이 불가능** |
| `location-auto` 스킬이 구(區) 단위 인구·병원 밀집도를 **수동 업로드**로 뽑는다 | 구 경계는 병원 상권과 무관(구 끝자락 병원은 옆 구가 진짜 상권). **거리 기반**이어야 한다 |
| 키워드 화면이 검색량 3종·질문 파생을 갖고, M4가 «업체 칩 → 질문 초안 8개»를 설계했다 | 질문 조립 재료인 **역명·동명·근처 경쟁 상호**가 사람 손으로 들어간다 |
| `/console/competitors`가 브랜드 신원 4요소·SOV 비교를 한다 | 경쟁사를 **누가 정하나** — 반경 안 실제 기관 목록이 없다 |
| 리포트가 발행 불변·판 규율을 갖췄다 | 입지 근거(«반경 1km 같은 과 12곳») 가 리포트에 없다 |

## 2. 사용자 시나리오 (거래처 기준)

1. 담당자가 거래처를 등록·수정하며 주소를 입력한다 → 저장 시 좌표·행정동코드가 붙고, 지도 위 핀을 **한 번 확인**한다(오지오코딩 방지).
2. 거래처 상세 **「입지」 탭**을 연다 → 첫 그림은 **동심원 지도 + 고리별 요약 표** 하나. 반경 칩(500m·1km·3km·5km·10km)을 고르면 아래 세 구역(경쟁·교통·인구)이 그 고리로 바뀐다.
3. 「이 결과로 키워드 만들기」 → 역명·동명×진료과 키워드가 키워드 화면에 초안으로 들어가고 검색량이 실측된다.
4. 「경쟁사 후보로 보내기」 → 반경 안 같은 과 기관을 체크해 브랜드 식별 화면의 비교 대상으로 등록한다.
5. 리포트 발행 시 **§입지**가 기준일·출처와 함께 발행본에 굳는다.
6. 월 1회 워커가 스냅샷을 다시 찍고, 이전 판과 **같은 기준 판일 때만** Δ를 표시한다(판 다르면 비교 금지).

## 3. 데이터 소스와 수집 방식 (실측 우선)

### 3.1 지오코딩 (주소 → 좌표)
| 후보 | 특징 | 판단 |
|---|---|---|
| 카카오 로컬 «주소 검색» | 도로명·지번 모두, 무료 한도 넉넉(콘솔 실측), 행정동(`region_3depth_h_name`)·법정동코드 동시 반환 | **정본** |
| 네이버 클라우드 Geocoding | 정확도 좋음, NCP 계정 필요 | 보조(불일치 검증) |
| VWorld(국토부) 지오코더 | 공공, 한도 있음 | 보조 |

- 저장: `lat`·`lng`·`h_code`(행정동)·`b_code`(법정동)·`geocoded_at`·`geocode_source`. 두 소스 좌표가 **200m 이상 벌어지면** «확인 필요» 상태로 두고 폼에서 핀을 옮기게 한다.

### 3.2 ① 경쟁 기관 (같은 진료과)
| 소스 | 무엇 | 반경 | 판단 |
|---|---|---|---|
| **심평원 병원정보서비스 OpenAPI**(공공데이터포털, 「병원·약국 찾기」) | 전국 요양기관 기본 목록. `xPos/yPos/radius`(m) 좌표 반경 검색, 종별코드(`clCd`)·진료과목코드(`dgsbjtCd`) 필터, 좌표 포함 | API 자체 지원 | **정본** — 월간 갱신 전수 파일도 있어 **자체 미러 테이블**로 두면 한도·장애와 무관 |
| 소상공인시장진흥공단 상가(상권)정보 API | 상가 단위 좌표·업종(보건의료 대분류), 반경·다각형 검색 | 반경 상한 있음(2km 안팎, 실측 확인) | 보조 — 비급여 위주(피부·미용) 상호 보강 |
| 카카오 로컬 카테고리(HP8 병원·PM9 약국)·키워드 검색 | 실시간, 반경 20km, **결과 45건 상한** | 넓은 고리는 못 센다 | **실시간 대조·플레이스 URL 확보용**(개수 산정 금지) |
| 네이버 지역검색(`search_local`) | 상위 5건 상한 | — | 「경쟁 상위 샘플」 표기 전용(개수 아님, 스킬 규칙 유지) |

- **진료과 매핑표**(업종 → 심평원 코드)를 한 곳에 둔다. 예: 피부→피부과(진료과목)+의원, 치과→치과의원·치과병원, 한방→한의원·한방병원, 정형→정형외과·재활의학과, 성형→성형외과, 다이어트·비만→가정의학과·내과·한의원(복수). 매핑은 사용자 편집 가능(«이 거래처의 경쟁 정의»).
- 산출(고리별): 총 기관 수, 종별 스택(의원·병원·종합·한의원·치과), **같은 과 기관 수**, 인구 1만 명당 같은 과 기관 수(= 경쟁 밀도), 가장 가까운 3곳(거리·상호·개설일). 개설일이 있으면 «최근 12개월 신규 개설» 도 셀 수 있다(심평원 필드 `estbDd`).

### 3.3 ② 교통 입지
| 소스 | 무엇 | 판단 |
|---|---|---|
| 국토교통부 **전국 지하철역 정보**(공공데이터포털) + 각 도시철도공사 역 좌표 | 역명·노선·좌표(좌표 없는 행은 지오코딩) | **정본(미러)** |
| 국토교통부 **전국 버스정류장 위치정보**(공공데이터포털, 정류장 ID·명·위경도) | 전국 정류장 좌표 | **정본(미러)** — 연 1~2회 갱신 |
| 국토교통부 TAGO 버스정류소정보 API(좌표 기반 근접 정류소·정류소 경유 노선) | 정류장별 **경유 노선 수** | 보조(500m·1km 고리만 — 근접 조회 반경이 짧다) |
| 카카오 로컬 SW8(지하철역) | 실시간 대조 | 보조 |

- 산출(고리별): 역 목록(역명·노선·직선거리·도보 예상 = 거리÷80m/분, «직선거리 기준» 단서), 정류장 수, 경유 노선 합계(잰 고리만), **가장 가까운 역까지 거리**. 도보 경로 실측(길찾기 API)은 유료·한도라 P3 이후.

### 3.4 ③ 인구 (연령 × 성별)
| 소스 | 무엇 | 판단 |
|---|---|---|
| **행안부 주민등록 인구통계**(jumin.mois.go.kr, 행정동 × 5세 구간 × 성별, 월간 CSV·OpenAPI) | 주민등록 기준 상주 인구 | **정본** — 행정동 단위 |
| **통계청 SGIS OpenAPI** — 행정구역 경계(행정동 다각형)·격자 통계 | 경계 다각형으로 원과 겹치는 면적을 계산 | **정본(경계)** |
| 통계청 센서스 집계구 | 더 잘게 나뉜 인구(5년 주기) | P3 정밀도 보강 |
| 통신사 유동인구(SKT·KT) | 시간대·요일별 실유동 | 유료 — 🔴 범위 밖(자리만 «—») |

- **반경 인구 산정법(면적 가중)**: 원 ∩ 행정동 다각형의 면적 비율 × 그 동의 연령·성별 인구. 등급 표기 🟡«추정(면적 가중)». 500m 고리는 동 하나가 통째로 걸쳐 오차가 크므로 «참고» 단서, 3km 이상에서 신뢰.
- 산출(고리별): 총인구·남·여·성비, **5세 구간 피라미드**, 핵심 타깃 비중(진료과별 기본 타깃 — 예: 피부·미용 20~44 여성, 정형 50+ 등, 편집 가능), 세대 수.

### 3.5 법·약관·저장 규칙
- 공공데이터(심평원·행안부·국토부·SGIS)는 공공누리 조건 확인 후 **자체 미러**로 저장(장기 보관 가능).
- 카카오·네이버 API 결과는 **약관상 저장 기간 제한**이 있으므로 캐시를 짧게(24h 안팎) 두고 개수 산정에 쓰지 않는다.
- 경쟁 기관 실명은 **콘솔 안**에서만. 공유 링크·공개 리포트에는 익명화(«A의원 · 320m»)를 기본으로 두고 실명 표시는 옵션(의료광고법상 타 기관 비교·비방 표현 금지 — 개수·거리 같은 사실만).

## 4. 계산·저장 설계 (veo-platform)

### 4.1 스키마(추가)
```
customers            + lat, lng, h_code, b_code, geocoded_at, geocode_source, geocode_status(ok|check|none)
customer_competition_profile   customer_id, dgsbjt_codes[], cl_codes[], target_age_band, target_sex  (경쟁 정의·타깃 정의)
location_snapshots   id, customer_id, taken_at, notation_version, source_versions(json: hira=YYYYMM, mois=YYYYMM, bus=YYYY, sgis=…)
location_ring_stats  snapshot_id, radius_m(500|1000|3000|5000|10000), competitors_total, competitors_same_dept, by_cl(json),
                     stations(json), bus_stops, bus_routes(nullable), pop_total, pop_m, pop_f, pop_by_age(json), households,
                     density_per_10k, estimate_flags(json)
location_pois        snapshot_id, kind(hospital|station|bus), ext_id, name, lat, lng, distance_m, attrs(json)
mirror_hira_hosp / mirror_bus_stops / mirror_subway_stations / mirror_hadm_boundary   (월·연 단위 미러)
```
- **판 규율 그대로**: 스냅샷마다 `source_versions`와 산정법 판(`notation_version`)을 박고, 판이 다르면 추이·Δ를 그리지 않는다(ADR 0010 방식).
- 스냅샷 **1회 = 10km 한 번 수집**하고 거리로 다섯 고리에 나눠 담는다(호출 5배 방지). 인구만 고리마다 면적 가중을 따로 계산.

### 4.2 API(콘솔)
```
POST /api/customers/{id}/geocode                → 좌표·행정동 확정(핀 수정 포함)
POST /api/customers/{id}/location/snapshots     → 수집 작업 큐 등록(워커)
GET  /api/customers/{id}/location?radius=1000   → 최신 스냅샷의 해당 고리 + 5고리 요약 표
GET  /api/customers/{id}/location/pois?kind=hospital&radius=3000
GET  /api/customers/{id}/location/history       → 같은 판끼리만 묶은 추이
```
- 거리: 하버사인(구면). 인구 면적 가중: 다각형 클리핑(shapely 또는 PostGIS `ST_Intersection` — DB에 PostGIS가 있으면 후자).
- 워커: 기존 큐(`/api/queue`)에 `location.snapshot` 작업 종류를 추가. 미러 갱신은 월 1회 정기 작업(심평원·행안부), 연 1회(정류장·역).
- 못 잰 값은 `null`로 두고 화면은 «—»(0 기록 금지 — 키워드 검색량 규칙과 동일).

## 5. 화면 설계 — 거래처 상세 「입지」 탭 (7번째 탭)

실물 공통 골격(상단 로고+AI 7종 스트립·하단 판 문구·다크 먹빛+민트·빈 상태 점선 상자) 위에 얹는다.
탭 순서: 진단 · SEO · GEO · AEO · **입지** · 이슈 · 리포트 (`lib/navigation.ts` `CUSTOMER_TABS`에 1행 추가).

### 5.1 첫 그림(히어로) — 동심원 지도 + 고리 요약 표
```
┌────────────────────────────────────────────┬─────────────────────────────────────┐
│  [지도]  거래처 핀 + 동심원 5개              │  고리   경쟁(같은과)  역  정류장  인구   │
│          같은 과 기관 = 민트 점               │  500m      3        0    6    4,120🟡 │
│          역 = 사각, 정류장 = 작은 점          │  1km       9        1   21   18,900🟡 │
│          반경 칩 ◉500m ○1km ○3km ○5km ○10km  │  3km      41        4  118  151,200  │
│                                            │  5km      88        9  260  402,000  │
│                                            │  10km    236       21  711 1,180,000 │
│  기준일 2026-09 · 심평원 2026-08 · 행안부 2026-08 │  (숫자는 예시 형식 — 실측으로 채움)     │
└────────────────────────────────────────────┴─────────────────────────────────────┘
```
- 지도는 **카카오맵 JS SDK**(지오코딩과 같은 키 계열) 또는 Leaflet+VWorld 타일. 다크 톤에 맞춰 타일 채도 낮춤.
- **반경을 고르면 지도 자체가 그 반경에 맞춰 확대·축소**된다(선택 고리 = 지도 가장자리, 바깥 고리는 사라지고 안쪽 고리만 남음). 고리 테두리만 바꾸지 않는다. 축척 막대가 같이 바뀐다(사장님 확정 09-03).
- 표는 tabular-nums, 추정치는 🟡 글자 표시(색만으로 말하지 않기). 선택 칩이 아래 세 구역의 기준 고리를 바꾼다.
- 어떤 «입지 점수»도 만들지 않는다(합산 점수 없음 원칙). 대신 **밀도 지표 한 줄**: «1km 안 같은 과 9곳 · 인구 1만 명당 4.8곳».

### 5.2 구역 A — 경쟁 (선택 고리)
- 종별 스택 막대(의원·병원·종합·한의원·치과) — 축 제목·단위·눈금 상시(M2 규칙).
- 거리순 목록: 상호·종별·거리·개설일·플레이스 링크(카카오 대조 결과 있을 때만). 체크 → 「경쟁사 후보로 보내기」.
- 보조 카드: «최근 12개월 신규 개설 N곳»(개설일 실측 있을 때만, 없으면 «—»).

### 5.3 구역 B — 교통
- 역 목록(역명·노선 색 칩+글자·직선거리·도보 예상, «직선거리 기준» 단서).
- 정류장 수·경유 노선 합계(잰 고리만; 3km 이상은 노선 «—»).
- 작은 지도 없이 목록만 — 히어로 지도가 이미 핀을 찍는다(서브 중복 금지 원칙).

### 5.4 구역 C — 인구
- **연령 피라미드**(5세 구간 × 남/여 양방향 막대), 타깃 구간은 민트 강조 + «타깃» 글자.
- 요약 칩: 총인구·성비·타깃 비중·세대 수. 산정법 팝오버(?): «행정동 인구를 원과 겹치는 면적 비율로 나눔 — 추정».
- 500m·1km 고리에서는 표 위에 «동 경계 오차 큼 — 참고용» 한 줄.

### 5.5 이력·발행
- 스냅샷 이력 썸네일(같은 판끼리만 선 연결, 판 바뀌면 점선 다리·Δ «—»).
- 「이 결과로 리포트 만들기」 고정 버튼(요구 1번 문법) → 리포트 §입지에 고리 표+피라미드+경쟁 개수(익명화 기본).

### 5.6 거래처 폼(등록·수정)
- 주소 입력 → 지오코딩 결과 핀 미리보기 + «맞음/옮기기». `geocode_status=check`면 목록에 «주소 확인» 칩.
- 업종 선택 시 §4.3 기본 경쟁 정의·타깃이 채워지고 접힌 «상세» 에서 편집.

### 5.7 빈 상태·오류 문법
- 좌표 없음: 점선 상자 «주소를 확인하면 입지를 잴 수 있습니다» + 「주소 확인」 동사 하나.
- 수집 전: «아직 측정 데이터가 없습니다» + 「지금 재기」.
- 소스 하나 실패: 해당 구역만 «못 읽음 · 심평원 응답 없음» — 나머지는 그린다(부분 실패 허용, 스냅샷에 실패 기록).

### 5.8 설정 → 「데이터 원천」 화면 (사장님 오더 2026-09-03: 데이터 관리를 쉽게)
**최고 관리자(owner) 전용** — 담당자·관리자에게는 메뉴 자체가 없고 주소로 열면 «권한 없음»(열쇠 화면과 같은 등급, 접근 시도는 감사 이력). 입지 탭이 그리는 모든 숫자의 **출처·기준일·적재일·갱신 방식**을 설정 묶음(usage·scoring-versions·credentials·team·account·changelog)에 한 화면 추가해 보여준다.
시뮬: `docs/ANSEO-데이터원천-설정-시뮬레이션.html`.

| 열 | 뜻 |
|---|---|
| 데이터 | 이름 + 쓰이는 곳(경쟁·교통·인구·지오코딩) |
| 출처 | 기관·데이터셋명·원문 링크(공공데이터포털·심평원·행안부·국토부·SGIS·카카오) |
| 기준일 / 적재일 | 원자료가 말하는 기준 시점 / 우리가 적재한 시각 |
| 갱신 | 주기(월·연·실시간) + 방식 **API 자동** / **파일 수동** / 키 필요 |
| 상태 | 최신 · 기한 지남(주기 초과) · 실패 · 키 없음 — 색+글자 병용 |
| 행동 | 동사 하나: API면 「지금 갱신」, 파일이면 「파일 올리기」(업로드→검증→적재→판 기록), 키 없으면 「키 등록」 |

- 파일 수동 갱신 흐름: 파일 올리기 → 형식·인코딩(cp949/utf-8)·행 수·좌표 결측 검증 결과 표시 → 「적재」 → `source_versions`에 새 기준일 기록 → 이후 스냅샷은 새 판. 지난 스냅샷은 그대로.
- 스키마: `location_sources(id, name, axis, provider, dataset, url, method(api|file|key), cadence_days, ref_date, loaded_at, rows, status, last_error, next_due)`.
- 기한 지남 판단: `loaded_at + cadence_days < today` → 상태 «기한 지남» + 대시보드 «할 일» 한 줄. 갱신 실패는 스냅샷 부분 실패와 같은 문법.
- 각 거래처 입지 탭 머리의 «기준일 · 심평원 YYYY-MM · 행안부 YYYY-MM»은 이 화면의 값을 그대로 읽는다(한 곳 정본).

### 5.9 공통 골격 — AI 스트립 연결 상태 신호등 (사장님 확정 09-03)
상단 «AI 7종 누적 답변» 스트립의 엔진마다 연결 상태 점을 신호등으로 둔다. **녹색 = 연결**(마지막 응답 시각), **주황 = 오류**(429·5xx·타임아웃, 재시도 중, 사유 코드 글자 병기), **빨강 = 연결 끊김**(키 만료·401·연속 실패, «끊김» 글자 + 설정 → 외부 연결 열쇠 링크). 색만으로 말하지 않는다 — 오류·끊김은 짧은 글자를 옆에 붙이고 툴팁에 사유·시각. 스트립 끝에 범례 3점. 전 화면 공통(입지·설정 시뮬에 반영, 실물은 스트립 부품 한 곳 수정).

## 8. 검증·품질

- **교차검증**: 남+여=총인구(행안부), 5고리는 단조 증가(안쪽 ≤ 바깥쪽), 10km 경쟁 수 = 심평원 반경 API와 미러 계산 ±5% 이내.
- **오지오코딩 방지**: 두 소스 200m 이상 차이 → check. 좌표가 행정동 경계 밖이면 오류.
- **성능**: 스냅샷 1회당 외부 호출 ≤ 10회(미러 위주), 화면은 스냅샷 읽기만(실시간 호출 없음).
- **시험**: 고리 분배 단위시험(경계값 499/500/501m) · 면적 가중 단위시험(원이 동 하나에 완전히 들어갈 때=그 동 비율) · «못 잰 값은 null» 관문 · 판 다르면 비교 거부 관문 재사용.
- **의료광고법**: 공개면 익명화 기본, 우열·최상급 문구 금지 검사(원고 검수 규칙 재사용).
