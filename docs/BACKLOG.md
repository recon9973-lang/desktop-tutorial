## SNS 소셜 로그인 (카카오·네이버·구글·애플)  — 보류

**요청 맥락**: "이메일 간편 로그인" 논의 중, 카카오/네이버/구글/애플 SNS 로그인 화면을 보고
"이런 기능"을 원함. 서비스별로 성격이 달라 그룹(realm)별로 나눠 설계하기로 결론.

### 핵심 결론 — 하나로 통일 X, 그룹별 최적화 O

| Realm | 서비스 | 추천 로그인 | 난이도 | 이유 |
|-------|-------|-----------|:--:|------|
| A. 직원 | **ERP** (marketing-agency-erp) | **구글** + 직원 화이트리스트 | 🟢 하 (~30분) | 에이전시=Google Workspace, 신원확인, 등록직원만 |
| B. 병원 고객(원장님) | **베놈사이트 AI 검색 진단** | **로그인 X → 연락처(이름+전화) 리드폼** | 🟢 하 | B2B 리드는 "가입"보다 가벼운 연락처가 전환↑, 로그인은 이탈 유발 |
| C. 일반 소비자 | **고객앱**(your-supplement 등) | **카카오** 우선 → 네이버 | 🟡 중 (~1h/1~2h) | 국내 소비자 점유율 = 카카오 압도적 |
| — | 전 서비스 | **애플은 후순위** | 🔴 상 | Apple 개발자 **유료 $99/년** + Service ID·JWT 서명 복잡. iOS 앱 낼 때만 |

### 기술 메모
- **OAuth(SNS)는 ID/PW와 달리 현재 DB 세션 방식 그대로 동작** → 세션 구조 변경 불필요 (ID/PW보다 오히려 깔끔).
- provider당 3단계: ①제공사 개발자콘솔 앱 등록 → ②client id/secret 발급 → ③auth 설정에 provider 추가 + redirect URI(`https://.../api/auth/callback/<provider>`).
- ERP User 모델에 `kakaoId String? @unique` **이미 있음**. 설정화면에 "Kakao Login — Auth.js OAuth 환경변수로 연결" placeholder도 있음(미구현).
- ERP 화이트리스트: `src/server/auth.ts` signIn 콜백이 등록 이메일만 통과 → SNS로 들어와도 미등록 차단됨(그대로 재사용).
- 네이버: NextAuth 기본 provider 없어 커스텀 OAuth 필요 + 서비스 URL 검수.

### 착수 시 추천 순서
1. ERP 구글 로그인 (직원 편의, 배포 흐름과 잘 맞음)
2. 진단 연락처 리드폼 (SNS 대신 가벼운 리드 수집)
3. 소비자앱 카카오 (상용 출시 시)
