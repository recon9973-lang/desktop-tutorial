## 1. 정보 구조(IA)

```
로고 영역    ANSEO  SEO · GEO · AEO · 네이버 키워드     (제품 축 4개를 로고 옆 상시 표기)

거래처 상세  진단 · SEO · GEO · AEO · 이슈 · 리포트     (탭 6개)
```

- 최상위 메뉴는 **업무 단위**(거래처·이슈·리포트·검수·관측·운영)이고, SEO·GEO·AEO는 **거래처 상세의 탭**이다. 사장님 확정사항(«SEO·GEO·AEO는 거래처 상세의 탭이고 최상위 메뉴로 안 올린다»)과 일치.
- 홈이 대시보드가 아니라 **«이번 주 실행»(작업 큐)**. 부제가 설계 선언문이다: «점수판이 아니라 작업 목록입니다. 앞 단계를 건너뛰면 뒤 단계 측정이 의미를 잃기 때문에, 작업 흐름 순서대로 놓고 그 안에서 품이 적은 것부터 세웁니다.»
- 모든 화면 상단에 **«표본» 배지**: «운영 콘솔에서 옮겨 온 표본 데이터입니다. 수집 파이프라인 연결 전까지 이 값으로 화면을 검증합니다.» — 목업임을 화면 스스로 선언. «저장됨» 배지(거래처·이슈 화면)는 «조직 데이터베이스에서 읽었습니다. 상태 변경은 이력으로 남습니다»로 저장 계층까지 구분한다.
- 푸터 고정 문구: «ANSEO가 계산하는 점수는 검색엔진과 AI 답변 엔진이 사이트를 읽을 수 있는 기술·구조 준비도입니다. 검색 순위를 예측하거나 보장하지 않으며, 수집한 값은 모두 출처와 수집 시각을 함께 표시합니다.»

## 2. 기능 워크플로우

### 2.1 핵심 루프 — 화면들이 그리는 상태 흐름

```
수집(크롤 40장) ─ 진단 실행(측정 39장) ──► 이슈 생성 ──► 실행 큐(이번 주 실행) ──► 사람이 조치
      ▲                                                                        │
      │                                                                        ▼
      └────────────── 재진단 ◄─── «재진단 대기» ◄─── «조치 중» ◄────────────────┘
                        │
                        ├─ 통과 → 이슈 자동 «닫힘» (사람이 닫을 수 없음)
                        └─ 실패 → 다시 «열림»
성공한 진단 실행 ──► 리포트 근거로 선택 ──► 발행본(불변 · sha256 · v버전) ──► 업체 전달
의료 규정 스캔(별도 축) ──► 후보 적발 ──► 사람이 «이슈로 올리기» ──► 위 루프에 합류
```

세 개의 불변 규칙이 루프를 지탱한다. 화면 문구 그대로:

1. **이슈는 사람이 닫지 않는다** — «닫힘은 사람이 누른 값이 아니라 재진단이 통과한 결과입니다.» (이슈 전역·거래처 이슈 탭·의료 규정에서 3회 반복)
2. **리포트에 수기 입력이 없다** — «숫자는 진단 실행에서만 옵니다» · «점수를 손으로 넣는 칸은 없습니다» · «발행본은 고칠 수 없습니다»(sha256·버전 고정, «발행본은 특정 진단 회차에 고정됩니다. 회차가 늘어도 이미 낸 문서의 숫자는 바뀌지 않습니다»)
3. **측정 실패 ≠ 0점** — «판정 못 한 항목은 0점으로 내리지 않고 분모에서 빼고 따로 셉니다» · «—는 아직 재지 않았다는 뜻이며 0점이 아닙니다» · «회색 칸은 0%가 아니라 진단 못 함입니다»

### 2.2 5단계 진행 퍼널 (이번 주 실행 상단 «어디가 막혀 있나»)

| 단계 | 질문 | 남은 일감 |
|---|---|---|
| 1 · 접근 | 읽을 수 있나 | **3** |
| 2 · 구조 | 무엇인지 알 수 있나 | **3** |
| 3 · 답변화 | 인용할 단위가 있나 | **2** |
| 4 · 관측 | 실제로 나오나 | 0 |
| 5 · 보고 | 설명할 수 있나 | 0 |

- «단계를 누르면 아래 목록이 걸러집니다» — 퍼널이 곧 큐의 필터(차트=내비게이션).
- 단계 의존성 각주: «1단계에 차단 항목이 있습니다. 접근이 막힌 주소가 있으면 그 뒤의 구조·답변화 점수는 **'낮다'가 아니라 '못 쟀다'** 입니다.» — 제품 제1원칙이 첫 화면 첫 카드에 있다.

### 2.3 실행 큐의 우선순위 로직

- 정렬 기준 공개: «오른쪽 막대는 **상승폭 + 품**입니다. 같은 시간을 넣었을 때 점수가 가장 많이 오르는 순서이며, 상승폭을 산정할 수 없는 항목은 0으로 내리지 않고 '산정 불가'로 둡니다.»
- 행 구성: 순번 · 문장형 제목 · 상태 배지 · 심각도 · 거래처 · 축 · metric id · 영향 주소 수 · 품(한 시간 안/반나절/여러 날) · 담당자 실명 · 기한 · 예상 상승폭.
- 집계도 분리: «예상 합계 +32.4 · 산정 불가 1건».

### 2.4 채점 모델 — SEO/GEO/AEO 3원 구조

| 축 | 성격 | 구조 | 환산 | 판정 종류 |
|---|---|---|---|---|
| SEO | 준비도 점수 | 6영역 · 배점 합계 128점 | 원점수/128×100 (41.70→32.58) | 감점·통과·판정 못 함·해당 없음 |
| GEO | 준비도 점수 | 5영역 · 배점 합계 100점 | 원점수=환산값 («배점 합계가 100이라 환산값과 같습니다») | 동일 4종 |
| AEO | **점수가 아니라 관측** | 물어봄→응답→언급→인용 4단 퍼널 | 단계마다 분모 상이, 합산 금지 | 언급됨·언급 안 됨·진단 못 함 |

- AEO 카드 제목이 «점수가 아니라 관측입니다». 분모 상이(215/215 → 208/215 → 30/215 → 22/**102**)를 매번 각주로 재설명: «출처를 주지 않는 엔진의 답변은 '인용 안 됨'이 아니라 '알 수 없음'으로 셉니다.»
- 채점 명세는 버전 관리(1.10.0)되며 «지금 명세로 다시 접기(재채점)» 버튼으로 저장된 원자료를 새 명세로 재계산한다.
- 항목마다 «판정 근거 → 실제로 본 응답·코드 조각 → 수정 내용(+기대 상승폭)»이 접힌 상세로 붙는다. openssl 핸드셰이크 출력, `<head>` 원문까지 증거로 첨부.

### 2.5 AEO 관측 절차 (탭 내 «키워드에서 AX 대응까지»)

1. **키워드 선별** — 검색량 상위 선별, 출처·수집 시각 기록
2. **질문 추출** — 실제 사용자가 물을 법한 문장으로 변환, 검수 후 확정
3. **7개 서비스 질의** — 동일 질문·동일 조건, 답변 원문 보관
4. **답변 구조화** — 출처 도메인·URL, 언급된 경쟁사, 인용 콘텐츠를 표로
5. **AX 대응 정리** — 서비스별·기간별 인용/밀림 비교 → 조치 항목 연결

- «검색량 조회는 **네이버 키워드**에서, 브랜드 식별자는 **브랜드 식별**에서 등록합니다» — 다른 모듈과의 연결 고리 명시.
- 질의 집합 규율: «발행한 집합만 매주 돕니다. 저장만 된 집합은 측정에 쓰이지 않습니다. **질문을 바꾸면 그 시점부터 추이가 갈라집니다.**»
- 답변 1건에서 구조화하는 필드: 답변 원문 / 출처 도메인·URL / 언급된 경쟁사 / 인용에 사용된 콘텐츠(페이지·문서) / 우리 거래처 인용 여부와 위치 / 서비스명·모델·실행 시각. «하나라도 얻지 못하면 0이 아니라 '진단 못 함'으로 남기고 사유를 함께 표시합니다.»

### 2.6 의료 규정(원고 검수)의 별도 축 설계

- «의료광고 심의 관점에서 별도로 세는 항목입니다. **일반 SEO 점수와 합치지 않습니다.**»
- 검사 방식이 항목마다 셋으로 구분: **자동 판정** / **후보만 수집** / **사람 확인** — 그리고 사전·페이지 요소로 판정 불가한 조항(거짓 광고·시술행위 노출·외국인환자 유치)은 «사전으로 찾을 수 없어 스캔하지 않음 = 진단 못 함»으로 정직하게 남긴다.
- 우선순위 레이블 3단: **먼저 볼 것 / 확인 필요 / 기록용**. 기계는 후보(55건)만 만들고, 사람이 «이슈로 올리기»를 눌러야 본 루프 합류. 올린 뒤에도 «사람이 닫지 않습니다. 문구를 고친 뒤 재진단이 통과해야 닫힙니다.»
- 법적 책임 경계 문구: «이 검사는 법률 자문이 아니며, 심의 소지가 있는 표현을 사람이 판단하도록 모아 줄 뿐입니다.»

## 3. 디자인 시스템

### 3.1 토대

- **다크 단일 기조**(라이트 토글 존재): 거의 순흑 배경 + 미세하게 밝은 카드 + 1px 보더 + 큰 라운드. 카드가 유일한 컨테이너 단위 — 전 화면이 카드 그리드 하나로 조립된다.
- **타이포 2원 체계**: 국문 산세리프(제목·본문) + 모노스페이스(**모든** 수치·백분율·metric id·코드·sha256). 숫자 열 정렬과 «측정값» 정체성을 타이포로 만든다.
- **컬러 시맨틱**: 파랑=우리/중립 측정, 초록=통과·양호·개선(+), 주황=중요·경고·깎임, 빨강=차단·심각·감점(-). 증감은 ▲초록/▼빨강 삼각형. 심각도 4단(차단·심각·중요·경미)과 상태 5단(열림·조치 중·재진단 대기·닫힘·판정 못 함)이 모두 이 팔레트의 배지로 처리.

### 3.2 반복 패턴 — 이 시안의 서명

1. **아이브로우 + 질문형 제목**: 모든 카드가 `자간 넓힌 소형 레이블`(예: `깎인 점수 구성`) 다음에 질문/문장형 제목(«총 손실이 어디서 나왔나» «누가 대신 인용되고 있나» «이 점수가 어디에 서 있나» «어느 AI가 우리를 부르나»). 차트 제목이 '무엇을 그렸나'가 아니라 '무슨 질문에 답하나'를 말한다. **27개 타일 전체에서 예외 0건.**
2. **각주 해설**: 카드 하단마다 회색 한 줄로 읽는 법·함정을 설명. 인포그래픽마다 «이 차트를 오독하는 법»을 선제 차단하는 문구가 붙는다(각 화면 전수 기록 참조).
3. **증거 접기**: 항목 행 → 판정 근거 + 실측 코드 조각 + 수정 방법(고치면 +N) 세트.
4. **CTA 절제**: 화면당 파란 버튼 1~2개(«+ 새 업체 등록», «이슈로 올리기», «재채점», «집계»). 나머지는 링크(«전체 이슈 보기 →», «항목별 근거 보기 →», «호출량·비용 보기 →», «칸별로 보기», «버전 열람·내보내기 →»)이거나 읽기 전용.
5. **한계 자백 카드**: «이 점수가 덮지 못한 것», «발행 리듬 — (달이 하나뿐이라 리듬은 그리지 않습니다)» 같은, 못 그린 것·못 잰 것을 **말하는 자리**가 레이아웃에 상설로 있다.

### 3.3 디자인 리스크

- **회색 보조 텍스트 대비 부족**: 순흑 위 중회색 각주·레이블 다수가 WCAG AA(4.5:1) 경계로 보인다. 각주가 이 시스템의 핵심 장치이므로 한 단계 밝혀야 한다.
- **metric id 노출**(`seo.onpage.title_present_and_unique` 등): 운영자 콘솔에선 추적성에 유리하나 업체 전달 발행본에 그대로 나가면 안 된다 — 발행 템플릿의 번역 레이어 확인 필요.
- **세로 길이**: 거래처 상세 AEO 탭 원본 10,718px, 의료 규정 17,250px. 섹션 앵커·카드 접기 없이는 후반 카드 도달률이 낮을 것.
- 의료 규정 히트맵의 빨강 농도 스케일 기준(최댓값 정규화인지 절대 구간인지)이 화면에 없다.

## S12. /console/dashboard — 소스 코드 검증 (Lovable 커넥터 경유)

> 프리뷰 URL 은 이 작업 환경의 네트워크 정책이 차단하지만(아래 «접근 확인 로그»), Lovable 커넥터로 프로젝트 소스에 접근해 **코드 자체를 판독**했다(커밋 `216233be`). 그 결과 `/console/dashboard` 는 **S1 «이번 주 실행» 화면의 구현체**임이 확인됐다 — 라우트 head 타이틀이 «이번 주 실행 — ANSEO 콘솔», 부제도 S1 과 동일. 아래는 스크린샷(정지 화면)으로는 볼 수 없던 것들이다.

### S12.1 인터랙션 레이어 (코드에서만 보이는 동작)

- **단계 퍼널 = 실제 필터**: `StageFlow` 클릭 → 실행 큐가 그 단계 항목으로 걸러지고, 큐 제목이 «{단계명} 단계 N건»으로 바뀌며, 우상단에 «전체 보기» 해제 버튼이 나타난다. 같은 단계 재클릭 = 해제(토글).
- **상태 반응형 각주**: 퍼널 하단 문구가 조건 분기한다 — 차단 항목이 있으면 «…'낮다'가 아니라 '못 쟀다'입니다», **없으면 «접근 단계가 비었습니다 — 뒤 단계 점수를 그대로 신뢰할 수 있습니다.»** 오독 방지 각주가 정적 캡션이 아니라 상태를 읽는 문장.
- **큐 행의 이중 링크**: 제목 → 이슈 상세(`/console/issues/$issueId`), 거래처명 → 거래처 상세. 실행 큐가 곧 내비게이션 허브.
- **정렬 기준의 최신 표기**: 각주가 «상승폭 **÷** 품»으로 코드에 있다(스크린샷 판은 «상승폭+품»). 막대(`LeverageBar`)는 큐 내 최대 leverage 로 정규화.
- **AEO 카드의 형식 분리는 코드 주석으로도 선언**: `{/* AEO — 점수가 아니라 관측 횟수. 0~100 게이지를 쓰면 준비도와 같은 척도로 오해된다. */}` — 디자인 원칙이 주석으로 코드에 박제. AEO 카드 안에 4단 미니 퍼널 바가 인라인으로 들어가고, 언급·인용 단만 ember 색으로 구분.
- **사분면 점에는 라벨 데이터가 이미 전달됨**(`label: c.name`) — §7-2 권고(라벨 표기)는 `Quadrant` 컴포넌트 렌더링만 열면 되는 상태. 점 색은 3值: 차단 보유=destructive, 관측 돌아감(aeoRuns>0)=mint, 그 외=signal — 스크린샷에서 «빨강/파랑»으로만 보이던 것이 실은 3단계.
- **동적 head 메타**: 라우트별 title·description·og 태그 지정 — 콘솔 자체도 자기 제품의 원칙(메타 채우기)을 지킨다.
- **조직명 개인화**: 제목이 `{membership.organizationName} · 이번 주 실행` — 멀티테넌트 전제.

### S12.2 IA 의 단일 소스 — `src/lib/navigation.ts`

내비게이션이 파일 하나로 강제되며, 머리 주석에 규칙이 명문화돼 있다: «화면 코드가 메뉴 이름을 따로 적지 않는다 — 이름·차례가 어긋나는 사고를 막기 위해 헤더·계정 메뉴·거래처 탭이 전부 이 파일 하나를 읽는다.»

**자리(place) 5종 분류**:

| place | 규칙 | 항목 |
|---|---|---|
| BRAND | 로고 자체가 그 화면. 메뉴에 안 건다 | 대시보드(=이번 주 실행) |
| MENU | 헤더에 이름 그대로 | 거래처 · 이슈 · 리포트 |
| TOOL | 헤더+계정 메뉴 양쪽 | 원고 검수(**의료 업종 조직에만 노출** — `industry: "MEDICAL"` 게이트) |
| GROUP | 묶음 메뉴 | AEO 관측(키워드 · 경쟁 도메인 · AI 답변 검수) / 운영(사용량·비용 · 채점 기준 버전 · 외부 연결 열쇠 · 팀원 관리 · 사이트맵·파이프라인 · 변경 이력) |
| ABSORBED | 헤더에 안 뜸, 다른 화면 링크로만 진입 | 거래처 등록 · 프로젝트 · 내 계정 — **각각 `enteredFrom`(실제 입구) 명기 의무** |

- **원칙 0-E가 주석으로 선언돼 있다**: «부를 수 없는 기능은 없는 기능이다. ABSORBED 항목은 반드시 enteredFrom 에 실제 입구를 적어 둔다. …비어 있으면 죽은 화면이다.» — 죽은 라우트(고아 화면)를 데이터 구조 차원에서 금지.
- 거래처 상세 탭 6개(진단/SEO/GEO/AEO/이슈/리포트)도 같은 파일의 `CUSTOMER_TABS` 가 순서·이름의 단일 소스.

### S12.3 라우트 전모 (스크린샷 11장 밖의 화면들)

소스의 라우트 파일로 확인된 전체 화면: 스크린샷으로 본 7종 외에 **키워드**(질문을 뽑는 검색량 표본) · **경쟁 도메인**(AI 답변에서 우리 대신 인용되는 곳 — S6-⑰의 전역판) · **AI 답변 검수**(사람이 확인해야 할 관측 답변) · **사용량·비용**(S1-⑪ «호출량·비용 보기» 링크의 목적지) · **채점 기준 버전**(명세 1.10.0 의 관리 화면) · **외부 연결 열쇠**(«열쇠 만료일 수 있습니다» 경보의 해결 화면) · **팀원 관리 · 사이트맵·파이프라인 · 변경 이력 · 거래처 등록 · 프로젝트 · 내 계정**, 그리고 콘솔 밖의 **`/results/$token`(업체에 주는 공유 결과 링크)** · **`/invite/$token`(초대 가입)** · **`/login`**(공개 가입 없음 — 초대 전용, 로그인 화면 좌측에 «측정 원칙» 5문장을 전시). 스크린샷의 경보·링크가 가리키던 목적지 화면이 전부 실재한다 — **매달린 링크 없음.**

### S12.4 소결

대시보드 코드는 시안 분석(제1~3부)의 결론을 그대로 확인시킨다: 질문형 제목·오독 방지 각주·형식 분리(게이지 vs 퍼널)·CTA 절제가 컴포넌트와 주석 수준까지 내려가 있고, IA 는 단일 소스 + 진입점 의무화로 구조적 부패(이름 불일치·죽은 화면)를 데이터 타입으로 막는다. 스크린샷 판과 어긋난 유일한 지점은 정렬 각주 표기(«+» → «÷»)로, 코드 쪽이 의미상 정확하다(같은 시간 대비 상승).

| 11 | 방사형 동심 아크 | S6-⑦ | 엔진별 %를 아크 길이로 | ✕ **유일한 실패작.** 안쪽 궤도일수록 같은 %가 짧게 그려지는 반지름 왜곡 + 분모 다른 %(Perplexity 100% 분모↓ vs ChatGPT 50%)가 같은 무게로 보임. 수평 막대+분모 병기(«n/N») 교체 권고 |
| 12 | 멀티라인 추이+끝 라벨 | S6 ×2회 | 5브랜드 색, 우측 끝 이름+% | ◎ 범례 왕복 제거. «못 잰 회차는 선을 끊고 점으로» — 결측 처리 정석 |
| 13 | 질문×엔진 히트맵 | S6-⑧ | 셀=언급률, 점선=못 잼 | ○ 값 병기로 판독 가능 |
| 14 | 거래처×항목 히트맵 | S11-① | 농도=적발 수, —=못 읽음 | ○ 0/— 구분 방어. 농도 스케일 기준 미표기 |
| 15 | 축×심각도 매트릭스 | S9-② | 3×4 건수 | ○ 작지만 질문에 정확히 답함 |
| 16 | 회차별 판정 띠 | S7·S9 | 칸=회차, 채움=판정, 점선=못 잼 | ◎ «언제부터 앓던 문제인가»를 4칸으로 압축 |
| 17 | 랭킹 롤리팝 | S11-⑥ | 점+선+건수 | ○ «건수는 위험이 아니라 분량» 각주가 백미 |
| 18 | 3단 감소 깔때기 | S2·S8·S10 ×3회 | n/12+감소분(-8·-4/-2) | ◎ 병목=감소 폭 직독. «깔때기의 목» 언어까지 |

## 5. 인포그래픽 문법의 3원칙 (전 차트 공통)

1. **분모가 다르면 절대 합치지 않는다** — AEO 퍼널 마지막 단(22/102), 게이지·바 형식 분리, «한 숫자로 합치지 않습니다» 반복.
2. **빈 값 3종 구분** — `0`(측정했고 없음) / `—`(재지 않음·분모 제외) / `점선 칸`(판정 못 함). 표·히트맵·와플·띠 전부에 일관 적용, «0과 구분해서 읽습니다» 명문화.
3. **모든 차트에 «오독 방지 각주»** — 18종 중 각주 없는 유형이 없다. 극단 사례: 발행 리듬 KPI는 «달이 하나뿐이라 리듬은 그리지 않습니다»로 차트 자체를 거부.

# 제4부 — 종합 평가

## 6. 이 시안의 자산 (본 구현에 이식 가치)

1. 질문형 카드 제목 + 오독 방지 각주의 짝 — 화면 문해력을 만드는 최상위 장치.
2. 빈 값 3종(0 / — / 판정 못 함)과 «측정 실패 ≠ 0점» 원칙의 전면 적용.
3. 실행 큐의 «상승폭+품» 정렬, 산정 불가 분리 집계, 품·담당·기한 병기.
4. AEO 퍼널의 분모-감소 주석 표기법과 «점수가 아니라 관측» 형식 분리.
5. 발행 깔때기(감소 폭=병목)와 발행본 불변성 UI(sha256·버전·«고칠 수 없습니다»).
6. 증거 접기(판정 근거→실측 코드→수정 방법+기대 상승폭) — 컨설팅 리포트의 신뢰 골격.
7. 사용 불가 엔진도 사유와 함께 목록 유지(«빼면 '여기 있는 게 전부'로 읽힙니다»).
8. 의료 규정의 검사 방식 3분류(자동 판정/후보만 수집/사람 확인)와 신호 어휘 사전·가이드라인 페이지 인용.
9. 한계 자백 카드(«이 점수가 덮지 못한 것», 발행 리듬 —).

## 7. 고칠 것 (디자인·구성 관점 · 우선순위순)

1. **[차트] 방사형 아크(S6-⑦) 교체** — 안쪽 궤도일수록 같은 값이 짧게 그려지는 반지름 왜곡 + 분모가 다른 %가 같은 시각 무게로 보이는 문제. 수평 막대 + 엔진별 분모(n/N) 병기로.
2. **[차트] 산점도(S1-⑥) 라벨** — 거래처가 십여 곳이면 점에 이름을 직접 붙일 수 있다. 동좌표 겹침 처리(지터/묶음) + «판 밖(못 잰 곳)»의 시각 표기 자리도 필요.
3. **[접근성] 회색 보조 텍스트 대비 상향** — 각주가 이 시스템의 핵심 장치인데 순흑 배경 위 중회색이 AA 경계. 한 단계 밝게.
4. **[범례] 색·스케일 기준 명시** — 와플의 파랑(SEO 계열)/초록(GEO 계열) 색 구분, 의료 규정 히트맵의 농도 스케일 기준이 화면에 없다.
5. **[UX] 초장문 화면 항해** — AEO 탭(약 10,700px)·의료 규정(약 17,000px)에 섹션 앵커 또는 카드 접기. 없으면 후반 카드 도달률이 떨어진다.
6. **[구성] 게이지의 의미 구분** — 이번 주 실행의 게이지(전 거래처 평균)와 거래처 상세의 게이지(개별 환산)가 같은 형태라 스캔 시 혼동 여지. 평균 게이지에는 분포(최저—최고)가 부제로만 있으니 형태 차이(예: 범위 밴드)를 주는 것도 방법.
7. **[발행] metric id·내부 용어의 고객용 번역 레이어** — `seo.onpage.*` 같은 id는 콘솔에선 추적성 자산이지만, 업체 전달 발행본 템플릿에서는 일반어로 번역돼야 한다.

## 8. 부록 — 코드 분석: 브랜드 식별 관문 (IdentityGate / IdentityCard / IdentityBadge)

시안과 함께 공유된 React 컴포넌트(`@/data/anseo-identity` 소비)를 같은 잣대로 분석한다.

### 8.1 워크플로우상의 위치 — «관측 앞의 관문»

파일 머리 주석이 설계 의도를 그대로 말한다: «AEO 언급률보다 앞에 놓인다 — 식별이 안 된 거래처의 언급률은 '낮은 값'이 아니라 '셀 수 없는 값'이기 때문이다. 그래서 여기서는 **점수를 그리지 않고**, 몇 곳이 잴 수 있는 상태인지와 무엇이 비어서 못 재는지만 보여 준다.»

- 시안의 제1원칙(측정 실패 ≠ 0점)을 **화면 이전 단계(게이트)로 끌어올린 구현**이다. 5단계 퍼널의 «앞 단계가 막히면 뒤는 못 잰 것» 논리가 AEO 안에서도 반복된다: 식별 → 관측.
- 상태 3단(측정 가능 / 일부 등록 / 등록 안 됨) + 파생 지표 «식별 못 해 검수로 넘어간 언급(pending)» — 등록 미비의 비용을 «검수 대기 적체»라는 작업량으로 번역한다. 점수가 아니라 일감으로 보여 주는 이번 주 실행의 어법과 동일.
- «인용에 나왔는데 등록 안 된 곳(unregisteredCitedDomains)» KPI는 S6-⑰ «누가 대신 인용되고 있나»와 맞물린다 — 관측이 발견한 미등록 도메인이 등록 후보로 되돌아오는 **피드백 루프**가 데이터 모델에 있다.
- IdentityCard 하단 «검수 대기 N건 — **등록을 채우면 자동 판정으로 내려갑니다**» — 시안의 «고치면 +N» 어법(조치→효과 예고)과 같은 마이크로카피 문법.

### 8.2 디자인 시스템 일치도

| 시안의 패턴 | 코드에서의 구현 |
|---|---|
| 아이브로우+질문형 제목 | `eyebrow` 클래스 + «이 그림이 답하는 것 — 지금 이대로 재면 무엇이 보류로 쌓이나» |
| 오독 방지 각주 | 카드 하단 «한국 병원 상호는 겹칩니다 — '서울치과'는 수십 곳입니다. …낮게 나온 언급률은 '성과가 없다'가 아니라 '가릴 수 없다'입니다.» |
| 빈 값 문법(점선=못 잼) | 미입력 필드 = `border-dashed` 투명 필, 입력 = `bg-signal` 채움 — 와플·히트맵의 점선 칸 문법을 필드 게이지로 이식 |
| 컬러 시맨틱 토큰 | `mint`(가능)/`ember`(경고)/`unknown`(못 잼)/`signal` — 토큰 이름 자체가 차트 문법을 인코딩. `text-mint` 같은 하드코딩 hex 없음 |
| 모노스페이스 수치 | `num`·`metric` 유틸 클래스 — 2원 타이포 체계 유지 |
| 상태 배지 | `IdentityBadge` 점+라벨, `Record<status, …>` 완전 매핑(타입이 상태 추가 시 갱신 강제) |
| 한계·이유 병기 | 필드마다 `f.why`(왜 필요한가)와 가중치 `f.weight` 노출, 빈 필드에 «비어 있음 — {why}» |

구성도 시안의 카드 문법 그대로: 제목 → 시각(스택 바) → 범례 → KPI 3분할(문제 우선 배치: ember→unknown→mint) → 각주.

### 8.3 코드 관찰 (품질·견고성)

잘 된 것:
- `STATUS`를 `Record<IdentityRecord["status"], …>`로 선언 — 상태 열거 누락을 컴파일 타임에 잡는다.
- 분모 0 가드(`|| 1`), 0건 세그먼트는 바에서 숨기되 **범례에는 유지**(범례 안정성 — 시안의 «빼면 전부로 읽힌다» 원칙과 상통).
- 세그먼트 경계를 `border-background`로 처리해 어느 테마에서든 분리선이 유지되는 트릭.

다듬을 것:
1. **`values` 매핑의 타입 느슨함** — `Record<string, string[]>` + `values[f.key] ?? []`라서 `IDENTITY_FIELDS`에 필드가 추가되면 조용히 «비어 있음»으로 렌더된다(데이터 형상 불일치가 은폐됨). `Record<(typeof IDENTITY_FIELDS)[number]["key"], string[]>`로 좁히거나 `satisfies`로 강제 권고.
2. **status와 채움 게이지의 이중 근원** — 배지 `record.status`와 `filledFields(record)`가 따로 온다. 파생 가능하면 한쪽에서 유도하거나 불일치 시 개발 모드 경고를.
3. **툴팁 의존** — 세그먼트 수치·필드 사유(`f.why`)가 `title` 속성에만 있어 터치 기기·스크린리더에서 소실. 시안의 «각주» 원칙과 어긋나는 유일한 지점 — 바에 `role="img"`+`aria-label`, why는 접히는 텍스트로.
4. **세그먼트 위 숫자 대비** — `text-background`(다크에서 짙은 색)를 mint/ember 위에 얹는 방식은 라이트 테마에서 background 토큰이 뒤집힐 때 대비가 무너질 수 있다. 세그먼트 전경색 토큰을 따로 두는 편이 안전.
5. **`collisionRisk` 이분 처리** — `high`가 아니면 전부 «고유한 상호»로 표기. 타입에 중간 단계가 있다면 스위치로 전개해야 한다(STATUS처럼 Record 매핑 권장).
6. 소소한 것: `seg`의 라벨·색이 `STATUS`와 중복 선언(한쪽에서 파생 가능), `text-[11px]` 반복은 캡션 토큰화 여지, 라벨 열 `86px` 고정폭은 긴 한글 라벨에서 줄바꿈 확인.

### 8.4 소결

이 컴포넌트는 시안의 4원칙 중 «측정 실패 ≠ 0점»을 데이터 진입 단계로 확장한, 문법적으로 가장 충실한 구현 사례다. 헤더 주석·마이크로카피·토큰 명명까지 제품의 목소리가 코드 레벨에 일관되게 내려와 있다. 다듬을 것은 전부 국소적(타입 좁히기, 이중 근원, 툴팁 접근성, 테마 대비)이고 구조 변경은 필요 없다.

## 9. 총평

«점수판이 아니라 작업 목록» · «점수가 아니라 관측» · «사람이 닫지 않고 재진단이 닫는다» · «숫자는 진단 실행에서만 온다» — 네 문장이 IA·워크플로우·차트 문법·마이크로카피 전부를 지배하는, 원칙 일관성이 대단히 높은 시안이다. 27개 타일 전수에서 흐름·기능·구성의 구조적 결함은 발견되지 않았고, 고칠 것은 전부 국소적이다(차트 1종, 라벨·범례, 대비, 장문 항해). 특히 «측정하지 못한 것»을 다루는 규율(3종 빈 값, 분모 제외, 한계 자백 카드)은 대시보드 설계 일반에서 보기 드문 수준으로, ANSEO 실물 구현의 기준 문서로 삼을 만하다.

# 제5부 — 확장 흐름 대비 현 콘솔 구조 분석

> 사용자(제품 오너)가 밝힌 목표 흐름과 담당 체계를 기준으로, 현 콘솔(스크린샷 11장 + 소스)의 화면들이 어디까지 덮고 어디가 비어 있는지를 매핑한다. AEO 관측·운영 두 묶음 메뉴는 **타이틀만 있고 내용은 작업 중**임이 확인된 전제다.

## 10. 목표 흐름 7단계와 현 화면의 매핑

목표 흐름: **진단 → 관측 → 콘텐츠 추출 → 콘텐츠 분석 → 콘텐츠 제안 → 재관측 → 진단** (순환)
차별점: 자사 콘텐츠와 AI 가 인용하는 콘텐츠를 분석해 **«다음에 어떤 콘텐츠로 작업할지»까지** 보여 주는 것.

| 목표 단계 | 현 콘솔의 대응물 | 상태 |
|---|---|---|
| ① 진단 | 거래처 상세 진단/SEO/GEO 탭, 채점 명세·재채점, 이슈 생성 | **완성** — 시안·코드 모두 갖춰짐 |
| ② 관측 | AEO 탭(질문×엔진 관측), 대시보드 AEO 퍼널, 키워드→질문 절차 | **완성**(개별 거래처 수준). 전역 화면(키워드·경쟁 도메인·AI 답변 검수)은 껍데기 |
| ③ 콘텐츠 추출 | 부분 소재만 존재: AEO 탭 «답변이 제시한 출처 N건»(URL 목록), «누가 대신 인용되고 있나»(도메인 표), 인용에 사용된 콘텐츠 필드(관측 구조화 6필드 중 하나) | **화면 없음** — 데이터는 이미 잡고 있으나 «인용된 콘텐츠를 모아 보는 자리»가 없다 |
| ④ 콘텐츠 분석 | 없음. 가장 가까운 것은 GEO 탭의 답변 가능성/구조화 점검(자사 콘텐츠의 «형식» 분석)뿐 — «내용» 분석(주제·질문 커버리지·인용 콘텐츠와의 비교)은 부재 | **화면 없음** |
| ⑤ 콘텐츠 제안 | 없음. 실행 큐는 기술·구조 조치(태그·인증서·스키마)의 큐이지 콘텐츠 제작 큐가 아니다 | **화면 없음** — 차별점의 핵심인데 현 IA 에 자리 자체가 없다 |
| ⑥ 재관측 | 집계(저장된 관측 다시 세기), 회차별 추이(질문을 바꾸면 추이가 갈라진다 규칙) | **완성** — 다만 «제안한 콘텐츠가 나간 뒤 언급률이 움직였나»를 잇는 고리는 없다 |
| ⑦ 재진단 | 재진단 대기 → 자동 닫힘 상태 머신, 재채점 | **완성** |

**구조적 결론**: 현 콘솔은 ①②⑥⑦ — 즉 **«재는 쪽» 반원은 완성**돼 있고, ③④⑤ — **«만드는 쪽» 반원이 통째로 비어 있다.** 이것은 결함이 아니라 작업 순서(측정 기반을 먼저 세움)로 읽히지만, 차별점이 ⑤(콘텐츠 제안)에 있다면 다음 설계는 아래를 채워야 한다:

1. **콘텐츠 추출 화면** — 관측이 이미 수집하는 «인용된 콘텐츠(페이지/문서)»를 거래처·질문·엔진 축으로 모아 보는 자리. 경쟁 도메인 화면(껍데기)의 자연스러운 확장: 도메인 수준 → **문서 수준**으로 한 단계 내려가면 된다.
2. **콘텐츠 분석 화면** — 자사 문서 vs 인용된 타사 문서의 비교 축이 필요하다. 현 문법에 맞는 형태: «이 질문에서 AI 가 인용한 콘텐츠는 무엇을 갖췄고 우리 문서엔 무엇이 없나»를 GEO 항목 문법(감점/통과/판정 못 함)으로 재사용.
3. **콘텐츠 제안 큐** — 실행 큐와 같은 문법(우선순위·기대 효과·품·담당·기한)으로 «만들 콘텐츠» 목록을 세우는 화면. 기존 «상승폭 ÷ 품» 정렬이 그대로 이식 가능하며, 제안→발행→⑥재관측으로 잇는 상태 머신(이슈의 열림→조치→재진단→닫힘과 동형)을 붙이면 흐름이 닫힌다.
4. **재관측과의 연결 고리** — 제안된 콘텐츠에 «발행일» 마커를 추이 차트에 찍어, «질문을 바꾸면 추이가 갈라진다»와 같은 규율로 «콘텐츠가 나간 뒤»를 읽게 한다.

현 5단계 퍼널(접근→구조→답변화→관측→보고)과 목표 7단계는 충돌하지 않는다 — 퍼널의 «답변화»가 ③④⑤로 세분되는 관계다. 대시보드 퍼널을 7칸으로 늘리기보다, «답변화» 칸을 누르면 콘텐츠 추출→분석→제안 하위 흐름이 열리는 2계층이 현 문법(단계 클릭=필터)에 더 맞는다.

## 11. 담당 체계 대비 현 화면

목표 체계: **최고 관리자 1~3명**(전체 진단·관측 책임) + **콘텐츠 담당자 1명당 거래처 10곳**.

현 콘솔에서 확인되는 것:
- 실행 큐·이슈에 **담당자 개인 이름**(이재훈·정수민·김하늘·박도윤)이 항목 단위로 붙는다 — 항목 단위 배정 모델.
- 헤더에 «관리자» 역할 표시, 팀원 관리 화면 존재(내용 미확인), 대시보드 제목의 조직명 개인화(멀티테넌트).
- 거래처 목록의 «맡은 곳 11곳» 표현과 ★고정 5곳 — «내 담당»의 씨앗은 있으나 담당자별 필터는 화면에 없다.

목표 체계와의 간극:
1. **역할 2종의 화면 분리가 없다.** 최고 관리자(전 거래처 진단·관측)와 콘텐츠 담당자(내 10곳)는 첫 화면부터 달라야 한다 — 관리자는 지금의 대시보드(전 거래처 관제탑)가 맞고, 콘텐츠 담당자는 «내 10곳의 콘텐츠 제안 큐»가 첫 화면이어야 한다. 현 IA 의 BRAND(로고=대시보드) 규칙에 역할 분기를 넣을 자리가 필요하다.
2. **배정 단위의 전환** — 현재는 이슈(항목) 단위 담당인데, 목표는 거래처 단위 담당(1인 10곳). 거래처에 담당자 필드를 두고 이슈 담당은 그로부터 상속하는 쪽이 목표 체계와 맞는다. «맡은 곳 N곳» 카운트도 조직 전체가 아니라 «내» 것이 된다.
3. **10곳 규모에 맞는 화면 밀도** — 콘텐츠 담당자 화면은 거래처 11곳 목록이 아니라 10곳 × 콘텐츠 파이프라인 상태(추출됨/분석됨/제안됨/발행됨/재관측 중)의 보드형이 자연스럽다. 관리자 화면의 «사람이 봐야 하는 것» 문법을 담당자용으로 바꾸면 «오늘 만들 것»이 된다.
4. **책임의 분모 표기** — 이 제품의 문법대로라면 담당자 화면에도 분모가 붙어야 한다: «10곳 중 관측이 도는 곳 7 · 제안 대기 3» 식으로, 관리자의 진단·관측 책임과 담당자의 콘텐츠 책임이 서로의 분모를 침범하지 않게.
