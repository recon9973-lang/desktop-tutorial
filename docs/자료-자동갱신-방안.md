# 자료를 손으로 올리지 않고 «기계가 받아 오게» 하는 방안

사장님 지시 2026-09-27: **«인구는 계속 변하는 데이터인데, 파일로 올리는건 장기적 관점에서
허점이 많아. api 데이터 활용 방안을 마련해»**

## 지금 무엇이 손으로 들어오나

| 자료 | 지금 | 문제 |
| --- | --- | --- |
| 인구·남녀·나이대 | ANSEO 저장소에 든 **파일**을 읽는다 | 달이 바뀌면 낡는다. 그 파일에 **세종이 통째로 빠져** 있어 세종만 손으로 채웠다 |
| 병의원 | 같은 곳의 **분기 파일** | 분기마다 사람이 새 파일을 넣어야 한다 |
| 업종별 점포 | **API 로 받는다** ✅ | — |
| 지도 분류 | **API 로 받는다** ✅ | — |

즉 **인구와 병의원 두 가지가 손으로 들어온다.** 이 둘을 API 로 바꾸는 것이 이 방안이다.

## 두드려서 알아낸 것 [실측 2026-09-27 · 러너]

```
apis.data.go.kr        살아 있음   기관이 직접 여는 통로
api.odcloud.kr         살아 있음   포털이 파일 자료를 API 로 바꿔 주는 통로
www.data.go.kr         200        포털 화면이 열린다 → 요청주소를 여기서 읽어 온다
kosis.kr               200        예비
sgisapi.kostat.go.kr   200        예비
```

**포털이 답을 세 가지로 갈라 준다. 이 구분이 이 방안의 핵심이다.**

| 답 | 뜻 | 고칠 사람 |
| --- | --- | --- |
| `NO_OPENAPI_SERVICE_ERROR` · `-3 등록되지 않은 서비스` | **주소가 틀렸다** | 나 |
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` · `-4 등록되지 않은 인증키` | **주소는 맞는데 활용신청이 안 됐다** | 사장님(브라우저에서 한 번) |
| 200 | 받아진다 | — |

## 주소를 «외워 쓰지 않고 찾아낸다»

포털 소개 화면 글 속에 요청주소가 그대로 들어 있다. 러너가 그 화면을 읽어
자료마다 `uddi`(요청주소의 꼬리표)를 뽑아 `raw/pop_endpoints.json` 에 적어 둔다.

[실측] 다섯 자료 모두 uddi 를 찾았다. 그 주소로 불러 보니:

| 자료 | 답 | 판정 |
| --- | --- | --- |
| **지역별(행정동) 성별 연령별 주민등록 인구수** (15097972) | `-4 인증키` | **주소 맞음 · 활용신청만 하면 된다** |
| 행정동별(통반단위) 인구·세대 (15108065) | `-3 서비스` | 이 통로로는 안 열린다 |
| 통계연보 지역별 주민등록인구 (15107303) | `-3 서비스` | 〃 |
| 도로명별 인구·세대 (15108092) | `-3 서비스` | 〃 |
| 심평원 전국 병의원 및 약국 현황 (15051059) | `-3 서비스` | 〃 |

## 그래서 할 일

### ① 사장님 — 한 번만 누르시면 됩니다

**https://www.data.go.kr/data/15097972/fileData.do** 에서 **「활용신청」**.

이 자료 하나에 **행정동 × 남녀 × 연령**이 전부 들어 있다. 이것만 열리면
지금 비어 있는 것이 한꺼번에 채워진다:

- 세종 나이대 (65세 이상·20~39·여성 20~49)
- 세종 동별 인구 (연령을 다 더하면 그 동 인구가 된다)
- 그리고 **전국 인구 전체를 달마다 새로 받는다** — 파일에 기대지 않는다

### ② 나 — 받는 장치는 이미 만들어 뒀다

```bash
# 러너에서 (workflow market-data.yml)
stage=pop-probe   어느 주소가 답하나
stage=pop-find    포털 화면에서 요청주소를 읽어 온다
stage=pop-try     찾은 주소로 불러 보고 셋으로 가른다
stage=pop         행정동 × 성별 × 연령 인구를 통째로 받는다  ← 신청만 되면 바로
```
칸 이름도 **외워 쓰지 않는다** — 첫 장을 받아 무슨 칸이 오는지 적어 두고
(`raw/pop_columns.json`) 표를 짜는 일은 그것을 보고 한다.

### ③ 그다음 — 달마다 저절로

받는 것이 한 번 확인되면 워크플로에 **달마다 도는 시각**을 걸어 둔다.
그때부터 사람이 손댈 일이 없다.

### ④ 병의원도 같은 길로

심평원은 이 통로(-3)로는 안 열렸지만 **기관이 직접 여는 통로**
(`apis.data.go.kr/B551182/hospInfoServicev2`)가 따로 있고, 그것을 부르는 도구
(`tools/market-data/hira_collect.py`)는 이미 있다. 인구가 끝나면 같은 방식으로
「주소가 틀렸나 · 활용신청이 안 됐나」를 갈라 확인한다.

## 왜 파일보다 나은가

- **낡지 않는다** — 달마다 새로 받는다.
- **빠진 곳이 안 생긴다** — 세종이 빠진 것은 중간에 한 번 변환한 파일 탓이었다.
- **어디서 왔는지가 남는다** — 받은 날·자료번호·출처를 원자료에 함께 적는다.
- **사람이 잊어도 된다** — 손으로 올리는 일은 잊히지만 시각표는 안 잊는다.
