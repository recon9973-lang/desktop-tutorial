사람

  • robots·noindex에 막히지 않고 HTTP 200으로 열린다
  • 제목·소제목·본문이 HTML에 «텍스트로» 있다
  • 내부 링크로 도달할 수 있고 대표 URL이 하나다

robots.txt — «막는 것»이지 «숨기는 것»이 아니다

  • 목적은 서버 과부하 방지. 검색에서 숨기는 수단이 아닙니다. 차단해도 외부 링크가 있으면 URL이 색인될 수 있고, 차단된 페이지의 noindex 태그는 Google이 볼 수 없어 계속 노출됩니다. 숨기려면 noindex 또는 비밀번호.
  • 지원 필드는 4개(user-agent·allow·disallow·sitemap). crawl-delay는 무시. 와일드카드 *·$, 더 긴(구체적) 규칙 우선, 경로 대소문자 구분.
  • 크기 500KiB·UTF-8·캐시 24시간. 5xx로 응답하면 12시간 크롤링 중단 후 30일 캐시 사용. CSS·JS 리소스 차단 금지(렌더링 못 함).
  • 네이버 크롤러는 Yeti. 사내 진단기는 Googlebot·Yeti·* 세 그룹의 루트 차단 여부를 RFC 9309 그룹 파싱으로 봅니다.

사이트맵·URL·표준화·리디렉션

항목규칙(공식 문서 기준)흔한 사고
사이트맵1개당 50MB(비압축) 또는 URL 50,000개. <lastmod>는 정확할 때만, <priority>·<changefreq>는 무시됨. 500페이지 이하·내부 링크가 촘촘하면 없어도 됨사이트맵에 noindex·리디렉션·404 URL이 섞임. lastmod를 «오늘»로 일괄 갱신(신뢰 상실)
URL 구조설명형 단어, 하이픈 구분, 매개변수 최소. 도메인·URL의 키워드는 순위에 거의 영향 없음세션ID·긴 임의 ID·필터 조합으로 무한 URL 생성 → 크롤링 예산 낭비
표준화(canonical)신호 강도: 리디렉션 > rel=canonical > 사이트맵. 절대경로, HTTPS 선호. robots.txt·noindex로 표준을 «지정»하지 말 것. 중복 자체는 스팸이 아님CMS가 모든 페이지 canonical을 홈으로 지정. http↔https, www↔non-www 양쪽 살아 있음
리디렉션영구 = 301/308(강한 신호, PageRank 손실 없음). 임시 = 302/303/307. 체인 최대 10홉(권장 3 이하). 사이트 이전 시 최소 1년 유지구 URL 대량 404 방치, 리디렉션 체인 5홉 이상
HTTP 상태2xx 색인 고려(204·빈 페이지는 soft 404). 4xx(429 제외)는 색인 삭제. 5xx·429가 이어지면 속도 저하 후 삭제존재하지 않는 페이지가 200으로 «찾을 수 없음» 문구만 출력(soft 404)

모바일·JavaScript·페이지 경험

  • 모바일 중심 색인: 스마트폰 크롤러가 본 내용으로 색인. 반응형 권장. 모바일·데스크톱의 콘텐츠·메타·구조화 데이터가 같아야 합니다.
  • JS SEO: Google은 렌더링하지만 «크롤링 → 렌더링 → 색인» 사이에 시간이 걸리고, robots로 JS를 막으면 렌더링이 안 됩니다. 페이지마다 고유 title·canonical·HTTP 상태를 서버 HTML에 두고, 프래그먼트(#) 대신 History API. 동적 렌더링은 «임시방편(권장 아님)».
  • 지연 로드·페이지 나누기: 뷰포트 진입 시 로드는 OK, «클릭해야 나오는» 콘텐츠는 색인 안 됨. 더보기·무한스크롤은 ?page=n 같은 고유 URL과 <a href>.
  • Core Web Vitals(순위에 직접 쓰이는 페이지 경험 신호): LCP ≤ 2.5초 · INP < 200ms · CLS < 0.1. 방해형 전면 광고(팝업)는 감점, 배너는 허용. 연령 확인 등 법정 팝업은 예외.
  • 이미지: 표준 <img src>만 색인(CSS 배경 이미지 안 됨). 구체적 파일명·alt. 형식 JPEG·PNG·WebP·SVG·AVIF 등.

1-2콘텐츠 SEO — «사람 중심»을 측정 가능한 규칙으로

Google이 콘텐츠를 판단하는 문서는 하나로 모입니다. «유용하고 신뢰할 수 있는 사용자 중심 콘텐츠». 요지는 검색엔진을 위해 만든 콘텐츠가 아니라 사람을 위해 만든 콘텐츠이며, 2024년 3월부터 «유용한 콘텐츠 시스템»은 핵심 순위 시스템 안에 편입됐습니다. 따라서 별도의 «콘텐츠 페널티»가 아니라 사이트 전체 평가로 작동합니다.

«누가 · 어떻게 · 왜» — 페이지 하나를 검수하는 순서

  • 누가(Who): 바이라인이 있는가, 그 사람의 배경·전문 분야로 이어지는 링크가 있는가. 병원이라면 집필 또는 감수한 의료진 이름·면허 분야·프로필 페이지.
  • 어떻게(How): 어떤 과정으로 만들었는가. 리뷰라면 «몇 개를 어떻게 시험했는지»와 증거 사진. AI를 썼다면 어디에 왜 썼는지 공개하는 문구가 신뢰를 만듭니다.
  • 왜(Why): 가장 중요한 질문. «검색 유입을 위해»가 답이면 Google이 보상하려는 콘텐츠가 아닙니다. «직접 방문한 환자에게 유용하려고»가 답이어야 합니다.

1-3링크빌딩 ① 내부링크 — 내가 통제할 수 있는 유일한 링크

Google은 «링크 연결»로 페이지의 중요도를 추론합니다. 메뉴 → 카테고리 → 개별 페이지로 이어지는 경로가 곧 «이 사이트에서 무엇이 중요한가»의 선언입니다. 외부 링크는 남이 주지만 내부 링크는 오늘 바로 고칠 수 있습니다.

규칙

  • href가 있는 <a>만 안정적으로 크롤링됩니다. JS 클릭 이벤트·버튼·onclick 내비게이션은 링크가 아닙니다.
  • 앵커 텍스트는 구체·간결. «자세히 보기»가 아니라 «임플란트 뼈이식이 필요한 경우». 단, 같은 키워드 앵커를 기계적으로 반복하면 과최적화(사내 GrowthOps 원칙에서도 금지).
  • 허브-스포크(토픽 클러스터): 허브(예: 치과마케팅)가 스포크(임플란트·교정·잇몸)를 실제 링크로 묶고, 스포크는 허브로 되돌아갑니다. 사내 사이트 규격은 «허브 3개 → H1 페이지 약 22개, 클러스터 양방향 링크 100%».
  • 고아 페이지 0: 어떤 내부 링크로도 도달 못 하는 글은 사이트맵에만 의존합니다. GrowthOps M2 모듈의 KPI가 «고아 글 비율 0%, 글당 평균 내부링크 상승»인 이유.
  • 탐색경로(BreadcrumbList)와 사이트링크: 사이트링크는 자동 생성(제어 불가)이며 논리적 구조·유익한 제목·내부 앵커가 재료입니다.
  • 페이지 나누기·필터 URL: 결과 없는 조합은 404, 임시 매개변수는 내부 링크에 넣지 않기(무한 URL 방지).

AI 답변 엔진과의 접점

Google 생성형 AI 가이드가 «AI 기능 표시를 위해» 든 SEO 권장사항 목록에 내부 링크가 명시돼 있습니다. AI 크롤러는 대부분 JS를 실행하지 않으므로, JS 메뉴 뒤에 숨은 페이지는 Google에는 보여도 ChatGPT에는 존재하지 않는 페이지가 됩니다(2-1 참조).

GEO — 생성형 AI가 답을 지을 때 «재료»로 뽑히기

GEO라는 말은 2023년 11월 프린스턴·IIT 델리 연구진의 논문(Aggarwal 외, KDD 2024)에서 왔습니다. 기존 5주 과정은 이를 «인용(Citation)» 단계로 정의했습니다. 이 모듈은 인용되기 위한 기술 조건과, 인용됐는지를 재는 법 두 가지만 다룹니다. 콘텐츠 자체의 «답변 구조»는 3모듈 AEO에서 다룹니다.

2-1테크니컬 GEO — AI 크롤러에게 «읽을 수 있는 페이지» 주기

생성형 엔진이 답을 만드는 과정

  1. 검색 확장(query fan-out): 질문 하나를 하위 주제·데이터 소스별 여러 검색어로 쪼개 동시에 검색. Google이 AI 개요·AI 모드 설명에서 공식적으로 쓴 표현입니다.
  2. 검색 증강 생성(RAG, grounding): 검색된 문서를 «근거»로 모델에 넣고 답을 생성. 근거가 된 문서가 «출처 링크»로 표시됩니다.
  3. 문장 단위 발췌·종합: 페이지 전체가 아니라 «답이 되는 구절»을 뽑습니다. 그래서 측정 단위가 페이지가 아니라 구절로 바뀝니다(기존 강의 «측정 전환표»).

Google은 «AI 기능에 표시되려면 페이지가 색인돼 있고, 스니펫과 함께 검색에 표시될 자격이면 되며 그 밖의 기술 요구사항은 없다»고 못 박았습니다. 그러나 Google 밖의 엔진들은 사정이 다릅니다.

질문 묶음을 정해진 엔진들에 던졌을 때 답변에 자사가 출처로 인용되거나 본문에 언급된 비율. 사내 판정은 4단계: 🟢 인용 🟡 언급 🔴 미노출 ⚠️ 측정불가. 측정불가는 분모에서 뺍니다.

같은 답변 안에서 경쟁 병원이 몇 번 언급됐는가. 사내 geo-sov는 자사·경쟁사 언급을 분리 집계. 고객 대면 자료에 경쟁사 순위표를 넣는 것은 의료광고법상 비교광고 위험 → «경쟁 강도(개수)»로 추상화.

인용 문맥·정확성

AI가 우리를 어떻게 설명하는가. 잘못된 진료과목·폐업 정보·옛 주소가 답에 들어가면 인용률이 높아도 손해. 오래된 정보 갱신·공식 채널 정비가 대응.

질문 설계 — 발견형과 브랜드형을 분리하라

  • 발견형(비브랜드): «춘천 여드름 흉터 치료 잘하는 곳», «죽도동 허리디스크 비수술». 새 환자가 던지는 질문. 이것이 진짜 성적표.
  • 브랜드형: «○○의원 어때?». 이미 아는 환자의 질문. 여기서 인용되는 것은 당연에 가깝습니다.
  • 사내 실측은 질문 5개 중 4개를 발견형으로 두고 tot_pct(전체)와 disc_pct(발견형)를 따로 냅니다. 질문 소스는 네이버 지식iN·Google «다른 사람들이 묻는 질문»(PAA)·영업/CS 기록.
  • 경쟁 제품 GPTO의 관찰: 질문은 전부 «지역구 + 증상/시술 + 진료과 + 추천 요청»의 무브랜드형, 통증·실패 경험형(«대학병원에서 받았는데도 효과 없어…»)이 섞임.

3-4E-E-A-T — 신뢰를 «보여 주는» 장치들

정의와 오해

  • Experience(직접 경험) · Expertise(전문성) · Authoritativeness(권위) · Trust(신뢰). 2022-12-15에 «경험»이 추가됐습니다.
  • Google 공식: 신뢰가 가장 중요하며 나머지는 신뢰에 기여한다. 모든 덕목을 다 갖출 필요는 없다(경험만으로 유용한 글도 있다).
  • E-E-A-T는 직접 순위 요인이 아닙니다. Google 시스템은 «훌륭한 E-E-A-T를 가진 콘텐츠를 식별하는 여러 신호»를 씁니다. 그래서 «E-E-A-T 점수»는 존재하지 않고, 우리가 할 일은 신호를 보여 주는 것입니다.
  • YMYL(건강·금융·안전·사회 안녕)에는 높은 E-E-A-T에 더 큰 가중치. 병원 콘텐츠는 전부 YMYL입니다.
  • 품질 평가자 가이드라인(QRG)은 2025-01·2025-09 두 차례 개정돼 생성형 AI 콘텐츠의 정의와 평가 지침이 처음 명문화됐고, YMYL «사회» 범주가 «정부·시민·사회»로 확장됐습니다. Google이 사람이든 AI든 같은 기준으로 본다는 뜻입니다.
