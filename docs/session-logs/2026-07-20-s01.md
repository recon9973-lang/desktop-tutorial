## 핵심축 1 — 자동블로그 이미지 거부감 해소

피드백: "AI 생성 이미지의 거부감(가짜 얼굴·깨진 글자)이 사이트 전체 신뢰도를 떨어뜨린다."

### 진단 (근본 원인)
- 자동블로그(크론)는 정적 블로그 규칙(실사진 image-to-image)과 달리 **순수 DALL-E 생성**(gpt-image-1/dall-e-3/dall-e-2).
- `lib/post-generator.js`의 `IMG_SUBJECTS`가 **AI 얼굴**(의사·환자 등)을 요구 → 언캐니 밸리.
- `lib/image-generator.js` 네거티브가 "No text overlay" 한 줄뿐 → 모니터·간판에 **깨진 한글** 박힘.

### 5대 제안(브레인스토밍) → 단계 로드맵
1. 실사진 image-to-image 전환(정석, 파이프라인 난이도 상)
2. 실사진 큐레이션 매핑(실용) — **단, 300장뿐이라 1:1 직접사용은 반복 위험** → 로테이션+분리+재가공 필요
3. 프롬프트·네거티브 강화(즉시 지혈)
4. 하이브리드/브랜드 일러스트
5. 이미지 거버넌스(검수·폴백)
→ 권고: Phase 0(지혈) → 1(실사진+QA) → 2(image-to-image 무한화).

### 실행·배포 (완료)
- **Phase 0 (PR #188, merged)**: `IMG_SUBJECTS`에서 인물 얼굴 제거(환경·손·뒷모습), 네거티브 대폭 강화, "마케팅 사진"→"에디토리얼 다큐멘터리".
- **Phase 0.1 (PR #189, merged)**: 화면(모니터·대시보드·스마트폰) 씬 전면 제거 → 깨진 글자 원천 차단.
- **실측**: 07-19 발행 5/5 확인, 실제 이미지 2장 확인 → 얼굴은 사라졌으나 **모니터 깨진 글자 잔존**(→ 0.1로 해결).

## 핵심축 2 — SEO 무료진단기 점검 + 수정코드 표시

요청: "무료진단기가 정상 체크되는지(예: H1 없음이 실제 없는지) 실측 + 실패 항목 하단에 문제 코드 표시."

### 정확도 실측 (완료 — 도구 정상)
- 진단 엔진 `seo/seo-engine.js`의 `SEOEngine.analyze`는 **DOMParser로 실제 `<h1>` 요소 수 카운트**(정규식 아님).
- VENOM 홈페이지 실제 DOM 파싱: **h1=1 → 통과**, title/desc/canonical/JSON-LD(8) 모두 정상.
- 결론: 자사 사이트엔 "H1 없음" 불가. 사용자가 본 것은 **JS 렌더링 외부 사이트**(원본 HTML에 h1 없음) 진단 시. 엔진은 SPA 감지 시 '정밀필요'로 하향.

### 기능 추가·배포 (PR #191, merged)
- `seo-engine.js`: 검사항목별 **FIX(붙여넣는 수정 코드) 맵 24종** + 항목 `fix` 필드, `renderItems`에 **실패항목 하단 "🔧 이렇게 고치세요" 다크 코드블록** 렌더.
- `index.html`: `seo-engine.js` 캐시 `v1.6.0 → v1.7.0`.
- 검증: 결함 페이지 진단 시 실패 18항목 전부 코드 노출(스크린샷 확인).
