## 원인 — 왜 상권 탭이 없었나 (3겹)

1. **설계 원본에 없었다.** `홈페이지 제작을 위한 최종 사이트맵 구조 (Sitemap).txt` 에서
   지역은 **「5. 블로그 > 2) 지역마케팅」 H3 하위 카테고리**로만 잡혔다. 상단 대메뉴
   후보가 아니었다. 즉 「빠진」 게 아니라 **처음부터 네비 축이 아니었다.**
2. **구현이 진료과목 축 하나로만 자동화돼 있었다.** 상단 메가메뉴는 `buildTopMega()` 가
   `HUB_META`·`HUB_TREE` 에서 동적 생성한다 — 축이 진료과목 하나뿐이라 지역·상권을 담을
   **자료구조가 없었다.** 라우트 73개(`PAGE_ROUTES` 15 + `DETAIL_ROUTES` 58) 중 지역·상권 0건.
3. **정작 상권 기능은 다른 제품에 지어졌고 다리가 없었다.** `/clinic` 「베놈 체크업」의
   입지 진단(`clinic/location/`)이 실제 상권 화면인데, 본진 `index.html` → `/clinic` 링크
   **0건** · `sitemap.xml` **0건** · `llms.txt` **0건**. `robots.txt` 는 전체 허용이라
   공개 의도인데 색인 경로가 없었다 = 공개 무료 도구 6종의 도달 0.

## 이번에 잰 것 · 다음 사람도 쓸 것

- **네비 겹침 공식** — 상단 네비는 `뷰포트 − 321px` 를 넘으면 헤더 우측 버튼과 겹친다
  (321 = 좌우 패딩 48 + 로고·간격 108 + 헤더 액션 165). 탭을 늘리기 전에 이 값부터 재라.
- **기준선 대조법** — `git show origin/main:…/index.html > __baseline.html` 로 머지 전 판을
  같은 서버에 띄워 **같은 자를 대고 잰다.** 「내 탓인가 원래 그런가」가 1분에 갈린다.
- **로컬 검증 서버는 `vercel.json` 의 rewrite 를 그대로 흉내내야 한다.** 규칙을 느슨하게
  쓰면(예: `/seo` 를 `/seo/...` 까지 매칭) `/seo/seo-engine.js` 가 HTML 로 돌아와
  **없는 JS 오류가 생긴다.** 아래 「내가 틀린 자리」 참조.

## 내가 틀린 자리

1. **「문의하기」를 8번째 탭으로 넣어 헤더를 깨뜨렸다.** 네비 폭 865px → 1024~1440px 전 구간
   겹침. 기준선 대조로 잡았고, 탭 대신 **헤더 CTA 버튼 자체를 `/contact` 로** 돌려 폭 비용
   0으로 같은 목적을 달성했다. 설계를 바꾼 것은 보고했다.
2. **테스트 하네스 오류를 사이트 결함으로 보고했다.** `Unexpected token '<'` 과
   `/dental 활성 페이지 0개` — 둘 다 **내가 만든 로컬 서버가 rewrite 를 잘못 흉내낸 것**이었다.
   처음엔 「기준선에도 있는 기존 오류」라고 적었는데 그것도 정확하지 않았다(기준선에서도
   같은 하네스를 썼으니 당연히 같이 났다). 서버를 vercel.json 대로 고치니 **오류 0건**.
3. **옛 해시 주소 회귀로 잘못 짚었다.** `/#blog-post/local_incheon` 이 안 열리는 것을 내 회귀로
   봤으나, 경로가 `/` 일 때 `PATH_TO_PAGE['/']` 가 먼저 걸려 해시를 무시하는 **기존 동작**이었다
   (`/index.html#blog-post/...` 는 양쪽 다 정상). 기준선을 같은 조건으로 놓고서야 갈렸다.

세 번 다 **기준선을 같은 조건에 놓기 전에 말한 것**이 원인이다.
