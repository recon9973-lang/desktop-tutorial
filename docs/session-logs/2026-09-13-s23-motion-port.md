```
구멍 1  한 파일의 첫 import 하나만 읽었다   — 둘 이상 가져오는 화면 30곳

구멍 3  홑따옴표만 읽었다                   — 쌍따옴표 7자리
```

공용 판을 쓰는 화면 **서른한 개가 처음부터 관문 밖**이었고, 관문은 그 사실을 말하지

> 교훈은 관문 하나에 그치지 않는다. **관문이 있다는 것은 관문이 본다는 뜻이 아니다.**

### 정적으로 훑어 나온 것 — 거의 없다

| 본 것 | 결과 |
|---|---|
| 바닥이 안 접히는 격자(`repeat(N, minmax(Npx…))`) | 0건 |
| 600px 넘는 고정 폭 | 하나(`source-matrix`) — 이미 `overflow-x` 틀 안 |
| 긴 글자(URL 등) | 전역 `body{word-break:keep-all; overflow-wrap:anywhere}` 가 덮는다 |
| `white-space: nowrap` 133곳 | 표본은 전부 길이가 정해진 것(배지·집계). `.urls` 는 이름과 달리 「영향 URL N개」였다 |

**이름만 보고 판단하지 않았다** — `.urls` 는 URL 이 아니었다(오류 212·213 과 같은 함정).

### 띄워서 재니 나왔다 — 로그인 화면

공개 화면 셋(`/` · `/login` · `/bot`)을 실제로 띄워 320~1440px 을 10px 씩 훑었다.

```
[실측 2026-09-14 · 크롬]   320px→73px   360px→33px   390px→3px   400px 이상→0
```

원인은 `.split { grid-template-columns: 1fr 1fr }` 의 **바닥**이다. `1fr` 의 최솟값은
`auto` — 곧 내용의 min-content 라서 칸이 제 그릇보다 넓어질 수 있다. 로그인 상자
min-content 329px + 안쪽 여백 64px = **393px 바닥**. 393 보다 좁은 폰은 전부 흘렀다.

`minmax(0, 1fr)` 로 바닥을 풀었다. [실측 · 다시 지어 띄운 판] **320~1440 전 구간 0**,
부모 밖으로 나간 것도 0. 접는 폭 860→**960**(관문 지침대로 · BASELINE 두 줄 뺌).

> 첫 화면이었다. 320px 폰에서 73px 이 흐르고 있었는데 관문 어느 것도 못 봤다 —
> **좁은 폭은 재야 보인다.** 정적 검사 넷이 전부 조용했다.
