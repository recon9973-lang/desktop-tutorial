- **veo-platform 배포 전 환경 세우기**: `PYTHON=/usr/bin/python3.12 make setup` · `pnpm install --frozen-lockfile` · `service postgresql start` · `su postgres -c "psql -c \"CREATE ROLE root LOGIN SUPERUSER PASSWORD 'veo'\""` · `PGPASSWORD=veo make db-test-create`. **postgres 는 세션 중에 죽는다** — 점검이 빨간불이면 먼저 `pg_isready`.

### 그 착각이 가리고 있던 것 (오류 213)

앞 보고 «28개 파일이 각자 머리를 쓴다»가 틀렸다. 「부르는 곳」을 세고 「정의하는 곳」을
안 세서 난 착각이다. 큰 일로 미뤄 둔 탓에 그 안의 **작고 확실한 결함 둘**을 못 봤다.

```
mine 화면         styles.note 넷   →  공용 판에 `.note` 가 없다
datasources 화면  styles.lead      →  없다(`.lede` 다)
```

CSS 모듈은 없는 이름에 undefined 를 주고 React 는 조용히 「클래스 없음」으로 그린다.
**단서 줄과 머리말이 맨 글자로** 서 있었다 — 값과 같은 크기·같은 진하기로.

### 더 나쁜 것 — 그것을 막던 관문이 눈을 감고 있었다

`styles-are-not-undefined.test.ts` 는 2026-09-01 에 **바로 이 결함을 막으려고** 세운
관문인데, 자기가 본다고 적은 것보다 훨씬 적게 보고 있었다.

```
구멍 1  한 파일의 첫 import 하나만 읽었다   — 둘 이상 가져오는 화면 30곳
구멍 2  점으로 시작하는 경로만 읽었다       — `@/…` 꼴 50자리가 통째로
구멍 3  홑따옴표만 읽었다                   — 쌍따옴표 7자리
```

공용 판을 쓰는 화면 **서른한 개가 처음부터 관문 밖**이었고, 관문은 그 사실을 말하지
않고 초록이었다. 세 구멍을 메우고 **「무엇을 보고 있나」를 함께 재게** 했다.
[실측] 구멍을 되살려 보니 **결함 시험은 초록인 채 덮개 시험만 빨강** — 노리던 그대로다.

> 교훈은 관문 하나에 그치지 않는다. **관문이 있다는 것은 관문이 본다는 뜻이 아니다.**
