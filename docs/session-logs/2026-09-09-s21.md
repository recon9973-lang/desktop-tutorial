## 2. 무엇이 진짜였나

**사이트는 멀쩡했다.** 네이버 77건·구글 모두 `https://www.venomad.com/` 로 색인돼 있고,
진단서 자신도 103개 중 102개가 정상이라고 적었다. 걸린 1개는 홈페이지의 **평문 표기**였다.

진짜 결함은 **진단기 쪽 셋**이었다.

```
① `_status_ok` 가 `site.unreadable` 을 상태 무관하게 실패로 더했다
   → 200 으로 답한 762바이트 차단 페이지를 「2xx 가 아닌 상태 코드」로 적었다
   → 같은 관측이 한 화면에 두 번, 서로 반대로 나갔다
       수집 고지: 「사이트의 결함이 아니라 우리 수집의 상태입니다」   ← 정확
       이슈    : 「2xx 가 아닌 상태 코드 · BLOCKER」                 ← 사실 아님
② 경유 수집이 인증서 만료일을 실어 보내지 않았다(`tls_expires_at=None`)
   → 해외 IP 를 막는 사이트는 만료일을 영영 못 봤다. 기획의 핵심 기능이
      가장 필요한 곳에서만 빠져 있었다
③ 진입 주소를 `http` 에서 `https` 로 올리는 길이 없었다
   → 방향이 하나뿐이었다(인증서 깨지면 내려가는 `_retry_over_http` 만 있었다)
```

**우리 크롤러가 본 상태 코드는 403 이 아니라 200 이다.** `read_failure` 는 상태를 가장
먼저 보는데 진단 메모가 크기 사유(762바이트)를 적었다 — 상태가 2xx 였다는 뜻이다.
PSI(구글 미국)는 같은 주소에서 403 을 받았다. **보는 쪽에 따라 다르게 답한다.**

## 5. 내가 틀린 것 (오류 대장 192)

세 번 단언하고 세 번 갈렸다 — ① 「301 이고 우리 오진」(실제 403) ② 「한국 경유가 301 을
잘못 적는다」(코드는 정상 · **고칠 목록에 올려 승인까지 받은 뒤** 근거 없음을 알았다)
③ 「등록 주소가 http 일 것」(https 였다). **발견자가 세 번 다 사장님이다.**

원인은 하나다 — 이 방에서는 venomad.com·운영 API·PSI 공용 몫이 전부 막혀 **잴 수 없었는데**,
코드로 만든 가설을 결론처럼 냈다. 못 재는 자리에서는 가설을 가설이라고만 말한다.

## 6. 남은 것

- **배포 결정** — 대기 표에 넷(0.3.556 둘 · 판 27 ANSEO · 판 28). 이 방은 `make deploy`
  권한이 없다. 판 27 은 다른 방 일이라 대신 판단하지 않았다.
- **사이트 쪽** — `http://www.venomad.com/` 80포트를 403 대신 **301 to https** 로.
  옛 링크·인쇄물 유입과 신뢰도가 지금 죽고 있다. 서버 설정이라 코드로 못 고친다.
- **무료 공개 진단** — 크롤러를 안 써서 https 승격이 안 들어갔다(별건).
- **3xx/4xx 분리** — 구글 기준 400~599. 이번 원인이 아니라 보류.

## 7. 덧 — 배포 (사장님 «배포 승인» 2026-09-09)

**이 방이 `make deploy` 를 돌린 것이 아니다.** 승인을 받고 배포하려고 상태를 확인해 보니
**다른 방(`work/shareboard-tune`)이 이 가지를 자기 판에 합쳐 이미 내보낸 뒤**였다.

```
[실측 2026-09-09 · gh]

  내 커밋 5건       전부 origin/main 의 조상 (5/5)
  main 끝 커밋      9d29ad5793b6…  판 0.3.557
  채점받은 커밋     9d29ad5793b6…  CI success · 15:29 KST · deploy-candidate-work-shareboard-tune
                    → 채점한 커밋 = 나간 커밋 (오류 135 가 막으려던 자리, 지켜졌다)
  가지가 main 보다 앞선 커밋  0건 → 다시 배포할 것이 없다
```

**못 잰 것.** Railway·Vercel 이 실제로 0.3.557 을 서비스하는지는 **이 방에서 못 쟀다.**
워크플로 「도는 판 확인」을 띄우려면 `actions:write` 가 필요한데 **403** 이다
(`gh workflow run` 은 GraphQL 이라 또 다른 403). 사장님이 그 워크플로를 직접 돌리시거나
콘솔 화면의 판 표시로 확인하시면 된다.

**이 방에서 배웠다 — `gh` 설치.** 릴리스 tarball 은 못 받는다(`cli/cli` 가 이 방의 GitHub
범위 밖이라 API 가 거절). `apt-get install -y gh` 로 우분투 universe 판(2.45.0)을 깐다.
`GH_TOKEN` 은 이미 환경에 있고 붙어 있는 저장소에는 잘 닿는다.

**대기 표.** 다른 방이 다섯 묶음을 0.3.557 한 판으로 정리해 두었고, 이 방 일은
「진단 이상값 정리 — https 승격 문턱을 조인다」 줄로 들어가 있다. 도는 판이 확인되면
**그 줄만** 지운다. 다른 방 줄은 건드리지 않는다.
