## 개체 지도 — 만든 것

```
서버   entity_graph.graph_map()  노드·선을 **이름째** 낸다(MapNode · MapEdge · GraphMap)
       entity_clarity            관측값에 지도를 싣는다(개수 넉 줄은 그대로)
       payload._split_entity_graph  응답에서 **제 칸**(entity_graph)으로 꺼낸다

```

**창구 자리를 제안서와 다르게 잡았다 — 관문이 시켰다.** 처음엔 제안서대로 관측값
(`observed`) 안에 넣었는데 `hand-written-types-follow-the-server` 가 빨간불이 됐다:
`observed` 는 계약상 `Any` 라 **그 안을 계약이 못 적고**, 못 적으면 화면이 필드 이름을
손으로 베끼며, 손으로 베낀 이름은 서버가 바꿔도 아무 데서도 안 걸린다(그 관문의 머리말이
그렇게 적혀 있다). 응답에 제 칸을 주자 관문이 도로 초록이 됐다.

**배치는 제안서의 글이 아니라 그림을 따랐다.** 본문은 「중심 1 + 바깥 고리 N」이라고
적었는데, 600눈금 폭에서 고리는 여덟만 넘어도 둘레가 모자라 이름이 겹친다. 제안서의
스케치가 이미 위(공식 프로필)·가운데(주체)·아래(나머지)였고 그쪽이 읽힌다. 같은 줄끼리
잇는 선은 **아래로 둘러** 간다 — 곧게 그으면 칸 밑에 깔려 이어져 있는데 안 이어져 보인다
(화면을 실제로 그려 보고 고쳤다).

**그림이 지키는 것 셋**

```
① 가리키는 곳이 없는 참조는 저쪽 끝에 칸을 만들지 않는다 — 점선이 붉은 ×로 끝난다
② 크기는 값이 아니라 역할이다 — 가운데 하나만 크고 나머지는 모두 같다
③ 자리가 모자라도 조용히 안 버린다 — 이름 그대로 그림 밖 칩 줄, 못 그린 끊긴 선은 수로
```
