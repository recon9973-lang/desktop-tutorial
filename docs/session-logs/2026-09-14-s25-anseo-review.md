## ③ 찾은 것 — `effective_at` 은 스위치가 아니다

사장님이 「1.9.0 은 어디서 확인하지?」를 물으셨다. 답을 찾다가 함정을 하나 봤다.

```yaml
# veo.geo.readiness/1.9.0.yaml
status: PUBLISHED
effective_at: '2026-09-15T00:00:00+09:00'    ← 내일 (오늘은 09-14)
```

**이 날짜를 보고 「아직 안 먹는다」고 읽으면 틀린다.** 엔진이 명세를 고르는
`latest_published()` 는 `effective_at` 을 **보지 않는다** [실측 · `scoring/spec.py`]:

```python
for version in reversed(versions):
    spec = load_spec(spec_id, version)
    if spec.status == "PUBLISHED":
        return spec          # ← 날짜 조건 없음
```

**1.9.0 은 0.3.577 이 도는 순간부터 이미 적용 중이다.** SEO 1.13.0 도 같은 날짜가 적혀
있지만 마찬가지다. `effective_at` 은 리포트에 적히는 **표기**일 뿐이다.

### 확인하는 길 셋 (뒤로 갈수록 확실하다)

| | 어디 | 무엇을 말해 주나 |
|---|---|---|
| ① | 콘솔 `/console/scoring-versions` | 「지금 적용 중인 명세」에 GEO 1.9.0 · SEO 1.13.0 |
| ② | `GET /api/scoring/specs` | 화면을 거치지 않은 엔진의 목록 — 화면과 갈리면 여기가 진실 |
| ③ | **막힌 거래처의 GEO 리포트** | 1.9.0 이 **실제로 점수를 움직이는지** |

③ 이 제일 확실하다. 1.9.0 의 핵심이 노출 차단을 점수에 **곱하게** 만든 것이므로:

```
noindex 거래처의 GEO 점수
  1.8.0 까지 → 95.062   (붉은 띠는 뜨는데 숫자는 태연했다)
  1.9.0 부터 →  0.000   (띠와 숫자가 같은 말을 한다)
```

**0 이 보이면 1.9.0 이 도는 것.** 95 대가 그대로면 화면에 1.9.0 이라 적혀 있어도
**워커가 옛 판**이다 — 인계의 「워커만 옛 판이면 나간 것이 화면에만 있다」가 이 경우다.

**이 방은 ①②③ 어느 것도 직접 못 쟀다** — 운영 주소 egress 403. 위는 전부 저장소 코드를
읽어 확인한 것이고 실제 값은 «—» 다.
