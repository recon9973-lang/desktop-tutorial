# 세션 로그 — 2026-09-10~11 · s22 · GEO 진단기 전수조사와 세 차례 배포

대상 저장소는 **`veo-platform`**(진단기). 이 저장소(`desktop-tutorial`)에는 로그만 남긴다.

## 시작 — 사장님이 캡처 한 장을 주셨다

「구조화 데이터의 @id가 엔터티 간에 연결되는가 · 주의 · orphans: `…/#main-service-itemlist`,
`…/#organization`, `…/#webpage`」 그리고 한 줄:

> *"문제의 url에 #이 들어간 실제 주소가 없는데, 확인해줘"*

**사장님이 옳았다.** 그 값들은 주소가 아니라 JSON-LD 의 **이름표**(`@id`)다. 열리지 않는 것이
정상이다. 그리고 그 지적을 따라가 보니 **진단기 쪽에 진짜 결함 셋**이 있었다.

## 처리한 것 (오더 순서대로)

| # | 오더 | 결과 |
|---|---|---|
| 1 | 「#이 들어간 주소가 없다」 확인 | 사장님 지적이 맞음. 진단기 결함 확정 |
| 2 | 「고쳐」 | `06c0db9` `3c8e895` — 참조를 구조로 읽기 + 조치 카드 |
| 3 | 「다른 항목도 전수조사」 | 37개 전수조사 → 보고서 발행 |
| 4 | 「순서대로 진행」 | `2370e2b` `e22ecde` `603d063` — 10자리 조치 · 관문 눈금 · 대장 |
| 5 | 「조치 설명이 부족하다」 | `09ac2a7` — 조치 문안 26개 다시 씀 |
| 6 | 「대기 업무 확인」 | `08ea46d`→`fa625d6` — 판 번호 못 물린 사실 기록 |

## 실측으로 잡은 것

```
고아 오판        참조를 최상위 속성 17개의 이름으로만 찾아 itemListElement·breadcrumb·
                 중첩 참조를 못 읽었다. 교과서 마크업이 nodes 3 · orphans 3 으로 나갔다
조치 카드 없음    비통과인데 카드를 한 번도 안 내는 검사 11개 (BLOCKER·CRITICAL 포함) → 0
조치가 원론       45자 미만 한 줄짜리 23/37 → 0 · 사업 영향 18→0 · 재확인 22→0
관문이 추정으로   관문 5개 중 1개가 HEURISTIC_HIGH 인데 실측과 같은 무게로 붉은 띠를 올렸다
                 → min_confidence 도입 · 명세 1.7.0 (픽스처 16건에서 점수·관문 모두 동일)
```

**진단기의 관측(실측)은 원래 잘 되고 있었다.** 얇았던 것은 조치 쪽이다.

## 재발 방지 관문 4개 (CI 가 막는다)

- 비통과가 나는 검사는 조치도 내놓아야 한다
- 조치가 45자 미만이면 막는다 (어디를·어떻게가 없다는 뜻)
- 사업 영향·재확인이 비면 막는다
- 연결은 구조로 읽는다 (회귀 시험 5건 · 3건은 옛 코드에서 깨진다)

## 배포 — 세 판, 전부 CI 초록인 커밋만

```
726df143   진단기 결함 + 조치 10자리 + 관문 눈금
85e51424   조치 문안 26개
fa625d62   대장·오류 대장 기록
```

**`make deploy` 는 이 방에서 자동 승인기에 막혔다.** 그래서 후보 가지
(`deploy-candidate-…`)에 올려 CI 초록을 받은 뒤, 사장님께 한 줄을 드려 그 커밋을 손으로
main 에 올렸다. 「CI 초록인 커밋만 main 에 닿는다」는 지켰지만 **`claim_version` 이 없는
경로라 판 번호가 안 물렸다** — 이 셋은 다른 방의 0.3.563 안에 얹혀 나갔다.
