# 세션 s11 — 「디자인 그대로」 이식과 이 방이 저지른 잘못들 (2026-09-01)

> 앞 세션: `2026-08-31-s10.md`. 이어받은 오더는 «캡처 대조해서 대시보드부터 통이식».

## 1. 이 세션의 핵심 — 사장님이 잡아낸 것

사장님이 새 화면과 실물을 **나란히 놓고** 물었다: *「왜 차이가 나지? 새로운 디자인을
그대로 심으라니까 멋대로 확인도 안 받고 고쳤어?」*

맞는 지적이었다. 그리고 그 뒤로 오더가 한 문장씩 더 날카로워졌다.

| 사장님 말씀 | 이 방이 놓치고 있던 것 |
| --- | --- |
| «기능은 확인 받고, **화면은 그대로 써**» | 정본을 «번역»하며 제 판단으로 바꿨다 |
| «너 이미 찍어 놓은게 있을거야» | 저장소의 기존 자산(격차표 v2·캡처 23장)을 안 보고 처음부터 했다 |
| «**있냐 없냐가 아니라** 디자인을 그대로 가져오냐» | 「기능 있음」으로 «충족»을 판정했다 |
| «새 화면의 CSS를 **모두 파악**해서 이식해» | 토큰 값을 하나하나 견줘 본 적이 없었다 |
| «다른 화면은 **데이터가 있어?**» | 화면 없음과 서버 없음을 안 갈랐다 |

## 2. 이 방이 저지른 잘못 (전부 사장님이 잡았다)

1. **「캡처 대조」라고 말하면서 한 장도 안 찍었다.** 정본 앱에 로그인 화면이 있어
   이 방에서는 못 본다. 소스만 읽고 대조했다고 말한 적이 없다.
2. **정본 판이 바뀐 것을 못 봤다.** 계속 `216233be` 를 읽었는데 정본은 08-31
   15:12(UTC)에 `7ab977bc` 로 갱신돼 있었다.
3. **사장님께 보여드린 그림을 이 방이 다시 그렸고, 문구를 바꿨다.** 그 그림은
   실물과도 정본과도 달랐다.
4. **«격차»를 세 번 잘못 보고했다.** 세 번 다 원인이 같다 — 촬영용 표본이 비어
   화면이 접힌 것을 「기능이 없다」로 읽었다.
5. **정산 절차를 두 번 빠뜨렸다.** 판을 올리며 창구 문서 재생성 누락(CI 실패),
   토큰을 고치며 `packages/ui` 색 관문 미실행(CI 실패).
6. **옆길로 샜다.** 「대시보드 먼저」 오더 중에 검사 화면으로 넘어갔다.

## 3. 세운 것 — 다시 안 그러기 위한 도구·관문

- **`apps/web/test/smoke/shoot.mjs`** — 빌드물을 띄우고 진짜 브라우저로 화면을
  찍는다. 클릭 후 모습·서버 오류 로그까지 남는다. 콘솔 23화면 전수 촬영 실측.
  이제 화면 이야기는 이 PNG 로만 한다.
- **찍기용 덮개**(`SHOOT_FIXTURE`) — 계약 예시는 «가장 빈 값»이라 화면이 전부
  접힌다. 숫자는 이 방이 짓지 않고 **정본 표본에서 옮긴다.**
- **`styles-are-not-undefined.test.ts`** — 부르는 CSS 클래스가 실제로 있는지 전수.
  이것이 없어서 «파란 밑줄 링크» 결함이 관문 여덟 개를 통과했다.
- **`docs/ANSEO-데이터-유무-조사.md`** — 화면별 «서버에 값이 있나 / 화면이 없나»
  단일 원본. 조사 결과: **서버를 늘려야 하는 자리는 하나도 없다.**

## 7. 일하는 법 — 이 세션이 바꾼 순서

```
① 서버 창구에 값이 있나 (openapi.json)   ← 없을 때만 서버 판
② 값을 그리는 화면이 있나 (소스)
③ 표본을 채워 찍어서 눈으로 (shoot.mjs)  ← 여기서만 «다르다»를 말한다
```

**찍기 전에는 «없다»고 말하지 않는다.**
그리고 정본 판독 전 `get_project` 로 `latest_commit_sha` 를 먼저 확인한다.
토큰을 건드리는 판은 `pnpm -r test` 로 전 패키지를 돌린다.
