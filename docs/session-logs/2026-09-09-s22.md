## 만든 것 — 「입지」 머리 요약 (관문 13건)

반경 칩 아래에 다섯 줄이 선다: 같은 과 · 정류장·역 · 인구 · 상가업소 · 밖에서 온 사람.
차례는 아래 상자 차례와 같다.

**이 요약이 더하는 것은 숫자가 아니라 「잰 자리」다.** 요약은 상자보다 틀리기 쉽다 —
상자에는 제목·단위·주석이 붙지만 요약에는 숫자 하나뿐이라, 잰 자리를 빼면 읽는 사람이
짐작으로 채운다. 사장님이 지금까지 걸리신 곳이 전부 그 자리였다:

```
2026-09-07  "인구수가 얼만 안되는데 몇백만명이 방문했다고?"  방문자는 시군구 · 연인원
2026-09-07  인구 이동이 「마산합포구」인데 값은 창원시 전체    행안부가 구를 시로 합침
0.3.539     3km 고리를 골랐는데 상권은 2km                  API 상한
```

그래서 줄마다 숫자 **밑에** 「반경 1km 안」·「창원시 마산합포구 전체」를 적는다.

- 못 잰 축은 «—» 와 짧은 까닭(받는 중 · 열쇠 없음 · 아직 못 받음) — 0 을 안 그린다.
- **합산 「입지 점수」는 만들지 않았다**(대장 §1). 관문이 총점·score 유입을 막는다.
- **안 적재된 갈래를 0 으로 놓고 더하지 않는다** — 지하철 미적재면 정류장·역 합도 «—».
  버스 수만 합이라 적으면 「없는 값」이 아니라 **틀린 값**이 된다.
- 날수·하루 평균 셈을 `apps/web/src/lib/location-days.ts` 한 군데로 모았다 — 머리와
  방문자 상자가 따로 나누면 같은 화면에 다른 숫자가 뜬다.

## 걸린 것 · 배운 것

- **PostgreSQL 이 세션 중 네 번 죽었다.** 로그가 종료 기록 없이 끊긴다(컨테이너 쪽에서
  거둬감). `pg_ctlcluster 16 main start` 로 살아난다. 시험 실패가 아니라 DB 가 안 뜬 것 —
  긴 검사에는 **15초마다 살펴 죽으면 되살리는 감시**를 붙여 돌리면 된다.
- **자동 물림(`claim_version.py`)이 문서 제목 꼴을 가린다.** 이력의 절 제목이
  `### … (v0.3.55x …)` 여야 찾는다. 옆 항목을 따라 `## … 0.3.55x` 로 쓰면 배포가 멈춘다.
- **변경이력 충돌은 두 방 글을 한 항목으로 붙인다.** 판 번호 줄이 같아 자동 병합이 그
  아래만 충돌로 잡는다 — 그대로 두면 저쪽 제목에 우리 항목이 달린 덩어리가 나간다.
  항목 둘로 갈라야 한다.
- **대기 표를 고치다 저쪽 줄을 떨어뜨린 적이 있다.** 표를 고친 뒤 줄 수를 세어 확인한다.
- **rebase 가 문서마다 충돌을 내면 접는 편이 빠르다.** `git diff --name-only <base> origin/main`
  으로 main 이 우리 코드 파일을 건드렸는지 보고(세 번 다 안 건드렸다), main 에서 새 가지를
  떠 **코드만 얹고 문서는 새로 쓴다.** 이 세션에서 세 번 그렇게 했고 매번 깨끗했다.
