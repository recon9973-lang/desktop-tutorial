## 원인 둘 — 이 세션의 본론

### ① 딸림 방이 한 시간에 세 번 멈춰 물었다 (이름 → 색 → 배치)

**원인은 그 방이 아니라 인계였다.** 시안을 그릴 때 veo-platform 안에
**`BubbleCloud` 라는 기존 부품이 있는 줄 몰랐다.** 그래서 시안 ≠ 기존 코드인
자리마다 스스로 못 정하고 올려보내게 돼 있었다.

내려보낸 규칙 — **이 뒤로 한 번도 안 멈췄다**:

```
시안이 기준이다. 시안과 기존 부품이 어긋나면 시안이 이긴다.
갈리면 ㉠시안 → ㉡사장님 문장에 가까운 쪽 → ㉢덜 어수선한 쪽. 적어두고 계속 간다.
멈춰도 되는 것은 하나 — 데이터의 진실이 걸린 것. 배치·색·이름은 그 방이 정한다.
```

배치 답은 **「대체」** — 언급현황 카드 안에서 BubbleCloud 를 워드클라우드로 바꾼다.
둘 다 두지 않고 따로 화면도 만들지 않는다. 근거는 사장님 문장
「이미지를 참고하는게 **가독성이 더 좋을 것 같아**」 = 지금 것이 안 읽힌다.
정확한 수는 「표 보기」 토글로 본다.

### ② 딸림 방 보고가 반쪽만 온다 — **관이 좁다**

`get_session` 으로 넘어오는 것은 **요약 두 줄뿐**이고,
그 두 줄은 **그 방이 쓰는 것이 아니라 기계가 짓는다.**

```
표로 채워 달라          → 두 번 요청, 두 번 다 안 옴
요약 자리에 압축 한 줄  → 안 먹는다 (저자가 못 쓰는 자리다)
받은 것                 "mention card layout complete, ready to deploy" 뿐
```

**결론: 이 관으로는 커밋 SHA·「나」·「다」를 못 받는다.** 더 캐물어도 같은 한 줄이다.
사장님이 그 방을 직접 여시는 것이 유일한 길이다.
