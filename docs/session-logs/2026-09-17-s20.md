## 낸 것 둘 — 둘 다 main 에 있다

### v0.3.556 — 재진단에 텀이 없다 (`93628efd`)

**텀은 요금이 아니라 호스트 예산 때문이었다.** 크롤은 우리 서버가 직접 보내는 HTTP 라
과금이 없고, PageSpeed 는 하루 25,000회 무료(진단 1판 = 최대 5회). 동반 GEO 는 AI 를
안 부른다. 텀이 있던 까닭은 한 판이 최대 **211회**(200장 + 사이트맵 10 + robots 1)를
쓰는데 예산이 **450/시간** 이라 두 판이 한계였고, 세 판째는 막히는 게 아니라 **도중에
잘려** 「재진단했더니 점수가 내려간 것」이 된 것이다.

```
① 텀 제거      시간이 아니라 판을 센다 — 예산 ÷ 한 판 = 2,000 ÷ 211 = 9판/시간
               아홉 판을 채운 뒤에만 **크롤 시작 전에** 거절(429 · 남은 시간을 말한다)
               리미터가 아니라 DB(ScanRun.started_at)를 센다 — 화면이 그릴 시각은
               재시작·새로고침에 같아야 한다. 읽는 칸은 count·min 둘뿐
② 예산 상향    console_target_host_limit_per_hour 450 → 2,000
               **순간 부하는 이 숫자가 안 정한다** — HostPacer 가 연결당 1초 간격 ×
               동시 연결 2 = 초당 최대 2회(의뢰서 §5.2). 거래처 서버가 한순간에 받는
               부하는 450 일 때와 **같다**. 늘어난 것은 한 시간의 총량뿐
③ 총량을 실제로 셈  (아래 별도 항)
④ 화면        브라우저가 「마지막 진단 + 30분」을 계산하던 자리 제거
```

### v0.3.598 — 겹친 판 번호를 합친다 + 안 그려지던 조각 제거 (`6806d955`)

겹친 판이 **여섯 쌍**: `0.3.593` · `0.3.591` · `0.3.556` · `0.3.555` · `0.3.552` · `0.3.16`.

**번호를 새로 매기려다 그만뒀다.** 「어느 항목이 어느 판으로 나갔나」를 `__version__`
이력과 커밋 포함 관계로 두 번 맞춰 봤는데, 한 항목이 **연속한 두 `__version__` 에서
맨 위**였던 자리가 있어 잰 값이 라벨보다 앞서기도 뒤서기도 했다. 그 상태에서 번호를
지어 적으면 오류 190 과 같은 모양이다. 대신 **같은 번호를 단 항목들을 한 항목으로
합쳤다** — 한 낱말도 안 버렸다.

막은 자리 셋: `claim_version.py`(그 번호를 이미 쓰는 항목이 있으면 선다) ·
`changelog-numbers-are-unique.test.ts`(겹친 번호 · 뒤집힌 순서) · `test_claim_version.py` 1건.

`RescanCountdown` 은 v0.3.556 뒤로 **한 번도 안 그려지고 있었다**(`nextScanAllowedAt` 을
넘기는 자리 0곳). 걷어냈다 — runtime 무변경(`waiting` 이 늘 `false` 였다).

## 이 방이 찾은 것 — 오류 대장 190

[실측 2026-09-08 · 코드 읽기]

```
seo/router.py:507   crawler = ConsoleCrawler()                 ← 인자 없음
seo/crawl.py:326    limiter=limiter or InMemoryRateLimiter()   ← 판마다 새 객체
```

콘솔 크롤이 **진단할 때마다 빈 리미터를 새로 만들고** 있었다. 「동일 호스트 시간당
요청」이 한 시간의 총량이 아니라 **한 판 안에서의 상한**으로만 돌았다 — 한 판이 211회니
닿을 일이 없고, 판이 바뀌면 0 부터 다시 셌다. 무료 진단 경로만 공유 리미터를 제대로 썼다.

그 상태에서 `/bot` 안내 페이지는 사이트 주인들에게 「시간당 450회 이하」를 **공개 약속**
하고 있었다. **지키는 자리가 없는 약속이었다.**

내가 두 번 틀린 것도 여기서 나왔다 — `cooldown.py` 머리말의 「세 번째는 도중에 잘렸다」를
**`[실측]` 표시가 없는데도 실측처럼 인용**했고, 그 위에서 사장님이 고르실 선택지까지
만들었다. 틀린 전제 위의 선택지는 고르셔도 틀린 곳으로 간다. 대장 190 에 적었다.

**되풀이 방지**: 저장소의 산문을 근거로 쓸 때는 **`[실측]` 표시가 있는지 먼저 본다.**

## 관문이 실전에서 막은 자리 셋

1. **겹침 관문** — main 을 합칠 때마다 겹침이 **두 번 더** 생겨 있었다(`0.3.593` ·
   `0.3.596`). 고치려던 병이 고치는 중에 재발했고 관문이 그 자리에서 잡았다.
2. **`_refuse_to_relabel`** — 문서만 바꾸느라 변경이력 항목을 안 썼더니 배포가 [1/4] 에서
   섰다. 그대로 갔으면 main 의 **이미 나간 기록**에 새 번호가 달렸다(2026-09-15 에 그렇게
   판 넷을 잃고 세운 관문).
3. **대장 관문** — 「머리말은 번호 미정 1건인데 표에는 2줄」을 잡았다.

## 배포 — 다섯 번 걸어 한 번 닿았다

```
회차 1~3 (코드)   1·2차 CI 초록 · main 밀기 ✗ → 3차 **main ✓** (v0.3.598 · e91a1f2d)
회차 4~5 (문서)   4차 [1/4] 관문이 세움 · 5차 CI 초록 · main 밀기 ✗ → **접음**
```

**CI 는 걸 때마다 초록이었다.** 막힌 자리는 늘 마지막 한 걸음이다 — preflight 12분 +
CI 8분 = **20분 창**이 열려 있고 그 사이 다른 방들이 계속 낸다. 판이 이 일 하나에
**네 번** 물렸다(554→556 · 595→596 · 596→597 · 597→598).

**[5/5] 도달 확인은 이 방에서 늘 실패한다** — 운영 주소로 못 나간다(egress).
**배포 실패가 아니라 확인을 못 한 것이다.** 대신 워크플로 「도는 판 확인」을 러너에서
돌려 바깥에서 잰다 — 그것이 이 방이 쓸 수 있는 유일한 자다.

## 접은 것 하나 — 그리고 왜

오더 8번(«대기 표에서 0.3.598 줄 빼줘»)은 **이미 되어 있었다.** 배포 경쟁에 지는 사이
다른 방이 같은 정리를 main 에 넣었다. 제 변경에는 「나간 판 줄 아홉을 뺐습니다」라는
변경이력 항목이 들어 있었는데, 그 아홉 줄은 이미 없다. 그대로 냈으면 **사장님이 읽는
자리에 하지 않은 일을 했다고 적힌다.** 가지를 main 과 같게 되돌렸다.

표를 열어 보고 찾은 것은 남는다: `0.3.596` 넉 줄과 `0.3.598` 넉 줄이 **같은 항목 넷이
두 번호로 복제된 것**이었다(글자까지 같다). 「0.3.598 만 빼 달라」를 글자대로 했으면
같은 항목이 0.3.596 으로 남아 「아직 안 나갔다」로 읽혔을 것이다.
