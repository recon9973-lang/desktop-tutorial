## 1. 전제가 틀렸다 — 재생 틈은 처음부터 없었다

사장님은 「영상 끝과 시작 사이의 딜레이」를 의심하셨다. 재보니 **딜레이가 없었다.**

```
[실측] Chromium · WebM · requestVideoFrameCallback 으로 프레임마다 벽시계 기록
  누락 프레임        0 / 774  (두 바퀴)
  평상시 프레임 간격  33.5ms (중앙값)
  되감기 지점 간격    33.4ms   ← 평상시와 같다. 멈칫하는 자리가 아니다.
```

`<video loop>` 의 되감기는 공짜였다. **결함은 재생이 아니라 영상 내용물에 있었다.**

## 2. 진짜 결함 — 15초 소스가 「한 번 재생용」 인트로였다

`ring-sq.webm` 은 처음부터 순환용이 아니라 **인트로 렌더**였다. 앞뒤에 이징(가속·감속)이
붙어 있어서, 한 바퀴 15.04초 중 **2초가 사실상 정지 화면**이었다.

```
[실측] 프레임마다 이미지 변화량(160px 회색조)을 재고, 각 영상 자기 최고 속도로 정규화
  기존 15초  칸 361 · 멈춘 칸 47 (13.0%) = 1.96초 · 가장 느린 칸이 최고의 0.4%
```

그리고 되감기 한 칸이 **하필 그 정지 구간 한복판에** 떨어졌다. 절대 이동량은 작은데
주변이 멈춰 있으니 그 자리 보통 한 칸의 **11배**로 보였다 — 서다가 톡 튀고 다시 출발.

> 같은 절대 크기의 어긋남도 빠르게 도는 중이면 안 보이고, 멈춰 있으면 확 튄다.
> 그래서 이후 모든 값은 **그 자리 보통 한 칸에 대한 비율**로 쟀다.

## 3. 버린 길 넷 (전부 재보고 버렸다)

| 길 | 왜 버렸나 |
|---|---|
| 이징 구간 잘라내기 | 4초 이상 모든 구간을 전수 탐색 — 지금의 0↔360 이 이미 최적. 다음 후보 [42,360] 은 2배 더 나빴다 |
| 핑퐁(정·역 이어붙이기) | 기하학적으로 완벽(720쌍 전부 해시 대조 ±1프레임)했지만 **이징 구간을 연달아 두 번 지나 3.42초 연속 정지** — 원본보다 한 번에 더 오래 선다 |
| 인코더 조이기 | 되감기 어긋남은 코덱 복원 오차라 설정으로 안 없어진다. 5가지 시도, CRF 33·2.5MB(3배 용량)에도 1.309 잔존 |
| 크로스페이드 | 어긋남은 4.2배 줄지만 **정지 구간은 그대로**. 사장님 주문을 못 푼다 |

**내가 두 번 틀렸다.** ① 연구 보고에서 핑퐁을 「수학적으로 유일한 진짜 0」이라고 단언했는데
인코딩하면 복원 오차로 어긋남이 되살아났다. ② 더 큰 잘못은, 핑퐁이 **사장님이 실제로 말한
문제(멈춤)를 오히려 악화**시킨다는 걸 만들고 나서야 쟀다는 것. 핑퐁 결과물은 폐기했다.

## 4. 고친 방법 — 등속 재추출 (호길이 리샘플링)

시간을 균등하게 자르지 말고, **이미지가 변한 양이 균등하도록** 프레임을 다시 고른다.
느린 구간은 건너뛰고 빠른 구간은 남겨서, 한 바퀴 전체가 같은 속도로 돌게 만든다.

```python
d    = [step(i-1, i) for i in range(1, 361)]   # 칸마다의 이미지 변화량
wrap = step(360, 0)                             # 닫힌 순환이므로 마지막 칸도 포함
cum  = 누적합(d + [wrap]);  S = 총합
T    = max(d);  N = round(S / T)                # 최대 칸을 기준 → 늘 버리기만, 붙잡지 않음
# t = k·S/N 에 가장 가까운 원본 프레임을 고르되, 같은 프레임을 두 번 쓰지 않는다
# → 164 프레임
```

**고른 164장은 전부 원본 프레임 그대로다** — 프레임 해시 164개를 대조해 확인했다.
보간도, 색공간 왕복도 없다. (PNG 로 뽑았다 다시 넣으면 yuv420p↔RGB 왕복으로 해시가
어긋난다 — 그래서 무손실 마스터에 `select` 필터를 직접 걸었다.)

## 9. 되돌리는 법

`ring-loader.js` 의 `v.innerHTML` 한 줄에서 `-loop` 만 빼면 원본 15초 소스로 돌아간다.
파일은 그대로 있다. `index.html` 의 `?v=` 를 올려 캐시를 털어야 한다.

## 10. 다시 만드는 법 (ffmpeg)

```bash
ffmpeg -i ring-sq.webm -c:v ffv1 -pix_fmt yuv420p -an src.mkv          # 무손실 마스터 361칸
ffmpeg -i src.mkv -vf "select='<164개 eq(n\,i)>',setpts=N/24/TB" -r 24 \
       -c:v ffv1 -pix_fmt yuv420p -an even.mkv                          # 164칸 6.834초
ffmpeg -i even.mkv -c:v libvpx-vp9 -pix_fmt yuv420p -b:v 550k -g 120 \
       -row-mt 1 -deadline good -cpu-used 0 -pass 1|2 -an -f webm even.webm
ffmpeg -i even.mkv -c:v libx264 -pix_fmt yuv420p -profile:v high -preset slower \
       -b:v 700k -maxrate 1400k -bufsize 2000k -g 120 -bf 0 -movflags +faststart -an even.mp4
```

`-bf 0` 이 핵심이다 — B프레임 재정렬이 없어지면서 `ctts` 가 사라지고 `elst media_time` 이
0 이 된다. 사파리의 되감기 목표가 제자리를 잡는다.

## 11. 주의 — 링 CSS 는 손대지 마라

`ring-loader.css` 에 비싸게 얻은 경고가 적혀 있고 이번에 그대로 지켰다.
`.rl-host` 에 `isolation:isolate` 를 주면 안 되고, `.rl-host/.rl-scrim/.rl-overlay/.rl-disc`
어디에도 `z-index`·`opacity`·`filter`·`transform`·`mask` 를 새로 얹으면 안 된다.
쌓임 맥락이 하나라도 생기면 `mix-blend-mode: screen` 이 깨지고 **검은 원반**이 돌아온다.
이번 변경은 영상 파일과 그것을 가리키는 한 줄만 건드렸다 — CSS 는 한 글자도 안 고쳤다.
