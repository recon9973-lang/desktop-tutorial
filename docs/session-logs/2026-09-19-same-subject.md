## 결정사항

- **「같은 과」 판정은 서버 한 곳**(사장님 확정) — `location/service._neighbours_of`.
  `same_subject` 는 `veo/location/` 밖으로 안 나간다(리포트·추계 환자 수로 안 흘러감).
- **좁히기는 실패하면 바닥으로 내려간다.** 기준이 사라지면 반경 안이 전부 「그 외」가
  되어 지금보다 더 틀린다. 빈 칸은 「0 명」이 아니라 「모름」.
- **사람이 고르는 칸은 안 만든다** — 사장님 「자동으로 분류해주고」(오더 16).
- 상호 접미사 표(`industries/registry.py`)와 `clinic_subjects.SUBJECT_ALIASES` 는
  **하는 일이 다르다**(저쪽 어간 자르기 · 이쪽 간판→심평원 과목명). 중복 아니다.

# 2026-09-21 — 사장님 화면이 잡은 결함: **만들어 놓고 연결을 안 했다** (0.3.640)

화면에는 그랜드연합의원 경쟁사로 **그랜드배내과의원(내과) · 그랜드우리안과의원(안과) ·
그랜드아름다운의원(피부과)** 이 전부 「같은 과」로 올라와 있었다 — 0.3.631·636·637 을
다 내고 난 뒤인데도 **첫 화면과 똑같았다.**

## 잰 것 둘

**① 사장님이 보시던 0.3.639 는 내 것이 아니었다.**

```
[실측] origin/main 의 0.3.639 = 「입지」 상권 칸 업종 막대 (입지 방)
       내 가지의 커밋은 main 에 안 들어가 있음 (git merge-base --is-ancestor → 거짓)
       site_lanes.py · site_lookup.py 가 main 에 **없음**
```

**② 내 것이 나갔어도 안 고쳐졌다** — 이것이 진짜 원인이다.

```
[실측] origin/main:location/service.py

  _center_of     lane_of(..., place_lane=place_lane)   ← 네이버 답이 들어감
  _neighbours_of lane_of(name, kind, subjects, doctors) ← **place_lane 이 빠짐**
```

우리 자리를 **두 곳에서 따로 재고 있었다.** 화면 위쪽은 네이버가 말한 「정형외과」를
적고, 아래 경쟁 목록은 **그 답을 버리고** 처음부터 다시 쟀다. 그랜드연합의원은 간판에도
등록 과목에도 갈래가 없어 아래쪽에서 늘 빈 갈래가 나왔고, `same_lane` 이 「모름」을
돌려 **예전 방식(등록 과목 겹침)으로 떨어졌다.**

**네이버를 붙인 판(0.3.637)도 홈페이지를 붙인 판도 경쟁 목록에는 한 번도 닿지 않았다.**

## 고침 — 다시 재지 않는 것

목록이 화면의 네 값(`licence_ko`·`lanes_ko`·`tier_ko`·`lane_source_ko`)을 **그대로**
쓴다. 두 자리가 어긋날 여지가 아예 없어진다.

`_geo_center`(주소로만 잡은 중심)도 같은 자리에서 갈래를 채웠다. **안 채웠으면 그
거래처만 반경 안이 통째로 「그 외」가 되어 고치려던 것과 반대로 틀렸다** — 한 곳으로
모으는 고침은 그 한 곳이 **모든 길**을 채우는지 같이 봐야 한다.

설명글도 무엇이 판정했는지 말하게 했다 — 갈래를 못 읽은 판에서는 「이번에는 과목
겹침으로 셉니다」라고 적는다.
