## 핵심 발견 — 판 번호가 하루에 열 번 겹친 진짜 이유

### 구멍

`deploy.sh` `[1/4]` 의 판단:

```
HERE_V > MAIN_V  →  "물릴 것 없습니다"      ← 건너뛴다
HERE_V ≤ MAIN_V  →  MAIN_V+1 로 물린다
```

첫 줄이 **«앞질러 잡기»를 되살린다** — 바로 아래 주석이 「안 통했다」고 적어 둔 그것이다
(0.3.540 을 미리 잡았는데 닿기 전에 집혔다).

### 진짜 값은 「번호가 굳는 시각」

```
번호 굳음 ──────────────────── main 도착
           이 사이에 남이 닿으면 내 번호가 낡는다

설계대로:    [1/4] → CI 9분 → main             9분
미리 박으면:  손 → 점검 15분 → CI 9분 → main   24분
```

[실측 2026-09-19 06:00~08:14] main 도착 간격 **평균 19.1분**(7번 관측).

| 방식 | 노출창 | 겹칠 확률 | 평균 시도 |
|---|---:|---:|---:|
| 미리 박기 | 24분 | **71%** | 3.5회 |
| 나갈 때 정하기 | 9분 | **38%** | 1.6회 |

**이 방은 0.3.620 부터 여섯 번 시도해 다섯 번 물러났다 — 표와 맞는다.**
운이 아니라 확률을 두 배로 만들어 놓고 들어갔다.

### 처방 (0.3.628 로 배포됨)

`version_to_claim` 이 **언제나 main+1** 을 찍는다. 이미 맞으면 무변경, 뒤처졌으면 올리고,
**손으로 높게 박았으면 끌어내린다.**

검사 `test_deploy_always_claims_from_main.py` **8건** — 옛 판단을 되살려 **3건이 빨개지는
것까지 확인**했다.

### 갈라 봐야 할 두 가지

```
겹침 1~8번째:  점검 전에 번호를 박음   ← 이 방 잘못 · 고쳤다
겹침 9~10번째: CI 9분 창              ← 구조상 남는 몫(38%)
```

둘을 같은 「겹침」으로 뭉뚱그리면 고칠 자리를 못 찾는다. 이 방이 여덟 번 그랬다.

## 이 방이 저지른 것 — 같은 실수 반복 금지

1. **판을 손으로 미리 박았다** (위 구멍 ③). 다음부터 **판 번호에 손대지 않는다.**
2. **`make ci-local` 을 건너뛰고 배포에 들어갔다** — 린트 5건이 관문에서 잡혔다.
   `pnpm verify` + pytest 는 CI 와 **다른 명령**이다.
3. **점검이 도는 중에 나무를 건드렸다** — 시험 파일을 만들어 「커밋 안 된 변경」으로 배포가 섰다.
4. **변경이력 구조를 두 번 깨뜨렸다** — 충돌 해소에서 `items` 배열을 안 닫았다.
5. **「ci-local 초록」이라고 잘못 보고했다** — 종료코드 0 은 뒤에 붙인 `echo` 것이었다.
   `cmd > log; echo $?` 는 **cmd 의 결과가 아니다.**
6. **원격 추적 ref 가 낡은 것을 보고 「안 올라갔다」고 했다** — `git ls-remote` 로 확인해야 한다.

## 못 한 것 · 막힌 것

- **방 간 메시지 전달이 안 된다.** 이 방에서 다른 방(클라우드 세션)으로 보내는 통로가
