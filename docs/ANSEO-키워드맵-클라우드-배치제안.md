## 0. 한 장 요약

**자리는 있다. 다만 「어디에 넣을까」보다 「이 저장소에서 그릴 수 있는 형태가 무엇인가」가
먼저 정해져야 한다** — 화면 규칙 셋(축 이름 필수 · 값 병기 · 못 잰 값 `—`)과 기술 조건
하나(차트 라이브러리 0개, 전부 손으로 그린 서버 SVG)가 형태를 반쯤 정해 버린다.

| 순위 | 자리 | 형태 | 왜 여기가 1순위인가 |
|---|---|---|---|
| **A** | 키워드 화면 · 연관 키워드 | **정렬 버블 클라우드** | 실측 752개가 글 목록으로 깔려 화면을 삼킨 자리 — 그림이 문제를 실제로 없앤다 |
| **B** | AEO 결과 · 출처·채널 | **트리맵**(채널→도메인) | 데이터 전부 보유. 「AI가 어디를 읽나 + 그중 우리가 올릴 수 있는 곳」이 한 장 |
| **C** | AEO 결과 · 한눈에 | **언급 버블 클라우드** | 접혀 있던 열 곳 밖 업체를 한 장으로. GPTO 「언급 현황」의 시각형 |
| **D** | GEO 탭 · 개체 항목 | **노드-간선 개체 지도** | 사장님이 준 마인드맵 그림과 가장 가까운 진짜 관계도. **ANSEO 고유** — 타사에 없다 |
| 보류 | 키워드 화면 하단 마인드맵 자리 | 방사 맵 | ERP JourneyMap 과 중복. A 가 같은 일을 더 정직하게 한다 |

**한 줄 결론: 워드클라우드(글자 크기로 값 말하기)는 이 저장소 규칙과 정면으로 부딪힌다.**
글자는 길이·획수에 따라 같은 값도 면적이 달라져 **크기가 값을 거짓말한다.** 대신
①**흐름 배치 칩 클라우드**(크기 5단계 + 숫자 병기) ②**버블** ③**트리맵** 셋으로 간다.
「구름처럼 보이는 것」은 ①이 그대로 준다.

## 1. 지금 ANSEO 에 무엇이 있나 — 실측

### 1-1. 맵·클라우드는 **한 장도 없다**

```
[실측 2026-09-15 · veo-platform main 2ae1592]
  워드클라우드 / word cloud / treemap / 버블차트 / 원 패킹  →  0건
  (검색 범위: *.ts *.tsx *.py *.md, node_modules 제외)
```

「지도」라고 불리는 것 셋이 있는데 **셋 다 다른 물건**이다.

| 이름 | 자리 | 실제 형태 |
|---|---|---|
| `KakaoTileMap` | 거래처 › **상권** 탭 | 진짜 지리 지도(카카오 타일) — 반경 고리·동종업종 |
| `ContentGapMap`(빈 칸 지도) | 거래처 › **콘텐츠** 탭 | **표**다. 질문×AI×채널 칸을 줄로 세운 것 |
| `MindmapLink`(키워드 마인드맵) | `/console/keywords` 하단 | **바깥 링크.** 베놈 ERP `erp.seokorea.org/journeymap` 새 창 |

세 번째가 이번 오더의 정중앙이다. 2026-08-10 사장님 결정(*"이 부분 이미 erp에 있어 일단
A로 하고"*)으로 **ANSEO 안에는 안 그리고 ERP 로 보낸다**가 확정돼 있다. 이 제안은 그 결정을
뒤집지 않는다 — **ERP 가 하는 일(시드 재귀 확장·여정 4단계 분류·의료광고법)과 겹치지 않는
자리**만 고른다(§6-①).

### 1-2. 그릴 수 있는 재료 — 손으로 그린 SVG 아홉

```
[실측] apps/web 의존성 5개 = next · react · react-dom · server-only · @veo/ui
       차트 라이브러리(d3 · recharts · chart.js · visx) 0개
```

`packages/ui` 그림 부품 아홉: `TrendChart` · `MultiTrendChart` · `RadarChart` ·
`FunnelChart` · `CoverageGrid` · `RatioBars` · `SplitBar` · `Sparkline` · `ScoreCard`.
**`MultiTrendChart` 만 `'use client'`이고 나머지는 전부 서버 부품이다** — 자바스크립트 없이
HTML 로 완성돼 내려간다.

이것이 형태를 고르는 첫 번째 제약이다.

| 그리려는 것 | 서버에서 되나 | 까닭 |
|---|---|---|
| 흐름 배치 칩 클라우드 | **된다** | 글줄처럼 흐른다. 크기는 5단계 CSS. 진짜 글자라 검색·읽기 다 됨 |
| 트리맵(squarified) | **된다** | 결정적 계산 40여 줄. 값 라벨 자리가 항상 남는다 |
| 정렬 버블(행 채우기) | **된다** | 큰 것부터 줄 세워 채운다. 면적 ∝ 값 |
| 노드-간선 지도(작은 그래프) | **된다** | 고리 배치(원둘레)로 고정. 힘 시뮬 없음 |
| 진짜 원 패킹 | 어렵다 | 반복 충돌 해소가 필요 → 서버 렌더와 안 맞음 |
| 진짜 워드클라우드(회전·충돌) | **안 된다** | 글자 폭 측정에 브라우저가 필요하다 |

### 1-3. 키워드·질문·인용 데이터는 **이미 있다**

| 재료 | 어디에 | 무엇이 들었나 |
|---|---|---|
| **연관 키워드** | `GET /api/keywords/lookups/{id}/related` (`keywords/router.py:284`) | 씨앗 · 연관어 · 순위 · 월간 검색량 · 값 품질 |
| 키워드 실측 | `KeywordMetricsPayload` | PC/모바일/합계 검색량 · 클릭 · CTR · 경쟁도 · 광고 깊이 |
| 기회 점수 | `keywords/opportunity.py` | 성분별 가중·기여 (VEO 자체 산식이라고 명기됨) |
| 검색 추이 | 데이터랩 상대지수 | **검색광고 조회수와 같은 축에 두지 않는다**(화면 주석) |
| 실수확 질문 | `observations/question_sources.py` | 지식iN 제목 · 구글 관련질문(SerpAPI). **AI 분류 안 함**(지어낸 분류 금지) |
| 언급 로스터 | `MentionRoster` → `mention-share-data.ts` | 업체명 · 언급률 · 분모 · 자사 여부 · 엔진 |
| 인용 출처 | `citation_sources` · `citations_by_site` · `citation_channels` | 도메인 · 채널 · 인용 수 · **올릴 수 있나 3판정** |
| 개체 그래프 | `geo/entity_graph.py` | JSON-LD 노드 · `@id` · 참조 · `sameAs` · 외톨이 · 끊긴 참조 |

**딱 하나가 창구 없이 갇혀 있다** — 개체 그래프는 채점에 **개수만** 실려 나간다
(`entity_clarity.py:243` — `nodes` · `identified` · `orphans` · `unresolved`). 노드와 간선
목록은 서버 안에만 있다. §7 에 그 창구를 적어 둔다.

## 2. 이 저장소에서 맵·클라우드가 지켜야 하는 것 — 규칙 일곱

새로 만드는 규칙이 아니라 **이미 문·시험으로 걸려 있는 것**들이다. 어기면 빌드가 깨지거나
시험이 붉어진다.

1. **모든 그래프는 축이 무엇인지 말한다** — `yLabelKo`·`xLabelKo` 가 **타입 필수**이고
   `axis-labels.test.tsx` 가 화면에 실제로 그려지는지까지 본다(사장님 지시 2026-08-19).
   → **맵·클라우드는 축이 없다. 그래서 축 대신 「읽는 법 세 줄」을 그림 안에 단다**(§2-A).
2. **수치는 그림 위에 직접 쓴다** — 범례로만 말하지 않는다(마감 규칙 2026-08-16).
3. **못 잰 값은 `0` 이 아니라 `—`** (ADR 0002). → 크기를 못 주는 항목은 **그림 밖 칩 줄**로
   빼고 「못 잰 N개」라고 적는다. 점 하나로 찍으면 「아주 작은 값」으로 읽힌다.
4. **색만으로 뜻을 지지 않는다** — 이름·꼬리표·굵기를 함께 쓴다(`mention-colours.ts`).
5. **남들 색은 여덟이다** — 뜻 없는 8색(`DOT_HUES`), 초록은 뺀다. **우리만 강조색**
   (`--veo-color-accent` = `#5c91ff`). 상태색(pass/fail)을 빌려 쓰지 않는다.
6. **자른 것은 숨기지 않는다** — 그림에 N개를 그렸으면 나머지 M개가 어디 있는지 각주가
   말한다(`mention-share-data.ts` 의 기존 규칙 그대로).
7. **있는 것을 다시 만들지 않는다(0-D) · 부를 수 없는 기능은 없는 기능이다(0-E)** —
   ERP JourneyMap 과 겹치는 순간 두 지도가 다른 답을 내는 날이 온다.

### 2-A. 새로 명문화할 것 하나 — 「축 없는 그림의 읽는 법」

축 이름 규칙의 자매 규칙을 제안한다. **타입으로 강제**하면 글로 적은 약속이 아니라 못
지나가는 문이 된다(축 규칙이 그렇게 걸려 있다).

```ts
interface CloudMeaning {
  readonly sizeMeansKo: string;    // "월간 검색량"
  readonly colourMeansKo: string;  // "씨앗과 글자가 겹치나"
  readonly placeMeansKo: string;   // "뜻 없음 — 큰 것부터 왼쪽 위"
  readonly unmeasuredKo: string;   // "못 잰 12개는 그림 아래 칩으로"
}
```

그림 왼쪽 위에 이 넉 줄이 11px 로 상시 노출된다. **이것이 맵·클라우드의 축이다.**

## 3. 디자인 종류 사전 — 일곱 형태, 언제 쓰나

사장님이 주신 참고 그림 다섯 장을 형태로 갈라 적는다.

| # | 형태 | 참고 그림 | 값을 어떻게 말하나 | 이 저장소 판정 |
|---|---|---|---|---|
| ① | **흐름 배치 칩 클라우드** | 워드클라우드 2장 | 글자 크기 **5단계**(연속 아님) + 숫자 병기 | **채택** — 서버 렌더 됨, 진짜 글자라 접근성 좋음 |
| ② | **버블 클라우드**(정렬) | 예산 버블 | 원 **면적** ∝ 값 | **채택** — 값 왜곡 없음, 라벨 자리 있음 |
| ③ | **트리맵** | 예산 버블의 정직한 사촌 | 사각 면적 ∝ 값 + 묶음 구조 | **채택** — 가장 정직. 빈틈이 없어 비교가 쉽다 |
| ④ | **노드-간선 지도** | 마인드맵 2장 | 관계(선). 값은 노드 크기 보조 | **채택**(개체 그래프에 한해) |
| ⑤ | **방사 마인드맵** | 마인드맵 2장 | 관계만. 값 표현 약함 | **보류** — ERP 중복 |
| ⑥ | **격자·히트맵** | — | 두 차원 교차 | **이미 있다**(`CoverageGrid`) — 새로 안 만든다 |
| ⑦ | **산점 버블 맵** | — | 축 둘 + 크기 | **채택** — 축이 있어 기존 규칙과 마찰 0 |

**진짜 워드클라우드를 쓰지 않는 이유를 한 번 더 적는다.** 「임플란트」와 「강남치과임플란트
잘하는곳」이 같은 값이어도 후자가 네 배 넓게 보인다. 값이 아니라 **글자 수가 크기를 정한다.**
이 저장소는 그런 그림을 「지어낸 수치」와 같은 급으로 다뤄야 한다. ①은 크기를 5단계로 끊고
숫자를 옆에 붙여 그 왜곡을 **눈으로 검산 가능**하게 만든 판이다 — 구름처럼 보이되 거짓말은
안 한다.

## 5. 권고 — 자리별 상세 시안

### A. 연관 키워드 버블 클라우드 — 1순위

**위치** `/console/keywords` › 「주소로 연 조회」 › `KeywordReport` 안 연관 키워드 카드의
**머리**(`RelatedKeywords.tsx` 목록 바로 위). 거래처 흐름으로 들어왔을 때도 같은 자리다.

**왜 여기가 첫째인가 — 이미 기록된 고장이 있다.**

```
[실측 2026-08-20 · RelatedKeywords.tsx 머리말]
  「대구병원마케팅」 연관 키워드 752개
  블로그 184,700 · 행사 12,380 · LMS 7,270 · RFP 4,530 · 부동산사이트 3,170
  → 첫 카드가 스크롤 5장으로 늘어나 나머지 조회 둘이 저 아래로 밀렸다
  → 사장님 눈에는 「3개 조회했는데 1개만 나옴」으로 보였다
```

지금은 20개씩 「더 보기」로 접어 급한 불을 껐다. **그림은 그 752개를 한 화면에 담는다** —
접는 것이 아니라 **한눈에 보이게** 하는 것이 이 자리의 본래 답이다.

**형태** 정렬 버블 ②. 큰 것부터 왼쪽 위에서 오른쪽으로 줄을 채운다(자리에 뜻 없음).

**디자인**

```
┌──────────────────────────────────────────────────────────────┐
│ 연관 키워드 752개 · 네이버 검색광고 실측 · 2026-08-20 14:03 잼  │
│ 크기 = 월간 검색량 │ 색 = 씨앗과 글자 겹침 │ 자리 = 뜻 없음     │
│                                                              │
│    ╭──────────╮                                              │
│    │  블로그   │   ╭──────╮  ╭────╮ ╭───╮ ╭──╮ ╭─╮ ╭╮       │
│    │ 184,700  │   │ 행사  │  │LMS │ │RFP│ │부│ │…│ ││       │
│    ╰──────────╯   │12,380│  │7,270│ ╰───╯ ╰──╯ ╰─╯ ╰╯       │
│                    ╰──────╯  ╰────╯                          │
│  ── 씨앗과 안 겹침 ─────────────────────────────────────────  │
│    ╭────╮ ╭──╮ ╭─╮                                          │
│    │ …  │ │… │ │…│   (테두리만, 채움 없음)                    │
│                                                              │
│  못 잰 12개 — [키워드] [키워드] [키워드] …  (검색량 10 미만)    │
└──────────────────────────────────────────────────────────────┘
```

- **색은 둘뿐이다.** 씨앗과 두 글자 이상 이어서 겹치면 채운 원(강조색 계열 `--veo-signal-*`),
  안 겹치면 **테두리만 있는 빈 원**. 기존 `overlapsSeed()` 판정을 그대로 쓴다 — 새 판정을
  만들지 않는다(0-D). *겹침은 재는 것이고 관련성은 사람이 정한다*는 그 파일의 원칙 유지.
- **숫자는 원 안에.** 원이 작아 글자가 안 들어가면 **글자를 줄이지 말고 숫자를 뺀다**(11px
  하한, 마감 규칙). 뺀 원은 마우스 올림·포커스에서 값을 말한다.
- **못 잰 값은 원이 없다.** `BELOW_PROVIDER_THRESHOLD`(10 미만 구간)와 조회 실패는 크기를
  못 준다 → 아래 칩 줄로 분리하고 「못 잰 N개」로 센다(ADR 0002).
- **면적 ∝ 값**(지름이 아니라). 최대 지름은 카드 폭의 1/4로 잠근다 — 184,700 대 12,380처럼
  15배가 벌어지면 하나가 화면을 먹는다. 상한에 닿은 원은 **끝을 자른 테두리**로 표시하고
  각주가 「상한에 닿음」이라고 적는다(값 왜곡을 숨기지 않는다).

**내용·상호작용**
- 원을 누르면 **지금 목록의 동작 그대로** — 그 키워드로 질문 만들기(`askBase` 링크 유지).
  입구를 새로 만들지 않는다(0-E).
- 그림/목록 전환은 **주소에 남는다**(`?shape=cloud`). 서버 부품이라 자바스크립트 없이 돈다.
  기본값은 **목록**으로 두고, 그림은 고른 사람에게만 — 지금 쓰는 사람의 손버릇을 안 깬다.
- 카드 머리에 출처·수집 시각·분모를 그대로 단다(이미 `countText`·`DataSourceBadge` 존재).

**공수** 버블 배치 함수(60줄) + 부품 하나 + 시험 셋(크기 왜곡·못 잰 값 분리·라벨 병기).
**1~2일.**

### B. 인용 출처 트리맵 — 1순위

**위치** 거래처 › AEO › 결과 `출처·채널`(`?view=sources`) — `CitationChannels` 바로 위.
독립 AEO 화면(`/console/geo`)도 같은 부품을 쓰므로 한 번 만들면 두 자리에 선다.

**왜** 지금 이 자리는 **표 둘**이다(채널 순위 + 출처×엔진 행렬). 표는 「어느 도메인이 몇
번」을 정확히 주지만 **판이 얼마나 한쪽으로 쏠렸는지**를 못 준다. 인용의 8할이 네이버 블로그
한 채널이면 처방이 달라지는데, 표에서는 줄을 다 읽어야 그것이 보인다.

**형태** 트리맵 ③ — 바깥 사각 = 채널, 안쪽 사각 = 도메인.

**디자인**

```
┌─────────────────────────────────────────────────────────────┐
│ 인용 214건 · 2026-09-14 정기 판 · GPT·Gemini·Claude·PPLX·Grok │
│ 넓이 = 인용 수 │ 색 = 우리가 올릴 수 있나 │ 굵은 테두리 = 우리 것 │
├──────────────────────────┬──────────────┬───────────────────┤
│ 네이버 블로그      98건   │ 뉴스   42건   │ 공공 31건 │커뮤 22 │
│ ┌──────────┬────────┐   │ ┌────┬─────┐ │ ┌───┬───┐│┌──┬─┐ │
│ │blog.naver│ m.blog │   │ │ A일보│ B뉴스│ │ │심평│보건│││ │ │ │
│ │  61      │  24    │   │ │ 18 │ 11  │ │ │ 17│ 9 ││└──┴─┘ │
│ │ ▓▓ 우리   │        │   │ └────┴─────┘ │ └───┴───┘│        │
│ └──────────┴────────┘   │              │           │        │
├──────────────────────────┴──────────────┴───────────────────┤
│ ■ 직접 올림  ▨ 매체가 실어 줘야  ░ 우리가 못 올림  □ 미분류    │
└─────────────────────────────────────────────────────────────┘
```

- **색이 처방이다.** 채널 규칙판의 `PUBLISHABILITY` 3판정을 그대로 칠한다 — 직접 올릴 수
  있는 채널이 넓으면 「할 일이 있다」, 못 올리는 채널이 넓으면 「여기는 포기하고 다른 데」.
  미분류는 **유형으로 부르지 않는다**(`ContentGapMap` 이 이미 지키는 규칙).
- **우리 자산은 굵은 테두리 + 강조색 글자.** 색으로만 말하지 않는다(규칙 4).
- 사각마다 **도메인 + 인용 수**를 쓴다. 안 들어가는 작은 사각은 이름을 줄이지 말고 **묶음의
  「기타 N곳」 사각**으로 합친다(잘라낸 것은 숨기지 않는다 — 규칙 6).
- 누르면 그 도메인의 인용 원문 목록으로(기존 `CitationSources` 자리로 이동).

**내용** 콘텐츠 탭 「빈 칸 지도」와 **짝**이다. 이 그림이 「AI가 읽는 곳」, 빈 칸 지도가
「그중 우리가 없는 칸」. 두 화면을 서로 링크로 잇는다.

**공수** squarified 트리맵 배치(50줄) + 부품 + 시험 넷. **2~3일.**

### C. 언급 버블 클라우드 — 2순위

**위치** 거래처 › AEO › 결과 `한눈에` — `MentionShareBoard` 의 순위 막대 **위**.

**왜 중복이 아닌가** 지금 이 판은 **열 곳까지만 막대로 세우고 나머지는 「더 보기」로 접는다**
(`RANK_ROWS_FOLDED = 10`). GPTO 화면에서 사장님이 보신 「점 25개」의 값은 **전부가 한 장에
있다는 것** 자체였다 — 25곳 사이에서 우리가 몇 번째로 작은지가 0.2초에 보인다. 막대는
순위를 읽는 도구, 버블은 **판 전체의 모양**을 보는 도구다. 자리를 뺏지 않고 위에 얹는다.

**디자인**
- 원 **면적 ∝ 가중 언급률(%)**. 분모(`answers_valid`)는 카드 머리에 그대로.
- **우리는 강조색 + 흰 테두리 + 이름 굵게.** 남들은 뜻 없는 8색(`mentionColour()` 재사용 —
  목록·추이선과 같은 색이어야 범례가 참이 된다).
- 등록 경쟁사는 글자 꼬리표 「등록」. 색으로만 가르지 않는다.
- **0%인 곳도 그린다** — 점 크기 최소값으로. 「답변에 이름은 나왔지만 언급률 0」과 「측정
  안 됨」은 다른 것이라, 후자는 그림에 안 넣고 각주로 센다.
- 각주: 「그림 N곳 전부 · 막대는 상위 10곳 · 추이선은 다섯 줄」 — 세 그림이 서로 다르게
  자르는 이유를 한 줄로(이미 `mention-share-data.ts` 가 그 규칙을 갖고 있다).

**공수** A 의 버블 배치를 **그대로 재사용**. **반나절~1일**(A 이후).

### D. 개체 지도 — 2순위, ANSEO 고유

**위치** 거래처 › **GEO** 탭 › 개체 명료성(`geo.entity.*`) 항목 결과 옆.

**이것이 사장님이 주신 마인드맵 그림에 가장 가까운 물건이다.** 다만 키워드의 마인드맵이
아니라 **이 사이트가 스스로 선언한 개체들의 관계도**다.

**왜 값이 큰가** 지금 화면은 「구조화 데이터가 있다/없다」 · 「끊긴 참조 3건」처럼 **말로만**
말한다. 그런데 이 항목의 본질은 *"선언한 개체들이 서로 이어지는가"* 이고(모듈 머리말이
그렇게 적혀 있다), **이어짐은 그림이 말의 백 배 빠르다.** 거래처에게 보여 주는 순간
「우리 사이트가 AI 에게 이렇게 보인다」가 설명 없이 전달된다.

**디자인**

```
            ┌─ sameAs 고리 (공식 프로필) ─┐
            │  네이버플레이스   인스타그램  │   ← 이어졌으면 실선
            └────────┬──────────┬─────────┘
                     │          ╎  ← 끊긴 참조는 점선 + 빨간 끝
               ╔═════▼══════╗
               ║ Organization║  ← 중심(굵은 테두리, 강조색)
               ║  온담한의원  ║
               ╚══╤═══╤═══╤══╝
                  │   │   │
            ┌─────▼┐ ┌▼───┐ ┌▼─────┐      ○ 외톨이 노드
            │WebSite│ │Article│ │FAQPage│      (@id 없음 · 회색)
            └───────┘ └──────┘ └───────┘
   노드 = 선언된 개체 │ 선 = @id 참조 │ 점선 = 끊긴 참조 │ 회색 = 외톨이
```

- **배치는 고리형 고정.** 힘 시뮬레이션 없이 중심 1 + 바깥 고리 N으로 서버에서 그린다.
- 노드 크기는 값이 아니라 **역할**(중심/일반)만 말한다 — 「크기=무엇」 줄에 그렇게 적는다.
- 끊긴 참조·외톨이는 **그림에서 결함으로 보이게** 하고, 누르면 그 항목의 조치 문구로 간다.
- 옆에 숫자 넉 줄을 그대로 병기: 노드 N · `@id` 있는 것 M · 외톨이 K · 끊긴 참조 J.

**선행 필요** `entity_clarity` 가 지금 **개수만** 실어 보낸다(`observed` 의 `nodes` ·
`identified` · `orphans` · `unresolved`). **노드·간선 목록을 싣는 창구가 필요하다**(§7-①).
그 전에는 못 그린다 — 지어내서 그리지 않는다.

**공수** 창구 1(반나절) + 부품(1~2일) + 시험 셋. **2~3일.**

### E. 질문 포트폴리오 산점 버블 맵 — 3순위

**위치** 거래처 › AEO › 결과 `질문·추이`.

**형태** ⑦ 산점 버블 — **축이 있어서 기존 규칙과 마찰이 0이다.**

```
  세로: 우리 언급률(%)          가로: 근거 키워드 월간 검색량(회)
  크기: 그 질문으로 받은 답변 수(분모)      색: 의도(추천·비교·신뢰)
```

읽는 법이 한 문장으로 나온다 — **오른쪽 아래(수요는 큰데 우리는 안 나오는 질문)가 할 일이다.**

**주의 하나.** 질문 문장 자체의 검색량은 **잴 수 없다**(개편 제안서 v3 지적 ④에서 확정된
사실). 가로축은 반드시 **「근거 키워드의 검색량」**이라고 적고, 수집형 질문(지식iN)은 근거
키워드가 없으므로 **가로축 없는 띠**에 따로 세운다. 없는 값을 0으로 찍으면 「검색 수요가
없는 질문」으로 읽힌다.

**공수** 2~3일(축·눈금·겹침 회피).

### F. 리포트 키워드 트리맵 — 3순위, 영업용

**위치** 콘솔 리포트 본문 「키워드 수요와 기회」 절 + **공유본**(`/results/{token}`).

**왜** 리포트 판은 **얼려서 보존**되고(불변), 공유본만 **종이 톤**이다. 거래처가 캡처해
가는 유일한 화면이라 「한 장으로 보이는 그림」의 값이 여기서 가장 크다.

**디자인**
- 트리맵 ③, 넓이 = 월간 검색량, 명도 = 기회 점수(같은 색상의 3단계).
- **흑백 인쇄를 견딘다** — 색이 빠져도 넓이와 숫자가 남는다.
- **그 판의 값으로만 그린다.** 판이 얼린 뒤 키워드 값이 바뀌어도 그림은 안 바뀐다
  (ADR 0012 · 판 불변). SVG 를 판에 함께 얼리는 편이 안전하다.
- 기회 점수는 **VEO 자체 산식**이라는 각주를 그림 안에 단다(리포트 창구가 이미 그렇게 적고
  있다 — *"검색량과 경쟁도로 VEO가 계산한 값입니다"*).

**공수** B 의 트리맵 재사용 + 종이 톤 팔레트 + 판 저장. **1~2일**(B 이후).

## 6. 안 두는 자리 — 왜 아닌지까지

### ① G. 키워드 화면 하단 「키워드 마인드맵」 자리 — **보류**

방사 마인드맵 ⑤ 를 여기 그리고 싶은 유혹이 가장 큰 자리다. **안 그리기를 권한다.**

- 2026-08-10 사장님 결정으로 **ERP JourneyMap 이 그 일**이다 — 시드 재귀 확장, 네이버·구글
  자동완성 수집, 여정 4단계 분류, 의료광고법 리스크, PNG/SVG/CSV 내보내기가 **이미 배포돼
  있다.** 여기에 둘째 지도를 지으면 두 지도가 다른 답을 내는 날이 온다(0-D).
- 게다가 **A(버블)가 같은 재료로 더 정직하다.** 방사 맵은 가지의 길이·각도에 뜻이 없어
  「읽는 법 세 줄」을 채우기 어렵다 — 크기만 값이고 나머지는 전부 장식이 된다.
- **다만 이 자리는 비워 두지 않는다.** 지금 카드 문구에 A 로 가는 줄을 한 줄 더한다:
  「이 조회의 연관 키워드는 위 그림에서 한눈에 봅니다 →」. ERP 링크는 그대로 둔다.

**되살릴 조건**: 사장님이 *"ANSEO 안에서도 여정 지도를 보고 싶다"* 고 하시면, 그때는
**ERP 의 그림을 가져오는 것**(같은 데이터·같은 분류)이지 새로 짓는 것이 아니다.

### ② H. 대시보드 전 거래처 도메인 클라우드 — **안 한다**

거래처마다 업종·지역이 달라 인용 도메인을 한 장에 섞으면 **무엇의 구름인지 답할 수 없다.**
전 거래처 합산이 뜻을 갖는 것은 「채널 5종 점유」 정도이고 그것은 막대가 이미 더 잘한다.

### ③ I. 상권 탭에 키워드 얹기 — **안 한다**

지도의 좌표는 미터이고 키워드는 검색량이다. 단위가 다른 둘을 한 판에 얹으면 위치가 뜻을
갖는 것처럼 보인다 — 「읽는 법 세 줄」의 *자리 = 뜻 없음* 과 정면으로 부딪힌다.

### ④ J. 경쟁 브랜드 이름 클라우드 — **안 한다(아직)**

개편 제안서가 이미 진단한 자리다 — 경쟁 브랜드는 **표기 정규화가 안 돼 있다.** 「○○한의원」과
「○○ 한의원」이 두 원으로 그려지면 그림이 거짓을 말한다. 정규화가 서기 전에는 목록이 낫다.

### ⑤ K. 질문 낱말 클라우드 — **안 한다**

한국어 낱말 쪼개기에는 사전이 필요하다. 이 저장소는 그래서 연관 키워드 관련성도 형태소가
아니라 **글자 겹침**으로 판정한다(*"사전이 틀리면 그 틀림이 화면에 「관련 없음」으로
나간다"*). 같은 이유로 질문을 낱말로 쪼개 구름을 만들면 **쪼갠 것이 지어낸 값**이 된다.
질문은 **문장 통째로** 다룬다 → 그것이 E 다.

---

## 7. 새로 필요한 것

### ① 창구 하나 — 개체 그래프 노드·간선 (D 의 선행)

```
지금:  entity_clarity 의 observed = { nodes, identified, orphans, unresolved[] }
필요:  nodes[] { id, type, name, has_id } · edges[] { from, to, property, resolved }
자리:  geo 채점 결과 payload (또는 별도 조회 창구)
```
**개수만으로는 못 그린다.** 없는 간선을 추측해 그리면 그것이 곧 지어낸 그림이다.

### ② 부품 셋 (`packages/ui`)

| 부품 | 무엇 | 재사용처 |
|---|---|---|
| `BubbleCloud` | 정렬 버블 + 못 잰 값 칩 줄 | A · C |
| `Treemap` | squarified 배치 + 「기타 N」 합침 | B · F |
| `EntityMap` | 중심 1 + 고리 N + 점선 간선 | D |

셋 다 **서버 부품**으로(자바스크립트 없이 그려진다). `CloudMeaning`(§2-A) 를 **필수 prop**
으로 받는다 — 읽는 법을 안 적으면 빌드가 깨지게.

### ③ 시험 넷

```
cloud-says-how-to-read-it        읽는 법 네 줄이 화면에 그려진다
unmeasured-is-not-a-dot          못 잰 값은 원이 되지 않고 칩 줄로 간다
area-not-diameter                값이 4배면 면적이 4배다(지름 2배)
nothing-is-silently-dropped      그림에 안 그린 것의 수와 자리를 각주가 말한다
```

## 8. 실행 순서와 공수

| 차례 | 무엇 | 선행 | 공수 |
|---|---|---|---|
| 1 | `BubbleCloud` 부품 + **A**(연관 키워드) | — | 1~2일 |
| 2 | **C**(언급 버블) | 1 | 반나절~1일 |
| 3 | `Treemap` 부품 + **B**(인용 출처) | — | 2~3일 |
| 4 | 창구 ①(개체 노드·간선) | — | 반나절 |
| 5 | `EntityMap` + **D**(개체 지도) | 4 | 2~3일 |
| 6 | **F**(리포트 트리맵 · 종이 톤) | 3 | 1~2일 |
| 7 | **E**(질문 산점 버블) | — | 2~3일 |

**1·2 만 해도 오더의 「키워드 관련 맵·클라우드」는 화면에 선다.** 3 이 사업 가치가 가장
크고, 4·5 가 ANSEO 에만 있는 그림이다.
