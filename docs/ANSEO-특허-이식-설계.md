# 특허를 프로그램에 녹이는 법 — 모듈 5개·환경 3개·도입 3판

> 2026-09-01 작성. 오더: «특허를 우리 프로그램에 녹일 방법 제안해줘».
> 대상 특허: 「의료 GEO 디지털트윈을 이용한 생성형 AI 답변의 반사실적 기여도 측정 및 최적화 시스템 및 그 방법」
> 앞선 결정: 특허는 별도 탭이 아니라 **콘텐츠 탭 안 계층**으로 — `docs/ANSEO-콘텐츠탭-설계.md` §7.
> 이 문서는 그 결정 다음의 물음, **「그래서 코드로는 어떻게 넣나」** 에 답한다.

**결론 먼저: 새 시스템을 짓지 않는다.** 특허 5구성이 전부 이미 있는 자산의 **확장 한 칸**으로 들어간다.
가장 큰 확장이 `ObservationCell.mode` 에 값 하나(`ctx`)를 더하는 것이다.

## 1. 열쇠 — 왜 지금 구현이 되는가

특허 청구항 1의 한 구절이 구현 난이도를 통째로 바꾼다.

> 「기준 콘텐츠 및 상기 반사실 콘텐츠 변형본을 각각 **질의 컨텍스트로 직접 제공**하는 실험환경에서」

**즉 문서를 사이트에 올리고 크롤을 기다릴 필요가 없다.** 문서 본문을 프롬프트의 컨텍스트로 넣고
질문하면 된다. 그래서:

- **기다림 0** — 색인·크롤 지연(보통 수일~수주)이 사라진다. 올리기 **전에** 잰다.
- **교란 0** — 같은 순간, 같은 조건에서 원문 판과 바꾼 판을 나란히 물으므로 시점·경쟁사 변동이 끼어들지 않는다.
- **되돌리기 0** — 사이트를 건드리지 않으므로 실패해도 원복할 것이 없다.
- **비용이 계산 가능** — 호출 수 = 블록 × 질의 × 반복 × 엔진. 예산을 미리 못 박을 수 있다.

그리고 우리 자산에는 이미 **모드 개념이 있다.**

```
A2 관측 칸 (scoring-spec.ts)
  ObservationCell{ engineId, mode: on|off, mentioned: bool|null }
                          ↑ 여기에 ctx 한 값을 더한다
```

`mode:on` = 웹검색 켠 채 물음(검색환경) · `mode:off` = 검색 없이 물음(모델이 학습으로 아는 것) —
여기에 **`mode:ctx` = 우리가 준 문서만 보고 답하라**를 더하면 실험환경이 생긴다.
**칸의 자료형·집계·«못 잼 = null» 규율이 그대로 승계된다.**

## 2. 환경 셋 — 이것이 상품의 핵심 차별

| 모드 | 무엇을 묻나 | 답해 주는 것 |
| --- | --- | --- |
| **`ctx` 실험환경** | 이 문서만 보고 답하면, 우리를 인용하나 | **콘텐츠 자체의 힘.** 사본 실험이 도는 자리 |
| **`off` 순수** | 검색 없이, 아는 것만으로 답하면 | **학습데이터에 우리가 있나** (콘텐츠로 못 바꾸는 몫) |
| **`on` 검색환경** | 실제 검색을 켜고 물으면 | **최종 결과.** 발행 후 재관측이 도는 자리 |

**세 값을 나란히 놓으면 「고쳤는데 왜 효과가 없나」가 갈린다.**

```
편집안 반영 후

  ctx 올랐다  &  on 올랐다   →  성공. 그대로 간다
  ctx 올랐다  &  on 그대로   →  콘텐츠는 맞다. 막힌 건 도달 경로
                               → robots 의 AI 크롤러 차단 · JS 없이 안 읽힘 · 색인 지연
                               → SEO·GEO 진단의 해당 항목으로 자동 연결 (이미 있는 판정 항목)
  ctx 그대로 &  on 그대로    →  콘텐츠가 부족하다. 편집안을 다시 짠다
  ctx 그대로 &  on 올랐다    →  우리 문서 때문이 아니다. 경쟁 이탈·엔진 판 변경 등 외부 요인
```

특허 효과 문단이 말하는 **「콘텐츠 자체에 의한 영향과 도달 경로에 의한 영향을 구분」** 이 화면에서는
이 2×2 한 장이다. 경쟁 도구는 `on` 하나만 재기 때문에 「효과 없음」에서 멈춘다. **우리는 원인까지 짚는다.**

> **한계도 같이 적는다.** `ctx` 는 **API로 컨텍스트를 넣을 수 있는 엔진에서만** 된다 —
> ChatGPT·Gemini·Claude 3종. Perplexity 는 검색이 본질이라 `ctx` 가 의미를 잃고,
> 네이버 AI브리핑·구글 AI오버뷰는 주입 경로 자체가 없다. **그래서 정밀 실험 엔진이 3종**이고,
> 이는 사장님이 확정하신 「엔진 3」과 정확히 같다. `on` 재관측은 7종 전부에서 돈다.
> 화면에는 엔진별로 «잴 수 있는 환경»을 표기하고, 못 재는 칸은 0이 아니라 **«—»** 로 둔다(A7 `NOT_MEASURED`).

## 3. 모듈 5개 — 특허 부호 ↔ 기존 자산

| 특허 구성 | 하는 일 | **재사용할 기존 자산** | 새로 짤 것 |
| --- | --- | --- | --- |
| **디지털트윈 생성부 (132)** | 문서를 의료 사실 단위로 정규화 | 거래처 상세의 **「의료사실」 자리** · 심평원 가져오기 | 정규화기(LLM 추출 + 스키마 검증) |
| **〃 (사본 생성)** | 사실 단위 **하나만** 바꾼 변형본 | 리포트 **B8 발행 불변**(sha256 스냅샷)의 해시 규율 | **사본 생성기** — 신규 |
| **AI 실험 실행부 (134)** | 통제 질의 × 반복 × 엔진 호출·수집 | **`ai-engines.js`** · 크론 워커 · `TrackedQuery` · `Snapshot` | 모드 `ctx` 분기 + 질의셋 생성기 |
| **반사실 기여도 산출부 (136)** | 변화량 → 기여도 + 폭(신뢰구간) | **A2 집계형**(`measuredCells`/`unmeasuredCells`) · 추이 그래프 | **쌍 비교·부트스트랩** — 신규 |
| **안전성 제약 최적화부 (138)** | 4판정 → 배제 + **사유와 함께 출력** | **A1 판정 4종** · **A4 처분 분해**(dropped 사유 categorical) · 원고 검수(`/console/medical`) 의료광고법 규칙 | 4판정 묶음 1개 |
| **후속 검증부 (139)** | 발행 후 재관측·검증 | **A3 이슈 생애**(`awaiting_rescan`) · 재관측 크론 · 추이 ◆ 표시 | 환경 2×2 대조 카드 |

**새로 짜는 것은 사실상 셋뿐이다** — 사본 생성기, 기여도 산출기, 환경 대조 카드.
나머지는 기존 자산에 **값 하나·필드 몇 개**를 더하는 일이다.

### 3.1 사실 정규화기 (132)

```
입력   우리 문서 HTML
출력   medical_fact[]  { entity, attribute, value, source_url, valid_until,
                         officiality(공식성 신뢰도), span(문서 내 위치) }
방법   LLM 추출 → 스키마 검증(zod) → 사람 확인 대기열
규율   추출값은 곧바로 쓰지 않는다. 의료진 확인 전에는 officiality='미확인'.
       미확인 사실은 사본 실험은 돌되, ④ 관문에서 «확인 전» 보류로 잡힌다.
```

편집안의 **블록 하나 = 의료 사실 단위 하나**로 맞춘다. 이래야 「한 번에 하나만 바꾼다」가
화면(블록)과 실험(변형본)에서 같은 뜻이 된다.

### 3.2 사본 생성기 (132)

```
입력   기준 문서 + 바꿀 사실 단위 1개 + 조작(add|delete|correct|rephrase)
출력   content_variant { base_hash, variant_hash, changed_fact_id, diff }
검사   ① diff 가 그 사실 단위의 span 밖을 건드리지 않았는가  ← 어기면 실험 폐기
       ② base_hash 는 회차 내 불변인가                      ← B8 발행 불변 규율 준용
```

**①이 특허의 「하나만 바꾼다」를 코드로 지키는 자리다.** 사람이 손으로 만들면 반드시 두 군데를 고친다.
검사기를 두어 기계적으로 막는다.

### 3.3 실험 실행기 (134)

```
질의셋   같은 환자 의도 1개 → 축 변형 8개
         (연령·성별·지역·비용 민감도·증상·질환·시술·긴급도)
         임상 동등성은 시술 온톨로지로 검증 — 같은 시술·같은 의도로 묶이는지
실행     base 1벌 + variant N벌 × 질의 8 × 반복 12 × 엔진 3
기록     run_conditions{ engine, model_build, temperature, asked_at, query_variant_id }
         ← 교란 보정(§4)의 입력이자, 원장의 재현 근거
```

**base 는 문서·질의셋·회차가 같으면 한 벌만 재고 블록끼리 공유한다.** 비용의 절반이 여기서 빠진다.

## 4. 통계 — 「움직였다」를 언제 말하나

```
쌍 비교      같은 (질의 변형 × 반복 회차 × 엔진)에서 base 와 variant 를 짝지어 차이만 남긴다
             → 엔진·시각의 공통 변동이 상쇄된다 (특허의 «보정변수» 취지를 짝짓기로 구현)

폭(신뢰구간)  질의 변형 단위 클러스터 부트스트랩 2,000회
             → 96쌍(8질의 × 12반복)이지만 독립 표본은 질의 8개에 가깝다.
               반복을 독립으로 세면 폭이 실제보다 좁게 나와 «움직였다»를 남발한다

말하는 규칙   폭이 0을 물면 → «움직였다고 말하지 않는다». 화면에 «0을 뭅니다» 병기, 색을 죽인다
             못 잰 칸 → 0이 아니라 «—», 분모에서 제외 (A1·A2 규율 그대로)
             엔진 판이 회차 사이에 바뀌면 → 나란히 놓지 않는다 (B10 판 비교 금지 준용)
```

**엔진별로 따로 낸 뒤 합친다.** 엔진 편차가 5배까지 나는 것은 이미 실측된 사실이므로
(GPTO 벤치마크 리포트 §관찰 2), 평균으로 뭉개면 정보가 사라진다. 화면은 엔진 3칸 + 합산 1칸.

## 5. 비용 — 반복 12회를 지키면서 줄이는 법

반복 수는 **확정대로 12회 × 엔진 3** 을 지킨다. 줄이는 것은 **재는 블록 수**다.

```
후보 블록 10개 · 질의 8 · 반복 12 · 엔진 3  가정

전량 정밀        base 288 + (288 × 10)              = 3,168 호출
─────────────────────────────────────────────────────────────
2단계 실행
  0 기계 게이트   금칙 표현·기한 만료를 먼저 걷어낸다 (호출 0)
                 → 10개 중 2개 탈락, 8개 남음
  1 스크리닝      질의 4 · 반복 4 · 엔진 1            = 16 + (16 × 8) = 144
                 → 효과 상위 3블록 추림
  2 정밀          확정 조건 그대로                     = 288 + (288 × 3) = 1,152
                                                       ─────────────
                                                        합 1,296 호출  (59% 절감)
```

**게이트를 먼저 돌리는 것이 왜 독립성을 깨지 않나** — 특허가 요구하는 것은 「안전성 판정을 **기여도와
독립적으로**」이지 「기여도를 먼저 재라」가 아니다. 게이트가 기여도를 **참조하지 않으면** 순서는 자유다.
오히려 먼저 돌리면 **어차피 못 쓸 것을 재는 낭비**가 사라진다.

단, 게이트를 둘로 나눈다:

| | 무엇 | 언제 | 안 잰 이유 표기 |
| --- | --- | --- | --- |
| **기계 게이트** | 금칙 표현(최상급·효과 보장·전후사진) · 유효기간 만료 | **실험 전** | «재보지 않음 — 광고법» |
| **사람 게이트** | 사실 정확성 · 진료 실행 가능성 | **실험 후**(의료진 확인) | 실측값을 갖고 «제외됨» |

이래야 **「효과가 컸는데도 뺐다」가 실제 숫자와 함께 남는다** — 특허 청구항 4의
「배제 사유와 함께 출력」이 화면에서 힘을 갖는 지점이고, 담당자의 신뢰가 여기서 생긴다.
(콘텐츠 탭 시뮬 ⑤의 «+11.5%p → 제외» 행이 바로 이 경우다.)

**예산 상한**: 거래처·월 단위로 호출 상한을 두고, 상한에 닿으면 정밀 단계를 다음 회차로 미룬다.
미룬 블록은 «순번 대기»로 표시한다 — 조용히 빠지지 않는다.

## 6. 안전성 게이트를 코드로 강제하는 법

말로 된 규율은 언젠가 깨진다. 셋을 **구조로** 막는다.

1. **`safety_verdict` 는 `cf_effect` 를 참조하지 않는다.** 외래키도, 조인도 만들지 않는다.
   효과를 보고 판정을 무를 **경로 자체가 없게** 한다.
2. **배제 사유는 고정 목록**(A4 «사유는 categorical, prose 금지»). 자유 문장이면 「이번만 예외」가 적힌다.
   목록: `광고법-최상급` `광고법-효과보장` `광고법-전후사진` `기한만료` `사실불일치` `진료불가` `복제금지위반`.
3. **`edit_block.basis` 는 다른 표의 id 로만 채운다.** 자유 문자열 금지 →
   「근거 없는 제안」이 물리적으로 저장되지 않는다.

판정형은 새로 만들지 않고 **A1 그대로** 쓴다 — `pass · fail · unknown · not_applicable`,
`unknown` 은 분모 제외 + `unmeasured` 별도 집계. 「확인 전」이 곧 `unknown` 이다.

## 7. 실험 원장 — 재현할 수 있어야 자산이다

특허 자산의 값어치는 **「그때 그렇게 쟀다」를 나중에 증명할 수 있는가**에 달려 있다.
회차마다 다음을 봉인한다(B8 발행 불변 준용).

```
cf_experiment
  base_snapshot_hash · variant_snapshot_hash   ← 문서 본문 sha256
  query_set_id · query_set_version             ← 질의셋 판
  engines[] · model_builds{}                   ← 엔진 판
  repeats · run_conditions{}                   ← 실행 조건
  scoring_spec_version                         ← 채점 명세 판
  started_at · finished_at · operator
```

화면은 콘텐츠 탭 ⑤의 «어떻게 쟀는지 보기» → **실험 원장**(하위 화면, 탭 아님).
판이 하나라도 다르면 회차 간 비교를 **차단**한다(B10 판 체크섬 준용).

## 8. 상품이 되는 자리

특허를 넣는 목적은 화면 장식이 아니라 **팔리는 차이**다. 셋으로 나온다.

1. **제안·영업** — 「추측으로 고치지 않습니다. **올리기 전에 사본으로 미리 재고** 올립니다.」
   경쟁 도구가 «측정»에서 멈출 때 우리는 «측정 → 원인 → 편집안 → 배제 사유»까지 간다.
2. **리포트 발행본의 「측정 방법」 부록** — 업체에 나가는 문서에 절차·조건·판을 부록으로 싣는다.
   발행본은 판이 찍히므로 「그때 그 방법으로 쟀다」가 문서에 남는다(B8).
3. **요금 설계** — 실험 호출이 실제 비용이므로 **정밀 실험 횟수**를 상품 등급의 축으로 쓸 수 있다.
   (기본: 월 N블록 정밀 / 상위: 월 M블록 + 재관측 주기 단축)

> **표시 문구 주의.** 특허 표시는 **실제 출원·등록 번호와 상태를 확인한 뒤**에만 쓴다.
> 확인 전에는 「특허 출원 기술」류 표현을 화면·리포트·제안서 어디에도 넣지 않는다.
> 문구 확정은 사장님 확인 사항.

## 8.5 이식 현황 — 실물을 열어 보고 고쳐 적는다 (2026-09-01)

**이 문서를 쓸 때의 전제가 하나 틀렸다.** 「새로 짤 것이 셋」이라고 적었으나, 실물
`veo-platform` 을 열어 보니 **반사실 실험의 뼈대가 이미 서 있었다**(v0.3.455 기준).

```
apps/api/src/veo/observations/counterfactual/   실험 설계·검증·기여도·선택   약 2,350줄
apps/api/src/veo/medical/                       사실 단위·안전성·검수 규칙   약 1,340줄
apps/web/.../CounterfactualCard.tsx             기여도 실험 화면
```

이미 있는 것 — 질의 최소 개수 관문(5개 미만이면 **시작을 거부**) · 단일요소 변형 강제 ·
호출 수 견적 · 월 상한 · 배제 게이트(기여도를 입력받지 않는 독립 판정) · 결과 없는
자리를 0 이 아니라 «—» 로 그리는 규율. **§4~§6 에 적은 것의 상당 부분이 이미 코드다.**

그래서 1판의 실제 일감은 「짓기」가 아니라 **「자리 잡기」**였다:

| 1판에서 한 것 | 판 |
| --- | --- |
| 거래처 탭 여섯 → 일곱, 「콘텐츠」 5번째 신설 | 0.3.456 |
| 기여도 실험 절을 AEO 탭 → 콘텐츠 탭으로 이관 | 0.3.456 |
| 특허출원중 표시 세 자리(콘텐츠 탭 머리·사실 단위 표·리포트 배제 사유 절) | 0.3.456 |

**2판에서 한 것** — 여기서도 전제 하나가 갈렸다. 「4판정 묶음을 새로 만든다」고 적었으나
관문은 이미 C1(근거 유효기간)·C3(의료광고 위험)을 판정하고 있었고, **비어 있던 것은 C2 하나**였다.
그 자리에 코드가 남긴 사유가 정확했다 — 「예약 속성이 표준 이름으로 고정되기 전에는 판정하지 못한다」.

| 2판에서 한 것 | 판 |
| --- | --- |
| 운영 속성 **표준 이름 고정** + 충돌 규칙 셋 (`medical/operating.py` 신규) | 0.3.457 |
| C2 를 배제 관문에 배선 — 주말·야간 진료 주장 ↔ 휴진일·진료시간, 당일예약 ↔ 예약방식 | 0.3.457 |
| **실험 원장** — 「어떻게 쟀는지 보기」(질의·반복·조건·호출·난수 씨·기준일·시작·끝) | 0.3.457 |

C2 의 판정 범위는 **우리가 가진 사실끼리의 모순**까지다. 「그 시각에 자리가 있나」는
예약 시스템 연동 전이라 판정하지 않고, 그 사실이 화면의 「검사 못 함」 줄에 남는다.
모순은 좁게 잡는다 — 주장과 반대 근거가 둘 다 읽힐 때만. 배제는 되돌리기 어려운
판정이라, 넓게 추측하면 멀쩡한 후보가 떨어진다.

**3판에서 한 것** — 여기서 전제 하나가 또 갈렸다. §1 은 「`ObservationCell.mode` 에
`ctx` 를 더한다」고 적었으나, **기여도 실험이 이미 컨텍스트 주입으로 돈다**
(`_injected_prompt`). 즉 실험환경은 이미 있었고, 없던 것은 **그 값을 검색환경과
잇는 경계**였다.

| 3판에서 한 것 | 판 |
| --- | --- |
| `published_at` 신설 — 담당자가 「올렸습니다」를 찍는다 (마이그레이션 `20260901published`) | 0.3.458 |
| `environments.py` — 올린 때 앞뒤 28일의 정기 진단을 갈라 두 비율 차의 95% 구간 | 0.3.458 |
| 사분면 넷 + 못 잼, 화면의 대조 카드 | 0.3.458 |

구간이 0을 물면 「그대로」다 — 사본 쪽 `confirmed` 와 같은 잣대라야 두 축을 한 표에
놓을 수 있다. 구간 조회는 주간·월간과 **같은 `_runs_in_window`** 를 쓴다.

**3판의 남은 둘도 마쳤다 (0.3.459)**

| 것 | 어떻게 |
| --- | --- |
| 2단계 실행 | 실험 설계에 **스크리닝(반복 4·엔진 1) / 정밀(반복 12·엔진 3)** 프리셋. 판은 반복과 엔진을 **함께** 옮긴다 — 하나만 바뀌면 두 판 어느 쪽으로도 못 읽는다. 호출 수를 누르기 전에 보인다. 반복 기본값 20 → **12**(정밀 판 확정값) |
| 리포트 「측정 방법」 부록 | 「다시 세우려면」 — 표기 규칙 판 + 채점 명세의 id·판·**체크섬**. **판띠가 이미 말하는 것은 다시 적지 않는다**(발행 시각·측정 구간·내용 지문) — 같은 값을 두 곳에 적으면 한쪽만 고쳐질 때 문서가 자기와 어긋난다 |

§5 의 비용 설계가 이것으로 화면에 선다.

가지 `claude/seo-geo-aeo-content-report-omspqb` · 커밋 `88178e1`(1판) · `92ea8e7`(2판) ·
`17005c7`·`adf936c`(3판) · **배포 안 함**(ANSEO 방 소관). 미배포 넉 판 = v0.3.456~459.

## 10. 한계와 위험 — 먼저 적어 둔다

| 위험 | 실제로 어떻게 되나 | 어떻게 다루나 |
| --- | --- | --- |
| **실험환경 ≠ 검색환경** | `ctx` 에서 오른 것이 `on` 에서 안 오를 수 있다 | 숨기지 않는다. 그 차이 자체를 §2의 진단 결과로 판다 |
| **엔진 커버리지** | `ctx` 는 3종에서만. AI브리핑·AI오버뷰는 못 잰다 | 엔진별 «잴 수 있는 환경» 표기 · 못 재는 칸은 «—» |
| **응답 변동성** | 폭이 넓어 «움직였다»를 못 말하는 블록이 나온다 | 그게 정상이다. 넓으면 말하지 않는다. 반복을 늘려 억지로 좁히지 않는다 |
| **엔진 판 변경** | 모델이 갱신되면 과거 회차와 비교 불가 | 판 체크섬으로 비교 차단 · 원장에 model_build 봉인 |
| **비용** | 정밀 1블록 = 288 호출 | 2단계 + base 공유 + 월 상한. 미룬 블록은 «순번 대기»로 표시 |
| **정규화 오류** | LLM 추출이 의료 사실을 잘못 쪼갠다 | 미확인 사실은 officiality='미확인' → ④에서 «확인 전» 보류. 의료진 확인 전에는 발행 근거로 안 쓴다 |
