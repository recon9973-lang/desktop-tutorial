## 이름부터 — ANSEO 와 VEO 는 같은 제품이다

- **VEO** — 저장소 이름, 개발 중 코드명. 문서·ADR·커밋 메시지 대부분이 이 이름을 쓴다.
- **ANSEO** — 2026-08-18 이후 화면에 노출되는 **제품명**(로고 워드마크, 헤더, 푸터,
  API 문서 타이틀, 초대 메일 등). "VAI" 라는 이름이 잠깐 쓰인 적이 있으나(v0.3.130
  전후) 지금은 ANSEO 로 최종 확정되어 있다.
- 개발사: **VENOM**(베놈애드) · 방법론 연구: **VEO-LAB**.
- 한 줄 태그라인: `SEO · GEO · AEO · 네이버 키워드 인텔리전스`.

## 이 제품이 무엇인가 (한 문단)

병원마케팅 대행사 VENOM이 자사 거래처(병·의원)의 검색 노출을 관리하기 위해 만든
**폐쇄형 사내 도구**다. SaaS가 아니다 — 회원가입 화면이 없고, 관리자가 초대해야만
계정이 생긴다. 세 축을 **하나의 점수로 합치지 않고** 각각 실측해서 보여준다:

1. **SEO 준비도** — 검색엔진이 사이트를 크롤·색인할 수 있는가 (URL 기반, 즉시 채점)
2. **GEO 준비도** — AI 답변 엔진이 사이트 구조를 추출·검증할 수 있는가 (URL 기반, 즉시 채점)
3. **AEO(AI 답변 관측)** — 실제 AI 챗봇이 질문에 우리 브랜드를 언급/인용하는가
   (질문 기반, 외부 API를 정기적으로 호출해서 관측 — 돈이 나가는 축)

그리고 이 셋을 **거래처별 이슈 → 조치 → 재진단 → 리포트 발행 → 공유 링크**로 이어
붙인다. 제품 전체의 제1원칙(`CLAUDE.md`, `PRODUCT.md`): **"화면에 나가는 모든 숫자는
잰 것이다"** — 못 잰 값은 `0`이 아니라 `—`로 표기하고, 자격증명이 없는 외부 연동은
그럴듯한 값을 지어내지 않고 "비활성" 상태를 그대로 보여준다.

## 지금 이 순간의 스냅샷 (다시 잴 명령 포함)

```bash
# 저장소 규모
git -C veo-platform log -1 --oneline
find veo-platform/apps veo-platform/packages -name "*.py" -o -name "*.ts" -o -name "*.tsx" | wc -l

# API 경로 수
python3 -c "import json;print(len(json.load(open('veo-platform/apps/api/openapi.json'))['paths']))"

# DB 테이블 수
grep -rhoE '__tablename__\s*=\s*"[a-z_]+"' veo-platform/apps/api/src/veo/db/models/*.py | sort -u | wc -l
```

[실측 2026-08-27] 테이블명 유일 개수 **60개**(`__tablename__` grep, 아래
`06-데이터-저장방식.md` 표 참고). `docs/README.md`(veo-platform, 2026-08-12 시점)에는
"48개"로 적혀 있어 그 사이 마이그레이션이 늘었다 — 문서 날짜가 다르면 숫자도 다르다는
것을 그대로 보여주는 사례이니, 재구현 시점에는 반드시 위 명령으로 다시 세야 한다.
