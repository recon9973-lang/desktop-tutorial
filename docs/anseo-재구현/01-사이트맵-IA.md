## 2. 전역 헤더 — "묶음 없는 납작한 목록" (2026-08-18 확정, v2)

```
[ANSEO 로고=대시보드]  거래처  ·  (거래처 안에서는 진단/AEO/이슈/리포트/설정 탭으로 교체)     [계정 ▾]
```

- 예전(2026-08-16) 구조는 `[대시보드][거래처][도구함 ▾]`처럼 묶음(그룹) 3개였다.
  각 묶음이 항목을 1개씩만 담고 있어서 묶음 이름이 화면에 나올 자리가 없다는 것을
  실측(사장님이 직접 "도구함은 어디서 나왔지?"라고 지적)으로 확인하고 폐기했다.
- 항목이 서는 **자리(`ConsoleNavPlace`)**는 4종류뿐이다:
  - `BRAND` — 로고 자체가 그 화면(대시보드)이다. 메뉴에 따로 걸지 않는다.
  - `MENU` — 헤더에 이름 그대로 선다. 지금 이 자리는 **"거래처" 하나뿐**이다.
  - `TOOL` — 헤더 **+ 계정 메뉴 양쪽**에 선다. "원고 검수"가 이 유일한 예다 —
    거래처 상세 안에서는 헤더가 거래처 탭으로 바뀌어 전역 메뉴가 밀려나므로,
    그때는 계정 메뉴가 유일한 입구가 된다.
  - `ABSORBED` — 헤더에 전혀 안 뜬다. 다른 화면 **안**의 링크로만 열린다(아래 §4).
- 계정 메뉴(▾): 내 계정 · 로그아웃. 원고 검수(TOOL)도 겹쳐 걸린다.
- 공개 메뉴(`PUBLIC_NAV`)는 **빈 배열**이다 — 폐쇄형 사내 도구라 비로그인 방문자에게
  보여줄 목록이 없다(사장님 확정 2026-08-15).

## 3. 거래처 상세 — 탭 6개 (2026-08-21 확정)

`CUSTOMER_TABS`, 헤더가 그린다(화면 코드가 따로 탭 이름을 적지 않는다 — 이름·차례가
어긋나는 사고를 막기 위해 단일 소스):

```
진단(diagnosis) · SEO · GEO · AEO(aeo) · 이슈(issues) · 리포트(reports)
```

- **"진단"은 개요다.** SEO·GEO·AEO 세 축의 카드를 보여주고 누르면 그 축 탭으로 이동.
  각 축의 저장된 결과판(board)만 읽으므로 API 왕복이 늘지 않는다.
- **"설정"은 탭이 아니다.** 사장님이 "설정은 업체등록/수정 페이지로 넣으라"고 지시
  (2026-08-19) — 재조사해보니 설정에는 업체 정보·주소·브랜드 식별·사실 단위만 있었고
  이건 전부 **등록/수정**의 일이었다. 그래서 `/console/customers/{id}/edit` 한 화면으로
  합쳤다. 정기 진단 on/off 스위치는 각 축(SEO/GEO/AEO) 탭 안에 있다.
- SEO/GEO가 탭으로 분리된 이유(2026-08-21 사장님 주문): 예전엔 "진단" 탭 하나가
  SEO 저장본과 GEO 판정을 **둘 다** 받아서 정보가 섞였다. 지금은 탭마다 자기 축의
  데이터만 받는다.

## 4. `ABSORBED` 화면들의 실제 입구 (헤더에 없다고 못 여는 게 아니다)

| 화면 | 헤더에 없을 때 실제 입구 |
|---|---|
| `/console/seo`, `/console/geo` | 거래처 상세의 SEO/GEO/AEO 탭이 이 부품을 그대로 품는다 |
| `/console/review` | 대시보드의 "검수 대기열" |
| `/console/keywords`, `/console/competitors`, `/console/reports` | 거래처 탭 속 링크 |
| `/console/usage`, `/console/scoring-versions`, `/console/credentials`, `/console/team`, `/console/changelog` | 대시보드 "운영 관리" 접힘 섹션 |
| `/console/account` | 계정 메뉴 |
| `/console/dashboard` | ANSEO 로고 |

이 규칙은 `navigation.test.ts`(입구 시험)로 강제된다 — 지침서 원칙 0-E("부를 수 없는
기능은 없는 기능이다")를 헤더가 항목을 감춰도 실제로는 어딘가에서 열려야 한다는
형태로 코드에 박아 둔 것이다. **재구현 시 이 시험을 반드시 이식할 것** — 화면을
새로 만들고 메뉴에 안 걸면 "존재하되 부를 수 없는 죽은 화면"이 생긴다.

## 5. 권한에 따른 메뉴 가시성

- `visibleConsoleNav(identity, orgIndustry)` — 로그인 안 했으면 빈 배열. 각 메뉴 항목은
  `permission: Permission | null` 을 갖고, `null`은 "로그인한 사람 전원"(예: 계정,
  변경이력), 특정 권한 문자열(`scan:read`, `customer:read`, `observation:review` 등)은
  그 권한 보유자에게만.
- `industry?: IndustryCode` — 업종별 메뉴 숨김. 지금 유일한 예는 "원고 검수"
  (`industry: 'MEDICAL'`) — 법률사무소 등 비의료 업종에는 의료광고법 검수기가 안
  보인다. **단, 링크를 숨기는 건 예의일 뿐** — 주소를 직접 치면 열리므로 화면
  자신도 같은 업종 게이트를 각자 둔다(`medical/page.tsx`).
- 기본 업종은 `MEDICAL`(과거 호출부·오류 상황의 폴백) — 서버의 `code_of` 폴백과 대칭.

## 6. 재구현 시 주의

1. **메뉴 구조를 손으로 두 번 적지 않는다.** 헤더와 거래처 탭 화면이 각자 탭 이름을
   중복 정의하면 이름/순서가 갈라진다 — `CUSTOMER_TABS` 상수 하나를 양쪽이 import.
2. **공개 랜딩 페이지를 만들지 않는다.** `/`는 그냥 `/login`으로 리다이렉트한다.
   마케팅 사이트가 필요하면 완전히 별도 프로젝트로 둬야 한다(실제로 VENOM은
   `desktop-tutorial` 저장소에 별도 워드프레스형 마케팅 사이트를 갖고 있다).
3. 무료 진단 도구(`/tools/checker` 등 3종)는 코드가 `archive/free-tools-web`에 보존만
   되어 있고 메뉴에서 완전히 뺐다 — 되살릴 계획이면 그 README 절차를 따를 것.
