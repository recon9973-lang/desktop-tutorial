# 헤더 · 히어로 · 푸터

## 0. 먼저 — "마케팅 히어로"는 없다. 이것이 설계 결정이다

`/` 접속 시 화면을 그리지 않고 **곧바로 `/login`으로 302 리다이렉트**한다
(`apps/web/src/app/(public)/page.tsx`). 코드에 남은 실제 주석:

> "ANSEO는 파는 SaaS가 아니라 폐쇄형 사내 도구다(사장님 2026-08-15: *"우리는 saas
> 페이지가 아니라 폐쇄형 사내 erp 형태가 컨셉이야"*). 소개 문구·무료 도구 노출이
> 있던 공개 랜딩은 그 결정으로 걷어냈다."

**재구현 시 반드시 짚을 것**: 만약 재구현 목적이 "마케팅 사이트"라면 이 프로젝트가
아니라 `desktop-tutorial` 저장소의 `venom-wordpress/preview/`(베놈 자체 홍보 사이트,
venom-new-site.vercel.app)를 참고해야 한다. ANSEO/VEO는 그 반대 — **로그인 게이트가
곧 첫 화면**인 내부 도구다. 무료 점검 도구 3종(SEO/GEO/네이버 키워드)이 한때
공개 랜딩 역할을 했으나 2026-08-15 결정으로 완전히 닫혔고, 코드는 `archive/free-tools-web`
에 통째로 보존만 되어 있다.

## 1. 헤더 (`SiteHeader.tsx`, 공개 구역 전용)

```tsx
<header>
  <Link href="/">
    <span>ANSEO</span>                         {/* 워드마크 */}
    <span>SEO · GEO · AEO · 네이버 키워드</span>  {/* 태그라인 */}
  </Link>
  <nav aria-label="주요 메뉴">
    <Link href="/console/dashboard">콘솔</Link>
  </nav>
</header>
```

- 공개 구역(로그인/초대/공유리포트) 헤더는 **의도적으로 도구 목록을 걸지 않는다.**
  코드 주석: "폐쇄형 사내 도구다. 로그인·초대·공유 리포트 화면 위에 무료 점검 도구
  메뉴가 떠 있으면 그 자체가 영업용 대문이 된다. 상표와 콘솔 입구만 남긴다."
- 로그인 후 콘솔 안에서는 이 헤더 대신 `ConsoleNav.tsx`가 그려진다(01번 문서 §2 참고,
  로고=대시보드 입구, 거래처 메뉴, 계정 메뉴).

## 2. 로그인 화면 (`/login`, 공개 구역의 사실상 첫 화면)

```
eyebrow: "콘솔"
title:   "로그인"
lede:    "콘솔은 로그인한 사용자만 사용할 수 있습니다. 로그인하면 계정에
          부여된 권한만큼의 화면이 열립니다."
카드:    "계정으로 로그인" (이메일+비밀번호 폼)
안내문:  "비밀번호를 잊었거나 계정이 없다면 조직의 콘솔 관리자에게 문의하세요.
          이 화면에서는 계정을 새로 만들 수 없습니다."
```

- `dynamic = 'force-dynamic'` — 로그인 폼은 절대 캐시되지 않는다.
- `next` 쿼리 파라미터를 안전하게 검증(`safeNextPath`)한 뒤 로그인 성공 시 그 경로로
  돌려보낸다(오픈 리다이렉트 방지 — 서버 라우트 핸들러에서 한 번 더 검증).
- 로그인 시도 실패는 해시된 식별자 기준으로 잠금 처리(8회 실패 시 900초 잠금) —
  응답은 "계정이 존재하지 않음"과 "비밀번호 틀림"을 구분하지 않는다(계정 존재
  여부를 흘리지 않기 위해).

## 3. 초대 수락 (`/invite/[token]`)

관리자가 팀원 관리 화면에서 발급한 1회용 토큰 링크. 회원가입 폼이 없으므로 이 경로가
유일한 계정 생성 통로다. 운영 환경에서 링크에 박히는 도메인은
`VEO_CONSOLE_BASE_URL` 환경변수로 결정되며, 이 값이 `localhost` 그대로면 운영에서는
아예 **거부**한다(`ConsoleBaseUrlNotSet` 예외) — 잘못된 링크가 조용히 나가는 것을
코드로 막는다.

## 4. 공유 리포트 (`/results/[token]`, 외부 거래처가 보는 유일한 화면)

`SharedReport.tsx`의 설계 원칙이 그대로 핵심이다:

> "별도 화면을 만들지 않는 것이 요점이다: 공유받은 사람이 보는 리포트와 진단한
> 사람이 본 리포트가 한 컴포넌트에서 나오므로, 둘이 다르게 그려질 방법이 없다."

- 콘솔 내부의 `Report` 컴포넌트(`tools/checker/PublicChecker`)를 그대로 import해서
  재사용. 차이는 딱 하나 — `previous`(직전 측정과의 비교)가 없다. 그 값은 진단한
  사람의 브라우저 `localStorage`에만 있고 링크를 받은 제3자는 접근할 수 없기 때문.
- 인쇄(PDF 저장) 대응: `beforeprint` 이벤트에서 접혀 있던 `<details>` 요소를 전부
  강제로 펼친다 — 인쇄물에 접힌 정보가 빠지는 사고 방지.
- TTL 90일(`report_share_ttl_days`), 만료 시 `not-found.tsx`.
- 콘솔(내부)과 공유 리포트(외부)는 **"물성"을 가른다**(PRODUCT.md 제약): 콘솔은
  "작업대"처럼, 공유 리포트는 "진단서"처럼 보이게 톤을 다르게 가져간다.

## 5. 푸터 (`SiteFooter.tsx`)

```
ANSEO — 개발 VENOM · 연구 및 방법론 VEO-LAB · 앱 버전 v{APP_VERSION} · 변경 이력 (링크)

ANSEO가 계산하는 점수는 검색엔진과 AI 답변 엔진이 사이트를 읽을 수 있는 기술·구조
준비도입니다. 검색 순위를 예측하거나 보장하지 않으며, 수집한 값은 모두 출처와 수집
시각을 함께 표시합니다.
```

- 버전 표기는 **커밋 SHA가 아니라 사람이 읽는 판번호**(`APP_VERSION`, `lib/changelog.ts`
  에서 관리) — "커밋 SHA는 구분이 안 된다"는 코드 주석 그대로. 클릭하면 변경 이력
  화면으로 이동.
- 법적 고지 문구가 하드코딩돼 있다 — "순위를 예측/보장하지 않는다"는 문구는
  ADR 0003/0010과 직결되는 규제 리스크 방어 문구이므로 재구현 시 임의로 빼면 안 된다.

## 6. API 문서 타이틀/설명 (개발자용 "히어로"에 해당)

FastAPI `docs_url=/docs`의 타이틀과 설명(`apps/api/src/veo/api/app.py`):

```
title:   "ANSEO API"
summary: "SEO · GEO · Naver Keyword Intelligence Platform"

측정 원칙
- SEO 준비도, GEO 준비도, 실제 AI 가시성, 네이버 키워드 수요는 각각 별도의 지표입니다.
  하나의 불투명한 총점으로 합치지 않습니다.
- 준비도 점수는 검색 순위 예측값이 아닙니다.
- 모든 점수에는 방법론 버전, 체크섬, 적용 분모, 계산 과정, 신뢰도가 함께 제공됩니다.
- '해당 없음'은 0점이 아니라 분모에서 제외되고, '진단 못 함'은 실패가 아니라
  coverage와 confidence에 반영됩니다.
- 외부 제공자 자격증명이 없으면 해당 항목은 '진단 못 함'이 되며, ANSEO는 추정값을
  실제 데이터처럼 표시하지 않습니다.
```

이 문구가 사실상 제품의 "브랜드 보이스" 전체다 — 화면 카피, 오류 메시지, 리포트
설명 문구 전부 이 톤(측정 원칙을 반복 명시)을 따른다. 재구현 시 새 카피를 쓸 때도
이 원칙 문구를 참고 톤으로 삼을 것.
