# 재구현 체크리스트 — 사용자가 안 물어본 것들

요청 목록(사이트맵·기능·히어로·푸터·API·Neon·Vercel·Supabase·Railway·저장 방식·코드)에
안 들어있지만, 실제 저장소를 보면 **제품의 정체성 그 자체**인 항목들. 빠뜨리면
"그럴듯하지만 다른 제품"이 나온다.

## 1. 이 제품의 진짜 제1원칙 — 기능이 아니라 "무엇을 안 하는가"

가장 놓치기 쉬운 것: ANSEO/VEO는 기능 목록으로 재현할 수 있는 제품이 아니다.
**"안 하는 것"의 목록이 제품의 핵심이다.**

| 하고 싶어지는 것 | 왜 안 하는가 |
|---|---|
| 못 잰 값을 `0`으로 표시 | `0`은 "쟀는데 없다"는 뜻이라 정반대 결과가 된다. 못 잰 값은 `—` |
| SEO·GEO·AEO를 하나의 종합 점수로 합산 | 합치는 순간 어느 쪽도 실행 가능한 정보가 아니게 된다(ADR 0003) |
| 자격증명 없을 때 그럴듯한 추정값 제공 | "고객에게 거짓말하는" 경로로 규정, 출시 차단 항목 B-2 |
| 조건이 다른 두 점수를 나란히 비교 | "우리가 잣대를 바꾼 것"이 "개선"으로 읽힌다(ADR 0010) |
| 표본 3회짜리 결과에 소수점 정밀도 | 표본이 감당 못 하는 정밀도 — Wilson 신뢰구간으로 처리 |
| 네이버 데이터랩 상대지수를 "검색량"으로 표기 | 절대값(검색광고 API)과 상대지수(데이터랩)를 섞으면 허위정보 |
| "실시간 인기 검색어" 명칭 사용 | 네이버가 2021년에 이 서비스를 종료 — 없는 출처를 있다고 말하는 것 |
| 이슈를 사람이 "완료" 버튼으로 닫기 | 재진단에서 실제로 통과해야 닫힘(ADR 0011) — 자기신고 방지 |

## 2. 보안 — SSRF 방어 (크롤러가 "고객이 준 임의 URL"을 여는 문제)

거래처 URL을 그대로 크롤링하는 제품이라 SSRF가 구조적 위험이다. 실제로 강제되는
체크리스트(`docs/operations/release-checklist.md` B-6):

- 리디렉션 **매 홉마다** 최종 IP를 재검사(DNS rebinding 방어)
- 한 호스트가 공인 IP와 사설 IP를 함께 반환하면 거부
- IPv4-매핑 IPv6(`::ffff:127.0.0.1`), NAT64(`64:ff9b::/96`), CGNAT(`100.64.0.0/10`),
  링크로컬(`169.254.0.0/16`) 전부 차단
- `http`/`https` 외 스킴 거부, 허용 포트 밖 거부
- 렌더러(헤드리스 브라우저) 컨테이너는 **별도 네트워크**에만 붙고 DB/Redis/오브젝트
  스토리지/메타데이터 엔드포인트에 접속을 실제로 시도해서 실패하는지 검증
- 네트워크 분리를 "이미 막았으니 됐다"고 여기지 않고 애플리케이션 계층 검증도 유지

## 3. 대상 서버에 대한 "크롤 예절" — 남의 서버를 두드리는 도구가 되지 않기

`core/settings.py`에 명시적 상한이 촘촘히 박혀 있다(값 자체보다 **"동시성"과
"총량"을 별개 숫자로 관리한다**는 설계가 핵심):

```
동시 연결(순간 부하)         2   (원래 4였다가 "의뢰서 §5.2 동일 호스트 동시연결 2 이하"로 낮춤)
최소 요청 간격(순간 밀도)     1초  (0.019초 간격으로 131장을 받아간 실측 사고 이후)
시간당 호스트 총 요청(총량)  콘솔 450 / 공개도구 60
페이지 상한                 200장 (100장이던 시절 실도메인 8/8이 잘림 실측)
링크 추적 깊이               4단계
사이트맵 문서 수             10개
템플릿 그룹 표본             12장 (블로그처럼 반복 템플릿인 페이지 그룹만, 상한 안에 들면 전량)
```

**"동시성"과 "시간당 총량"은 서로 다른 것을 막는다** — 하나만 있으면 총량 한도
안에서 순간적으로 몰아서 두드릴 수 있다(실측: 초당 50번). 재구현 시 이 둘을
반드시 별도 파라미터로 설계할 것.

## 4. 비용 상한 — "기본 꺼짐"인 유료 기능들

돈이 나가는 기능은 전부 **기본값이 꺼짐**이고, 켜지 않으면 아무 소리도 안 난다 —
그래서 "서비스 전이라 0건"과 "오픈했는데 깜빡하고 안 켜서 0건"이 똑같이 보인다는
것이 릴리스 체크리스트가 명시적으로 경고하는 함정이다.

| 기능 | 기본값 | 안 켜면 |
|---|---|---|
| 정기 재진단(`rescan_after_days`) | 7(주1회, 이미 켜짐이 기본) | — |
| 월간 리포트 자동발행(`report_auto_publish_day`) | 0(꺼짐) | 자동 발행 자체가 없음 |
| 정기 AI 관측(`observation_runs_per_week`/`observation_days_of_month`) | 0/빈값(꺼짐) | AEO 축이 전혀 안 돎 |
| 반사실 실험 월 예산(`counterfactual_monthly_budget_usd`) | 0.0(꺼짐) | 실행 창구가 거절 |
| 운영 알림 웹훅(`alert_webhook_url`) | 빈 값(꺼짐) | 점수 급락 알림 없음(DISABLED로 보이지만 아무도 화면을 안 보면 모름) |

확인은 설정값이 아니라 **실제로 돌았는지 SQL로** 검증:
```sql
select count(*) from scan_runs where requested_by_user_id is null;  -- 정기 재진단
select count(*) from report_versions;                                -- 자동 발행
select count(*) from observation_runs;                               -- AI 관측
```

## 5. 법적/규제 제약 — 의료광고법

- 병원 대상 서비스이므로 **의료법 제56조(의료광고)** 규칙이 별도 검사기(`/console/medical`)
  로 내장돼 있다. "최상급 표현", "효과 보장", "전후사진" 등 금지 패턴 검사.
- 실제 사고 기록: "복사해서 붙여넣으세요" 형태의 예시 코드 안에 **지어낸 진료비·
  통계·의학 서술**이 들어가 운영까지 나간 적이 있었다(2026-08-08). 이후 금액·기간·
  통계·주소가 `[대괄호]` 표기 밖에 있으면 실패하는 테스트가 관문으로 추가됨 —
  **예시/플레이스홀더 데이터도 검증 대상**이라는 뜻. 재구현 시 "이건 그냥 예시라
  괜찮다"는 예외를 두지 말 것.
- 리포트/화면 문구에 "검색 순위를 예측하거나 보장하지 않는다"는 고지가 하드코딩돼
  있음(푸터, 03번 문서 §5) — 준비도 점수를 순위 예측처럼 팔면 안 된다는 규제
  리스크 방어.

## 6. 감사 로그·부인방지

- 모든 판정에 **근거(수집물의 해시)**가 따라온다 — "이 결과를 낳은 원본이 무엇인지"
  를 나중에도 재현할 수 있어야 한다는 요구가 데이터 모델(`evidence`, `fetch_captures`
  테이블)에 그대로 반영돼 있다.
- 자격증명 조회/변경, 로그인 시도, 조직 간 접근 시도가 `audit_logs`/`login_attempts`
  테이블에 남는다.

## 7. 배포 빈도 상한이 "코드에" 있다는 것의 의미

무료 GitHub Actions 분(2,000분/월)을 지키기 위해 **하루 배포 2회 상한**이
`scripts/deploy.sh` 안에 하드코딩돼 있다(2026-09-01까지 한정, 그 뒤 자동 해제). 이건
"글로 적어 둔 규칙"이 아니라 **스크립트가 카운트해서 거부**하는 관문이다 — 재구현 시
"운영 정책"이라고 문서에만 적어두면 반드시 안 지켜진다는 게 이 프로젝트 전체의
반복된 교훈(0-H: 규칙에는 관문이 필요하다).

## 8. 빌드 성공 ≠ 배포 성공 ≠ 기능이 실제로 도는 것 (세 번 반복된 사고 패턴)

- 타입체크·린트·테스트가 전부 초록이어도 **Next.js 빌드**는 별도로 깨질 수 있었다
  (Next.js 16의 `middleware`→`proxy` 규약 변경, `next build`에서만 드러남). Vercel은
  **이미 배포한 뒤**에 실패를 알려주므로, 화면은 옛 코드로 조용히 남는다.
- 배포 이미지에 필요한 데이터 폴더가 빠져도 **배포 자체는 성공**한다(05번 문서 §5,
  세 번 반복). "성공" 표시를 믿지 말고 **바뀐 화면을 실제로 열어서** 확인하는 것이
  체크리스트 마지막 항목으로 명시돼 있다.
- **재구현 시 교훈**: "관문 통과"와 "실제로 켜져서 돈다"를 별개 사실로 취급하고,
  둘 다 자동 검증(스모크 테스트 + 실제 데이터 카운트 확인)에 넣을 것.

## 9. 이 문서 세트가 다루지 않은 것 (의도적 범위 밖)

- `venom-wordpress/`(베놈 자체 마케팅 사이트, `desktop-tutorial` 저장소 내부) — ANSEO와
  완전히 다른 프로젝트다. "히어로/랜딩" 감각이 필요하면 이쪽을 봐야 한다.
- 특허 출원 관련 상세 청구항 해석 — `docs/plans/2026-08-17-anseo-integration-PLAN.md`
  에 있으나 법적 판단(변리사 영역)은 이 문서가 다루지 않는다.
- 실제 API 키 값, 조직/거래처의 실 데이터 — 이 문서 어디에도 없고, 있어서도 안 된다.
