# 화면과 기능 상세

콘솔 화면 15개 + 공개 화면 4개를 실제로 무엇을 하는지 기준으로 정리한다. 화면 이름은
`navigation.ts`의 라벨을 그대로 쓴다(코드 파일명과 다른 경우 병기).

## 1. 대시보드 (`/console/dashboard`)

전 거래처 **통합** 현황판. `PRODUCT.md`가 규정하는 역할:
- 아침에 열어 밤사이 변화 확인 + 오늘 할 일 확인
- 바로 실행(진단 걸기·거래처 등록) 버튼
- 통합 결과(SEO/GEO/AEO 전체 요약)
- 이슈(전 거래처 통합) · 검수 대기열(전 거래처 통합)
- **운영 관리**(접힘 섹션): 사용량·채점기준·외부 연결 열쇠·팀원·변경이력 — 개별 메뉴가
  아니라 여기 한 자리에 접혀 들어간다(`ABSORBED`).

## 2. 거래처 (`/console/customers`, `/customers/new`, `/customers/projects`, `/customers/[id]`)

- **목록** = 거래처 메인. 전 거래처 표. 목표 규모 50~100곳 — 15곳/페이지, 밀도 규칙 적용.
- **등록**(`new`) — 상호·주소·측정 URL 입력.
- **프로젝트**(`projects`) — 측정 단위(사이트/URL 세트) 관리. 원래 독립 메뉴였다가
  "업체 관리와 헷갈린다"는 사용자 감사로 거래처 관리 하위 화면으로 흡수됨.
- **상세**(`[customerId]`) — 탭 6개(01번 문서 §3): 진단(개요)·SEO·GEO·AEO·이슈·리포트.
  설정(브랜드 식별·측정 주소·사실 단위)은 탭이 아니라 `edit` 화면.

## 3. SEO 진단 (라우터 `seo`, 화면은 거래처 탭에 흡수)

- **한 번 크롤 → 두 눈금(SEO+GEO)이 동시에 나온다.** "SEO 따로, GEO 따로 두 번 재는"
  실수를 메뉴 통합으로 막았다.
- 명세: `veo.seo.readiness` v1.10.0(2026-08-12 발행) — 9개 영역(6개가 채점 대상),
  검사 59개(49개 채점+10개 점수 밖), 분모 100.0 고정, 치명 관문(gate) 5개, 5단계 등급.
- 크롤 예산: 페이지 상한 200장 · 그룹(블로그 등 템플릿) 표본 12장 · 링크 깊이 4단계 ·
  사이트맵 문서 10개 · 동시 연결 2 · 최소 간격 1초 · 시간당 호스트 한도 450회.
- 결함이 템플릿 단위로 퍼지는 경우 `breadth = coverage ** 0.7`로 확산도를 과소평가하지
  않는다(문서화된 산식, `06`/`07` 참고).
- 재진단: 기본 7일 주기(`rescan_after_days`), 한 번의 청소에 최대 6곳, 900초 간격.

## 4. GEO 준비도 (SEO와 같은 크롤에서 계산, 탭만 분리)

- 명세: `veo.geo.readiness` v1.4.0(2026-08-11) — 7개 영역(6개 채점), 검사 37개
  (33개 채점+4개 점수 밖), 가중치 합=분모(SEO와 계산 방식이 다름: SEO는 검사별
  배점+영역별 고정분모, GEO는 배점 없이 영역 가중치 합이 곧 분모).
- **AI 노출(AEO)과 절대 합치지 않는다**(ADR 0003) — "우리 사이트를 뜯어보는 것(구조
  준비도, 점수)"과 "AI에게 직접 물어보는 것(관측 기록)"은 대상도 방법도 다르다.

## 5. AEO — AI 답변 관측 (라우터 `geo`+`observations`, 메뉴 라벨 "AEO")

가장 복잡한 축. 흐름:

```
키워드 조사 → 질문(프롬프트) 생성 → 발행(prompt_sets) → 정기 관측(observation_runs)
  → 사람 검수(review) → 결과(언급률·인용·격자) → 이슈·조치
```

- **질문은 담당자가 "발행"한 집합으로만 관측이 돈다**(ADR 0015) — 질문 선택 자체가
  조작 지점이 될 수 있어서 프롬프트 집합을 감사 대상 산출물로 취급한다.
- **엔진 5종, 전부 동일 횟수로 호출** — 비중 조절 금지: OpenAI(gpt-5) · Anthropic
  (claude-haiku-4-5) · Google Gemini(gemini-3.5-flash) · Perplexity(sonar) · xAI(grok-4.3).
  각 엔진에서 가장 싸면서 인용 반환률 5/5인 모델 조합을 실측으로 골랐다(2026-08-10).
- **검색 켬/끔 2모드**(Perplexity는 끔 없음 — 항상 검색형).
- **관측 주기**: 매월 1·4·7·…·28일(3일 간격, 월 10회). 29~31일은 받지 않음(달마다
  일수가 달라 표본이 흔들리는 것을 막음). 거래처가 많아지면 **최대 3개 코호트**로
  나눠 시작일만 다르게(1조=그날, 2조=+1일, 3조=+2일) — 여전히 거래처 개별로는
  3일 간격·월 10회.
- **한 판에 반복 1회만** — 여러 판을 합쳐서 봄(같은 순간에 3회를 몰아 던지면 독립
  표본이 아니게 되므로 반복 사이 최소 120초 간격을 둠, `observation_repetition_interval_seconds`).
- **수동 측정**(`kind=MANUAL`)은 정기 추이와 별도 저장, 추이 그래프에서 제외.
- 브랜드 식별(경쟁사 라우터 `competitors`, 메뉴 라벨은 "브랜드 식별")이 관측의
  전제조건 — 이게 없으면 관측 자체가 거부된다. "AI 답변 속 어느 상호가 우리 고객
  인가"를 식별하는 화면이지 사업적 "경쟁사 분석"이 아니다(이름이 나중에 바뀜).
- 반사실(counterfactual) 실험 — "이 문장을 이렇게 고치면 언급이 얼마나 오르는지,
  신뢰구간과 함께" 계산하는 고급 기능. 특허 출원 내용(청구항 c/f)을 도입 검토한 것.
  월 예산 상한 기본 **0**(꺼짐), 실험당 호출 상한 600회, 변형본 상한 5개 —
  `docs/plans/2026-08-17-anseo-integration-PLAN.md` 참고.

## 6. AI 답변 검수 (`/console/review`, 라우터 `observations`)

AI 답변이 지적한 위험 표현(예: 의료광고법 저촉 소지)이나 사실관계는 **사람이 검수해서
확정**해야만 리포트·경보에 반영된다 — 자동 확정 없음. "위험 검수"와 "의료광고 검수"는
대상이 달라(전자는 AI 답변, 후자는 우리가 쓴 원고) 이름에 대상을 명시해서 구분한다.

## 7. 키워드 (`/console/keywords`, 라우터 `keywords`)

네이버 키워드 인텔리전스. 짧은 키워드(검색량 있음) → 연관 키워드 → 마인드맵 → PAA·
지식iN에서 질문 추출 → 그 질문 집합이 AEO의 프롬프트가 된다. **질문 자체엔 검색량이
안 붙는다** — 검색량은 질문이 출발한 짧은 키워드 쪽에만 있고, 그 숫자로 "어느
키워드에서 질문을 뽑을지"를 고른다.

## 8. 이슈 (`/console/issues`, `/issues/[id]`, 라우터 `issues`)

- SEO/GEO/AEO 세 축에서 나온 "조치가 필요한 항목"을 한 화면에 통합(대시보드) 또는
  거래처별로(거래처 탭) 본다.
- **재진단으로 닫힌다**(ADR 0011) — 사람이 "완료"를 누르는 게 아니라 다음 진단에서
  같은 항목이 통과해야 이슈가 닫힌다. 조치의 진위를 자체 검증하는 구조.

## 9. 리포트 (`/console/reports`, `/reports/[reportId]`, 라우터 `reports`)

- 회차가 쌓이면 "판(version)"으로 리포트를 발행, 공유 링크(90일 TTL, `report_share_ttl_days`)
  로 거래처에 전달. 공유 링크는 `/results/[token]`으로 열리고, 그 화면은 콘솔에서 보는
  Report 컴포넌트를 **그대로 재사용**한다(별도 화면을 만들지 않음 — 콘솔이 본 리포트와
  거래처가 본 리포트가 다르게 그려질 방법이 구조적으로 없다).
- 월간 자동 발행 옵션(`report_auto_publish_day`, 기본 꺼짐. 1~28일 중 지정 가능).
- 발행된 방법론(채점 명세)은 **불변**(ADR 0012) — 과거 점수는 그때 규칙으로 설명된다.
  나중에 채점 기준이 바뀌어도 지난 리포트의 점수가 조용히 바뀌지 않는다.

## 10. 원고 검수 (`/console/medical`, 라우터 `medical` + `medical_facts`)

의료광고법(의료법 제56조) 규칙 기반 검사기. 원고에서 규제 저촉 소지 표현을 표시.
MEDICAL 업종 조직에만 노출(비의료 업종에 걸려 있으면 "그 도구로 검수됐다"는 잘못된
신뢰가 생기므로).

## 11. 사용량·비용 (`/console/usage`, 라우터 `usage`)

AI 호출 횟수와 이번 달 지출. `packages/model-prices`(날짜 붙은 가격표)를 근거로 계산.
가격표가 비어 있으면 "0원"이 아니라 "가격 미설정"으로 표시(제1원칙 그대로 적용).

## 12. 채점 기준 버전 (`/console/scoring-versions`, 라우터 `scoring`)

지금 적용 중인 SEO/GEO 명세 버전·체크섬을 보여준다. 명세는 `packages/scoring-specs/`의
YAML 이며 **코드가 아니라 데이터**(ADR 0001) — 배점·심각도·상한을 바꾸는 것은 배포가
아니라 이 YAML의 새 버전을 내는 일이다.

## 13. 외부 연결 열쇠 (`/console/credentials`, 라우터 `credentials`)

조직이 등록한 API 키의 **상태만**(연결됨/미연결/자격증명 오류) 보여주고 값은 절대
화면에 내보내지 않는다. 자격증명은 암호화 볼트에 저장(`06-데이터-저장방식.md` §3).

## 14. 팀원 관리 (`/console/team`, 라우터 `users`)

초대(이메일 링크, 1회용 토큰) · 역할 배정. 회원가입 화면 없음 — 초대로만 계정 생성.

## 15. 변경 이력 (`/console/changelog`)

버전별로 무엇이 바뀌었는지. 권한 게이트 없음 — 콘솔에 들어온 모두가 본다. 푸터의
버전 링크가 여기로 연결(`03-헤더-히어로-푸터.md` 참고).

## 16. 내 계정 (`/console/account`)

비밀번호 변경만. 계정 생성/탈퇴 없음(관리자만 초대/제거 가능).

## API 라우터 ↔ 화면 대응표 (재구현 시 파일 분할 기준)

`apps/api/src/veo/api/app.py`에 마운트된 라우터 26개:

```
auth · brands · budget(observation) · competitors · credentials · customers ·
geo · hira(+region+subjects) · issues · jobs · keywords · lab · medical_facts ·
medical · observations(+counterfactual) · operations · organizations · projects ·
public · reports · seo · sites · usage · users · scoring · meta · shared_reports
```

각 라우터는 **도메인 하나 = Python 패키지 하나**(`veo/<domain>/router.py`) 구조를
그대로 따른다 — 화면 기능과 1:1은 아니고(예: `geo` 라우터가 GEO 준비도와 AEO 관측
양쪽에 걸침), 재구현 시엔 화면 단위가 아니라 이 도메인 단위로 백엔드를 나누는 편이
검증된 구조다.
