# 배포 인계 — 현행 (판 번호를 안 적는다)

> **이 문서에는 판 번호가 없다.** 앞선 인계문 둘이 몇 시간 만에 낡았기 때문이다
> (`ANSEO-배포-인계.md` 2026-08-23 · `ANSEO-배포-인계-0.3.620.md` 2026-09-19).
> 판은 20분에 한 번꼴로 움직인다 — 적어 두면 틀린다. **읽는 법**을 적는다.

---

## 1. 지금 상태 — 먼저 이걸 돌린다

```bash
cd veo-platform && git fetch origin main -q

echo "main 판:  $(git show origin/main:apps/api/src/veo/__init__.py | grep -o '0\.3\.[0-9]*' | tail -1)"
echo "대장:     $(git show origin/main:docs/WORKLIST.md | grep -o '미배포 \*\*[^*]*\*\*' | head -1)"
git log --oneline -3 origin/main
```

**운영에서 실제로 도는 판**(이 방 컨테이너는 바깥이 막혀 못 잰다 — 바깥 자리에서):

```bash
API=https://veo-platform-production.up.railway.app
curl -fsS "$API/api/health" | jq -r '.data.version'
curl -fsS "$API/api/queue"  | jq -c '.data.worker_versions, .data.stale_workers'
curl -fsS https://veo.seokorea.org/login | grep -oE '0\.3\.[0-9]+' | sort -u | head -1
```

셋이 같은 값이면 그 판이 돈다. **「main 에 밀었다」와 「그 코드가 돈다」는 다른 사실이다.**

## 2. 내보내는 법

```bash
VEO_DEPLOY_ORDER="<사장님 오더 원문>" make deploy
```

`make deploy` 가 전부 한다 — 점검 → 판 물림 → 후보 가지 → CI → **나가기 직전 main 재확인**
→ main 반영 → 도는지 확인.

### 지켜야 할 것 넷

**① 판 번호에 손대지 마라.**
`[1/4]` 가 점검 직후에 정한다. 미리 박으면 번호가 점검(15분) 전에 굳어, 남이 채 가는 창이
9분에서 24분으로 벌어진다.

```
[실측 2026-09-19] main 도착 간격 평균 19.1분 → 겹칠 확률 38% 대 71%
                  이 방은 미리 박아 놓고 여섯 번 시도해 다섯 번 물러났다
```

판 0.3.628 부터 `version_to_claim` 이 **언제나 main+1** 을 찍어 미리 박아도 끌어내린다.
그래도 손대지 않는 것이 맞다 — 헛도는 일이 없다.

**② `make ci-local` 을 건너뛰지 마라.**
`pnpm verify` 와 **다른 명령**이다. 건너뛰면 배포 ③ 관문에서 선다(이 방이 린트 5건으로 겪음).

**③ 점검이 도는 중에 나무를 건드리지 마라.**
파일 하나만 만들어도 「커밋 안 된 변경」으로 배포가 선다(이 방이 겪음).

**④ 쪽문(손으로 main 에 밀기)을 쓰지 마라 — 그리고 쓸 이유도 없다.**
「이 방은 `make deploy` 권한이 막혀」라고 적힌 기록이 있지만 **오해다.**
[실측] 바깥길이 막힌 방에서도 정문은 돈다. 마지막 `[5/5]`(운영에 닿았나)만
「못 쟀습니다」로 적고 넘어가며, **배포를 죽이지 않는다.**

> 쪽문으로 나간 판은 기록이 빈다. `make audit-deploys` 가 [실측 2026-09-19]
> **0.3.615~618 네 판**을 그렇게 찾아냈다.

## 3. 나간 뒤 — 도장

```bash
make audit-deploys        # 오더 기록에 판이 남았는지
```

그리고 **실측한 뒤에만** 대장에 도장을 찍는다(§1 의 세 줄). 머리말을 «미배포 **없음**» 으로
바꾸고 **대기 표에서 나간 줄을 지운다.**

> 나간 줄을 표에 남기면 다음 사람이 그 표를 믿고 **이미 끝난 일을 또 내보낸다**
> (감사 A-07·B-07). 실제로 겪은 자리다.

## 4. 재시도에서 부딪히면 — 늘 같은 네 곳

CI 가 도는 9분 사이에 main 이 움직이면 배포가 **main 을 건드리지 않고** 선다.
그때 `git merge origin/main` 하면 아래가 부딪힌다. 규칙은 매번 같다.

| 파일 | 어떻게 |
|---|---|
| `apps/api/src/veo/__init__.py` | 이 가지 것 (판은 `[1/4]` 가 다시 정한다) |
| `apps/web/src/lib/changelog.ts` | **둘 다 남긴다** — 이 가지 항목이 위, main 것이 아래. `],` `},` `{` 로 잇는다 |
| `apps/api/openapi.json` | 풀지 말고 **다시 뽑는다** (`apps/api/scripts/export_openapi.py`) |
| `docs/WORKLIST.md` | 이 가지 것 |
| `docs/WORKLIST-HISTORY.md` | **양쪽 다** — 지난 기록은 안 지운다 |
| `docs/DEPLOY-ORDER-LOG.md` | 양쪽 줄을 합쳐 시각순 |

**코드가 부딪히면 멈추고 사람이 본다.** 문서와 번호는 규칙이 있지만 코드는 없다.

> `changelog.ts` 는 충돌 블록이 `items` 배열 **한가운데**를 가르기 쉽다. 닫는 `],` 를
> 빼먹으면 파일이 깨지고 시험이 파싱 오류로 빨개진다 — 이 방이 두 번 그랬다.

## 5. 잴 때 지키는 말

- 못 잰 값은 **«—»** 로 둔다. 짐작해서 채우지 않는다.
- 배포 `[5/5]` 의 「못 쟀습니다」는 **「도달 못 했다」가 아니다.** 재지 못한 것이다.
- 사장님께 나가는 글은 「커밋」·「배포」 두 낱말만 쓴다.
