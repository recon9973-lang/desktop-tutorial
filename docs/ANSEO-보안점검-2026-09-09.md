## 1. 뿌리 넷 — 개별 고침보다 이쪽이 값이 크다

### 뿌리 ① 관문이 한 파일만 본다

금고에는 이렇게 적혀 있다(`credentials/vault.py:501`):

> **어떤 HTTP 라우터도 이 메서드를 부르면 안 된다, 지금도 앞으로도.**
> …그리고 `router.py` 에 `resolve_for_use` 가 없다는 것을 시험이 확인한다.

그 시험(`tests/credentials/test_vault.py:294`)은 **`credentials/router.py` 딱 한 파일을
읽는다.** `location/router.py` 는 안 본다. 그래서 **불변식이 깨진 채로 시험은 초록불**이다.

같은 모양이 하나 더 있다. `tests/api/test_console_routes_require_a_principal.py:62` 는
「모든 콘솔 창구는 신원을 요구한다」를 지키는 계약 시험인데, 라우터 목록을 **손으로
적어 놨다.** `app.py` 가 실제로 매단 라우터 중 다섯(`content` 둘 · `location` 셋)이
그 목록에 없다 — 창구 204개 중 9개가 사각지대다. 하필 발견 ①의 그 창구가 거기 있다.

**처방**: 두 시험 모두 손목록을 버리고 **반사(reflection)로 바꾼다.**
`create_app().routes` 를 걸어 다니거나 `src/veo/**/router.py` 를 glob 한다.
예외가 필요하면 **한 줄씩 근거를 적은 허용목록**으로 둔다. 한 경로를 손으로 박은
관문은 그 경로 밖에서는 관문이 아니다.

### 뿌리 ② 경계를 못 좁히면 조용히 통과한다

`authz/tenancy.py:85-112`, `_bounded_by_customer_scope`:

```
model 이 Customer      → id 로 좁힌다
customer_id 가 있으면   → 그걸로 좁힌다
project_id 가 있으면    → 그걸로 좁힌다
observation_run_id 가 있으면 → 그걸로 좁힌다
넷 다 없으면           → return statement      ← 원문 그대로
```

**막히는 쪽이 아니라 새는 쪽으로 실패한다.** 부르는 코드는 `tenant_select` 를
거쳤으니 안전하다고 읽는데, 실제로는 조직 자물쇠만 남고 거래처 경계는 사라진다.
오류도 없고 로그도 없다. 발견 ④·⑥(중간)·⑧이 전부 이 한 줄에서 나온다.

**처방**: 좁힐 수 없는 모델을 만나면 **예외를 던진다.** 그 모델을 통과시키려면
`_UNSCOPED_BY_DESIGN` 같은 명시적 허용목록에 근거와 함께 올리게 한다.
`assert_tenant_scoped` 가 조직 축에서 이미 하는 일을, 거래처 축에서도 한다.

### 뿌리 ③ 상쇄 논리가 다른 층에 걸려 있다

`upload-action.ts` 주석은 정직하다 — 「세션 토큰이 잠깐 브라우저 JS 로 나가는 예외다.
XSS 리스크는 이 화면이 SUPER_ADMIN 전용이라는 것으로 상쇄한다」.
그 전용은 **페이지**(`page.tsx:40` `PermissionGate`)에 걸려 있다. Next.js 서버 액션은
페이지를 안 거치고 **따로 POST 로 부를 수 있는 창구**다. 그때는 `PermissionGate` 도
레이아웃 가드도 안 돈다. 즉 상쇄가 실제로는 안 걸려 있다.

**처방**: 상쇄를 **그것이 상쇄하는 자리와 같은 층**에 둔다. 액션 안에서
`requireConsoleIdentity()` 로 `datasource:manage` 를 직접 확인한다. 그리고 이미 적어 둔
계획(v0.3.502+ signed URL)을 마저 낸다 — 그러면 Bearer 가 아예 서버 밖으로 안 나간다.

### 뿌리 ④ 설정은 있는데 읽는 코드가 없다

`credential_previous_encryption_keys` 는 `settings.py:489` 에 선언돼 있고, 운영 문서
둘이 이걸 쓰라고 안내한다. **읽는 코드가 없다** — 저장소 전체 검색 결과가 선언 한 줄뿐이다.
`rotate_key` 도 부르는 곳이 없다(스크립트·Makefile·CI 전부).

같은 모양: `egress_kr.py:58` 의 `MAX_BODY_BYTES` 는 선언만 있고 아무도 안 쓴다.

**처방**: 선언만 있고 안 읽는 설정은 **시작할 때 터지게** 한다. 최소한 열쇠 교체는
실제 진입점(스크립트나 관리 명령)을 만들고, **재암호화 0건을 성공으로 보고하지 않게** 한다.

## 2. HIGH 일곱 — 자리와 근거

### ① 금고 복호화가 HTTP 로 새는 유일한 자리
`apps/api/src/veo/location/router.py:523` · `GET /api/providers/kakao-map/config`

저장소 전체에서 `resolve_for_use` 를 부르는 **유일한 HTTP 라우터**다. 붙어 있는 검사는
로그인 확인(`get_principal`) 하나뿐 — 권한 검사가 없다. 그래서 자격증명이 **등록됐는지조차**
볼 권한이 없는 `SALES_VIEWER`·`CLIENT_VIEWER` 도 값을 받아 간다.

**지금 새는 값 자체는 위험이 낮다.** 카카오 지도 JS 앱 키는 원래 브라우저에 실려 나가는
값이고, 방어벽은 카카오 콘솔의 도메인 제한이다. 창구 설명에도 그렇게 적혀 있다.
**값이 문제가 아니라 관문이 문제다** — 다음 사람이 이 패턴을 복사해 OpenAI·네이버 키에
쓰면 시험은 **그때도 초록불**이다(뿌리 ①).

- 고침: 이 창구에 `CREDENTIAL_READ_STATE` 를 붙인다. 그리고 브라우저에 내보낼 값은
  금고(`CredentialField.API_KEY`)가 아니라 **「공개 키」라는 별도 개념**으로 옮긴다 —
  설계가 브라우저에 주려는 값과 절대 안 주려는 값이 지금 한 통에 있다.

### ② 열쇠 교체가 코드에 연결돼 있지 않다
`core/settings.py:489` · `credentials/vault.py:521` · `providers/for_organization.py:180`

사고 대응 문서(`runbook-incident-response.md` §3.5)대로 마스터 키를 갈면:

1. 저장된 행은 전부 옛 판 번호 → `self._keys.get(row.key_version)` 이 `None`
2. `resolve_for_use` 가 **「자격증명 없음」과 구분이 안 되는** 예외를 던진다(`vault.py:521`)
3. `for_organization.py` 가 조용히 **공용 열쇠로 내려간다** — 조직별 격리가 통째로 풀린다
4. 3단계 복구(`rotate_key`)도 같은 `None` 에 걸려 **0건 재암호화를 성공으로 보고**한다

즉 **사고 대응 절차를 그대로 따르면 사고가 커진다.** 그리고 `key_version` 은 로그 허용
목록에 없어서(`observability/logging.py:81`) 운영자는 사건 이름만 보고 숫자는 못 본다.

- 고침: `previous_keys` 를 실제로 파싱해 두 생성 자리에 넘긴다. 열쇠 교체 진입점을 만든다.
  **`skipped_count > 0` 이면 시끄럽게 실패**시킨다.

### ③ 서버 액션이 세션 토큰을 브라우저로 넘긴다
`apps/web/src/app/(console)/console/datasources/upload-action.ts:79`

`issueUploadTicket` 이 HttpOnly 쿠키에서 Bearer 를 꺼내 그대로 돌려준다.
검사는 「쿠키가 있나」 하나 — 권한 검사 0건(grep 으로 확인).

**의도는 정당하다.** Vercel 의 4.5MB 요청 상한을 우회해 20MB 파일을 Railway 로 직접
올리려면 브라우저에 Bearer 가 필요하다. 실측 근거도 대체 계획도 코드에 적혀 있다.
빈 곳은 **상쇄 논리의 층**이다(뿌리 ③).

토큰은 자기 것이라 역할 상승은 아니다. 값은 **콘솔 오리진에서 도는 스크립트가

이유 자체를 무른다.

### ⑥ 헤드리스 크롬이 가드를 통째로 건너뛴다
`apps/api/src/veo/render/browser.py:335` · `:256`

`render/` 묶음은 **`UrlGuard` 를 임포트조차 안 한다**(확인). `page.goto(url)` 이 그대로다.
크롬은 자기가 DNS 를 다시 풀고, 자기가 리다이렉트를 따라가고, 그 페이지의
자바스크립트를 실행한다. 크롤 때 가드를 통과한 URL 이라도, **렌더 때는 다른 시각·
다른 해석기**다 — TTL 5초짜리 도메인이면 그 사이에 답이 바뀐다.

포트 제한도 없어서 `http://postgres:5432/` · `http://minio:9000/` 이 사정권이다.
`--no-sandbox` 로 뜨고(`:256`), compose 가 「`veo-backend` 에 절대 붙이지 않는다」고
못 박은 격리망 `veo-renderer` 는 **아무 서비스도 안 쓴다.**

**지금은 안 돈다** — `renderer_enabled` 기본 `false`. 다만 `docs/WORKLIST.md:1174` 에
「코드는 다 됐다」로 대기 중이라 **환경변수 하나 거리**다.

- 고침: 켜기 **전에** ① `page.route("**/*")` 로 모든 항해·부속요청을 가드로 다시 확인,
  ② compose 가 적어 둔 대로 렌더러를 분리 컨테이너로 실제로 낸다,
  ③ 그 격리 안에서만 `--no-sandbox` 를 받아들인다.

### ⑦ robots.txt 정규식 폭발 — API 한 대가 멈춘다
`apps/api/src/veo/seo/parsing/robots.py:225`

```python
regex = "".join(".*" if char == "*" else re.escape(char) for char in body)
```

`*` 만 `.*` 로 바뀐다. `.*` 가 반복되고 끝에서 실패하면 되짚기가 지수로 터진다.
파이썬 `re` 에는 걸음 수 상한도 메모이제이션도 없다.

**이 방에서 직접 잰 값** — 패턴 `/a*a*…X`, 경로 40자:

```
별  8개 →   0.386 초
별  9개 →   1.561 초
별 10개 →   5.539 초
별 11개 →  18.314 초        별 하나에 3.5배 · 16개면 시간 단위
```

`decide()` 는 그룹의 **모든 규칙**을 돈다(`robots.py:130`). 크롤러 목록 × 페이지 수만큼
곱해진다. 그리고 파이썬 정규식은 **매칭 중 GIL 을 안 놓는다** — `geo/router.py:147`
`scan_readiness` 가 sync 핸들러 안에서 `ConsoleCrawler()` 를 돌리므로, 한 요청이
**uvicorn 프로세스 전체**를 세운다. 다른 거래처까지 같이 멈춘다.

무인증은 아니다 — 무료 창구(`public_surface_enabled`)는 기본 꺼짐. **로그인한 거래처가
자기 사이트 robots.txt 에 저 줄을 넣고 진단을 부르면 된다.**

- 고침: robots 패턴을 정규식으로 컴파일하지 않는다. 구글 규격은 `*` 와 끝 `$` 뿐이라
  **선형 탐욕 스캔**이면 된다. **형제 구현 `geo/robots.py:71` 의 `Directive.matches` 가
  이미 그렇게 돼 있고 안 터진다** — 그것을 쓰면 된다.

## 5. 잘 돼 있는 것 (헛수고 막으려고 적는다)

- **SSRF 가드가 진짜다.** 십진·8진·16진·`127.1`·`[::1]`·`::ffff:` 매핑·전각 숫자·
  사용자정보 `@`·`file:`/`gopher:`/`http+unix:` — 시험한 바이패스가 **전부 막혔다.**
  검증한 IP 에 연결을 못 박아 DNS 리바인딩이 안 된다. 리다이렉트는 매 홉 다시 본다.
- **AES-256-GCM 이 규격대로다.** NIST SP 800-38D 시험값과 바이트까지 일치. 태그를
  `compare_digest` 로 **복호화 전에** 확인한다. 논스는 매번 새로 뽑는다. AAD 가
  `(조직·제공자·필드·판)` 을 묶어 남의 조직으로 옮겨 심을 수 없다. 마스터 키에
  기본값·개발용 대체값이 **없다** — 없으면 시작을 못 한다.
- **JWT 가 제대로다.** `HS256` 고정 · 서명 검증 · `aud`/`iss` 확인 · 필수 클레임 강제.
  `verify_signature=False` 가 저장소에 없다. 갱신 토큰은 1회용 + 재사용 감지.
  역할은 매 요청 DB 에서 다시 읽는다 — 토큰의 `roles` 는 아무 힘이 없다.
- **조직 간 격리는 안 뚫렸다.** 창구 204개 전수. `tenant_select` 는 OR 가지와
  안 걸린 조인을 구조로 거부하고, 읽기뿐 아니라 **고치기·지우기**도 받는다.
  요청 본문에 `organization_id` 를 받는 스키마가 **하나도 없다.**
- **주입은 깨끗하다.** 원시 SQL 없음(정적 리터럴 뿐) · `pickle`·`eval`·`yaml.load` 0건 ·
  Celery 직렬화 JSON 고정 · 명령 주입 없음 · 경로 이탈은 `is_relative_to` 로 막음 ·
  `lxml` 이 없어 XXE 없음 · 스프레드시트 수식 주입은 이미 중화 중.
- **공유 링크가 튼튼하다.** 256비트 난수 · SHA-256 만 저장 · `compare_digest` ·
  만료 강제 · 없는 것과 만료된 것이 같은 답 · 발행 시점 사본을 `CSP: sandbox` 로 낸다.
- **CI 에 관문이 있다** — `pip-audit`(파이썬 의존성) · `gitleaks`(전체 이력).
