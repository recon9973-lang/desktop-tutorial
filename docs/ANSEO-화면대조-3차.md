## 4. 이 방이 저지른 것 — 같은 실수 반복 금지

**덮개의 값을 지어내면 두 번 틀린다 — 한 번은 사라지고, 한 번은 없던 격차가 생긴다.**

첫째, **없던 격차를 지어냈다.** 리포트 해시 덮개에 접두어 없는 맨 16진수를 넣어 놓고
「`sha256:` 라벨이 없다」를 격차로 올렸다. 실제로는 서버가 값에 붙여 보내고 있었다.
사장님께 이미 보고한 뒤 창구 코드를 되짚어 잡았다. **덮개가 만든 화면을 실물의 증거로
쓸 때는, 그 자리의 값이 창구 규칙대로인지 먼저 본다.**

둘째, **덮개 값을 다른 자로 넣어 멀쩡한 그림을 결함으로 볼 뻔했다.** 「추이」 열의
스파크라인을 세 번 잘못 짚었다 — ①창구에 덮개가 없어서 열이 안 보였고(격차 아님)
②회차의 날짜 열쇠를 `finished_at` 으로 적었고(창구는 `started_at`) ③영역 점수를
배점 단위로 넣었다(창구 문서: 「회차별 영역 점수(0~100)」). 셋을 차례로 바로잡은
**뒤에야** 진짜 원인(칸이 14px)이 드러났다. **덮개를 고칠 때마다 다시 찍었기 때문에**
잘못된 보고가 안 나갔다.

셋째, **있던 화면을 지웠다.** 검수 덮개에 심각도를
`HIGH`/`MEDIUM`/`LOW` 로 적었는데 실제 코드는 `BLOCKER`/`CRITICAL`/`MAJOR`/`MINOR`/`INFO`
였다. `QueueStand` 가 「맞는 칸이 하나도 없으면 안 그린다」로 되어 있어 **카드 하나가
통째로 없어졌고**, 하마터면 「검수 대기 카드가 없다」고 잘못 보고할 뻔했다.
덮개를 만들 때는 **창구 문서(openapi)에서 코드값을 그대로 옮긴다.**
