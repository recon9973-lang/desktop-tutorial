# 작업 기록 — 4대 AI 노출 실측 & 관리자 연결 (2026-07-13)

> 이 문서는 시원마취통증의학과의원·시원스킨클리닉 대상 **4대 AI 노출 실측**을 확정하고,
> 측정 신뢰성을 높이고(Gemini 하드닝), 결과를 **관리자단(admin)에 실측 연결**하기까지의 작업을 정리한다.
> 관련 위치 지도는 [`핵심두뇌_MASTER.md`](../핵심두뇌_MASTER.md) 참고.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 대상 업체 | 시원마취통증의학과의원(pain), 시원스킨클리닉(skin) |
| 측정 방식 | 환자 질문 5개 × 4대 AI(Perplexity·ChatGPT·Gemini·Claude) = 업체당 20문항 |
| 실행 주체 | GitHub Actions `AI Exposure Check` 워크플로 (러너가 배포된 `/api/insights?type=aeo` 호출) |
| 관련 PR | #136(Gemini 재시도 하드닝), #144(관리자 실측 패널 연결) |
| 배포 타깃 | venom-new-site.vercel.app (main 자동 배포) |

> **왜 GitHub Actions인가**: 작업 컨테이너(샌드박스)는 `vercel.app` egress가 차단돼 있어 배포된 API를 직접 호출할 수 없다.
> GitHub 러너는 egress + Vercel env 키가 있으므로, 러너가 40회(2업체×5문항×4AI) 호출해 실측한다.

## 2. 파이프라인 구조

```
ai-expose-input.json (업체·질문·cores 정의)

   40콜(동시성 5) → 판정: cited / mentioned / none / error
        │
        ├─ 로그: RESULTS_JSON=[...]           (원자료)
        └─ content/ai-expose-latest.json 생성·커밋(HEAD:main)   ← #144에서 추가
                    │
                    ▼
        [배포] Vercel이 main 재배포 → 정적 JSON 서빙
                    │
                    ▼
        admin.html '🤖 AI 노출 실측' 메뉴 → fetch 후 매트릭스 렌더
```

### 판정 기준 (`lib/ai-engines.js` + 워크플로)
- **cited(인용)**: 답변 citation URL에 업체 core 키워드 포함
- **mentioned(언급)**: 답변 본문에 core 포함 또는 `d.mentioned === true`
- **none(미노출)**: 위 어디에도 없음
- **error(측정불가)**: API가 오류 반환(분모에서 제외)
- **발견형/브랜드 구분**: 마지막 질문(q4)은 업체명을 직접 포함한 **브랜드 지정형**, q0~q3은 신환이 실제로 검색하는 **비브랜드 발견형**

## 3. Gemini "측정불가" 원인 규명 및 하드닝 (PR #136)

### 원인 (초기 실행 run 28850153774 로그 기준, 5셀 error)
| 유형 | 메시지 | 건수 | 성격 |
|---|---|---|---|
| 서버 과부하 | `This model is currently experiencing high demand...` | 3 | Google 백엔드 일시 과부하(5xx 계열) |
| 네트워크 무응답 | `Gemini HTTP 0` | 2 | 연결 타임아웃/소켓 끊김(`httpReq` status 0) |

근본 원인: `askGemini`의 폴백 재시도 조건이 `429/404/quota/billing/exceeded`에만 해당 →
위 두 유형은 첫 모델에서 곧바로 throw되어 측정불가로 처리.

### 조치 (`venom-wordpress/preview/lib/ai-engines.js`)
- 재시도(폴백) 대상에 **status 0·5xx·overload/high demand/try again/unavailable/timeout/deadline** 추가
- 시도 간 짧은 백오프: `min(300ms × attempt, 1.5s)`
- 에러 메시지에 `r.error`(네트워크 사유) 반영 → 진단성 향상

### 결과 (재실행 run 29172884932)
**40셀 전부 정상 판정 — 측정불가 0건.** Gemini 5개 공백이 모두 채워짐.

## 4. 실측 결과 (run 29172884932 · 2026-07-11 · 측정불가 0건)

| 업체 | 전체 노출률 | 발견형(신환) 노출률 | 비고 |
|---|---|---|---|
| 시원마취통증의학과의원 | **25%** (5/20) | **6%** (1/16) | 발견형 중 Claude가 '죽도동 허리디스크' 1건만 언급 |
| 시원스킨클리닉 | **15%** (3/20) | **0%** (0/16) | 브랜드 질문만 노출(Gemini는 브랜드도 미노출) |

**핵심 진단**: 두 병원 모두 **브랜드명을 아는 질문**에서는 대체로 노출되나,
신환이 실제로 검색하는 **발견형 질문("포항 정형외과 추천" 등)**에서는 거의 미노출.
→ "이미 아는 환자"는 AI가 찾아주지만 "새로 찾는 환자"에겐 노출되지 않는 상태.

**개선 방향(AEO)**: ① 지역·증상 키워드 질문형 콘텐츠 발행 ② 플레이스·홈페이지 구조화 ③ 월 1회 재측정.
