## 1. 신설의 근거 — 왜 탭이 하나 더 필요한가

지금 6탭은 **재는 탭 4개**(진단·SEO·GEO·AEO)와 **처리하는 탭 2개**(이슈·리포트)다. 그 사이에
「그래서 무엇을 쓰나」가 없다.

- AEO 탭에 4a(추출)·4b(분석)·4c(제안)이 이미 설계돼 있으나, **관측 화면의 맨 아래 카드**로 붙어 있다.
  관측을 보러 온 사람과 원고를 만들러 온 사람의 일이 한 화면에 섞인다.
- 「우리가 2위」는 SEO 탭의 값이고 「ChatGPT 무인용」은 AEO 탭의 값이다. **두 값이 같은 일감**(같은 문서를
  고치면 둘 다 움직인다)인데 두 탭에 흩어져 있어, 담당자가 두 탭을 오가며 손으로 합쳐야 한다.
- 이슈 탭은 「닫아야 할 것」이고 콘텐츠는 「만들어야 할 것」이다. 성격이 달라 한 목록에 섞으면 둘 다 흐려진다.

**콘텐츠 탭 = 두 축의 격차를 한 목록으로 모으고, 하나를 고르면 경쟁 문서 해부 → 편집안 → 관문 → 핸드오프까지
한 화면에서 끝나는 자리.**

## 2. 들어오는 일감 — 격차 두 축

### 2.1 축 1 · 검색 순위 격차

| 판정 | 조건 | 화면 표기 |
| --- | --- | --- |
| **따라잡기** | 우리 2~3위 · 경쟁 1위 | 호박 «따라잡기» |
| **밀림** | 우리 4~30위 · 경쟁 1위 | 빨강 «밀림» |
| **미진입** | 우리 30위 밖 또는 색인 없음 | 회색 점선 «미진입» — **순위 숫자를 지어내지 않는다** |
| **지킴** | 우리 1위 | 민트 «지킴» — 일감이 아니라 **뺏기면 안 되는 자리** |

- 입력: SEO 탭의 키워드 순위 관측 + 키워드 탭의 월간 검색량(수집 전이면 «수집 대기», 0 아님).
- 1위 문서는 URL·소유자(자사/경쟁/포털/매체)까지 붙인다. 소유자 구분이 §3-② 해부의 취급을 가른다.

### 2.2 축 2 · AI 답변 격차 (질문 × 엔진)

칸 하나 = 한 관측. 상태 네 가지:

| 상태 | 뜻 | 이 탭에서 |
| --- | --- | --- |
| **우리 인용** | 그 엔진 답변이 우리 문서를 인용 | 지킴 |
| **경쟁 인용 · 우리 없음** | 경쟁 문서만 인용 | **주된 일감** — 「걔네 문서에 있고 우리에 없는 것」이 있다 |
| **아무도 인용 없음** | 어느 문서도 못 잡음 | **신규 발행 후보** — 해부할 대상이 없으므로 §3-② 를 건너뛰고 ③ 으로 |
| **성숙 중** | 판정 전 | **분모에서 뺀다.** 격차로 세지 않는다 |

- 엔진 7종: ChatGPT · Gemini · Claude · Grok · Perplexity · 네이버 AI브리핑 · 구글 AI오버뷰.
- 「우리는 ChatGPT 미진입, 경쟁은 진입」은 이 격자의 **한 칸**이다. 칸을 누르면 ②~⑤가 그 칸의 근거로 다시 접힌다.
- 엔진별로 다르게 나온 것을 평균으로 뭉개지 않는다. **엔진이 다르면 일감도 다르다**(같은 문서라도 인용 이유가 다름).

### 2.3 두 축을 합치는 규칙

- 같은 **대상 문서**로 해결되는 순위 격차와 AI 격차는 **하나의 일감**으로 묶는다(예: g1 순위 2위 +
  ChatGPT·Claude·Perplexity 무인용 → `/lifting/ulthera` 한 문서 보강).
- 묶인 일감의 우선순위는 **영향 질문 수 × 검색량**이지 점수가 아니다. **SEO·GEO 점수와 합산하지 않는다**(판 규율).

## 3. 화면 명세 — 6구획

### ① 격차 인박스 — «어디서 밀렸나»

- 상단 세그먼트로 **[검색 순위] / [AI 답변]** 축 전환. 두 축이 같은 목록의 두 얼굴임을 보인다.
- 순위 표: 키워드 · 월 검색량 · 우리 순위 · 1위 · 1위를 가져간 문서 · 판정.
- AI 격자: 질문 × 엔진 7. 칸 색 = 상태, 칸 글자 = 상태 이름(**색으로만 말하지 않는다**).
- 행/칸 선택이 ②~⑤ 전체를 구동한다. 선택 상태는 왼쪽 띠로도 표시.

### ② 경쟁 문서 해부 — 4a 추출 · 4b 분석

- **4a 가져간 문서**: 인용·순위를 실제로 먹은 문서 목록 + 엔진별 인용 횟수(분모 병기).
- **4b 구조 대조**: 「짜임새」 항목별 경쟁 있음/없음 ↔ 우리 있음/없음 2열 대조표.
  기본 항목 — 질문에 바로 답하는 첫 문단 / 비교 표 / 시술 주기·경과 표 / 가격·샷수 표 / 갱신일 표기 /
  작성·감수자 표기 / 의료진·시설 정보 / FAQ 구조화 선언.
- **인용문**: 「왜 저 문서가 먹었나」를 보이기 위해 실제 인용 문장을 **출처와 함께 인용 표기로만** 싣는다.

> **베끼기 금지 (규율).** 가져오는 것은 **짜임새**뿐이다. 경쟁 문서의 문장·표·이미지는 복제하지 않으며,
> ②의 인용문은 ③ 편집안 본문으로 옮기지 않는다. 값은 우리 의료진이 확인한 사실로 다시 쓴다.
> 저작권 문제이기도 하고, 경쟁사의 장비·프로토콜 값이 우리와 다를 수 있어 **의료 사실 오류의 원인**이 되기도 한다.
> 화면에도 이 문장을 상시 배너로 띄운다(시뮬 ②의 빨강 배너).

### ③ 편집안 — 4c 제안

- 대상 문서 1개(기존 보강) 또는 신규 발행 1건을 정하고, **블록 단위**로 제안한다.
- 블록 종류: **추가**(없던 블록 신설) / **수정**(있는 문장 교체) / **제외**(만들었다가 ④에서 떨어진 것).
- 블록마다 **지금 ↔ 편집안** 2열. 편집안의 새 문장은 초록 배경(`<ins>`), 뺄 문장은 취소선(`<del>`).
- 블록마다 **근거 목록 필수** — 근거 없는 제안은 만들지 않는다(신설 규칙 6 승계). 근거는 셋의 교집합:
  1. **어느 격차**에서 왔나(①)
  2. **경쟁 문서의 어느 짜임새**가 우리에게 없나(②의 4b)
  3. **우리 문서의 비인용 사유**가 무엇인가(자사 콘텐츠 대장)
- 떨어진 블록도 **지우지 않고 사유와 함께 남긴다** — 담당자가 「왜 이건 안 넣었나」를 뒤에서 물을 수 있어야 한다.

### ④ 안전성 관문 — «올리면 안 되는 것 걸러내기»

네 판정을 **효과 예측과 독립적으로**, 블록마다 매긴다.

| 판정 | 묻는 것 | 실패 예 |
| --- | --- | --- |
| **사실 맞나** | 의료 사실이 우리 의료진 확인분과 일치하나 | 경쟁 문서 값을 그대로 옮김 |
| **기한 지났나** | 그 사실의 유효기간이 살아 있나 | 단종된 장비·중단된 시술 |
| **광고법** | 의료광고법에 걸리나 | 최상급 표현·효과 보장·전후사진·비교우위 단정 |
| **진료 되나** | 그 글이 약속하는 시술을 **지금 이 병원에서 실제로 예약해 받을 수 있나** | 담당 의료진 부재·예약 불가 |

- **하나라도 걸리면 효과 크기와 무관하게 뺀다.** 순서를 반대로 하면 「효과가 크니 이번만」이 생긴다.
- 「진료 되나」를 넣는 이유: 받을 수 없는 시술로 노출이 늘면 환자에게는 헛걸음이다. 노출을 **실제 이용
  가능성**과 묶는 축(특허 효과 항목과 같은 취지).
- 「확인 전」은 실패가 아니라 **보류**다 — 의료진 확인 뒤 다시 판정한다.

### ⑤ 미리 재보기 — 올리기 전에 효과를 재는 자리 (특허 구간)

- 원문 사본을 떠서 **블록 하나만** 바꾼 판을 만들고, 원문 판과 바꾼 판에 **같은 뜻의 질문**을 같은 조건으로
  여러 번 물어 **차이만** 남긴다. 한 번에 하나만 바꾸는 이유 = 둘을 같이 바꾸면 어느 쪽이 움직였는지 못 가린다.
- 지표 전환: **인용 획득률 / 언급률 / 추천 위치**(특허 청구항 3의 결과지표 중 우리가 실제로 재는 셋).
  나머지(답변 점유율·사실 정확도·진료 실행 가능성)는 데이터가 붙는 대로 추가.
- 표기 규율:
  - 점 = 값, 가는 선 = **폭**(반복했을 때 값이 놓이던 범위).
  - **선이 0을 물면 «움직였다고 말하지 않는다»** — 화면에 «0을 뭅니다»를 병기하고 색을 죽인다.
  - **못 잰 블록은 0이 아니라 «—»**.
  - 이 값은 **사본으로 잰 예상이며 보장이 아니다.** 실제 판정은 올린 뒤 재관측.
- 배제된 블록도 값을 지우지 않고 «제외됨»으로 남긴다(§3-③ 과 같은 이유).

### ⑥ 검수·업로드 핸드오프 — «담당자가 직접»

- 체크리스트 5줄: 원고 반영 → 의료진 의료 사실 확인 → 의료광고법 검수 → **담당자가 직접 업로드** → 주소 적고 재관측 예약.
- 내보내기: 원고(.md) + 근거표(.csv) 내려받기 / 블록만 복사 / 이슈로 넘겨 담당자 배정 / 발행 후 재관측 예약.
- 화면에 **「ANSEO 가 하지 않는 것」** 을 명시: 대신 올리지 않고, 병원 계정에 접속하지 않으며, 검수를 대신
  통과시키지 않는다. 이 탭의 산출물은 **근거가 붙은 초안까지**.

## 4. 데이터 모델 (실물 이식 시)

```
content_gap            일감 1건 (두 축이 합쳐진 단위)
  id · customer_id · axis(rank|ai|both) · topic
  keyword_id? · our_rank? · top_rank? · search_volume?          ← 축 1
  question_id? · engine[]? · our_state · rival_state            ← 축 2
  target_doc_id? (기존 보강) | new_doc_slug? (신규 발행)
  verdict(chase|behind|absent|hold) · impact_questions · status

competitor_doc         4a — 인용·순위를 가져간 문서
  id · gap_id · url · owner(rival|portal|media|community|ours)
  cite_count_by_engine{} · rank_position? · quoted_text · quoted_at

structure_factor       4b — 짜임새 한 항목의 대조
  id · gap_id · factor_key · rival_has(bool) · ours_has(bool) · evidence

edit_block             4c — 편집안 한 블록
  id · gap_id · op(add|fix|out) · title · before · after
  basis[] (gap_id · structure_factor_id · inventory_reason_id 로만 구성)
  order · adopted_at? · exported_at?

safety_verdict         ④ 관문 — 블록당 4판정
  id · edit_block_id · fact_ok · not_expired · ad_law_ok · bookable
  verdict(pass|hold|drop) · reason · judged_by · judged_at
  ※ cf_effect 와 참조 관계 없음 — 독립 판정을 구조로 강제

cf_experiment          ⑤ 사본 실험 회차
  id · edit_block_id · base_snapshot_hash · variant_snapshot_hash
  query_set_id · repeats · engines[] · run_conditions{} · started_at

cf_effect              ⑤ 회차의 결과
  id · experiment_id · metric(cite|mention|rank|share|accuracy|bookable)
  delta · ci_low · ci_high · touches_zero(bool) · n · measured(bool)

handoff                ⑥ 넘김 기록
  id · gap_id · exported_at · assignee · published_url? · published_at?
  recheck_scheduled_at? · recheck_result_id?
```

**설계상의 두 강제**

1. `edit_block.basis` 는 **다른 표의 id 로만** 채운다 — 자유 문자열을 금지해 「근거 없는 제안」을 구조로 막는다.
2. `safety_verdict` 는 `cf_effect` 를 참조하지 않는다 — 효과를 보고 관문을 무르는 경로를 아예 만들지 않는다.

## 5. 파이프라인 접점

```
1 수집 → 2 채점(SEO·GEO) → 3 이슈 → 4 관측(AEO)
                                      │
                                      ├─ 4a 추출 ─┐
   SEO 순위 관측 ──────────────────────┤          ├─→ ① 격차 인박스 ─→ ② 해부 ─→ ③ 편집안
                                      └─ 4b 분석 ─┘                              │
                                                                    ④ 관문 ──────┤ (떨어진 것 제외)
                                                                    ⑤ 미리 재보기 ┤ (효과 예측)
                                                                                 ↓
                                                              ⑥ 핸드오프 → 5 실행(담당자 검수·업로드)
                                                                                 ↓
                                                              발행 후 재관측 → 4 관측으로 복귀(◆ 표시)
```

- **이 탭은 이슈를 닫지 않는다.** 이슈는 발행 후 재관측이 판정한다.
- 재관측 결과는 ⑤의 예상값과 **나란히 놓여 다음 회차의 예측 보정**에 쓰인다(특허 후속 검증부와 같은 취지).

## 6. 규율 (화면·구현 공통)

1. **베끼기 금지** — 짜임새만, 문장·표·이미지는 복제 금지. 인용은 출처 표기와 함께 ②에서만.
2. **근거 없는 제안 금지** — 블록마다 근거 3종의 교집합. 근거는 id 참조로만.
3. **자동 발행 금지** — 검수·업로드는 담당자. 시스템은 초안까지.
4. **효과와 안전은 독립** — 관문이 먼저, 효과는 그 다음. 참조 관계도 만들지 않는다.
5. **못 잰 값은 0이 아니라 «—»**, 백분율은 분자·분모 병기, 색은 항상 글자와 병용.
6. **판이 다르면 나란히 놓지 않는다** — 질문셋 판·명세 판이 다른 회차의 값을 한 그래프에 얹지 않는다.
7. **예상은 보장이 아니다** — ⑤의 값에는 항상 「사본으로 잰 예상」 단서를 붙인다.
8. **의료광고법 준수** — 최상급·효과 보장·전후사진·근거 없는 비교우위는 ④에서 기계적으로 뺀다.

## 7. 특허를 어디에 두나 — 3안 검토와 권고

### 7.1 특허 구성 ↔ 화면 대응

| 특허 구성 | 하는 일 | 콘텐츠 탭에서의 자리 |
| --- | --- | --- |
| 디지털트윈 생성부 (132) | 기준 콘텐츠를 의료 사실 단위로 정규화하고 **하나만 바꾼** 사본 변형본 생성 | **⑤** — 블록 하나당 사본 1개 (블록이 곧 의료 사실 단위) |
| AI 실험 실행부 (134) | 통제된 같은 뜻 질의를 엔진에 **복수 회** 적용, 답변·인용을 실행 조건과 함께 수집 | **⑤** — 「물어본 횟수 12회 × 엔진 3」 |
| 반사실 기여도 산출부 (136) | 결과지표 변화량 → 기여도 + **신뢰구간** | **⑤** — 점(값) + 가는 선(폭), 0을 물면 말하지 않음 |
| 안전성 제약 최적화부 (138) | 정확성·유효기간·의료광고 위험·진료 실행 가능성 판정 → **기여도 크기와 무관하게 배제**, 배제 사유와 함께 출력 | **④** — 네 판정 + 「제외 — 사유」. ③에 떨어진 블록을 사유와 함께 남김 |
| 후속 검증부 (139) | 실제 반영 후 후속 답변 수집·검증 | **⑥ → 재관측** — 발행 주소 등록 + 14일 뒤 같은 질문 재관측 |

**즉 특허의 다섯 구성이 이미 이 탭의 ③→④→⑤→⑥ 한 줄에 그대로 놓인다.** 흩어져 있지 않다.

### 7.2 세 안

| | A안 · 「특허」 탭 신설(8탭) | **B안 · 콘텐츠 탭 안 계층 (권고)** | C안 · B안 + 실험 원장 하위 화면 |
| --- | --- | --- | --- |
| 상단 탭 | 8개 | 7개 | 7개 |
| 특허 흐름 | 독립 화면 | ③④⑤⑥ 계층 | 좌동 + 「어떻게 쟀는지 보기」 하위 화면 |
| 장점 | 특허 구성이 그대로 보여 대외 설명이 쉬움 | 관문·효과가 편집안 옆에 있어 **「왜 뺐나」가 같은 화면에서 답해짐** · 탭을 안 늘림 | B안의 유일한 약점(실험 이력·재현 로그 자리 없음)을 메움 · 리포트 부록으로 대외 설명도 해결 |
| 단점 | 상단 탭은 **담당자가 하는 일**의 줄인데 「특허」는 일이 아니라 **방법**이라 언제 눌러야 할지 알 수 없음 · 입력(우리 원고·의료 사실)도 출력(편집안)도 콘텐츠 탭 것이라 **한 작업이 두 탭을 왕복** · 떨어진 후보를 콘텐츠 탭에서 못 봄 | 실험 이력·재현 로그를 카드 하나에 다 못 담음 | 화면 2개(원장·부록)를 새로 만들어야 함 |

### 7.3 권고 — **B안 + C안 보완. 「특허」 탭은 신설하지 않는다**

이유 넷:

1. **탭은 일의 줄이지 기술의 줄이 아니다.** 기존 6탭은 전부 담당자가 하는 일(재기·처리·보고)이다.
   「특허」를 그 줄에 끼우면 담당자가 **언제 들어가야 하는지 알 수 없는 탭**이 하나 생긴다.
2. **입력도 출력도 콘텐츠 탭 것이다.** 특허 흐름의 입력은 우리 기준 콘텐츠와 의료 사실, 출력은 콘텐츠 수정안이다.
   탭을 나누면 한 작업이 두 탭을 왕복하고, 그 왕복에서 근거가 끊긴다.
3. **관문은 편집안 옆에 있을 때만 작동한다.** 안전성 제약의 값어치는 「효과가 큰 후보를 뺐다」를 담당자가
   **보는 것**이다. 남의 탭에 있으면 떨어진 후보를 아무도 안 본다 — 특허의 핵심 청구가 화면에서 사라진다.
4. **특허의 값어치는 탭 수가 아니라 근거의 부착이다.** 「편집안마다 근거와 배제 사유가 붙는다」가 경쟁 도구와
   갈리는 지점이고, 그건 편집안 옆에서만 전달된다.

**대외 설명용 가시성은 탭이 아니라 다음 둘로 확보한다(C안):**

- **실험 원장 화면** — ⑤ 카드의 «어떻게 쟀는지 보기» → 회차·사본 해시·질의셋 판·엔진·반복 수·실행 조건·재현
  가능 여부. **탭이 아니라 콘텐츠 탭의 하위 화면**(설정묶음과 같은 층위).
- **리포트 발행본의 「측정 방법」 부록** — 업체에 나가는 문서에 측정 절차를 부록으로. 발행본은 판이 찍히므로
  「그때 그 방법으로 쟀다」가 문서에 남는다.
