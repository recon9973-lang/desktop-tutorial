## 2. 스크린샷 전수 분석

### S1 — 전체 대시보드 (일부, 자막 "이 질문의 경쟁도를 확인할 수 있는 게")

좌측 질문 리스트 + 우측 대시보드의 **마스터/디테일 2단 레이아웃**. 상단에 흰색 알약형 `+ 새 질문 추가` 버튼.

질문 카드 구조가 극도로 절제돼 있다 — **질문 텍스트 / `기존% → 현재%` / 연필 아이콘** 이 셋뿐이다.

| 질문 (고객 식별 부분 블러) | 변화 |
|---|---|
| 강동구에서 ▩ 치료 가능한 한의원 알려 줘 | 0% → **70%** |
| 광진구에서 ▩ 근본 치료 가능한 ▩ 치료 전문 한의원 알려 줘 | 0% → **51%** |
| 강동구에서 ▩ 잘 치료하는 피부전문 한의원 추천해 줘 | 0% → **46%** |
| 강동구에서 ▩ 잘 치료하는 한의원 추천해 줘 | 0% → **44%** |
| 광진구에서 ▩ 잘 치료하는 한의원 추천해 줘 | 0% → **35%** |
| 송파구에서 ▩ 치료 한의원 추천해 줘 | 0% → **31%** |
| 송파구에서 ▩ 근본 치료 가능한 ▩ 한의원 추천해 줘 | 0% → **30%** |

우측: `전체 대시보드` → `주차별 전체 언급률` 라인차트(y축 0/26/51%, x축 4/6~5/4), 그 아래 **`전체 언급률: 0.0% (+37.6%p) → 37.6%`** 대형 수치, 그 아래 `AI 모델별 언급률` 레이더 시작부.

> **관찰**: 질문이 전부 `지역구 + 증상/시술 + 진료과 + 추천 요청` 형태다. 브랜드명이 없다. 즉 **환자가 실제로 칠 법한 무브랜드 탐색 질문**만 추적한다. "○○한의원 어때?" 같은 브랜드 질문은 애초에 넣지 않는다 — 그건 이미 아는 사람의 질문이라 신규 유입 가치가 없기 때문.

### S2 — 전체 대시보드 (완전판, 6:00)

S1과 동일 고객. 헤더 우측에 **`질문: 10 · 모니터링 기간: 7주`** 메타.

주차별 곡선: 4/6~5/11까지 **0% 평탄** → 5/11~5/18 **S자 급등** → 5/18 정점 ~37% → 5/25 소폭 하락. 영상에서는 보라색 박스로 질문 목록을 강조.

`AI 모델별 언급률` — 오각형 레이더(ChatGPT·Gemini·Claude·Grok·Perplexity) 위에 `기존`(주황) / `현재`(초록) 2계열 오버레이 + 우측 표:

| 모델 | 기존 | 현재 | 변화 |
|---|---|---|---|
| ChatGPT | 0.0% | 14.0% | ↗ +14.0%p |
| Gemini | 0.0% | **69.0%** | ↗ +69.0%p |
| Claude | 0.0% | 49.0% | ↗ +49.0%p |
| Grok | 0.0% | 42.0% | ↗ +42.0%p |
| Perplexity | 0.0% | 60.0% | ↗ +60.0%p |

> **관찰 1 — 0%에서 시작한다는 것.** 모든 모델 기존값이 0.0%다. 이건 "아무것도 안 하면 AI에 우리는 존재하지 않는다"를 한 화면으로 증명하는 영업 자산이다. 진단 도구의 첫 실행값이 곧 계약 근거가 된다.
> **관찰 2 — 엔진별 편차가 크다.** ChatGPT 14% vs Gemini 69%. 같은 작업의 결과가 엔진마다 5배 차이 난다. 엔진을 하나로 뭉뚱그리면 이 정보가 사라진다.
> **관찰 3 — S자 곡선.** 7주 중 5주가 0%였다. AEO는 즉각 반응하지 않고 **임계점 이후 계단식으로 뛴다.** 이 곡선 모양 자체가 "3주차에 왜 아무 변화 없냐"는 고객 클레임을 막아주는 커뮤니케이션 도구다.

### S3 — 모니터링 추이 + 언급 현황 (15개 질문)

다른 고객. 헤더 우측에 **월별 카운터** `0(12월) 0(1월) 0(2월) 0(3월) 141(4월) 33(5월)` + `조직 설정` 버튼 → **멀티테넌트 + 월 사용량/쿼터 과금 구조**의 증거.

좌측 `모니터링 질문 목록 15개 질문`, 첫 항목 선택 상태(테두리 강조). 대부분 `0% → 0%`.

질문 성격이 S1과 결이 다르다 — **지역이 아니라 통증·실패 경험 기반**이다:
- ▩ 대학병원에서 ▩ 받았는데도 효과없어. 잘 고치는 곳 추천해줘
- ▩ 재발없이 잘 치료할 수 있는 병원 추천해줘
- ▩ 먹고 있는데 효과 없어 잘 고치는 곳 추천해줘
- ▩ 완치로 유명한 병원 추천해줘
- ▩ 치료 제일 잘하는 곳 리스트 좀 뽑아줘
- 너무 심한데 한방으로 치료 잘하는 유명한 한의원 추천해줘
- 더 심해지는데 잘 고치는 곳 추천해줘

우측 `모니터링 추이 — 각 모니터링 실행 시점의 AI 모델 언급률 변화`.

**`언급 현황`** — 답변에서 추출된 **모든 브랜드**를 컬러 점 + `언급모델수 (가중%)`로 나열. 약 25개 엔티티:
`▩한방병원 2 (25%)` · `▩한방병원 2 (25%)` · `▩한의원 2 (20%)` · `▩한의원 2 (16%)` · `▩한의원 1 (14%)` · **`▩한의원 1 (10%)` ← 흰 점 = 자사** · `▩한의원 1 (6%)` ×3 · `▩한방병원 2 (3%)` · 이후 다수 `0 (0%)`

하단은 **경쟁사별 다중 라인차트**(y축 언급률 0~100%, x축 `4.1 오후07` / `4.6 오전02` / `4.13 오전09` / `4.20 오전03:11` / `4.27 오전03:04` / `5.4 오전09:00`).

> **관찰 1 — 자사가 흰 점이다.** 경쟁사는 컬러, 자사만 흰색. 25개 점 속에서 우리를 0.2초에 찾게 하는 최소 비용 설계.
> **관찰 2 — `2 (25%)` vs `2 (3%)`.** 둘 다 모델 2개인데 %가 8배 차이 난다. **%가 단순 비율이 아니라는 결정적 단서** — S5/S6에서 확정된다.
> **관찰 3 — 실행 시각이 03:00~09:00대다.** 야간 배치 크론. 비용·레이트리밋 회피 + 고객이 아침에 갱신본을 본다.

### S4 — 모니터링 추이 툴팁 (9:47, "경쟁사들이 얼마나 있는지")

강남 소아/정신건강 계열 고객. 질문에 `6% → 25%`, `16%`, `10%` 등 **0이 아닌 기존값**이 섞여 있다(이미 일부 노출 중인 고객).

질문 예: `강남 ▩ 한의원 추천해줘` / `강남에서 초등학생 ▩ 병원 추천해줘` / `초등학교 고학년인데 ▩ 강남에서 치료할 수 있는 곳 추천해줘.` / `강남 ▩ 경험 많은 곳은 어디야?` / `▩ 진단받았는데 강남에서 잘 고치는 곳 추천해줘`

`언급 현황`: `▩한의원 5 (56%)` · **`▩한의원 2 (25%)` ← 흰 점, 자사** · `▩한의원 1 (10%)` · `▩한의원 1 (6%)` · 나머지 `0 (0%)` 다수(정신건강의학과의원들).

**핵심은 라인차트 호버 툴팁이다** — `2026년 4월 20일 오전 03:22:07` 시점에서:

```
▩한의원  49%   ChatGPT, Grok, Claude, Perplexity
▩한의원  24%   Claude, Perplexity
▩한의원  16%   Grok, Perplexity
▩한의원   6%   Grok
▩한의원   6%   Grok
```

> **관찰 — 툴팁이 "누가, 몇 %, 어느 엔진에서"를 한 번에 준다.** 이게 처방으로 직결된다. 위 데이터는 "1등은 4개 엔진 전부 장악, 우리는 Grok에만 걸림 → Grok은 X 소스를 본다 → 거기를 공략" 같은 판단을 즉석에서 가능하게 한다. 단순 순위표와 질적으로 다르다.

### S5 — AI 모델별 응답 14개 모델 (9:57, 4/27 실행)

`AI 모델별 응답` `[14개 모델]` — 우측 **`2 / 14 (25%)`**. 실행 시각 `2026년 4월 27일 오전 03:18`.

2열 그리드. **좌열 = 웹검색 ON, 우열 = 웹검색 OFF.** 각 카드에 모델명 + 상태 아이콘 + **고정 %**:

| 모델 | 상태 | 가중치 | 인용/언급된 것 |
|---|---|---|---|
| ChatGPT with Web Search | ⊗ 자사 미언급 | 19.6% | ▩한의원 |
| ChatGPT | ⊗ 자사 미언급 | 8.4% | 카카오맵 |
| Claude with Web Search | ⊗ 자사 미언급 | 14.0% | ▩한의원, ticadhd.com, ▩한의원 |
| Claude | ⊗ 자사 미언급 | 6.0% | — |
| Grok with Web Search | **✓ (초록)** | 5.6% | (자사 언급) |
| Grok | ⊗ 자사 미언급 | 2.4% | 카카오맵, 자생한방병원, 서울대병원 |

> **관찰 — `2/14`인데 `(25%)`다.** 2/14 = 14.3%. 25%가 나올 수 없다. **%는 별도 가중치의 합이다.** S6이 이를 확정한다.

### S6 — AI 모델별 응답 14개 모델 (10:02, 5/4 실행) — **가중 언급률 확정**

같은 고객, 실행 시각 `2026년 5월 4일 오전 09:00`. 헤더 `2 / 14 (25%)`.

| 모델 | 상태 | 가중치 | 내용 |
|---|---|---|---|
| **ChatGPT with Web Search** | **✓ 초록** | **19.6%** | **▩한의원(초록=자사)**, 이어서 주황 ▩한의원, ticadhd.com |
| ChatGPT | ⊗ | 8.4% | 자사 미언급 |
| Claude with Web Search | ⊗ | 14.0% | 자사 미언급 — ▩한의원 |
| Claude | ⊗ | 6.0% | 자사 미언급 — 네이버 지도 |
| **Grok with Web Search** | **✓ 초록** | **5.6%** | (자사 언급) |
| Grok | ⊗ | 2.4% | 자사 미언급 — 카카오맵 |

**산술 검증: 19.6 + 5.6 = 25.2 ≈ 25%.** ✓ 표시된 두 모델의 가중치 합이 헤더 %와 정확히 일치한다.

> **→ `언급률 = Σ(자사를 언급한 모델의 가중치)` 확정.** 단순 비율이 아니다.
>
> 가중치 구조도 읽힌다:
> - ChatGPT 19.6 + 8.4 = **28.0%** / Claude 14.0 + 6.0 = **20.0%** / Grok 5.6 + 2.4 = **8.0%**
> - 세 엔진 모두 **웹검색 : 순수 = 70 : 30** 으로 정확히 동일 분할
> - 3개 엔진 합 56% → 나머지 44%가 Gemini·Perplexity 등에 배분 (화면 밖)
>


원인 규명: `parsed_documents(context)`가 매 호출마다 전 문서를 재파싱 → 40장에서 80회 × 40문서 = 3,200 파싱(28초), 200장이면 400회 × 200문서 = **80,000 파싱(~700초)**. 결론 *"장수의 제곱입니다. 같은 문서를 수만 번 다시 읽고 있습니다."*

좌측 세션 목록: `Veo 진단기 로그인 세션 유지 문제` · `Veo SEO/GEO 진단 개선` · `100개 업체 검색 및 관리 UX` · `공유 리포트 살리기 — 발급만 되고 열람이…` · `V-Qmap` · `VEO 프로젝트 특허 기획안` · `Veo UX/UI 설계 및 개선 방안` · `그래프 축 수치 표시` · `veo.public.router 단독 임포트 순환 해소` · `Fix undefined CSS tokens in geo.mo…` · `Fix flaky AI-status locator in web-ai…` · `Monaco 편집기 지연 로딩으로 초기 로딩…`

> **관찰 — 이 화면이 적용 대상의 제약을 알려준다.** VEO는 **다중 페이지 크롤 기반 SEO/GEO 채점기**이고, 지금 O(n²) 병목을 잡는 중이다. 아래 로드맵에서 **모니터링(주기 실행 · 외부 API 다중 호출)은 진단(동기 크롤·채점)과 물리적으로 분리된 비동기 워커여야 한다**고 못 박은 근거가 이것이다. 같은 요청 경로에 얹으면 이미 아픈 곳이 더 아파진다.
> 참고: `그래프 축 수치 표시` 세션이 이미 있다 — S9/S12의 **동적 y축**은 그 작업에 바로 얹을 수 있는 개선점이다.

## 3. 역설계로 확정한 핵심 메커니즘

### 3.1 가중 언급률 — **확정** (S5·S6 산술 일치)

```
언급률 = Σ (자사를 언급한 모델의 가중치)
가중치 = 엔진 점유율 × 모드 분할(웹검색 0.7 / 순수 0.3)
```

관측된 가중치:

| 엔진 | with Web Search | 순수 | 엔진 합 |
|---|---|---|---|
| ChatGPT | 19.6% | 8.4% | **28.0%** |
| Claude | 14.0% | 6.0% | **20.0%** |
| Grok | 5.6% | 2.4% | **8.0%** |
| (Gemini + Perplexity + α) | — | — | **44.0%** |

검증: S6에서 ✓ 표시 = ChatGPT w/WS(19.6) + Grok w/WS(5.6) = **25.2 ≈ 헤더 25%** ✓

> ⚠️ **이 가중치 수치를 그대로 베끼지 말 것.** 19.6/8.4는 GPTO의 자체 가정이고 근거가 공개돼 있지 않다. ANSEO는 **자체 근거를 명시한 가중치**(공개된 국내 AI 서비스 MAU/트래픽 통계 등)를 쓰고, UI에 `가중 기준: ○○ 기준(가정치)` 라벨과 근거 링크를 반드시 노출해야 한다. 근거 없는 가중치는 우리 원칙상 **날조**다. 근거를 못 구하면 `균등 가중`을 기본값으로 두고 가중치를 사용자 설정으로 빼는 게 정직하다.

### 3.2 3단 판정 → 우리 것이 더 정밀하다

GPTO는 **언급 O/X** 2단(⊗ / ✓)이다. 우리 `_geoAeoCell()`은 이미 **🟢인용 / 🟡언급 / 🔴미노출 / ⚠️측정불가** 4단이다. *인용(citations에 우리 도메인)* 과 *언급(본문에 이름만)* 을 구분하는 건 GPTO에 없는 우위다. **버리지 말고 가중 언급률과 결합**하라 — 예: 인용 1.0 / 언급 0.6 가중.

### 3.3 정직성 장치 3종 (그대로 채택 권장)

1. **하락은 빨강, 무변화는 `—`** (S12 Grok -28%p)
2. **실패한 질문을 케이스에 남김** (S9 `9% → 9%`)
3. **0%에서 시작한 사실을 숨기지 않음** (S2 전 모델 기존 0.0%)

## 5. 디자인 분석

### 5.1 색·톤

| 요소 | 값(추정) | 규칙 |
|---|---|---|
| 배경 | 거의 검정 `#0a0a0c`~`#111` | 단일 톤, 그라데이션 없음 |
| 카드 | 배경보다 한 단계 밝게 + 1px 미세 보더 | 그림자 대신 보더로 층 구분 |
| **초록** | `#22c55e`계 | **자사 · 상승 · 언급됨** — 단 하나의 주 액센트 |
| **주황** | `#f97316`계 | **경쟁사 · 기존값** |
| **빨강** | `#ef4444`계 | **하락** (S12 Grok) |
| 회색 | `#6b7280`계 | 미언급 ⊗ · 0% 항목 |

> 액센트가 사실상 **초록 하나**다. 나머지는 의미가 배정된 색뿐이라 화면에 색이 뜨면 무조건 뜻이 있다. 대시보드가 알록달록해지는 흔한 실패를 이 규칙 하나로 막는다. 유일한 예외가 `언급 현황`의 다색 점인데, 거기선 **자사만 흰색**으로 빼서 대비를 만든다.

### 5.2 레이아웃

- **마스터/디테일 2단** — 좌 질문 리스트(고정폭) / 우 대시보드(가변). 좌측 선택이 우측 전체를 바꾸고, **선택한 질문 텍스트가 우측 패널 제목으로 승격**된다(S11). 컨텍스트 미아가 안 생긴다.
- **질문 카드 = 3요소** — 텍스트 / `기존%→현재%` / 연필. 그 이상 없음.
- **2열 모델 그리드 = 설계된 비교** — 좌 웹검색 ON, 우 OFF. 나란히 놓는 것만으로 "검색 붙이면 달라진다"가 설명 없이 읽힌다.
- **접이식 섹션 + 카운트 배지** — `[14개 모델]`, `[35개 사이트]`, `[9개 모델]`. 열기 전에 규모를 알려준다.

### 5.3 타이포 — 대표 수치의 3단 구성

```
전체 언급률:  0.0%   (+37.6%p)  →   37.6%
             작은     중간          거대
             회색     초록          흰색
```

과거는 작게·흐리게, 델타는 중간·컬러, 현재는 압도적으로 크게. **한 줄에 서사(전·변화·후)가 다 들어간다.** 슬라이드에 그대로 캡처해도 설명이 필요 없다.

### 5.4 차트

| 차트 | 설계 포인트 |
|---|---|
| 주차별 곡선 | **동적 y축**(3~49%, 0~18%, 0~24% — 매번 다름), 단색 초록, 하단 그라데이션 필, 부드러운 스플라인 |
| 경쟁사 다중선 | 엔티티당 1선, **호버 툴팁에 순위 + % + 인용 엔진명** |
| 5축 레이더 | 기존(주황)/현재(초록) 오버레이. **형상 자체가 진단** — 찌그러지면 엔진 편중 |

### 5.5 마이크로 인터랙션

- 상태 아이콘 `⊗`(회색) / `✓`(초록) — 2열 그리드에서 스캔 속도가 결정됨
- 모든 출처 URL에 **복사 + 새창 아이콘 쌍** (S11) — 실무자가 바로 집어가는 동선
- 자사는 항상 **흰 점**, 경쟁사는 컬러

### 6.2 저장 계층 — `docs/intel-ai-exposure.prisma`

**이미 있는 것**: `TrackedQuery`(clinicId·query·active·cadence) / `AiExposureSnapshot`(engine·mentioned·**rank**·answerText·**competitors**·**citations**·**sentiment**) / `AiExposureDaily`(enginesHit/Total·exposureRate)

**보강해야 할 필드**

| 갭 | 현재 | 필요 |

## 7. ANSEO 적용 로드맵

> 전제(S13 근거): **모니터링은 진단(동기 크롤·채점)과 분리된 비동기 워커로 만든다.** VEO의 GEO 채점이 지금 O(n²) 병목을 겪는 중이라, 외부 API 다중 호출을 같은 요청 경로에 얹으면 안 된다.

### P0 — 기반 (수일, 의존성 없음)

1. **Grok 추가** — `lib/ai-engines.js`에 `askGrok()` + `engineKeys().grok`. `_GEO_AI4` → `_GEO_AI5`. 가장 싼 즉시 개선.
2. **웹검색 ON/OFF 2모드** — 엔진당 2콜. 엔진키를 `openai` / `openai:web`으로 분기. 화면은 S5/S6의 2열 그리드를 그대로.
3. **가중 언급률** — `weight` 상수 도입, 합계를 개수에서 가중 %로 교체. **가중치 근거를 UI에 명시하고, 근거를 못 대면 균등 가중을 기본값으로.**
4. **언급 판정 강화** — 정규화 + 별칭 + 도메인 동시 검증으로 오탐 제거.
5. **동적 y축** — 이미 `그래프 축 수치 표시` 세션이 있으니 거기 얹는다.

### P1 — 모니터링 루프 (핵심 가치)

6. **스키마 확정·마이그레이션** — 6.2 보강 필드 반영.
7. **크론 워커** — 주 1회 야간(03:00~06:00 KST). `cron-daily-posts.js`의 스케줄·에러 처리 패턴 재사용.
8. **질문 세트 CRUD UI** — 좌 리스트 + `+새 질문 추가` + 인라인 편집. 카드는 3요소만.
9. **주차별 곡선 + `기존% → 현재%`** — 5.3의 3단 타이포 그대로.
10. **참조 출처 집계** — `citations`를 도메인 단위로 롤업 + 모델 귀속 배지 + 복사/새창 아이콘. **`utm_source=openai` 같은 AI 경유 파라미터를 별도 태깅**해 고객 GA 세그먼트로 연결.

### P2 — 차별화 (수주 무기)

11. **경쟁 브랜드 추출** — 답변에서 기관명 엔티티 추출(LLM 구조화 출력 + 심평원 요양기관 명부 대조로 검증). **여기가 가장 어렵고 가장 값지다.** 병원명은 표기 변형이 심해(`○○의원`/`○○ 의원`/`○○클리닉`) 정규화 사전이 필수.
12. **경쟁사 시계열 + 엔진 귀속 툴팁** (S4) — 순위 + % + 인용 엔진명.
13. **5축 레이더 (기존/현재)** — 형상 인지가 목적.
14. **기회 점수** — `언급률 × 언급가능성 × (1/경쟁강도)`. **다만 우리 원칙상 "80점" 같은 합성 점수는 산식과 입력값을 반드시 펼쳐 보여야 한다.** 블랙박스 점수는 날조와 구분이 안 된다.
15. **전략 서술 + 콘텐츠 발행 연결** — **`api/generate-post.js` + `cron-daily-posts.js`가 이미 있다.** 모니터링에서 나온 미노출 질문 → 콘텐츠 브리프 → 기존 발행 파이프라인. **F14는 사실상 배선 작업**이라 투입 대비 효과가 가장 크다.

### P3 — 확장

16. **다국어** (S7) — 인바운드 의료관광. 구현비 거의 0, 시장은 신규.
17. **멀티테넌트 + 월 쿼터** (S3) — ERP 인증(`server/auth.ts`) 재사용.
18. **케이스 스터디 자동 생성** — S8의 6요소 템플릿(업종/질문3/before-after/곡선/델타)으로 제안서 슬라이드 자동 출력. `venomad-proposal`·`location-auto` 스킬과 연결.

## 8. 비용 · 리스크 · 주의

### 8.1 비용 — 설계 전에 계산할 것

| 구성 | 주간 호출 | 월 호출 |
|---|---|---|
| 질문 10 × 14모델 × 주1회 | 140 | ~600 |
| 질문 10 × 10모델(5엔진×2모드) × 주1회 | 100 | ~430 |
| **권장 시작점**: 질문 5~7 × 10모델 × 주1회 | 50~70 | ~215~300 |

**고객 1곳당** 수치다. 20곳이면 월 4,000~6,000 호출. 웹검색 모드는 단가가 더 비싸다. **질문 수 상한과 주기를 플랜에 묶어 파는 구조(S3의 월 카운터)가 선택이 아니라 필수**인 이유다.

### 8.2 리스크

| 리스크 | 대응 |
|---|---|
| **가중치 날조** — 근거 없는 19.6/8.4 복사 | 자체 근거 명시 or 균등 가중 기본값. UI에 `가정치` 라벨 |
| **의료광고법 — 비교광고** | 경쟁사 순위표를 **고객 대면 자료에 그대로 노출하지 말 것.** 내부 진단·전략 문서로 한정하거나, 자사 지표만 노출하고 경쟁 구도는 "경쟁 강도(개수)"로 추상화 |
| **AI 답변 변동성** (S12 급락·재상승) | 단발 측정 결과를 성과로 제시 금지. **최소 4주 추세**만 성과로 말한다 |
| **엔티티 추출 오탐** | LLM 추출 + 명부 대조 2단 검증. 미검증 항목은 `확인 필요`로 강등 (SEO 엔진 `markTri()` 선례) |
| **VEO 성능 병목** (S13) | 모니터링은 별도 비동기 워커. 진단 요청 경로에 절대 얹지 않음 |

### 8.3 우리가 이미 더 나은 것 — 버리지 말 것

1. **4단 판정** (인용/언급/미노출/측정불가) — GPTO는 2단. *인용* 과 *언급* 구분은 처방이 달라지는 실질 차이다.
2. **`markTri()` 정직성 철학** — 실측만 통과, 정황은 `확인 필요` 강등. GPTO의 "80점" 같은 합성 지표를 도입할 때 이 규율을 유지하면 신뢰에서 앞선다.
3. **발행 파이프라인 보유** — `generate-post.js` / `cron-daily-posts.js` / 카드뉴스 렌더. GPTO의 F14를 배선만으로 따라잡을 수 있다.
4. **203문서 지식근거** (`google_seo_guide/`) — 전략 서술의 근거를 실제 문서로 댈 수 있다. GPTO의 서술형 전략은 근거가 안 보인다.
