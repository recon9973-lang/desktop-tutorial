## 1. 화면 구성의 뼈대 — 어디에 무엇을 놓나

v3-04 의 구성이 GPTO 데모(1편)와 같은 **2단 구조**다. 유지한다:

```
┌ 헤드라인 강조 패널 (화면당 1개 — 기존→현재 + 추이 곡선) ────────────┐
├ 왼쪽 넓은 열 (1.35fr)              ┬ 오른쪽 좁은 열 (1fr)          ┤
│  증거의 흐름 (위→아래로 깊어짐)       │  상태·행동의 흐름               │
│  · AI 별 노출 막대                  │  · 검수 대기                  │
│  · 질문별 기존→현재                 │  · 측정까지 가는 길(사다리)       │
│  · 응답 원문 (켬/끔)                │  · 발행 상태                  │
│  · 질문×AI 격자                    │  · 참조 출처                  │
│  + [빈곳①] 빈 질문 펼침 처방         │  + [빈곳②] 출처 목록·유형        │
│  + [빈곳③] 빠진 답변의 경쟁 집계      │                             │
└──────────────────────────────────┴─────────────────────────────┘
```

**배치 원칙 셋** (v3 관례에서 추출, 새 카드도 따른다):

1. **왼쪽은 증거, 오른쪽은 행동.** 숫자·원문·격자는 왼쪽, 단추·사다리·대기열은 오른쪽.
2. **위에서 아래로 "요약 → 원인 → 원문" 순.** 큰 숫자를 먼저, 그 숫자를 만든 답변 원문을
   아래에 — 결론→근거 순서(UX-RENEWAL 원칙 1).
3. **강조 패널은 화면당 하나.** GPTO 데모의 힘은 큰 숫자가 하나뿐인 데서 온다.
   빈곳 카드 셋은 전부 일반 패널 톤으로 넣는다 — 헤드라인과 경쟁하지 않는다.

## 2. 빈 곳 3개의 화면 구성 (실물은 첨부 HTML)

### 빈곳① 질문×AI 격자에 「다음 할 일」 열 + 빈 질문 펼침

격자 행을 언급 수 오름차순으로 두고(빈 질문 위), 행 펼침에 **탈환 처방 한 줄**:
그 질문에서 나온 경쟁 이름(U7 데이터) + 그 질문에서 인용된 출처(U4 데이터).
*"교통사고 후유증(0/27)의 지면은 ○○한의원(6회), 근거는 지식 Q&A 2·카페 1 —
우리 글이 실릴 자리는 저 유형"* 이 한 줄이 이 화면의 존재 이유다.

### 빈곳② 출처 카드의 완성 — 목록 1층 + 유형 2층

v3-04 의 "참조 출처 — 몇 개 모델이 봤나"(3줄)를 확장한다:
- **1층 목록**: 도메인/URL · 인용수 · 엔진 칩 · **평균 순번** · 귀속(자사▣/경쟁◼/제3자▷/미확인?)
  · 줄마다 복사/열기 · **「빠진 답변에서만」 필터** (GPTO 1편 ④ + 우리만의 순번·귀속)
- **2층 유형**: 도메인→유형 규칙표 분류(미분류는 그대로) · "AI 가 근거로 쓰는 유형 ×
  우리 문서 0 × 빠진 답변 집중" = ⚠⚠ 배포 목표 1순위

### 빈곳④ 「인용 문서 해부」 — U9 의 화면 (2026-08-15 추가)

**어디에**: 독립 메뉴가 아니라 **막다른 상세 카드**다. 진입은 두 곳 — 빈 질문 펼침(빈곳①)의
「인용 문서 해부 보기 →」 단추, 출처 목록(빈곳②)의 문서 아이콘. 질문 하나에 종속된
분석이므로 항상 질문 맥락을 제목에 이고 나온다("「교통사고 후유증」 질문에서 인용된 4건").

**어떻게** — 표현 결정 다섯:

1. **비교표가 본체다** — 행=구조 요소(질문형 제목·첫 문단 직답·FAQ·지역 표지·숫자·길이),
   열=인용된 문서들 + **맨 오른쪽 우리 글 열**(보라 테두리로 격리). 눈이 왼쪽에서
   오른쪽으로 훑으면 "남들은 있고 우리는 없는 것"(⚠ amber)에 도달한다.
2. **✓ 초록 · ✗ 회색 · 우리 열의 ✗ 만 ⚠ amber** — 경쟁 문서의 ✗ 는 판단거리가 아니라
   그냥 사실이므로 회색. 강조는 우리의 결핍에만.
3. **robots 차단 문서는 행으로 남긴다** — "못 잼 — VEOBot 차단 · 0 아님". 표에서
   조용히 빼면 4건 해부가 3건 해부처럼 읽힌다.
4. **발췌는 문서당 1문장 + 원문 링크** — 전문은 저장·표시하지 않는다(표절 방지가 화면
   구조에 박힘). 참고하려면 원문 링크로 나가야 한다.
5. **출력은 체크리스트다** — ⚠ 요소를 그대로 「글 설계 체크리스트」로 목록화(지어낸 항목
   금지) + 「콘텐츠 브리프로 복사」. 해부가 감상으로 끝나지 않고 다음 글의 입력이 된다.

### 빈곳③ 「우리가 빠진 답변엔 누가 나오나」 집계 카드

원문 카드의 "경쟁 2곳 등장" 단편을 집계로: 이름(표면) · **빠진 답변 N/110** ·
동반 N/25 · 주 질문 · [경쟁사로 등록→]. 대체(빠진 답변)와 동반(같이 나옴)을 갈라
탈환 대상만 짚는다. 상세 규칙은 U7(계획서) 그대로.

## 3. 표현 문법 — 숫자·색·크기·문구

### 3-1. 숫자 문법

| 규칙 | 형태 | 출처 |
|---|---|---|
| **변화는 쌍으로** | `기존 → 현재` + 델타 칩(`+15.6%p`) · 같은 집합·같은 판끼리만 | GPTO 채택 + ADR 0010 |
| **모든 비율에 분모** | 큰 % 옆에 mono 소자로 `25/135` | 0.3.130 인용 막대 원칙 |
| **시각을 붙인다** | 헤드라인엔 주차(`기준선 8/15 주`) · stamp 엔 실행시각 | 규칙 2-D |
| **못 잼은 `—` + 사유** | `— 첫 관측 대기 · 0% 아님` | ADR 0002 |
| **소수점은 분모가 감당할 때만** | 분모 < 100 이면 정수 %(`19%`, `55%`) | `VisibilityReport` 머리말 |
| **순번은 평균+서술** | `평균 1.4위 (대부분 첫 번째)` | 첫 관측 실측 |

⚠ **v3-04 지적 하나**: 질문별 표가 `55.0%` 로 소수점을 붙였다 — 분모 27 에 소수점
한 자리는 감당 못 할 정밀도다(운영 화면 `percent_text_ko` 원칙과 상충). 시안 이식 시
정수 %로 고칠 것.

### 3-2. 색 문법 — 색은 의미에만 쓴다

```
축 색 (고정)      teal = SEO · 연teal = GEO · 보라(beam) = AEO
시간 색           보라 = 현재 · 회색(dim) = 기존/과거
사실 색           검붉음 = 재서 미등장 · 회색 = 답변 없음/못 잼 (둘은 다른 사실 — 다른 색)
판단 색           초록 = 상승 델타 · amber = 검수/보류 · red = 위반/실패
경쟁사 색         중립 회색 계열 하나
```

**GPTO 와 갈리는 자리 둘:**
- GPTO 1편의 30개 색점은 **색이 의미 없이 분산**된다(브랜드마다 임의 색) — 장식이다.
  우리는 경쟁사를 전부 중립 회색으로: 색이 많으면 눈이 색을 읽으려다 실패한다.
  경쟁사를 붉게 칠하지도 않는다 — "적" 연출은 오독을 만든다.
- GPTO 는 초록 하나로 "성장"을 판다. 우리는 **미등장(검붉음)을 상승(초록)과 같은
  강도로** 보여준다 — 못 한 일을 한 일과 같은 크기로(`VisibilityReport` 원칙).

### 3-3. 크기 위계

```
30px mono   헤드라인 변화 쌍 — 화면에 하나
21px mono   지표 타일 숫자
13.5px      본문 · 13px 표 · 11.5px 카드 제목(대문자 느낌의 자간)
10px mono   stamp(각주) — 접지 않고 항상 노출
```

### 3-4. 문구 문법

| 규칙 | 예 |
|---|---|
| 카드 제목은 **사실 질문형** | "우리가 빠진 답변엔 누가 나오나" · "AI 가 근거로 쓴 출처" — GPTO 의 명사 라벨("모니터링 추이")보다 읽는 이의 질문에 붙인다 |
| 상태엔 **부정 방지 문구** | "0% 아님" · "분모에서 제외 · 0 아님" · "기준선 잡는 중" |
| **이유는 근거 있을 때만** | 인과 문장엔 출처를 달거나 완화형("움직이기 쉬운 자리")으로 — 2-B |
| 각주(stamp)는 **접지 않는다** | 접힌 주의사항은 없는 것과 같다 |
| 표면/확정을 문구로 가른다 | "표면 기준 — 동명 업체 미구분" vs "확정 검출" |
| 의료법 고지는 상수 | "이 비교는 내부 판단용 · 병원 광고물 게시는 의료법 제56조 금지" |

### 3-5. GPTO 표현에서 — 가져온 것 / 버린 것

| 가져온 것 (이미 v3 반영 포함) | 버린 것 |
|---|---|
| 변화 쌍 `A → B` + 델타 칩 | 분모 없는 % |
| 화면당 큰 숫자 강조 패널 하나 | 배수 화법("9.6배") |
| 출처 줄 "N개 모델" 칩 | 켬/끔 합산 |
| 원문 카드 속 자사명 `mark` 강조 | 30색점 장식 색 |
| 좌 질문 / 우 결과 2단 | 상위 질문만 골라 싣기 (싣으면 "상위 N" 명기) |

## 4. 결정이 필요한 것 (사장님 몫 — 이 연구는 판단 보류)

1. **어두운 관제탑(v3 시안) vs 노션 라이트(0.3.130 운영 반영본)** — 시안 계열과 운영
   콘솔의 색 세계가 갈라져 있다. v3 는 UX-RENEWAL 의 A안(관제탑) 계열, 운영은 B안 계열.
   어느 쪽으로 수렴할지는 시안 세션과 함께 정할 일.
2. **레이더 차트** — v3-04 스스로 "사장님 지시와 상충 · 재확인 뒤에" 로 보류해 두었다.
   이 연구도 같은 판단: 엔진마다 분모가 달라(브리핑 6 · 나머지 18) 넓이가 거짓말을 한다.
