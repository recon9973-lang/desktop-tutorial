# veo-design — VEO 화면 샘플링 프로젝트

`veo/` 의 **코드는 한 줄도 건드리지 않는다.** 여기서는 화면만 그린다.

## 왜 따로 두나

돌아가는 제품 위에서 디자인을 실험하면 두 가지가 섞인다 — "이게 더 나은가" 와
"이게 안 깨지나". 섞이면 둘 다 못 본다. 여기서는 앞의 질문만 본다.

여기서 고른 안이 정해진 뒤에, 그때 `veo/` 에 옮긴다.

## 보는 법

```bash
open veo-design/샘플-B안-480px.html
```

원본을 고치며 볼 때는 로컬 서버로 연다 (`.claude/launch.json` 의 `veo-design`,
포트 4600 → `http://localhost:4600/index.html`). 고친 뒤 배포본을 다시 만든다:

```bash
python3 veo-design/build.py
```

## 판정 — 관문 하나

보고서 §5 원칙 7: **화면은 토큰을 거치지 않고 색·크기를 정할 수 없다.**
글로 적은 규칙은 안 지켜진다는 것이 지금 제품에서 이미 증명됐다(보고서 §2-7·2-8).
그래서 명령 한 줄이 판정한다 — `tokens.css` 를 뺀 어떤 CSS 에도 hex 색·rgba·
직접 쓴 px 글자 크기가 있으면 안 된다.

```bash
cd veo-design/samples && grep -nE '#[0-9a-fA-F]{3,8}\b|rgba?\(|font-size:[[:space:]]*[0-9]' \
  base.css b-clinical/clinical.css || echo "0줄 — 통과"
```

**[실측] 2026-08-09 현재 0줄.** (처음엔 2건 나왔다 — `#ffffff` 하나와
`rgba(255,255,255,.07)` 하나. 관문이 잡아서 토큰으로 옮겼다.)

## 지키는 것

* `veo/` 를 import 하지 않는다. 복사해 온 값은 어디서 왔는지 주석으로 남긴다.
* 샘플은 **고정된 가짜 데이터**로 돈다. 진짜 API 를 부르지 않는다.
* 숫자는 지어내되 **지어낸 숫자라고 화면에 적는다** — 샘플을 실측으로 오해하지 않게.
* 채점 영역·가중치·등급 이름은 **지어내지 않는다.** 실제 명세
  `veo/packages/scoring-specs/specs/veo.geo.readiness/1.3.0.yaml` 에서 가져온다.
