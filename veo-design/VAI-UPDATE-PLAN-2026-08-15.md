## U1. 기준선 대비 헤드라인 — 격차의 최우선

**GPTO 근거** 3·4·5편 전부: 파는 것은 42.2%가 아니라 **+31.4%p** 다. 리포트 최상단이
항상 "기존 → 현재" 한 줄.
**VAI 현재** 추이선·6회 막대는 있는데 **첫 눈에 오는 변화 한 줄이 없다.**
UX-RENEWAL 원칙 3("변화량이 없다")과 같은 결론이 경쟁사 분해에서 재확인된 것.

**설계 규칙 (우리 원칙과의 절충):**
- 기준선 = **그 질문 집합이 발행된 뒤 첫 완결 주**. 계약일이 아니다 — 잰 값만 기준선이 된다.
- 질문 집합이 바뀌면 **기준선도 다시 선다**(추이선을 끊는 자리와 같은 자리, ADR 0010).
  GPTO 처럼 집합이 다른 두 시점을 한 화살표로 잇지 않는다.
- 분모·시각을 화살표 옆에 병기. 1회차뿐이면 화살표 대신 **"기준선 잡는 중"**.

**화면 구성도** — 거래처 AEO 탭 최상단 (기존 `VisibilityTrend` 카드 위):

```
┌─ AEO 언급률 ────────────────────────────────────────────────┐
│                                                             │
│   18.5%  ──────────▶  34.1%   (+15.6%p)                     │
│   기준선 8/15 주                최근 9/26 주                   │
│   25/135                      46/135                        │
│                                                             │
│   질문 집합: 핵심 질문 v1 (5문항 · 발행 08-15) · 같은 집합끼리만 비교  │
├─────────────────────────────────────────────────────────────┤
│   [주별 추이선 — 기존 VisibilityTrend 그대로]                    │
│    %                                    ●                   │
│         ●      ●          (빈자리)   ●                        │
│    ●                 ●                                      │
│   ─┴──────┴──────┴──────┴──────┴──────┴─                    │
│   8/15   8/22   8/29   9/5    9/19   9/26                   │
└─────────────────────────────────────────────────────────────┘
   집합이 바뀐 경우:
   ┌───────────────────────────────────────────┐
   │  34.1% (46/135)   ← 현재 · 핵심 질문 v2      │
   │  v1 시절 기록은 아래 추이에서 끊긴 선으로 보존       │
   │  ⚠ v1 과 v2 는 질문이 달라 비교하지 않습니다      │
   └───────────────────────────────────────────┘
```

**관문** 헤드라인 부품 시험: 분모 없으면 렌더 거부 · 집합이 다른 두 주를 화살표로 이으면
실패 · 1회차뿐일 때 "기준선 잡는 중" 문구 확인.

## U2. 질문 유형 표지 — 첫 관측이 이미 증명한 것

**GPTO 근거** 3편(공휴일 진료 0→55) · 4편(가품 이슈 없는) · 5편(중국어 서비스 완비).
**VAI 근거 [실측]** 첫 관측: 지역 표지 있는 질문만 언급(14/27·11/27), 없는 3개는 0/27.
WORKLIST 가 "지역 표지 요구" 를 이미 개선점으로 적음 — 이것을 표지 체계로 확장한다.

**설계** — `prompt-sets` 에 질문마다 유형 표지(복수 가능):

```
지역형     "마산 교통사고 한의원"          ← 지역 표지 없으면 발행 관문이 경고
운영정보형  "일요일에 진료하는 ~"           ← GPTO 3편의 최대 상승 유형
속성형     "과잉진료 없는 ~" "야간진료 되는 ~" ← 4편 "가품 이슈 없는" 의 병원판
비교형     "A동 근처 한의원 추천"
(외국어형은 U8 보류와 함께 보류)
```

**화면 구성도** — `PromptSetForm` 질문 줄:

```
┌─ 질문 집합: 핵심 질문 v2 (작성 중) ──────────────────────────────┐
│                                                                │
│  1. 마산 교통사고 한의원 추천해줘                                   │
│     유형: [지역✓] [운영정보 ] [속성 ] [비교✓]     지역표지: 마산 ✓    │
│                                                                │
│  2. 교통사고 후유증 잘 보는 한의원은?                               │
│     유형: [지역 ] [운영정보 ] [속성✓] [비교 ]     지역표지: 없음 ⚠    │
│     ⚠ 지역 표지가 없습니다 — 첫 관측에서 이 유형은 0/27 이었습니다      │
│        (막지는 않음 · 발행 시 사유 한 줄 요구)                       │
│                                                                │
│  [+ 질문 추가]                    유형별: 지역 3 · 운영 1 · 속성 2   │
└────────────────────────────────────────────────────────────────┘
```

**관문** 발행 시 지역 표지 없는 질문은 사유 없이 통과 못 함(경고형, 차단 아님 — 브랜드
직접 질문 등 예외가 실재한다). 유형별 집계가 관측 결과 화면까지 따라간다.

## U3. 질문별 기회 표시 — 빈 질문 우선

**GPTO 근거** 3·4·5편: 0% 출발 질문이 가장 크게·빨리 오른다(0→55 두 번, 0→51, 0→47,
0→45). 2편의 「삽입 난이도」 — 빈 답변은 난이도 최저.
**VAI 현재** 질문×AI 격자(0.3.130)가 있으나 "그래서 어느 질문부터" 가 없다.
GPTO 의 「기회 점수 80점」 같은 **합성 점수는 만들지 않는다** — 이유를 지어내게 되는
자리다(0.3.131 원칙 "이유를 지어내지 않는다"). 대신 **사실 그대로를 정렬 기준으로** 쓴다.

**화면 구성도** — 질문×AI 격자 아래 (기존 `CoverageGrid` 확장):

```
┌─ 질문별 언급 (회차 3회 합산 · 조건 9칸) ──────────────────────────┐
│                                                               │
│  질문                     언급     GPT Cl Gm Px Gk   다음 할 일   │
│  ────────────────────────────────────────────────────────    │
│  마산 교통사고 한의원…      14/27    ●  ●  ●  ●  ○   유지        │
│  월영동 침 잘 놓는…        11/27    ●  ○  ●  ●  ○   유지        │
│  교통사고 후유증…           0/27    ○  ○  ○  ○  ○  ★빈 질문     │
│  한방 재활 잘하는…          0/27    ○  ○  ○  ○  ○  ★빈 질문     │
│  야간 진료 되는…            0/27    ○  ○  ○  ○  ○  ★빈 질문     │
│                                                               │
│  ★빈 질문 = 어느 AI 도 이 질문에 우리를 언급하지 않았습니다.            │
│    인용 출처(아래 U4)에 우리 문서가 없다는 뜻이므로,                   │
│    콘텐츠를 넣으면 가장 먼저 움직이는 자리입니다.                       │
└───────────────────────────────────────────────────────────────┘
```

("가장 먼저 움직인다"의 근거는 GPTO 관측 사례 — 화면 문구에는 근거 링크를 달거나,
근거 문서화 전이면 "움직이기 쉬운 자리" 로 완화한다. 화면 문구는 남는다 — 2-B.)

**관문** 정렬이 언급 수 오름차순(빈 질문 위)임을 고정 · `—`(못 잼)와 0 을 다르게 그림.

## U4. 인용 출처 — 목록·귀속·배포 목표 (2026-08-15 확장, GPTO 1편 ④ 전면 벤치마킹)

**GPTO 근거** 1편 ④ 참조 출처: 출처 **URL 목록 자체가 화면의 한 축**이다 — 줄마다
`2개 모델`/`ChatGPT` 라벨(누가 인용했나), 복사·새창 버튼, `utm_source=openai` 수거.
그리고 2편에서 그 목록이 채널 7유형(리포트·블로그·위키·비교리뷰·디렉토리·발표자료·
논문)으로 묶여 배포 목표가 된다. **진단과 처방이 같은 데이터.**

**VAI 현재 [실측, 코드·DB 확인]** — **저장은 이미 GPTO 보다 낫다. 없는 것은 화면이다:**

| 층 | 상태 | 근거 |
|---|---|---|
| 답변마다 **모든 인용 URL 저장** (자사 것만이 아니라) | **있음 — [실측 2026-08-15] 첫 관측에서 656건·도메인 99개·전건 순번 포함 실제 확인** | `citations` 표 — url · domain · **position** · is_own_domain · **competitor_id** |
| URL 정규화 — 껍데기(`google.com/url?q=`)·`utm_*` 벗김, 확신 없으면 `UNRESOLVED`→사람 | **있음** | `detection/citations.py` — *"남의 URL 을 우리 것이라 주장하지 않는다"* |
| 인용률 + 분모(인용을 볼 수 있던 답변만) | **있음, 화면까지** | `EngineBreakdown` 채움 막대 · 첫 관측 41.7% (25/60) |
| **출처 목록 화면** (GPTO 1편 ④에 해당) | **없음** | 화면은 비율 막대뿐 — 표에 쌓인 URL 이 안 보인다 |
| 출처 → 채널 유형 → 배포 목표 | 없음 | — |

특히 **`position` 과 `competitor_id` 는 GPTO 화면에도 없는 것**이다 — 몇 번째 인용인지,
어느 경쟁사의 문서인지가 이미 저장 구조에 있다. 화면만 열면 GPTO 를 넘어선다.

**[실측 2026-08-15] 첫 관측의 인용 실물 (운영 DB 조회):**

```
자사 인용의 실제 링크        chamsarang1075.com/교통사고-후유증… 19회
                          chamsarang1075.com/참사랑한의원…    19회 · 홈 21회
                          /?utm_source=openai 3회  ← GPTO 1편의 그 꼬리표가 실재
자사 인용 평균 순번          1.4위 (대부분 첫 번째 인용)
자사가 빠진 110건의 근거     naver 39 · youtube 32 · a-ha.io(지식Q&A) 26 ·
                          경쟁 한의원 자체 사이트 mokhuri 18 · kangchuh 27 ·
                          jaseng(자생한방병원) 8 · 뉴스 donga 11 · joins 8
```

한 페이지(`/교통사고-후유증…`)가 자사 인용의 3할을 벌고 있다 — **글 단위 처방의 근거**가
이미 나온다. 그리고 2편의 GPTO 채널 유형(Q&A·블로그·뉴스·디렉토리)이 우리 데이터에서
그대로 재현된다.

**설계 — 출처 화면 두 층:**

```
1층 · 출처 목록      GPTO 1편 ④ 벤치마킹 — 도메인/URL 단위, 누가·몇 번·몇 번째로
                    인용했나 + 귀속(우리/경쟁사/제3자) + 빠진 답변(U7)과 교차

                    않는다) → "AI 가 근거로 쓰는 유형인데 우리 문서가 없는 곳" = 배포 목표
```

**화면 구성도 2층** — 같은 카드의 「유형으로 묶어 보기」 전환:

```
┌─ 유형별 (도메인 분류 규칙표 기준) ─────────────────────────────────┐
│                                                               │

│  ────────────────────────────────────────────────────        │

│  미분류          2      —        1   (분류 규칙 없음 — 그대로 둠)   │

한 줄로 완성된다: *"교통사고 후유증 질문(0/27)의 지면은 ○○한의원(6회)이 갖고 있고,
그 근거는 지역 카페 글 2개와 ooclinic 공지 1개다 — 우리 문서가 실릴 자리는 저 유형이다."*

**관문** ① 출처 줄마다 인용 수 분모 병기 ② 경쟁사 귀속은 `competitor_id` 있는 것만
(이름 유사로 추정 귀속 금지) ③ `UNRESOLVED` 를 제3자로 뭉개면 시험 실패 ④ 유형 분류는
규칙표에 있는 도메인만 · 없는 것은 미분류 유지 ⑤ "우리 문서" 판정은 등록 사이트
출처(`is_own_domain`)와만 대조.

**주의** 뒷반(콘텐츠 자동 생성·배포)은 이 문서 범위 밖이다 — 2편에서 본 대로 검증 안 된
숫자가 500 채널에 굳는 구조라, **의료 검수 관문 설계 없이는 시작하지 않는다.**

## U5. 성과의 켬/끔 두 줄 표기 — 이미 가진 것을 화면까지

**GPTO 근거** 3편: 성과 화면에서 켬/끔이 합산돼 "검색 경로 효과인지 AI 기억 효과인지"
고객이 알 수 없다. 그들의 진단 화면(1편)에는 있던 구분이 파는 화면에서 사라졌다.
**VAI 현재** 저장은 나뉘어 있다(BROWSING 75 / NO_BROWSING 60 실측). 화면 합산 여부만 문제.

**화면 구성도** — U1 헤드라인의 펼침(기본은 합산 한 줄, 펼치면 두 줄):

```
┌─ AEO 언급률 ────────────────────────────────────────┐
│   18.5% ─▶ 34.1% (+15.6%p)          [▾ 경로별 보기]  │
├─────────────────────────────────────────────────────┤
│   검색 켬 (AI 가 지금 웹을 읽음)   21.3% ─▶ 45.3%       │
│     └ 우리가 콘텐츠로 바꿀 수 있는 자리                   │
│   검색 끔 (AI 기억 속)           15.0% ─▶ 21.7%       │
│     └ 느리게 따라오는 자리 — 켬이 오르면 뒤따릅니다*        │
│   * 이 문장은 GPTO 사례 관측(3편)에 근거. 우리 데이터로     │
│     확인되기 전까지는 문구를 "느리게 움직이는 자리" 로만.     │

```

**관문** 두 줄의 분모 합 = 합산 줄 분모 · Perplexity(끔 미지원)는 끔 분모에서 빠짐을 명기.

## U6. 반복 3회 완화 검정 — 화면 아님, 연구 항목

**목적** 반복 3→1이면 같은 돈으로 질문 3배(5→15). GPTO 와의 최대 격차(질문 규모)를
비용 없이 좁히는 유일한 길.
**방법** 새 호출 불필요 — 기존 135건에서 반복 1회만 뽑아 언급/비언급 판정이 3회 합산과
얼마나 갈리는지 계산. 회차가 몇 개 더 쌓이면(지금 "데이터만 수집" 방침과 정확히 맞물림)
검정력이 오른다.
**판단 기준(제안)** 질문×엔진 칸 단위로 1회 표본 판정이 3회 판정과 90% 이상 일치하면
완화 — 아니면 유지. 어느 쪽이든 결과를 research 문서로 남긴다.

## U7. 경쟁 브랜드 — 발견 · 승격 · 측정 3단 (2026-08-15 확장, 사장님 제안 반영)

**GPTO 근거** 1편: 질문에 브랜드가 없으니 답변에 나온 이름 30개가 공짜 경쟁 명단이 되고,
색점 + 정수(%) 목록이 화면의 중심이다.

**VAI 현재 [실측, 코드 확인 완료]** — 뒷단의 절반이 이미 있다:

| 층 | 상태 | 근거 |
|---|---|---|
| 등록된 경쟁사를 **자사와 같은 검출기**로 잰다 | **있음** | `detection/competitors.py` — *"검출기는 정확히 하나, 이 모듈은 배선일 뿐"* |
| SOV(점유율) 원천 — 선언된 브랜드 전부의 결과 저장 | **있음** | `runs.py:222 sightings` |
| 신원 비대칭 경고 | **있음** | `brand_identity.describe_identity_asymmetry_ko` |
| 비교 화면 골격 (같은 조건만 · 거부 사유 표시) | **있음** | `comparisons.ts` |
| **답변 속 미등록 이름 자동 발견** | **없음** | detection 패키지에 임의 이름 추출 없음 — 전부 선언 기반 |

**왜 GPTO 방식 그대로는 안 되나** — 우리 코드가 이미 이유를 적어 두었다:

> *"자사 브랜드는 너그럽게, 경쟁사는 엄격하게 검출하면 산수를 한 줄도 안 바꾸고 모든
> 점유율이 우리에게 유리해진다"* (`competitors.py` 머리말)
> *"서울치과는 수십 곳이고 중앙병원은 더 많다"* (`brand_identity.py` 머리말)

추출된 맨이름(전화·구·구분자 없는)은 **대칭 검출이 불가능**하다 — 자사는 신원 4요소로
확정 검출하면서 경쟁사는 이름만으로 검출하면 그 순간 SOV 가 왜곡된다. GPTO 의 30개
색점 %는 바로 이 왜곡 위에 서 있을 가능성이 크다[추정]. 그래서 **3단으로 가른다**:

```
① 발견·집계 (자동·무료)  답변에서 미등록 이름을 긁고 곧바로 지표를 낸다 —
                       핵심 지표는 「자사가 빠진 답변에서의 등장」(아래).
                       분모가 명확한 횟수라 등록 없이도 정직한 측정이다.
                       단 자사 확정 언급률과 나란한 SOV 막대는 안 그린다(비대칭).
② 승격 (사람 한 번)     이름을 경쟁사로 등록 — 신원(전화·구·구분자)을 채운다.
③ 측정 (기존 파이프)    등록된 순간 기존 competitors.py 대칭 검출 · SOV · 비교
                       화면에 자동으로 들어간다 — 새 셈법 없음.
```

**① 의 핵심 지표 — "우리 자리를 누가 차지했나".** 답변을 자사 언급 여부로 가른다:

```
전체 답변 135  =  자사 언급 25  +  자사 미언급 110        [실측, 첫 관측]
                                   └─ 이 110건이 "우리가 놓친 지면"이다.
                                      여기 자주 나오는 이름 = 실질 경쟁사.
```

이름마다 세 값을 낸다 — ⓐ **빠진 답변 등장** N/110 (주 지표: 우리 대신 나옴)
ⓑ 동반 등장 N/25 (자사와 같이 나열됨 — 경쟁이라기보다 동급 취급)
ⓒ 질문별 분포 (특히 **빈 질문(U3)에서 누가 나오나** — 그 질문의 지면을 가진 자).
ⓐ와 ⓑ를 가르는 이유: 우리와 함께 나열되는 이름과 **우리를 밀어내고 나오는 이름**은
다른 사실이고, 처방도 다르다(동반=유지 경쟁, 대체=탈환 대상).

**구현 방향** — 병원 도메인은 오탐(지역명+과목명 조합이 상호처럼 생김)이 많으므로
자유 추출이 아니라 **패턴 제한 추출**로 시작한다: 「지역어+과목어+의원/한의원/치과/병원」
꼴 + 나열 구조(번호·불릿) 안의 고유명사. 확신 없는 것은 "패턴 밖 후보"로 접어 둔다.
표기 정규화(한/영·병기형)는 기존 `normalize.py` 그대로. 답변별 자사 언급 여부는
`AnswerDetection.own` 이 이미 주므로 **가르는 축은 공짜**다. 검토 대기(`mention_
pending_review`) 답변은 "빠진 답변" 분모에서 빼고 그 수를 각주로 적는다(확정 아님).

**화면 구성도** — AEO 탭 새 카드 「우리가 빠진 답변엔 누가 나오나」:

```
┌─ 우리가 빠진 답변엔 누가 나오나 (자사 미언급 110/135건 기준) ──────────┐
│                                                                   │
│  이름(표면 기준)      빠진 답변   동반 등장   주로 나온 질문             │
│  ─────────────────────────────────────────────────────────────    │
│  ○○한의원             9/110      2/25    교통사고 후유증(6) ★빈 질문  │

│    자사 언급률(확정 검출)과 나란히 놓는 점유율 비교는 등록 후에 나옵니다.   │

  U3(빈 질문) 카드와 연결 — 빈 질문 줄을 펼치면:

  [경쟁사로 등록 →] 누르면 (기존 브랜드 식별 화면으로):
