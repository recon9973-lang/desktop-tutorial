## 0. 한 줄 결론 (추천)

**세 갈래는 양자택일이 아니다. 지식맵을 "SEO/GEO 룰 엔진(내부 근거 레이어)"으로 만들고(①), 그 위에 [측정 도구](②) → [컨설팅·수정 도구](③)를 순서대로 쌓는다.**

- 지식맵은 **제품이 아니라 토대**다. 단독 상품화하면 가치가 낮지만, 모든 진단·처방의 **"공식 근거(citation)"** 원천으로 쓰면 우리 진단의 신뢰도·차별화를 결정한다.
- **측정(②)은 이미 80% 완성**돼 있다(아래 인벤토리). 지식맵을 붙여 "왜 이 점수인지 = Google 공식 문서 근거"를 노출하면 바로 차별화된다.
- **컨설팅·수정(③)이 미개척·최고가치 영역**이다. 원장(비전문가)에게는 점수보다 **"그래서 뭘 고쳐야 하나"**가 전환을 만든다(기존 기획서에서도 확인된 결론).

## 2. 세 갈래 옵션 평가

| 기준 | ① 별도 엔진 | ② SEO/GEO 측정도구 | ③ SEO/GEO 컨설팅·수정 도구 |
|---|---|---|---|
| 정의 | 지식맵을 룰/지식 베이스(JSON+LLM 그라운딩)로 코드화 | 사이트의 SEO·AI노출 상태를 점수·근거로 측정 | 측정→진단→**처방→(반자동) 수정안 생성** |
| 기존 자산 활용 | 높음(seo-guidelines가 이미 연결) | **매우 높음**(seo-engine·AEO·medirank 재사용) | 높음(처방 규칙 뼈대 존재) |
| 신규 작업량 | 중(룰 추출·매핑) | **소**(통합+근거 노출) | 중~대(처방·수정 생성 로직) |
| 차별화 | 단독으론 낮음(내부 토대) | 중(근거 붙이면 상) | **상**(경쟁사 대비 희소) |
| 원장 전환력 | — | 중("점수만") | **상**("뭘 고칠지"+대신 고쳐줌) |
| 상품화 | ❌ 단독 판매 부적합 | ⭕ 무료 리드젠·유료 리포트 | ⭕⭕ 컨설팅·구독(리테인션) |
| 리스크 | 낮음 | 낮음 | 중(할루시네이션·의료광고법) |

**판정**: ①은 **수단**(토대), ②는 **입구**(리드젠), ③은 **수익·차별화**. 셋을 계층으로 결합하는 것이 정답.

## 3. 추천 아키텍처 — 3계층

```
L3  컨설팅·수정 도구   측정→처방→수정안 생성(+공식 근거)   ← 수익·차별화 (③)
        ▲
L2  측정 도구          기존 진단 통합 + "근거[n]" 노출      ← 리드젠 입구 (②)
        ▲
L1  룰 엔진            지식맵 → rules.json + LLM 그라운딩    ← 내부 토대 (①)
```

### L1. 룰 엔진 (지식맵의 제자리)
지식맵 18카테고리를 **하나의 규칙 지식베이스**로 코드화:
```
rule = { id, 축(SEO|AEO/GEO), 항목, 배점, 판정로직, 근거[문서번호 n], 처방템플릿, 위반예시 }
```
- 이미 `seo-engine.js`의 채점 항목과 지식맵 항목이 **1:1로 매핑 가능**(title·meta·H1·canonical·robots·JSON-LD·CWV 등 전부 지식맵에 근거 존재).
- LLM(수정 생성)에는 이 지식베이스를 **그라운딩 소스**로만 주입 → **할루시네이션 금지, "공식 문서에 있는 말만"**.

### L2. 측정 도구 (거의 완성 → 근거로 무장)
- `diagnose-redesign.md`의 원클릭 오케스트레이터를 채택하되, 각 항목 결과에 **"근거: 지식맵 [n] / Google 공식"** 배지를 붙인다.
- AI 노출(AEO) 축은 `insights.js` 멀티엔진 실측(엔진×질문 매트릭스)을 그대로 사용 — "20번 물어 몇 번 나왔나"가 단일 점수보다 설득력 높음.
- 병원 특화 축은 medirank(노출·경쟁·수요·플레이스)를 결합.

### L3. 컨설팅·수정 도구 (신규 고가치)
측정 결과의 각 미달 항목에 대해:
1. **처방**(무엇을·왜) — 조건부 규칙(이미 기획됨) + 지식맵 근거.
2. **수정안 생성**(반자동) — LLM이 지식맵 그라운딩으로 실제 개선안 산출:
   - `<title>`·메타 디스크립션 재작성안
   - JSON-LD(Organization/LocalBusiness/Article) 스니펫 생성
   - E-E-A-T·콘텐츠 개선 문단(의료광고법 검증기 통과분만)
   - robots/canonical/사이트맵 수정 지시
3. **가드레일**: `medical-ad-validator.js`로 생성물 사후검증, 전후사진·효과보장·최상급 표현 차단.

## 4. GEO(생성형엔진최적화)에 대한 정직한 포지셔닝 — 중요

지식맵의 Google 공식 문서 **[39] 생성형 AI 최적화 · [1] AI 기능과 웹사이트**는 명시한다:
- "AI 노출에 **특별 최적화 불필요** — 기존 SEO·E-E-A-T면 충분"
- "**LLMS.txt·AI 전용 재작성은 무시**해도 됨"

따라서 우리 GEO 상품은 **"AI 전용 마법"으로 팔면 안 되고**, 다음으로 포지셔닝한다:
> "AI 검색 노출 = 정석 SEO·E-E-A-T·구조화데이터의 결과. 우리는 그걸 **실측(멀티AI)** 하고 **공식 근거로 처방·수정**한다."

이 정직함이 오히려 경쟁 GEO 업체(근거 없는 과장) 대비 **신뢰 차별화**가 된다. 지식맵이 그 근거를 제공한다.

## 6. 비즈니스 관점 (병원 원장 대상)

- **측정만** = 커모디티(경쟁사도 함) → 무료 리드젠 입구로만.
- **근거(지식맵) + 처방 + 수정** = 희소 가치 → 유료 리포트·월 구독·컨설팅 리테인션.
- 강의자료(Session1~5)는 **컨설팅 상품의 신뢰 자산**(교육→진단→처방→대행의 퍼널).

## 부록 — 결론 재확인
지식맵은 **"별도 엔진"으로 만들되 단독 상품이 아니라 측정·컨설팅을 관통하는 근거 레이어**로 둔다.
우선순위: **근거화(P0) → 처방(P1) → 수정 생성(P2)**. 측정도구는 이미 있으니 근거를 입히는 것부터 시작하는 것이 투입 대비 효과가 가장 크다.
