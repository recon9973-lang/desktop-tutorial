# location-auto — 지역 입력 → 상권분석+제안서 자동화

**한 줄:** 지역(또는 회사명+주소)만 주면 → **실측 상권분석 리포트 + 분석 PPT + 경쟁사 브리핑 + 1페이지 제안서(문서·슬라이드)** 를 자동 산출.

이 스킬은 `대구-달서구-다이어트-상권분석` 작업에서 검증된 파이프라인을 **모든 지역·진료과에 재현**하도록 패키징한 것이다.

---

## 0. 절대 원칙 (MUST)
1. **통계 날조 금지 — 실측 > 추론 > 날조.** 모든 숫자는 출처 3등급으로 표기: ✅실측/공식 · 🟡정성/추정 · 🔴미실측(비우고 확정법 명시). 임의 수치로 채우지 않는다.
2. **의료광고법 준수.** 전후사진·효과 보장·최상급 표현 금지. 제안서 KPI는 "목표치"로 명시(보장 아님).
3. **egress 제약 인지.** 이 환경은 조직 정책상 외부 원문 fetch가 403 차단될 수 있다(SGIS/행안부/KOSIS/심평원 포털 대부분). WebFetch 실패 시 **재시도하지 말고**, WebSearch 스니펫으로 총계만 잡고 **정밀 수치는 사용자에게 원자료 업로드를 요청**한다(§2 참조).
4. 모델 ID·비밀키를 커밋/문서/채팅에 넣지 않는다. 커밋 트레일러 준수(CLAUDE.md).

## 1. 시작 질문 (인테이크) — MUST
스킬이 시작되면 **먼저 `AskUserQuestion`으로 요건을 받고** 진행한다. 사용자가 이미 명시한 항목은 건너뛰고, **빠진 것만** 묻는다. 한 번의 `AskUserQuestion` 호출에 필요한 질문을 묶어서(최대 4개) 낸다.

물어볼 항목:
1. **메인 키워드/진료과** — 예: 다이어트·비만 / 피부 / 성형 / 정형외과 / 치과 / 한방. (경쟁·키워드 검색어의 기준)
2. **지역 또는 주소** — 구/동 단위. 주소를 주면 시/도+시군구를 자동 추출.
3. **업체명(병원명)** — 있으면 실명 맞춤 제안서, 없으면 "일반형"(자리 비움).
4. **(선택) 목표·예산** — 목표(문의·예약 증가 / 인지도 / 검색유입) · 월 예산대(미정 가능).

- 각 질문 옵션에는 "직접 입력"이 자동 포함되므로, 대표 보기 2~4개만 제시(예: 진료과 보기, 목표 보기).
- **필수 2개(메인 키워드·지역)** 가 확보되면 즉시 §2로 진행. 업체명/예산은 없으면 일반형·표준안(월 200만 그로스)으로 기본값 처리.

### 입력 해석
- **회사명 + 주소** → 주소에서 **시/도 + 시군구(구)** 추출. 분석은 **구(區) 단위**, 그 병원을 제안서 **클라이언트(실명)** 로.
- **지역만(구/동)** → 구 단위 분석 + **일반형** 제안서(병원명 자리 비움).
- **진료과 미지정** → 기본 "다이어트·비만". 지정 시 해당 과로 키워드·경쟁 검색어 치환(진료과별 키워드 예시는 `references/data-collection.md`).
- 확정 후 `get_current_korean_time`으로 기준일 확보.

## 2. 데이터 수집 (4축) — 상세: `references/data-collection.md`
축별로 **실측 우선**, 막히면 총계+업로드 요청. Naver MCP 도구는 `ToolSearch`로 로드.

| 축 | 1차(자동) | 정밀(원자료 업로드 요청) |
|---|---|---|
| ① 인구·남녀·세대 | WebSearch로 구 총인구 | 행안부 주민등록 CSV(동별 성별) → 합산 |
| ② 병원 밀집도·종별 | WebSearch 총계 | 심평원 요양기관 명부 xlsx → 구 필터·종별 카운트 |
| ③ 의료 수요 | (선택) | 심평원 진료통계 CSV(주상병별 진료인원) → 비만/대사 코드 추출 |
| ④ 키워드·경쟁 | `datalab_search`(진료과 키워드 추이), `datalab_shopping_keyword_by_gender/age`, `search_local`(경쟁 상위·읍면동 밀집) | — |

- **CSV/xlsx는 cp949/utf-8 자동감지**로 파싱(파싱 스니펫은 data-collection.md). 성별·종별·진료코드 합산은 반드시 **교차검증**(남+여+외국인=총인구 등).
- 원자료가 없으면 사용자에게 **정확히 무엇을 어디서 받는지** 안내(행안부 jumin.mois.go.kr, 심평원 opendata.hira.or.kr)하고, 없는 항목은 🔴로 남긴다.

## 3. 산출물 생성 (4종)
1. **상권분석 리포트** (`references/templates.md`의 리포트 스켈레톤) — 4축 + 종합진단 + 부록(데이터 상태). 출처 3등급 표기.
2. **분석 PPT** (`assets/deck_template.js`) — 상단 `DATA` 객체만 채우면 되는 pptxgenjs 생성기. 표지→요약→인구(성별바)→병원 밀집도(종별 막대)→의료수요→경쟁→연령→키워드추이→전략→로드맵→출처. 빌드·검증은 §4.
3. **경쟁사 브리핑** — `search_local` 상위 5곳 + `venomad-proposal` STEP2 구조(주력채널·톤·강점·약점·공략점 + 포지셔닝 갭 3종).
4. **제안서** — `venomad-proposal` STEP3~5 + 예산배분(STEP4). 문서(md) + **1페이지 발표 슬라이드**(deck_template.js의 proposal 변형, templates.md 참조).

## 4. PPT 빌드·검증 (MUST 순서)
```bash
cd <scratchpad> && npm install pptxgenjs   # 최초 1회(미설치 시)
node deck.js
pip install -q defusedxml lxml Pillow markitdown[pptx] openpyxl python-pptx   # 최초 1회
python3 /root/.claude/skills/pptx/scripts/office/validate.py "<out>.pptx"      # PASS 필수
markitdown "<out>.pptx" | grep -iE "undefined|NaN|866|<stale>" || echo clean   # 스테일 수치 점검
```
- pptxgenjs 주의: 색상 `#` 금지·8자리 금지, `LAYOUT_WIDE`(13.3×7.5) 먼저 설정, 옵션객체 재사용 금지, 스택막대 `outEnd` 금지. 한글 폰트 `Malgun Gothic`.
- 이 샌드박스는 LibreOffice 렌더가 깨져 **이미지 시각 QA는 불가**할 수 있음 → validate PASS + markitdown 내용점검으로 대체하고 사용자에게 폰트/줄바꿈 확인 요청.
