# FlowLens 브레인스토밍 (대행사 MVP 의사결정)

작성일: 2026-07-14
목적: 리서치 결과를 바탕으로 "무엇을 먼저, 어디까지" 만들지 제품 결정을 확정한다.

---

## 1. "가치 증명 최소 루프"는 무엇인가

대행사가 FlowLens를 처음 켰을 때 **"오, 이거 고객 보고에 쓰겠다"** 를 느끼게 하는 최소 흐름:

> 고객사 사이트에 스크립트 한 줄 심음 → 몇 분 뒤 대시보드에 클릭 히트맵과 지표가 뜸 → 자동 생성된 한국어 개선 제안 3개가 보임 → 대행사 로고가 박힌 읽기전용 링크를 고객에게 전달.

이 한 문장이 MVP의 전부다. 나머지는 후순위.

## 2. 핵심 결정들 (선택지 → 결정)

### 결정 1: 세션 리플레이를 넣을까?
- 선택지: (A) rrweb 풀 리플레이 (B) 이벤트 타임라인만
- **결정: (B)**. 풀 리플레이는 저장 비용·민감정보 리스크·개발 공수가 크다. MVP는 "세션별 클릭/스크롤/이탈 타임라인"으로 충분히 인사이트 제공. 풀 리플레이는 2단계.

### 결정 2: 히트맵 범위
- **결정: 클릭 히트맵 + 스크롤 도달률**. 마우스 이동(무브) 히트맵은 데이터량이 크고 인사이트 대비 가치가 낮아 후순위. pointermove는 rage/dead click 판정용으로만 최소 수집.

### 결정 3: 인증/설치 인증 수준
- **결정: MVP는 siteKey 기반**. 스크립트에 발급된 siteKey가 있으면 수집. 도메인 화이트리스트(등록된 도메인에서 온 이벤트만 수집)로 도용 방지. DNS TXT/HTML 파일 인증은 2단계.

### 결정 4: 개선 제안 엔진
- **결정: 룰 엔진 우선, AI 문장화는 나중**. 결정론적 규칙으로 신뢰 확보. 룰 결과를 한국어 템플릿 문장으로 출력. LLM은 이후 "문장 다듬기" 역할로만.

### 결정 5: 결제
- **결정: MVP 코드베이스에는 요금제 데이터 모델과 사용량 제한(세션 수/보관기간)만 반영, 실제 PG 연동은 스텁**. 결제는 베타 유료화 시점에 붙인다.

### 결정 6: 기술 스택
- **결정: Next.js(App Router, TS) 단일 앱**이 대시보드 + 수집 API를 모두 담당. DB는 Prisma + SQLite(개발) → PostgreSQL(운영). 차트/히트맵은 외부 라이브러리 없이 SVG/Canvas 직접 구현(의존성·빌드 리스크 최소화).

## 3. 대행사가 매일 볼 화면 (정보 구조)

```
로그인
 └ 대행사 대시보드 (전체 고객사 한눈에)
     ├ 고객사 목록 + 각 사이트 핵심 지표(세션, 이탈, rage click, 개선제안 수)
     └ 사이트 상세
         ├ 개요 (핵심 지표 카드 + 추세)
         ├ 히트맵 (클릭 열지도 + 스크롤 도달률)
         ├ 세션 (최근 세션 타임라인 목록)
         ├ 개선 제안 (룰 엔진 결과, 신뢰도 배지)
         └ 설치 (스크립트 한 줄 + 설치 확인 상태)
     └ 리포트 / 공유
         └ 화이트라벨 읽기전용 공유 링크 생성
```

## 4. 무엇을 "일부러 안 만드는가" (MVP 스코프 컷)

명시적으로 제외 — 이게 출시 지연을 막는다:
- 완전한 DOM 세션 리플레이
- A/B 테스트
- 퍼널 빌더 (2단계)
- 실시간 스트리밍 집계 (MVP는 요청 시 집계 or 단순 주기 집계)
- 실제 PG 결제
- GTM/Shopify/WordPress 자동설치 (MVP는 "스크립트 한 줄" + 설치 가이드만)
- 팀 초대/세밀한 RBAC (MVP는 OWNER/MEMBER 2종)
- 이메일 발송, 알림

## 5. 데모 시나리오 (완성 시 이렇게 보여준다)

1. `대행사 계정`으로 로그인 → 데모 고객사 2곳(쇼핑몰/병원), 사이트 3개가 이미 있음(시드 데이터).
2. 한 사이트를 열면 수천 개의 (가짜) 이벤트로 만들어진 **실제 클릭 히트맵**과 지표가 뜬다.
3. "개선 제안" 탭에 **한국어 개선 과제 3~5개**가 신뢰도 배지와 함께 표시된다.
4. "설치" 탭에서 **스크립트 한 줄**을 복사, 로컬 데모 페이지에 붙이면 실시간으로 새 이벤트가 수집됨을 확인.
5. "공유" 탭에서 **화이트라벨 읽기전용 링크**를 만들어 새 탭에서 열면 대행사 로고가 박힌 고객용 리포트가 계정 없이 보인다.

이 5단계가 그대로 돌아가면 "실제 서비스가 가능함"이 증명된다.

## 6. 브레인스토밍 결론

MVP = **멀티테넌시 뼈대 + 추적 SDK + 수집 API + 클릭/스크롤 히트맵 + 룰 엔진 개선 제안 + 화이트라벨 공유 링크**.
나머지는 전부 후순위. 다음 문서(기획)에서 이 범위를 데이터 모델·API·화면 단위로 확정한다.
