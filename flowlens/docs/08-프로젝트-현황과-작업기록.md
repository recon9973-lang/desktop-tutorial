## 1. 한 줄 요약

**FlowLens** — 웹사이트 방문자의 클릭·마우스이동·스크롤을 분석해 **무엇을 고쳐야 하는지** 알려주는 행동 분석 SaaS.
**대행사(에이전시)가 여러 고객사를 관리**하는 구조. 개인정보(IP·입력값)를 수집하지 않는 것이 설계 원칙.

## 3. 기능 구성

### 대시보드 (대행사)
- **개요** — 세션·이탈률·모바일 비중·전환
- **히트맵 (5종)** — 클릭맵 / 무브맵 / 셀렉터 / 스크롤맵 / 제스처
  - 배경 = **실제 사이트 화면**(기기별 자동 캡처), 기간 필터(전체/7/30/90일)
  - 진하기 슬라이더 · 집중(딤) 모드
- **퍼널 · 세션 리플레이 · 전후 비교 · 개선 제안 · 설치/공유 · 데이터 관리**

### 랜딩 (잠재고객)
- **무료 진단** — URL 입력 → 페이지 점검 + **실제 화면 위 데모 히트맵** + **플랫폼 자동 감지**

### 시각화 규칙 (리서치 근거: Clarity/Hotjar/Crazy Egg)
- **클릭맵 = 컬러** 열지도 (파랑→초록→노랑→빨강)
- **무브맵 = 블랙** 궤적(곡선) + 체류 점
- 배경은 **원색 유지** (블러·무채색 안 씀), 가독성은 **오버레이 투명도**로 조절

## 5. ⚠️ 반드시 알아야 할 함정 (하드코딩된 교훈)

이 프로젝트에서 **실제로 사고가 났던** 것들. 잊으면 또 당합니다.

### ① GTM은 `data-site` 속성을 지운다
GTM 맞춤HTML로 넣으면 `data-*` 속성이 **제거**되어 추적이 조용히 실패.
→ **GTM에서는 반드시 `?site=KEY`** 형태를 쓸 것. (`t.js`는 data-site / `window.FLOWLENS_SITE` / `?site=` 3경로 지원)

### ② 사이트에 실제 붙어있는 GTM 컨테이너를 확인할 것
good-tour.kr은 `GTM-PVL5HQDD`가 아니라 **`GTM-NGPZ4BF2`** 였음. 엉뚱한 컨테이너에 넣으면 아무 일도 안 일어남.
→ 확인법: 페이지 소스에서 `GTM-` 검색.

### ③ Vercel 함수 기본 리전은 미국(iad1)
DB가 싱가포르인데 함수가 미국이면 **요청마다 태평양 왕복** → 704ms.
→ `vercel.json`에 **`"regions": ["sin1"]`** 지정 → **121ms (6배 개선)**.
→ 진단법: `x-vercel-id` 가 `엣지::함수리전::id` 형식 (`icn1::sin1::...`).

### ④ 마우스 이동을 낱개 이벤트로 저장하면 적자
90ms 샘플링 = 세션당 400건 → **세션당 150KB** → 에이전시 30곳이면 **월 $400**.
→ **세션·페이지별 "경로 1줄"**(`MovePath`, `"x,y|x,y|…"`)로 저장 → **8KB (19배↓)**, 월 $10.

### ⑤ `prisma db push`가 파괴적 변경을 요구할 때 `--accept-data-loss`를 쓰지 말 것
unique 인덱스 변경·추가 시 발생. 그 플래그를 빌드에 넣으면 **이후 모든 배포에서 데이터가 조용히 날아갈 수 있음**.
→ **Neon SQL로 수동 실행** 후 배포(그러면 db push가 in-sync로 통과). 전례:
```sql
-- Screenshot에 device 추가 시 실제로 사용한 SQL
ALTER TABLE "Screenshot" ADD COLUMN IF NOT EXISTS "device" TEXT NOT NULL DEFAULT 'DESKTOP';
DROP INDEX IF EXISTS "Screenshot_siteId_path_key";
CREATE UNIQUE INDEX IF NOT EXISTS "Screenshot_siteId_path_device_key" ON "Screenshot"("siteId","path","device");
```

### ⑥ 일부 한국 사이트는 해외 IP의 일반 fetch를 WAF로 차단
good-tour.kr은 우리 서버(싱가포르)의 `fetch`에 **빈 페이지를 200으로** 반환 → 진단이 "분석도구 없음·33점"이라는 **틀린 결과**를 냄.
(헤드리스 크롬은 통과, 일반 fetch는 UA를 바꿔도 차단 — TLS 지문 차이 추정)
→ **틀린 점수 대신 정직한 실패**로 처리 중.

### ⑦ Prisma `Bytes`는 `Uint8Array<ArrayBuffer>` 요구
`Buffer`를 그대로 넣으면 TS 에러 → `Uint8Array.from(buf)`.

### ⑧ 캐시된 이미지는 `onLoad`가 안 뜬다
기기 전환 시 배경 비율이 갱신 안 돼 **이미지 아래 빈 스크롤**이 생김.
→ `useEffect([bgUrl])`에서 `img.complete`면 `naturalWidth/Height`를 직접 읽어 재계산.

### ⑨ `meta` 필드는 300자로 잘린다
보안상 allowlist + 길이 제한. 큰 데이터(좌표 경로 등)는 **전용 컬럼/테이블**로.

### ⑩ CTA 탐지를 CSS 클래스 관례에 의존하면 지표가 조용히 거짓말한다
`ctaViewRate`(= `cta_view`/`page_view`)는 **impact 5짜리 `mobile-cta` 제안의 유일한 근거**다.
과거 `t.js`는 CTA 후보를 `"button, a.btn, .cta, [data-cta]"` 로만 찾았는데, **이 클래스 관례를 안 쓰는 사이트가 대부분**이다.
good-tour.kr 실측: 이 셀렉터에 걸린 건 **헤더의 30×25 검색 돋보기 아이콘 1개뿐**. 진짜 CTA("나도 울릉도여행 문의하기", "여행문의", "고객상담 010-…") 8개는 **평범한 `<a>`** 라 전부 누락.
그 아이콘은 첫 화면에 항상 보이므로 → 노출률이 **항상 ~100%** → `ctaViewRate < 40` 이 영영 거짓 → **제안이 절대 안 뜬다(조용한 거짓 음성).**
반대로 셀렉터에 0개 걸리는 사이트에서는 노출률 0% → **근거 없는 제안이 최상단에 뜬다(거짓 양성).**
→ **텍스트·크기로 판정**한다 (`isCta()`). 확정된 세부 교훈:
- **`.btn` 을 CTA 근거로 쓰면 안 된다** — 로그인·쿠키동의 버튼에도 똑같이 붙는 범용 스타일 클래스다. (`.cta`·`[data-cta]`는 의도 선언이므로 신뢰 OK, `type=submit`도 OK)
- **영어 키워드는 반드시 `\b` 단어경계로 감쌀 것** — 없으면 `Facebook`의 `book`, `restart`의 `start`, `border`의 `order`가 걸려 푸터 SNS 링크가 CTA가 된다.
- **최소 크기(60×24) 미만·글자 없는 요소는 배제** — 아이콘 버튼 오인 방지.
- **스캔은 1회로 끝내면 안 된다** — GTM은 DOM이 비어있는 초반에 스크립트를 넣기도 하고, 버튼이 비동기로 나중에 그려지기도 한다. → `DOMContentLoaded`·`load` + `MutationObserver`(디바운스, 30초 후 해제).
> 참고: `cta_click` 이벤트는 집계·퍼널 코드가 조회하지만 **`t.js`가 한 번도 발생시키지 않는다**(죽은 코드). 추가하려면 `getHeatmapPoints`가 `click`과 `cta_click`을 모두 읽어 **같은 클릭이 두 번 찍히지 않도록** 먼저 정리할 것.

### ⑩-2 `ctaViewRate` 계산식 자체가 틀렸었다 (⑩을 고쳐도 제안이 안 뜨던 이유)
```js
ctaViewRate: Math.min(100, pct(ctaViews, pageViews))  // ← min(100,…)이 이미 자백이다
```
**cta_view 이벤트 수 ÷ page_view 수.** 한 화면에 CTA가 3개 보이면 페이지뷰 1건에 cta_view 3건 → **300% → 100%로 잘림.**
즉 **화면에 CTA가 하나라도 늘 보이는 사이트는 노출률이 항상 100%** → `ctaViewRate < 40`인 `mobile-cta`는 **영영 안 뜬다.**
⑩에서 CTA를 1개→8개로 잘 찾게 만들면 **오히려 100%가 더 확실해진다**(고치면 더 나빠지는 함정).
→ **세션 단위로 교체**: `CTA를 1개 이상 본 세션 ÷ 전체 세션`. 같은 파일 `formStarts`가 쓰던 `distinct:["sessionId"]` 방식 그대로.
지표 이름("CTA 노출률 = 방문자 중 몇 %가 핵심 버튼을 봤나")과도 이제 일치한다.

### ⑩-3 IntersectionObserver는 "가려짐"을 모른다 + 고정 레이어 클릭은 좌표가 흩어진다
- **가려짐**: IO는 *화면 영역 안에 있나*만 본다. **팝업이 새까맣게 덮은 CTA도 노출 100%로 보고**한다(대조군 실험으로 확인).
  → `document.elementFromPoint(중심점)`으로 실제로 뭐가 위에 있는지 확인. 가려졌으면 보류했다가 **팝업이 닫히면 그때 기록**(IO는 스크롤 없으면 재발화하지 않으므로 2초 주기 재확인).
  판정이 애매하면 **"보였다" 쪽으로 기울일 것** — 과소집계는 없는 문제를 있다고 하는 오진을 만든다.
- **고정 레이어 클릭**: `position:fixed/sticky` 안의 클릭을 문서 좌표(`pageY = clientY + scrollY`)로 환산하면 **같은 버튼이 스크롤 위치에 따라 히트맵의 딴 곳에 찍힌다**(맨 위에서 누르면 9%, 중간에서 누르면 99%). → 좌표를 보내지 않는다(`meta:{fixed:1}`). 좌표가 null이면 `getHeatmapPoints`(xRel not null)에서 자동 제외되고 클릭 수·라벨은 남는다.
> ⚠️ **팝업이라고 다 fixed가 아니다.** good-tour.kr의 팝업은 `position:absolute`(문서에 박힘, pageY 고정)라 좌표가 흩어지지 않고, **배경 스크린샷에도 팝업이 같이 찍혀 위치가 오히려 맞는다.** 실제 fixed는 **상단 헤더(`div.hd_wrap`)와 우측 상담 배너(`div.favorite`)** 였다. 추측하지 말고 `getComputedStyle`로 확인할 것.

### ⑩-4 좌표를 빼면 셀렉터 랭킹에서도 사라진다 (⑩-3이 만든 회귀)
⑩-3에서 고정 레이어 클릭의 좌표를 안 보내게 했더니, **상단 헤더·상담 배너 클릭이 `셀렉터` 탭("가장 많이 클릭된 요소")에서도 사라졌다.**
원인: 셀렉터 랭킹이 `getHeatmapPoints`(= `xRel not null`)를 재사용하고 있었다. **랭킹은 라벨만 있으면 되는데 좌표를 요구**한 것.
→ `getClickLabels()` 분리 (좌표 조건 없음). 히트맵은 좌표가 있어야 점을 찍으니 그대로 두고, "무엇을 눌렀나" 목록은 전부 보여준다.
> 교훈: **데이터를 한 곳에서 빼면 그 데이터를 쓰던 다른 화면도 같이 죽는다.** 조회 함수를 재사용할 땐 "이 화면이 정말 이 조건을 필요로 하나"를 확인할 것.

### ⑩-5 배경의 팝업이 "뒤에 뭘 클릭했는지"를 가린다 → 팝업 닫고 캡처(선택)
팝업이 히어로·CTA를 덮으면 그 자리의 점들이 **"팝업을 누른 건지 뒤 내용을 누른 건지" 구분이 안 되고, 애초에 뒤에 뭐가 있는지 안 보인다.**
good-tour.kr 실측: 팝업을 치우니 **보라색 CTA "여행 패키지 신청하기"** 와 히어로 문구·메뉴 아이콘이 드러났다. **팝업이 CTA를 덮고 있었다.**
→ **"팝업 닫고 캡처" 버튼**(선택). 기본은 방문자가 실제로 본 화면 그대로 둔다.
- 정의: **"닫기/오늘 하루 열지 않기 같은 컨트롤을 품은 위치지정 레이어" = 팝업.** good-tour에서 `#popup11`·`#popup12`만 정확히 잡히고 헤더·히어로·푸터는 그대로 남는 걸 확인.
- **클릭하지 말고 `display:none` 으로 숨길 것** — 닫기가 `<a>`인 사이트가 많아 클릭하면 페이지가 넘어간다.
- 숨긴 뒤에도 **팝업 클릭은 여전히 그 자리에 찍힌다.** 무엇을 눌렀는지는 `셀렉터` 탭에서 라벨(`닫기` 등)로 구분한다(⑩-4 덕분에 좌표 없는 것도 보인다).
- `page.evaluate(fn)`은 함수를 **문자열로 직렬화해 브라우저에서 실행**한다 → 바깥 변수를 참조하면 깨진다. 컴파일 결과가 self-contained인지 확인할 것(실제로 확인함).

### ⑬ 개인정보 미수집 약속을 깨던 3곳 (보안감사 MEDIUM — 영업 1번 무기라 우선 처리)
"입력값·IP 미수집"이 이 제품의 핵심 약속인데 실제로 새는 경로가 있었다.
- **M14 contenteditable 입력값 유출** — `labelOf`가 input/textarea/select만 값 미접근으로 처리하고, **리치 에디터·일부 검색창(contenteditable div)에 친 글은 textContent로 그대로** targetLabel에 담겼다. → `el.isContentEditable`면 `[edit]`로 대체(자식 span에서도 true). 일반 라벨은 유지(브라우저 실측 확인).
- **M17 수집제외(.fl-sensitive)가 6단계까지만** — 깊은 DOM에서 무시됨("무조건 미수집" 위반). → 뿌리(body)까지, 상한 40으로.
- **M7 미래 타임스탬프로 보관기간 회피** — collect가 클라이언트 `e.ts`를 그대로 저장 → 미래 시각을 넣으면 cleanup의 `ts < cutoff`에 영영 안 걸려 데이터가 안 지워진다. → `safeTs()`로 미래(+시계오차 60초 허용)·30일 초과 과거는 서버 시각으로 대체. Event·MovePath 양쪽 적용.
> 남은 MEDIUM(미착수): 공유링크 revoke(M2), 비번변경 시 세션 무효화(M4), 계정단위 로그인 잠금(M5), 세션 리플레이 요금제 게이팅(M13), SSRF 심층방어(M8~11) 등. 상세는 이 세션 전수조사 결과.

### ⑫ 수집 창구(/api/collect)는 siteKey 공개값에 의존하는 사실상 무인증 쓰기 API였다 (보안감사 HIGH)
전수조사에서 나온 최상위 리스크. **한 뿌리에서 HIGH 4건**이 나왔다.
- **fail-open 도메인 검증** — `hostAllowed`가 Origin/Referer 헤더 부재 시 `return true` 였다. curl 등 비브라우저는 헤더를 생략할 수 있어 검증이 통째로 무력화. 게다가 `d.endsWith("."+h)` 역방향 매칭 탓에 `Origin: http://com` 으로도 우회됐다.
  → **fail-closed** (`!reqHost → return false`), 역방향 매칭 제거. 정상 추적기는 브라우저에서 돌아 Origin이 항상 붙으므로 진짜 방문자엔 영향 없음(로컬에서 ①헤더없음 202무시 / ③정상Origin 200저장 실측 확인).
- **rate limit 전무** — siteKey는 공개값이라 아무나 위조 이벤트를 대량 주입 → 데이터 오염 + 가짜 세션으로 요금제 쿼터 고갈(FREE 500세션이면 몇 초 만에 그 달 수집 정지) + DB 무한 부풀리기.
  → `src/lib/ratelimit.ts` 신설(DB 카운터 고정윈도우, 서버리스라 메모리 불가). collect는 IP·siteKey당 10초 20요청. 요청당 이벤트 100개 상한도 추가. 로컬 실측: 20건 후 429, 101개 이벤트 413.
- **캡처 남용**(HIGH·별건) — `/api/sites/[id]/screenshot`은 인증은 있으나 횟수 제한이 없어 계정 하나로 헤드리스 크롬 비용을 태울 수 있었다. → 대행사당 1분 10회 제한. (무료 진단 경로 `/api/diagnose/screenshot`은 이미 IP당 1회 제한이 있었음 — 로그인 경로만 누락이었다.)
> ⚠️ **RateLimit은 새 테이블이라 배포 때 `prisma db push`가 자동 생성한다. 함정 ⑤(unique 인덱스)와 달리 파괴적 경고가 없어 Neon 수동 SQL 불필요.**
> 남은 근본책(보류): siteKey 공개값 대신 t.js 발급 시 단기 서명 토큰. rate limit + fail-closed로 급한 불은 껐다.
> 아직 안 고친 감사 지적(MEDIUM 24 / LOW 19): CRON_SECRET 미설정(자동삭제 안 돎), 세션 쿠키 무효화 불가, 계정단위 로그인잠금 없음, 공유링크 revoke 없음, contenteditable 입력값 수집, 개인정보처리방침 공란, 요금제 서버측 게이팅 일부 누락 등. 상세는 이 세션 전수조사 결과 참조.

### ⑪ `alert()` 한 줄이 헤드리스 크롬을 영원히 멈춘다 (+ 쿼리 없는 경로는 배경을 못 만든다)
good-tour.kr 히트맵 배경이 "캡처 중…"에서 안 넘어가던 원인. `POST /api/sites/[id]/screenshot` 이 **500**이었다.
원인: 추적기는 개인정보 보호로 **쿼리를 떼고 `location.pathname`만** 저장한다. 그런데 상세페이지는 쿼리가 있어야 열린다.
`https://good-tour.kr/product/prodDetail.php` (쿼리 없음) → 서버가 **105바이트**짜리 이걸 준다:
```html
<script>alert('잘못된 접근 방식입니다.');location.replace('/');</script>
```
**헤드리스 크롬엔 확인 버튼을 눌러줄 사람이 없어 `page.goto()`가 끝나지 않는다** → 45초 타임아웃 → 500 → UI는 "캡처 중…"으로 영원히 거짓말.
실측: `/`·`/product/prodList.php` ✅ / `prodDetail`·`boardView`·`prodOrder` ❌ (쿼리 필요한 페이지 전부)
→ 조치:
- **`page.on("dialog", d => d.dismiss())` 필수.** 이거 하나로 45초 멈춤 → 5초. 경고창 띄우는 모든 사이트에 해당.
- **`waitUntil: "networkidle2"` 를 믿지 말 것** — 채팅위젯·폴링 트래커가 있으면 영영 안 온다. `domcontentloaded` + `waitForNetworkIdle(...).catch(()=>{})`로.
- **도착지 검증**: 경고창을 닫으면 이제 홈(`/`)·목록(`/board/boardList.php`)으로 튕긴 화면이 찍힌다. 그걸 배경으로 저장하면 **상세페이지 클릭을 홈 그림 위에 뿌리는 거짓말**이 된다 → 경로가 다르면 **422로 거부하고 배경 없이 표시**(5-⑥ "정직한 실패" 원칙). 경로 비교는 `normPath()`로 정규화(`//a/b/` = `/a/b`).
- UI는 "다시 시도해 주세요"로 뭉개지 말 것 — 재시도해도 절대 안 되는 실패다. 버튼을 감추고 이유를 설명한다.
> 남은 과제: `/product/prodDetail.php` 클릭 20건은 **서로 다른 상품이 뭉친 것**이라 배경 이전에 히트맵의 의미 자체가 흐리다. "이 경로의 배경은 이 주소로 찍어라"를 **직접 지정하는 기능**이 필요하다.
