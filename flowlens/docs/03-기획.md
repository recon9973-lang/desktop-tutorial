# FlowLens MVP 기획서 (개발 착수용)

작성일: 2026-07-14
대상 독자: 개발자 (이 문서 + 코드베이스만으로 개발 지속 가능)
스택: Next.js 15 (App Router, TypeScript) · Prisma · SQLite(개발)/PostgreSQL(운영) · Canvas/SVG

---

## 1. 시스템 구성도

```
[고객사 웹사이트] --tracker.js--> [FlowLens 수집 API] --> [DB]
                                                          |
[대행사] --로그인--> [Next.js 대시보드] <----집계/룰엔진----+
                                     |
                                     └--화이트라벨 공유링크--> [고객사]
```

- **tracker.js**: 정적 파일. 고객 사이트에 삽입되는 추적 SDK. (`public/t.js`)
- **수집 API**: `POST /api/collect` — 이벤트 배치 수신, siteKey 검증, 저장.
- **대시보드**: 대행사용 인증 화면들.
- **공유 링크**: `/share/[token]` — 인증 없이 열람하는 화이트라벨 리포트.

## 2. 데이터 모델 (Prisma)

```
User      id, email, name, passwordHash, agencyId, role(OWNER|MEMBER)
Agency    id, name, logoText, plan(FREE|STARTER|GROWTH|AGENCY)
Client    id, agencyId, name, industry(ECOMMERCE|CLINIC|EDU|B2B|ETC)
Site      id, clientId, name, domain, siteKey(unique), createdAt, retentionDays
Session   id, siteId, sessionKey, device(MOBILE|DESKTOP|TABLET),
          referrer, startedAt, lastEventAt, maxScrollPct, pageCount, isBounce
Event     id, siteId, sessionId, type, url, path, xRel, yRel, vw, vh,
          scrollPct, targetLabel, meta(json), ts
ShareLink id, siteId, token(unique), createdAt, expiresAt, active
```

이벤트 타입(enum 아님, string):
`page_view · click · rage_click · dead_click · scroll · pointer_sample · form_focus · form_submit · cta_view · cta_click · conversion · session_end`

### 수집 원칙(모델 레벨)
- 좌표는 **xRel/yRel = 0~1 상대값** (문서 폭/높이 대비). 절대 픽셀 미저장.
- `targetLabel`은 클릭 대상의 짧은 텍스트/셀렉터. **전송 전 SDK에서 마스킹** 후에만 저장.
- 폼 입력값 컬럼 자체가 없음. IP 컬럼 없음.

## 3. 추적 SDK 스펙 (`public/t.js`)

설치:
```html
<script async src="https://app.flowlens.kr/t.js" data-site="SITE_KEY"></script>
```

수집 동작:
- 로드 시 `page_view` 전송, `sessionKey`(sessionStorage, 30분 만료) 생성.
- `click`: 상대 좌표 + 마스킹된 대상 라벨. 300ms 내 같은 위치 3회+ → `rage_click`. 클릭 대상이 링크/버튼이 아니고 아무 반응 없음 → `dead_click` 후보.
- `scroll`: throttle 250ms, 세션 최대 스크롤% 갱신.
- `pointermove`: throttle 200ms 샘플만(`pointer_sample`), rage/dead 판정 보조용, 저장은 최소화.
- 배치: 이벤트를 큐에 모아 5초마다 또는 20개 쌓이면 전송. `visibilitychange(hidden)` / `pagehide` 시 `sendBeacon`으로 잔여 flush + `session_end`.
- **개인정보**: `input,textarea,select,[type=password]` value 접근 금지. 라벨 텍스트는 전송 전 정규식 마스킹(이메일·전화·카드·주민번호).
- **봇 제외**: `navigator.webdriver` true면 수집 중단.

## 4. API

| 메서드 | 경로 | 설명 | 인증 |
|---|---|---|---|
| POST | `/api/collect` | 이벤트 배치 수신·저장 | siteKey(+도메인 검증) |
| POST | `/api/auth/login` | 로그인(쿠키 세션) | 이메일/비번 |
| POST | `/api/auth/logout` | 로그아웃 | 세션 |
| GET | `/api/sites/:id/overview` | 사이트 지표 요약 | 세션(agency 범위) |
| GET | `/api/sites/:id/heatmap` | 히트맵 좌표 집계 | 세션 |
| POST | `/api/sites/:id/share` | 공유 링크 생성 | 세션 |
| GET | `/api/health/:siteKey` | 설치 확인(첫 이벤트 여부) | siteKey |

대시보드 페이지들은 서버 컴포넌트에서 Prisma로 직접 조회(별도 REST 최소화). 위 표는 외부(스크립트/공유)와의 경계 API 중심.

## 6. 룰 엔진 (개선 제안)

입력: 사이트 집계 지표(세션 수, 디바이스 분포, CTA 노출/클릭, 스크롤 도달률, rage/dead click 수, 폼 시작/제출).
규칙 예시 (코드 `lib/rules.ts`):

| 규칙 | 조건 | 제안 문구(한국어) |
|---|---|---|
| 모바일 CTA | 모바일 비중>50% & CTA노출률<40% | "모바일 방문자 다수가 핵심 버튼을 보기 전에 이탈합니다. 첫 화면 고정 CTA를 추가하세요." |
| Dead click | dead_click 비율>5% | "클릭되지 않는 요소를 반복 클릭하는 방문자가 있습니다. 해당 영역을 실제 버튼/링크로 만드세요." |
| Rage click | rage_click 발생 | "특정 요소에서 좌절 클릭(rage click)이 감지됩니다. 반응 속도나 클릭 영역을 점검하세요." |
| 스크롤 이탈 | 50% 도달률<40% | "방문자 다수가 페이지 중반 이전에 이탈합니다. 핵심 메시지를 상단으로 올리세요." |
| 폼 이탈 | 폼시작 대비 제출<30% | "폼을 시작한 방문자의 이탈이 큽니다. 입력 항목을 줄이거나 단계로 분리하세요." |

각 제안은 `confidence`(HIGH/MEDIUM/LOW, 세션 수 기준)와 `impact`(추정 우선순위)를 함께 출력.

## 8. 개발 순서 (본 코드베이스 구현 순서)

1. 프로젝트 스캐폴딩(Next.js+TS+Prisma), 스키마, 시드
2. 추적 SDK(`t.js`) + 수집 API
3. 대시보드 개요 + 사이트 상세
4. 히트맵(Canvas) + 스크롤 도달률
5. 룰 엔진 + 개선 제안 화면
6. 설치 확인 + 화이트라벨 공유 링크
7. 데모 페이지로 end-to-end 수집 검증

## 9. 운영 전환 메모(SQLite→PostgreSQL)

- `prisma/schema.prisma`의 `provider = "sqlite"` → `"postgresql"` + `DATABASE_URL` 교체, `Json`/타입 확인 후 `prisma migrate`.
- 이벤트 테이블이 커지면 `Event`만 ClickHouse로 분리하고 집계 쿼리를 이관.
- 인증은 MVP의 단순 쿠키 세션 → NextAuth/OAuth로 교체.
