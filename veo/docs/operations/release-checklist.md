# 릴리스 체크리스트

배포 전에 이 문서를 위에서 아래로 통과시킵니다.

**§1 출시 차단 항목(Launch Blockers)은 하나라도 걸리면 배포하지 않습니다.**
협의 대상이 아니고, 일정 압박으로 넘길 수 있는 항목도 아닙니다.
이 여덟 가지는 전부 "VEO 가 고객에게 거짓말을 하게 되는" 경로이고,
그 신뢰는 한 번 깨지면 회복되지 않습니다.

---

## 1. 출시 차단 항목 — 하나라도 걸리면 중단

### B-1. 하드코딩된 점수

점수는 **명세(spec) + 관측된 근거**에서만 나옵니다.
코드 안에 박힌 상수 점수, 데모용 고정값, "일단 이렇게 보이게" 만든 값이
하나라도 남아 있으면 배포 금지입니다.

- [ ] 점수를 만들어내는 경로에 리터럴 상수가 없다
- [ ] 모든 점수가 `packages/scoring-specs` 의 명세를 거쳐 계산된다
- [ ] 골든 케이스(`packages/scoring-specs/golden/`)가 전부 통과한다
- [ ] 데모·목업용 시드 데이터가 운영 경로에 섞이지 않았다

```bash
make test-api      # 골든 케이스 포함
```

### B-2. 제공자 데이터 날조

자격증명이 없거나 호출이 실패했을 때 **그럴듯한 값을 지어내지 않습니다.**
`ProviderState.DISABLED_NO_CREDENTIAL` 은 정상 상태이고, 그때의 올바른
출력은 UNKNOWN 입니다.

- [ ] 제공자 미설정 상태에서 전체 스캔을 돌렸을 때 숫자가 지어지지 않는다
- [ ] 실패·타임아웃·회로차단 시 UNKNOWN 으로 보고하고 사유를 함께 준다
- [ ] 추정치·보간값·기본값이 실측값과 같은 자리에 표시되지 않는다
- [ ] `GET /providers` 가 실제 상태를 그대로 보고한다

```bash
# 모든 제공자 키를 비운 상태로 기동해 확인한다
```

### B-3. N/A 를 실패로 취급

"측정 불가"와 "검사 실패"는 **다른 사실**입니다.
해당 요소가 없어서 검사할 수 없는 것을 감점하면 점수가 거짓이 됩니다.

- [ ] `ValueQuality.MISSING` / `SUPPRESSED_BY_PROVIDER` /
      `BELOW_PROVIDER_THRESHOLD` 가 FAIL 로 환산되지 않는다
- [ ] N/A 항목이 점수 분모에서 정확히 제외된다
- [ ] 0 과 "데이터 없음"이 화면과 API 양쪽에서 구분된다
- [ ] N/A 비율이 높을 때 그 사실이 리포트에 드러난다
      (모르는 게 많은데 점수만 높게 나오면 안 된다)

### B-4. 추적 불가능한 점수 계산

**"이 점수가 왜 이렇게 나왔는가"에 답할 수 없으면 그 점수는 못 씁니다.**

- [ ] 모든 점수 결과에 `scoring_spec_id`·`version`·`checksum` 이 붙는다
- [ ] 각 검사 결과에 근거(evidence)가 연결돼 있다
- [ ] 같은 입력 + 같은 명세로 재계산하면 같은 점수가 나온다
- [ ] 로그에 점수 산출 이벤트가 상관관계 ID 와 함께 남는다
      (`infra/monitoring/logging.md` §2.3)
- [ ] 명세가 바뀌면 과거 결과가 조용히 바뀌지 않는다 (버전 고정)

### B-5. 테넌트 간 데이터 유출

**단 한 건이라도 발생하면 사업이 끝나는 종류의 사고입니다.**

- [ ] 조직 범위 데이터를 읽는 모든 쿼리에 `organization_id` 필터가 있다
- [ ] 다른 조직의 리소스 ID 를 직접 넣었을 때 404/403 이 나온다
      (존재 여부조차 알려주지 않는다)
- [ ] 잡·리포트·서명 URL·캐시 키가 조직 경계를 넘지 않는다
- [ ] 캐시 키에 `organization_id` 가 포함돼 있다
- [ ] 교차 테넌트 접근 테스트가 CI 에서 돈다
- [ ] 로그의 `organization_id` 로 사후 검증이 가능하다

### B-6. SSRF 우회

크롤러와 렌더러는 **고객이 준 임의의 URL** 을 엽니다.

- [ ] 리디렉션 **매 홉마다** 최종 IP 를 재검사한다 (DNS rebinding 방어)
- [ ] 한 호스트가 공인 IP 와 사설 IP 를 함께 반환할 때 거부한다
- [ ] IPv4 매핑 IPv6(`::ffff:127.0.0.1`), NAT64(`64:ff9b::/96`),
      CGNAT(`100.64.0.0/10`), 링크로컬(`169.254.0.0/16`) 이 전부 차단된다
- [ ] `http`/`https` 외 스킴이 거부된다
- [ ] 허용 포트 목록 밖의 포트가 거부된다
- [ ] 렌더러 컨테이너가 `veo-renderer` 네트워크에만 붙어 있다
      (`veo-backend` 에 붙어 있으면 배포 금지)
- [ ] 렌더러에서 `postgres`·`redis`·`minio`·메타데이터 엔드포인트로
      **실제로 접속을 시도해** 실패하는지 확인했다
- [ ] 애플리케이션 계층 검증이 살아 있다 (네트워크 분리는 대체재가 아니다)

### B-7. GEO 준비도와 관측 결과 혼합

이 둘은 **성격이 다른 정보**입니다.

- **GEO 준비도(readiness)**: 우리가 사이트를 보고 판정한 구조적 준비 상태.
  재현 가능하고 결정적입니다.
- **GEO 관측(observation)**: 특정 시점에 특정 AI 엔진이 실제로 뭐라고
  답했는지. 같은 질문에도 매번 달라질 수 있습니다.

섞으면 고객은 "우리가 통제할 수 있는 것"과 "관측된 현상"을 구분하지
못하게 되고, 개선 행동을 잘못 고릅니다.

- [ ] 준비도 점수에 관측 결과가 가중치로 들어가지 않는다
- [ ] 화면·리포트·API 응답에서 두 영역이 시각적·구조적으로 분리돼 있다
- [ ] 관측 결과에 **관측 시각·엔진·모델·질의문**이 함께 표시된다
- [ ] 관측의 변동성이 사용자에게 설명돼 있다
      (한 번의 관측을 확정된 사실로 읽게 두지 않는다)
- [ ] 관측 원본은 로그가 아니라 통제된 스토리지에 있다
      (`logging.md` §3.4)

### B-8. 출처·시점 없는 네이버 수치

- [ ] 모든 네이버 수치에 `SourceAttribution`(출처·수집시각·기간)이 붙는다
- [ ] **검색광고 API 의 절대 검색량**과 **데이터랩의 상대 관심도 지수**가
      명확히 구분된다
- [ ] 데이터랩 지수가 "검색 횟수"로 표기된 곳이 **한 군데도** 없다
- [ ] 두 출처의 값을 하나의 숫자로 합치거나 평균 내지 않는다
- [ ] 캐시된 값에 원본 수집 시각이 그대로 유지된다
      (캐시 조회 시각이 아니라)
- [ ] 데이터 기준 기간(`source_period`)이 화면에 보인다

> 데이터랩 지수는 상대값입니다. 이걸 검색량처럼 보여주는 순간 고객은
> 없는 숫자를 근거로 예산을 씁니다. 이건 버그가 아니라 허위 정보입니다.

### B-9. 빌드를 돌리지 않은 채 "됐다" 고 말하기

**타입체크·테스트·린트가 통과해도 빌드는 깨질 수 있다.** 실제로 그랬다 — Next.js 16 이
`middleware` 규약을 `proxy` 로 바꿨는데 둘 다 존재해서 빌드가 거부했고, 그 오류는
`next build` 에서만 난다. 앞의 셋은 전부 초록이었다.

그때 빌드를 돌리는 곳은 Vercel뿐이었고 Vercel 은 **이미 배포한 뒤**에 실패한다.
화면은 옛 코드로 남고, 고쳤다고 말한 기능은 실제로 없는 상태가 된다.

- [ ] `pnpm --filter @veo/web verify` 가 통과한다 (타입체크·린트·테스트·**빌드**)
- [ ] CI 의 `웹 · 빌드까지` 작업이 초록이다
- [ ] 배포 후 **바뀐 화면을 실제로 열어** 확인했다. Deployments 목록의 `Ready` 는
      빌드가 끝났다는 뜻일 뿐, 내가 만든 것이 거기 있다는 뜻이 아니다

```bash
pnpm --filter @veo/web verify
```

## 3. 데이터베이스

**마이그레이션은 사람이 치지 않는다.** `railway.json` 의 `preDeployCommand` 가 새 판이
트래픽을 받기 **전에** `alembic upgrade head` 를 돌린다. 그러려면 마이그레이션 파일이
이미지 안에 있어야 하고, `tests/release/test_migrations_ship_with_the_image.py` 가
그 세 조각(설정·본체·실행 지시)이 함께 있는지를 검사한다.

한동안 이 자리에 **"배포 후 Railway 에서 `alembic upgrade head` 를 실행하십시오"** 가
적혀 있었다. 그 명령은 컨테이너 안에서 실행될 수 없었다 — 이미지에 라이브러리만 들어가고
마이그레이션 파일은 빠져 있었기 때문이다. 아무도 실제로 쳐 보지 않아 오래 남아 있었다.

- [ ] 마이그레이션에 `downgrade()` 가 구현돼 있고 실제로 되돌아간다
- [ ] 스테이징에서 운영과 같은 규모의 데이터로 마이그레이션을 돌려봤다
- [ ] 파괴적 변경(컬럼·테이블 삭제)이면 배포 직전 백업을 확인했다
      (`runbook-backup-restore.md`)
- [ ] 롤백 절차를 문서에 적었고, 담당자가 읽었다
- [ ] 새 테이블에 `organization_id` 가 NOT NULL + 인덱스로 들어갔다

### 7-1. 최초 1회 — 관리자 계정 만들기

**마이그레이션만으로는 로그인할 수 없다.** 모든 경로가 principal 을 요구하고,
principal 은 로그인에서 나오고, 로그인은 사용자 행을 필요로 한다. 갓 마이그레이션한
데이터베이스에는 조직도 사용자도 없으므로 이 단계를 건너뛰면 아무도 들어갈 수 없다.

```
VEO_JWT_SECRET=... VEO_DATABASE_URL=... \
  python apps/api/scripts/bootstrap.py \
    --name "베놈" --slug venom \
    --email owner@example.com --display-name "이재훈"
```

- [ ] `VEO_JWT_SECRET` 이 설정되어 있다 — 없으면 로그인은 되지만 토큰 발급에서
      막힌다(기본 키로 서명하지 않는다). 부트스트랩 자체는 이 값 없이도 성공하므로,
      "계정은 만들었는데 로그인이 안 된다"로 나타난다
- [ ] 비밀번호를 **명령행 인자로 주지 않았다** — `ps` 로 같은 서버의 다른 사용자에게
      보이고 셸 기록에도 남는다. 프롬프트나 `VEO_BOOTSTRAP_PASSWORD` 를 쓴다
- [ ] 만든 계정으로 실제 로그인해 봤다
- [ ] 이 계정은 `SUPER_ADMIN` 이다. 조직이 하나라도 생기면 이 스크립트는 다시
      실행되지 않으므로, 비밀번호를 잃어버리면 데이터베이스를 직접 손대야 한다

**해결됨(2026-07-30).** 팀원 관리는 `veo.users.router` 에 전부 들어왔다 — 목록·초대·
초대 재발송·역할 변경·계정 비활성, 그리고 로그인 없이 받는 초대 수락. 콘솔 화면은
`/console/team` 이다.

초대 메일은 보내지 않는다. 엔진이 1회용 링크를 돌려주고 관리자가 직접 전달한다.
메일 발송을 붙일 자리는 남겨 두었으나, 직원 몇 명을 들이는 데 메일 인프라를 세울
이유가 적어 지금은 넣지 않았다.

## 6. 자동으로 검사되는 항목과, 사람이 해야 하는 항목

§1 출시 차단 항목 여덟 가지는 `apps/api/tests/release/test_launch_blockers.py` 가
빌드마다 검사합니다. 체크박스를 손으로 누르는 대신 실패하면 배포가 멈춥니다.

```bash
make test-api      # 차단 항목 포함
```

**다만 아래는 자동으로 확인할 수 없습니다.** 검사가 스스로의 적용 범위를 과장하면
가드가 없는 것보다 나쁘므로, 무엇이 남는지 명시합니다.

### 부하

- [ ] 예상 동시 진단 수에서 큐가 밀리지 않는지 확인했다
- [ ] 큐가 밀렸을 때 회복되는지(backlog recovery) 확인했다
- [ ] 크롤 대상 사이트에 과부하를 주지 않는 속도인지 확인했다

부하는 이 장비에서 재현되지 않습니다. Docker 와 Redis 가 있는 환경에서 1회 확인이
필요합니다.

### 접근성

- [ ] 실제 스크린리더(VoiceOver)로 로그인·진단·보고서 열람을 통과했다
- [ ] 키보드만으로 모든 기능에 도달했다
- [ ] 색상만으로 상태를 구분하는 화면이 없다
- [ ] 확대 200% 에서 레이아웃이 깨지지 않는다

자동 검사는 라벨과 역할까지만 봅니다. 실제로 쓸 수 있는지는 사람이 써 봐야 압니다.

### 백업·복구

- [ ] 깨끗한 장비에 백업을 복원해 서비스가 뜨는 것을 확인했다
- [ ] 복원한 데이터로 과거 보고서의 숫자가 재현되는지 대조했다
- [ ] 자격증명 금고 마스터 키 없이는 복원해도 자격증명을 못 읽는 것을 확인했다

백업이 있다는 것과 복구가 된다는 것은 다른 사실입니다. 복원해 보지 않은 백업은
백업이 아닙니다.
