# 호스팅 지역

세 조각이 서로 다른 대륙에 있으면, 화면 하나를 그리는 데 태평양을 여러 번 건넌다.
아래 배치는 그래서 정해진 것이고, 하나만 옮기면 오히려 느려진다.

| 조각 | 지역 | 이유 |
| --- | --- | --- |
| Neon (DB) | `ap-southeast-1` 싱가포르 | FlowLens 와 공용 프로젝트라 여기서 시작했다 |
| Railway (API) | `asia-southeast1` 싱가포르 | **DB 옆.** 요청 하나가 질의를 여러 번 한다 |
| Vercel (콘솔) | `icn1` 서울 | 사용자 옆. API 까지는 한 번만 건너간다 |

## 왜 이 순서인가

한 요청은 DB 를 **여러 번** 부르지만, API 는 **한 번** 부른다. 그래서 가장 붙여야 하는
짝은 API–DB 이고, 그다음이 사용자–콘솔이다.

Railway 를 옮기기 전에 Vercel 만 서울로 옮기면 느려진다. 그때는 Vercel 과 Railway 가
둘 다 미국에 있어서 그 구간이 공짜인데, 콘솔만 서울로 빼면 그 구간이 태평양이 된다.

## 2026-07-29 실측 (개선 전, 한국에서)

```
GET  /api/health          (DB 안 씀)   0.21s
POST /api/auth/login      (DB 씀)      1.8 ~ 2.5s
```

당시 배치는 Vercel `iad1`(미국 동부) · Railway 미국 · Neon 싱가포르였다. 화면 렌더링
자체는 0.3초로 빨랐고, 느린 것은 전부 DB 왕복이었다 — 콘솔은 탭을 누를 때마다 세션을
API 에 되묻고, API 는 그 답을 싱가포르에서 가져왔다.

콘솔이 느리다는 신고가 들어오면 코드보다 이 표를 먼저 확인할 것. 위 두 줄을 재보면
DB 왕복 때문인지 아닌지가 한 번에 갈린다.

## 바꾸는 곳

- Vercel: `apps/web/vercel.json` 의 `regions`. 프로젝트 설정이 아니라 코드에 둔다 —
  설정 화면의 값은 배포 이력에 남지 않아 나중에 왜 이렇게 됐는지 추적할 수 없다.
- Railway: 서비스 → Settings → Regions. 코드로 고정할 방법이 없으므로 이 문서가 기록이다.
- Neon: 프로젝트 생성 시에만 정해진다. 옮기려면 새 프로젝트를 만들어 옮겨 담아야 한다.
