# 동명 업체 오인 방지 — 홈페이지에서 식별 정보를 읽어 온다

2026-08-09 · 사장님 요청

## 요청이 무엇이었나

> "거래처 상호가 중복될 경우, 예를 들어 서울치과가 거래처인데 서울미소치과,
> 서울치과의원이 있다면 … 유사 상호의 데이터를 거래처 상호로 오인하는걸 막기 위함이야.
> **별도 탭을 만들 필요는 없어.**"

이어서 —

> "AI 대답에 언론기사나 블로그, 티스토리 등 홈페이지가 아닌 곳의 자료에는 홈페이지 주소,
> 전화번호 같은 것이 없을 수 있기 때문에 **포괄적으로 수집**하고 등록한다로 바꿈.
> 포괄적이라는 것은 상호, 웹사이트주소, 전화번호, 대표자명 등으로."

## 이미 있던 것 / 없던 것

| | 상태 |
|---|---|
| 오인 방지 구조 (`brand_identities` · 확신도 밴드 · 검수 큐) | **있었다** |
| 입력 칸 (상호·전화·소재지·도메인·원장 이름·별칭) | **있었다** (`BrandForm.tsx`) |
| 부족하면 무엇을 넣으라는 안내 (`describe_identity_gaps_ko`) | **있었다** (`BrandCard.tsx:36`) |
| 사이트에서 값을 읽어 오는 함수 (`profile_from_site`) | **있었다** — 다만 GEO 진단 안에서만 쓰였다 |
| **등록 화면에서 그것을 부르는 곳** | **없었다** ← 이번에 만든 것 |

즉 빈 것은 칸이 아니라 **채워 주는 손**이었다. 별도 탭 없이 브랜드 식별 폼 안에
「홈페이지에서 불러오기」를 붙였다.

## 왜 자동으로 채우지 않는가

식별 값이 하나 더해지면 확신도가 올라가고, 확정선(0.75)을 넘으면 **사람 검수를
건너뛴다**(`detection/disambiguation.py`). 그러므로 틀린 값을 자동으로 넣는 것은
**틀린 판정을 검수 없이 확정시키는 일**이다. 오인을 막으려고 만든 기능이 오인을 만든다.

실제로 틀린 후보가 나왔다 — 아래 실측을 보라.

## 실측 — 등록된 거래처 홈페이지 5곳

명령: `SiteIdentityReader().read(url)` (운영이 밟는 진입점 그대로)

```
                      상호   도메인   전화        소재지      대표자   사업자번호
참사랑한의원           선언    ✓       1개         2개         —       608-91-…
good-tour.kr          선언    ✓       3개(1 선언)  2개(1 선언)  —       506-81-…
koreahhospital.com    —      ✓       3개         2개         제현태   509-04-…
venomad.com           선언    ✓       1개(선언)    2개(1 선언)  김보형   291-86-…
xn--9m1bm…kr          선언    ✓       1개(선언)    2개(1 선언)  권영재   301-95-…
```

* 구조화 데이터(JSON-LD)로 상호·전화·소재지를 **선언한 사이트는 5곳 중 3곳.**
* 대표자 성함은 **5곳 중 3곳**에서 나왔다.
* 사업자등록번호는 **5곳 전부**.

### 걸러 낸 오검출 (전부 실제로 나온 것)

| 후보 | 정체 | 어떻게 막았나 |
|---|---|---|
| `4299926757` 를 전화번호로 | 사업자등록번호(10자리라 자릿수 검사 통과) | 전화 앞자리 열거 + 사업자번호 제외 |
| `변경시 반드시 사전동` 을 소재지로 | "…변경시 반드시 사전 동의…" | 아는 지역명 또는 도로명+번지 요구 |
| `원장` `소개` `정회원` `약속` `진료` `전화` 를 대표자로 | 낱말 | 제외어 목록 + 첫 글자 성씨 검사 |

대표자 원시 후보 12개 → 실명 3개만 남고 오검출 0건.

**그래도 남는 것이 있다.** 코리아H병원의 전화 후보 3개 중 둘은 `010` 이다. 대표번호인지
담당자 번호인지 화면만 봐서는 모른다 — 그것을 가르는 것은 사람이다.

## 왜 대표자 성함을 넣었나

전화번호는 **글에 없으면 아무 일도 하지 않는다.** 기사·블로그에는 전화번호가 없다.
`assess()` 를 블로그 모양 글에 직접 돌린 값:

```
이름만                      0.40  검수 대기
+ 소재지                    0.60  검수 대기
+ 소재지 + 전화(글에 없음)    0.60  검수 대기
+ 소재지 + 대표자 성함        0.75  확정
```

사장님 지적대로, 홈페이지 밖 자료에서 고객을 가려내는 것은 대표자 쪽이다.

## 사업자등록번호는 왜 저장하지 않는가

5곳 전부에서 깨끗하게 나오고 업체마다 유일한 값이다. 그런데 **AI 답변에 인쇄될 일이
거의 없다.** 이 값들은 답변 본문과 글자로 대조하는 데 쓰이므로, 넣어도 대조에 안 걸리고
칸만 채운다 — 진료시간을 구별 표현에 넣지 않는 것과 같은 이유다(`BrandForm.tsx` 주석).

그래서 **참고로 보여만 준다**: "같은 상호의 다른 업체인지 대조하실 때 쓰십시오."
저장할 자리가 필요하다는 판단이 서면 `customers` 에 칸을 만드는 것이 맞다 — 브랜드
식별이 아니라 거래처 대장의 값이다.

## 아직 없는 것

* **`customers` 에 주소 칸이 없다.** 소재지는 브랜드 식별의 `address_terms` 로만 산다.
  거래처 대장에서 "이 서울치과가 어느 서울치과인지" 를 사람이 눈으로 보려면 그 칸이
  있어야 한다. 이번 작업 범위 밖.
* 비교 대상(경쟁사) 폼에는 홈페이지 주소를 미리 채우지 않는다. 우리 사이트 주소를 그
  칸에 넣어 두면 그대로 눌러 **경쟁사에 우리 도메인이 저장된다.**
