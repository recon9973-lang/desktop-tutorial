# 무료 Actions 2,000분은 어디로 갔나 — 전수 감사

**날짜** 2026-08-09 · **대상** `recon9973-lang` 계정의 모든 저장소, 실행 206건 전부

배포가 막혔고, 원인을 두 번 잘못 짚었다(`CORRECTIONS.md` 15·16번). 세 번째는 짐작하지
않으려고 전수로 셌다.

---

## 어떻게 셌나

`gh api .../actions/runs` 로 실행을 전부 받고, 실행마다 `.../jobs` 로 잡별 시작·종료
시각을 받아 **분 단위로 올림**해 더했다. GitHub 이 잡마다 올림해 과금하므로 같은 방식이다.

스크립트는 `scratchpad` 에 두었고 재현은 이 문서의 숫자로 충분하다고 본다. 다시 재려면
같은 두 창구를 쓰면 된다.

**한계.** GitHub 의 `/timing` 창구는 `billable.UBUNTU.total_ms = 0` 을 돌려준다(실측).
그래서 청구액을 직접 읽지 못하고 **시각 차이로 계산**했다. 실제 과금과 몇 % 다를 수 있다.

## 2. 2,000분의 행방

**[실측]** `veo-platform` 전수:

```
2026-07   실행  52건    455분
2026-08   실행 154건  2,155분   ← 무료 2,000분 초과
```

### 가지별 — 여기가 전부다

```
main               1,500분  (114건)   ← 전체의 70%
deploy-candidate     655분  ( 40건)
```

**같은 커밋을 main 에서 다시 검사한 것이 2,000분 중 1,500분을 먹었다.**

`make deploy` 는 후보 가지에서 초록불을 받은 **바로 그 SHA** 를 main 으로 민다. main 의
검사는 같은 입력에 같은 답이라 새로 알아내는 것이 없다. 워크플로의 `push.branches` 에서
`main` 을 뺐다(2026-08-08, `37eb308a`).

## 3. 저장소 크기와는 무관하다

작업 가지의 `+298,770줄` 을 보고 "다 같이 배포돼서 그런가" 를 의심할 만하다. 아니다.

**[실측]**

```
desktop-tutorial  397,330 KB  공개    ← 모든 프로젝트·동영상. 29만 줄은 여기. 그런데 공짜
veo-platform        4,680 KB  비공개  ← veo 만. 85배 작다
```

`veo-platform` 최상위: `apps` `packages` `docs` `infra` `scripts` `tests` + 설정 파일.
`flowlens`·`nexola-clone`·동영상은 올라가지 않는다 — `make deploy` 가
`git subtree split --prefix=veo` 로 `veo/` 만 떼어 민다.

그리고 CI 시간은 저장소 크기가 아니라 **의존성 설치 + 테스트 실행**이 정한다.

## 4. 무료로 계속 쓸 수 있나

**[계산]** main 검사를 없앤 뒤 남는 것으로:

```
655분 ÷ 8일               =  81.9분/일
81.9 × 31일               = 2,538분        ← 2,000 보다 27% 많다
배포 1회당                = 655 ÷ 40 = 16.4분
무료로 감당되는 배포 횟수  = 2,000 ÷ 16.4 = 122회/월 = 하루 3.9회
8월 첫 8일의 실제 속도     = 40 ÷ 8 = 하루 5.0회
```

**하루 4회 이하면 무료 안에서 된다.** 최근이 하루 5회였다.

**[실측]** 문서만 고친 커밋은 8월 142개 중 16개(11%)뿐이라, 경로별 건너뛰기의 효과는
제한적이다. 큰 것은 이미 뺀 `main` 이었다.

## 5. 무엇을 했나

| | 조치 | 효과 |
|---|---|---|
| 2026-08-08 | 워크플로에서 `main` 트리거 제거 (`37eb308a`) | **−70%** |
| 2026-08-09 | `make deploy` 에 **하루 2회 상한** 관문 | 남은 8월을 무료/소액 안에서 |

상한은 `scripts/deploy.sh` 에 있고 **미는 것보다 먼저** 센다 — 밀고 나면 분은 이미
나간다. 넘으려면 `VEO_DEPLOY_LIMIT_PER_DAY=99` 를 직접 적어야 한다(실수로는 못 넘는다).
`2026-09-01` 부터 자동으로 풀리고, 그때 한 줄로 알린다.

시험 넷이 이 성질들을 지킨다(`tests/release/test_ci_paths.py`).
