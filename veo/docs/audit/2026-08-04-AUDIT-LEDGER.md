# 진단기 전수조사 대장 — 2026-08-04

**계기.** venomad.com 진단이 22.7~27.3점으로 나왔다. 타사 도구는 94점이었다. 같은
사이트를 잰 두 숫자가 67점 벌어졌고, 항목별 관측값이 재진단마다 달랐다.

**이 문서의 목적.** 감사 6건에서 나온 지적을 **하나도 잃지 않고** 추적한다. 감사 보고서는
길고 흩어져 있어 읽는 순간에만 존재한다. 여기 모아 두고, 고칠 때마다 상태를 옮긴다.

## 0. 실측으로 확정된 사실

추측이 아니라 실제로 돌려서 나온 값이다. 이후 모든 판단의 근거다.

| 잰 것 | 결과 |
|---|---|
| 운영 서버 → venomad.com | **25.3점** → 몇 분 뒤 **15.5점** → **20.3점** |
| 운영 서버 → veo.seokorea.org | 61.0점 · 제목 정상 읽음 · 모순 0건 |
| 운영 서버 → chamsarang1075.com | **78.9점** · 제목 정상 읽음 · **모순 0건** |
| 로컬(한국) → venomad.com, 같은 엔진 | **75.9점** · 제목 정상 |
| 독립 채점관(구글 기준, 우리 코드 미열람) | 홈 **78점** · 사이트 전체 **65점** |
| 재현성 시험 (고정 입력, 8회 × 1,180항목) | **불일치 0건** |

**두 가지 결론**
1. **엔진은 작동한다.** 다른 사이트는 정상으로 읽고 타당한 점수를 낸다.
2. **venomad 에서만 문서를 못 받는다.** 그리고 못 받은 것을 사이트의 결함으로 채점했다.

**핵심 산수** — venomad 홈 1장(로컬 75.9점) 기준:

```
잃은 점수 24.1  =  사이트와 무관 19.5 (81%)  +  실제 결함 4.6 (19%)
잰 것 안에서만 계산한 점수 = 94.3점
```

**94.3.** 타사가 매긴 94와 사실상 같다. 측정 공백을 걷어내면 두 도구가 일치한다.

## 4. 배점 알고리즘 — 측정도 정책도 아닌 숫자

산식 전체를 뽑아 **측정 / 정책(근거 문서화됨) / 임의(근거 없음)** 로 분류한 결과.

**측정은 넷뿐이다**: `status`, `coverage_ratio`, `affected/evaluated_weight`, `evidence_ids`.
나머지는 전부 우리가 정한 숫자다.

| # | 임의 숫자 | 문제 | 상태 |
|---|---|---|---|
| 4.1 | **`unknown: SCORE_AS_ZERO_KEEP_IN_DENOMINATOR`** | 정책 자체는 ADR 0016 으로 가장 잘 문서화됨. 그러나 **UNKNOWN 한 건은 언제나 FAIL 한 건 이상으로 무겁다** (배수·범위·신뢰도를 전부 안 곱함). 현실적 실패 대비 2~3배 | ⏸ 명세 2.0.0 |
| 4.2 | `breadth_exponent 0.7` | 방향은 논증됐고 **값의 근거 없음.** 코드가 자인: *"어디쯤이 옳은지는 표본이 더 쌓여야"* | ⏸ |
| 4.3 | WARNING 계수 `0.5` | 유도 근거 없음 | ⏸ |
| 4.4 | confidence `0.65`·`0.4` | 원안은 범위만 제시. 특정 값의 근거가 저장소 전체에 없음 | ⏸ |
| 4.5 | 상한 5값 (25/35/40/55/60) | 원표를 승계했는데 **그 표에 유도가 없음** | ⏸ |
| 4.6 | 상한 `min_coverage` (0.9/0.3/0.5/0.5/0.5) | 원안에 없던 값. 신설 시 근거 없음 | ⏸ |
| 4.7 | **밴드 경계 90/75/50/25** | **연구문서가 재정의를 요구했으나 두 판이 지나도록 미이행.** v1 분포용 경계가 v2 산식에 그대로 | ⏸ **우선 검토 권고** |
| 4.8 | 관문에 breadth 미적용 (품질 ^0.7 / 관문 ^1.0) | 차이의 근거 없음 | ⏸ |
| 4.9 | 심각도 계수 5값 | 점수에 미사용인데 화면에 남아 **배점과 다른 순위**를 말함 (역전 사례 다수 실측) | ⏸ |
| 4.10 | trace 키 `severity_coefficient` 에 points 기반 가중치가 담김 | 감사 추적이 오독을 유발 | ⏳ 한 줄 수정 |

**구조적 결론 (실측):**
```
완벽한 사이트를 홈 1장만 재면 → 71.30점
우리가 잰 배점 비율          → 71.3%
```
두 숫자가 같은 것은 우연이 아니라 **항등식**이다. 잰 것이 전부 통과일 때, 현행 점수는
사이트가 아니라 **우리가 얼마나 쟀는지**를 보고한다.

## 6. 고객에게 **틀린 숫자**가 나가는 것 — 실행으로 검증됨

파이프라인(측정→알고리즘→점수)은 지켜졌는데, **그 결과를 화면으로 옮기는 과정**에서
산식과 다른 숫자가 만들어진다. 감사관이 전부 실제 실행으로 확인했다.

| # | 지적 | 실측 | 상태 |
|---|---|---|---|
| 6.1 | **페이지 점수가 항상 100점.** 저장이 `confidence or 0.0` 으로 접어 모든 저장 신뢰도가 0.0 → 페이지 손실 = points × … × **0** = 0 | 실패 2건인 페이지가 **100점**으로 나감 | ⏳ **최우선** |
| 6.2 | **`gain_points` 오차 33%** + 거짓 `blocked_by_cap`. 분모가 평가기와 다르고(`reach` 미반영) | 실제 8.58 → 표기 5.72 / 실제 0.858 → 표기 **0.0 "상한 때문"** | ⏳ |
| 6.3 | **요약문 "못 잰 배점 N점" 의 단위 오류.** 영역별 배점(s1=30·s3=20·s6=5) 단위를 종합 단위처럼 더함 | 실제 14.3 → 문장 **10.0** | ✅ 영역가중치로 환산. 시연 확인 **14.3 = 14.3** |
| 6.4 | 공개 리포트가 **severity 순**으로 정렬 — 배점과 다른 순위. 위에서부터 고쳐도 점수가 예상대로 안 오름 | 역전 6쌍 실측 | ⏳ |
| 6.5 | 같은 "관문 단계 점수" 를 사이트와 페이지가 **다른 산식**으로 계산 | | ⏳ |

| # | 지적 | 분류 | 없애면 |

| 7.1 | **`confidence` 가 감점에 곱해짐.** 확신도는 사이트가 아니라 **우리 방법**에 대한 사실인데 남의 점수를 바꾼다. 같은 결함이라도 **우리가 덜 확신하는 방법으로 잰 사이트가 더 좋은 점수**를 받는다. 라벨 배정은 명세 밖에서 정해진다 | 자기평가 | **없애도 정보가 사라지지 않는다.** 확신도는 이미 별도 보고 항목으로 존재 |

## 13. 정상으로 확인된 것 — 손대지 않는다

마녀사냥을 막기 위해 명시한다. 감사관들이 **정상**으로 판정한 자리다.

- **성능 측정** — 못 잰 LCP 를 페이지 크기로 추정하지 않고 Lighthouse·CrUX 의 구간 분류를 그대로 옮김. lab 과 field 를 섞지 않음
- **`gain_points`** — 화면이 어림하지 않고 채점기 산식 값만 씀. **"예상 점수 상승폭을 지어내는 자리" 는 발견되지 않음**
- **`verify_complete()`** — 침묵한 수집기를 거부. 점수를 조용히 부풀리는 경로를 타입 수준에서 차단
- **인증서 만료일** — 못 읽으면 `None`. 통과로 접지 않음
- **휴리스틱에 라벨** — 유사도·앵커·렌더 대조는 전부 `HEURISTIC_*` 로 표시
- **`<img alt="">`(장식)와 `<img>`(누락) 구분** — 끝까지 유지
- **본문에서 nav/header/footer 제외** — 보일러플레이트가 "분량" 으로도 "중복" 으로도 둔갑 못 함
- **보안 수집 경계** — 가드 승인 IP 고정, 리다이렉트 홉마다 재검증, 쿠키·자격증명 미전송
- **배점 산수** — 손계산 97.885 vs 엔진 97.882. 정확
- **PASS/FAIL 이 전부 아니면 전무가 아님** — 전부 중요도 가중 비례. 나쁜 게시글 한 장의 비용은 1.2점
- **coverage/confidence 가 점수를 곱하지 않음** — 신뢰도를 0.4 로 바꿔도 점수 동일(실험 확인)
