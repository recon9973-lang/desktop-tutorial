## 1. GPTO 화면 판독 — 이번엔 이미지 원본을 봤다

등급 `[이미지 판독]`. 출처: 사장님이 제공한 화면 캡처 5장(2026-08-07 촬영, 하단
`© 2026. Across Inc.`). 이전 기록(`CONTENT-PROGRAM-NOTES.md`)은 콘텐츠 패턴만 적혀
있었고 **화면 배치는 이번에 처음 확인**했다.

### 1-A. 화면은 아홉 덩어리다

| # | 덩어리 | 안에 있는 것 |
|---|---|---|
| A | 모니터링 질문 목록 | 질문마다 `기존% → 현재%`, 연필(수정), `+ 새 질문 추가` |
| B | 주차별 추이 | 면적 그래프. x축 주 단위, 관측 기간 8주 |
| C | 한 줄 요약 | `전체 언급률: 10.8% (+31.4%p) → 42.2%` |
| D | AI 모델별 언급률 | 오각형 레이더(기존/현재) + 표(모델·기존·현재·변화) |
| E | 언급 현황 | 경쟁 브랜드를 `건수 (비율%)` 로 나열 — 30개 넘게 |
| F | AI 모델별 응답 | 모델 × 검색켬/끔 셀마다 **답변 원문**, 자사 브랜드 강조 |
| G | 참조 출처 | URL 목록 + `2개 모델` / `ChatGPT` 배지 = **몇 개 모델이 이 출처를 봤나** |
| H | 현황 분석 / 전략 설계 | 브랜드 언급률·자사 언급 가능성(정성 등급) + **종합 기회 점수 80점** + 경쟁 브랜드 63개 + 전략 방향성 5개 |
| I | 학습 데이터 발행 | 생성된 기사 3편(제목·본문·해시태그) |

### 1-B. 이미지에서 직접 읽은 값

투자사 사례(A·E·F·G):
```
질문 4개 · 100% / 75% / 52% / 30%
AI 모델별 응답 9개 모델 (9/9, 100%)  — Claude 2/2, ChatGPT 2/2 … 검색 켬·끔이 각각 한 칸
참조 출처 35개 사이트
경쟁 브랜드: 프라이머 9(100%) · 퓨처플레이 7(75%) · 스파크랩스 6(69%) … 30개 이상
```

안산 치과 사례(A·B·C·D):
```
질문 5개 · 모니터링 기간 8주
19%→55% · 0%→55% · 19%→46% · 9%→40% · 9%→9%
전체 언급률 10.8% (+31.4%p) → 42.2%
모델별  ChatGPT 0.0→30.0 · Gemini 0.0→40.0 · Claude 0.0→30.0 · Grok 40.0→50.0 · Perplexity 40.0→80.0
```

다국어 사례: 일본어·영어·중국어 질문 그대로. `18개국 언어 AI 학습 가능`.

### 1-C. 표기 규칙 두 가지

* **모든 값이 소수점 한 자리.** `42.2%` · `+31.4%p` · `30.0%`.
* **모든 값이 `기존 → 현재` 쌍.** 절대값 하나만 보여주는 칸이 없다.

두 번째가 핵심이다. 이 화면의 문법은 점수가 아니라 **변화**다. 세션 기록에 적혀 있던
한 줄이 그대로 맞다 — *"대시보드는 파는 물건이 아니라 '일해서 올렸다' 는 영수증이다."*

## 4. 이 조사에서 나온 제일 큰 것 — 업계가 표본을 안 밝힌다

출처: [popsight.ai](https://popsight.ai/blog/ai-visibility-tools-compared/) ·
[maxaeo.ai](https://maxaeo.ai/blog/ai-visibility-sample-size/)

> 여덟 개 도구 중 신뢰구간 방법론을 공개한 곳은 **한 곳(Gumshoe)** 뿐이다.

> 같은 프롬프트를 1,000번 돌려 서로 다른 답변 80종. 반복 질문 100번 중 브랜드 추천
> 목록이 똑같이 나온 것은 1번 미만. 같은 질문끼리 인용 겹침 9.2%.

> 분산 분해 연구 — 같은 프롬프트를 다시 뽑는 것만으로 전체 분산의 **34.8%**. 정작
> 브랜드 정체성 신호는 **1.5%**.

권고 설계(maxaeo):

```
질문 150~200개 × 각 3회 × 엔진별 × 기간별   ->  답변 450~600개  ->  ±5%p (95%)
같은 예산으로 질문 20개 × 30회             ->  ±15pp          ->  "세 배 나쁘다"
```

### 4-A. 이 잣대를 GPTO 이미지에 대 봤다

[계산] `MoE = 1.96 × √(p(1−p)/n)`. `n` 은 이미지 표기(질문 5개 · 9개 모델)에서
**질문 하나당 한 주 응답 9개**로 잡았다 — 이미지에 반복 횟수가 없어 이것은 **가정**이다.

| 화면에 나온 값 | n | 오차 폭 |
|---|---|---|
| 라미네이트 `19% → 55%` | 9 | **±32.5pp** |
| 공휴일 `0% → 55%` | 9 | **±32.5pp** |
| 수면마취 `9% → 9%` | 9 | **±18.7pp** |
| 전체 언급률 `42.2%` | 45 | **±14.4pp** |

**질문 하나짜리 숫자는 오차가 값만큼 크다.** `55%` 는 `22%` 일 수도 `88%` 일 수도 있다.
반면 **전체 언급률의 변화 `+31.4%p` 는 오차 폭 ±14.4pp 보다 크다** — 그 한 줄은 살아
남는다. 즉 **GPTO 화면에서 믿을 수 있는 것은 C 칸(전체 요약)이고, A 칸(질문별
19%→55%)은 근거가 감당 못 하는 정밀도다.**

### 4-B. 우리는 이미 이걸 막아 놨다

`apps/api/src/veo/observations/sampling.py`:

```
MIN_RUNS_FOR_EXPLORATION = 3      # 탐색 진단 최소 반복
MIN_RUNS_FOR_COMPARISON  = 5      # 비교 보고 최소 반복
wilson_interval(...)              # 모든 비율에 Wilson 95% 구간
ObservedRate.require_comparison_grade()   # 미달이면 비교 보고를 거부한다
```

그리고 `metrics.py` 는 분모를 셋으로 갈라 놓았다 — 언급률(유효 응답), 인용률(인용을 볼
수 있었던 응답), 질문 도달률(질문 수). 실패한 실행을 "언급 없음"으로 세지 않는다.

> "표본이 3~5회인 값은 소수점 없이 정수로 표시되어야 하는데, 원시 숫자만 주면 화면이
> 습관적으로 소수점 한 자리를 붙이고 그 순간 표본이 감당 못 하는 정밀도를 [갖는다]"
> — `observations/metrics.py:56`

**우리 코드는 GPTO 화면이 하는 일을 이미 금지하고 있다.** 이건 우연이 아니라 설계다.
그래서 우리 화면은 저들보다 **덜 시원해 보일 것이다.** `55%` 대신 `55% (9회, 22~85%)`
라고 쓰게 된다. 그것이 맞다.

## 6. 결론 — 무엇을 만들 것인가

**GPTO 화면을 그대로 베끼면 빈 화면이 나온다.** A~G 일곱 칸이 전부 관측 자료를 먹는데
`observation_runs` 가 0행이다.

**그런데 배치는 베낄 수 있다.** 저 화면의 문법은 `기존 → 현재` 이고, 그 문법을 먹일
재료를 우리는 **다른 축에** 갖고 있다 — SEO·GEO 진단 47회 이력.

그래서 업체별 대시보드는 이렇게 간다:

```
업체 화면 (거래처 하나)
├ C 자리  이번 점수와 지난번 점수     SEO 67.78 → 71.03   ← 진단 이력에서 나온다
├ B 자리  진단 추이 그래프            47회 이력            ← 이미 readHistory 가 읽는다
├ A 자리  항목별 기존→현재            45+19건 판정 변화     ← check_results 에 있다
├ 이슈    열린 것 / 닫은 것            165건                ← 재측정 경로 어제 완성
├ D~G 자리  AI 답변                    "아직 켜지 않음"      ← 0 을 쓰지 않는다. 켜는 단추를 둔다
└ [ 리포트 발행 ]                                          ← 출력 시스템은 여기 붙는다
```

**D~G 칸을 0% 로 채우지 않는다.** ADR 0002(N/A 와 UNKNOWN 은 다르다)와 `dashboard.ts:22`
의 규칙이 같은 말을 한다 — *"0 과 모름은 다른 말이고, 0 으로 적으면 '다 처리했다' 로
읽힌다."* 빈 칸에는 **왜 비어 있고 무엇을 하면 채워지는지**를 적는다.

이 배치의 이득은 하나 더 있다. **비어 있는 칸이 화면에 남아 있으면 그 축을 켤 이유가
매주 눈에 보인다.** 지금은 관측 축이 코드에만 있어서 아무도 없다는 것을 모른다.

### 관측 축을 켜려면 실제로 무엇이 필요한가

[실측] 코드 확인 결과 세 가지뿐이다.

1. `ai_engines` 에 엔진 1행 (열쇠는 OPENAI 만 살아 있음)
2. `prompt_sets` 에 질문 집합 1개 — 화면 `PromptSetForm.tsx` 이미 있음
3. `POST /observations/runs` 실행 — 비용 추정은 `estimates` 가 미리 내준다

### 개수·주기는 이미 정해져 있다 — 그리고 그 설계면 충분하다

**[정정]** 이 문서 초판은 *"5개로 시작하면 GPTO 와 같은 ±32pp"* 라고 적었다. **틀렸다.**
maxaeo 의 권고(질문 200개 × 3회)는 **엔진 하나·모드 하나**를 전제한 설계이고, 우리
확정 설계는 질문 하나당 **반복 3회 × 엔진 5 × 모드 2 = 관측 30건**이다
(`docs/observation-engine.md` §9, 사장님 결정 2026-08-08). 나는 우리 쪽 설계 문서를
열지 않고 남의 전제를 우리 숫자에 갖다 댔다(`CORRECTIONS.md` #22).

[계산] `MoE = 1.96 × √(p(1−p)/n)`, `p = 0.5`(최악):

| 무엇을 보는 값인가 | n | 오차 폭 |
|---|---|---|
| 질문 1개 · 엔진 1개 · 한 모드 | 3 | ±56.6pp |
| 질문 1개 · 엔진 1개 · 두 모드 | 6 | ±40.0pp |
| **질문 1개 · 전체 엔진** | 30 | **±17.9pp** |
| **핵심 5개 전체 언급률** | 150 | **±8.0pp** |
| **핵심 8개 전체 언급률** | 240 | **±6.3pp** |
| 핵심 8 + 확장 20 = 28개 | 840 | ±3.4pp |

**확정 설계는 이미 GPTO 보다 네 배 촘촘하다** (질문당 30 대 9로 추정).

읽는 규칙은 그래서 이렇게 된다:

```
전체 언급률(핵심 5~8개)   ±6~8pp    거래처에 보고해도 되는 값
질문 하나짜리             ±17.9pp   방향은 말할 수 있으나 소수점은 못 붙인다
질문 × 엔진 한 칸         ±40pp     "이 모델이 안 뜬다" 를 이 칸 하나로 말하면 안 된다
```

이 표가 `sampling.py` 의 `MIN_RUNS_FOR_COMPARISON = 5` 와 어긋나지 않는지는 별개
문제다 — 저 상수는 **엔진·모드별 반복 수**에 걸리는 하한이고(지금 3회), 위 표의 `n` 은
합친 분모다. **합쳐서 촘촘하다고 칸마다 촘촘한 것이 아니다.**
