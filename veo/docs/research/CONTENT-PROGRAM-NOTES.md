# 콘텐츠 제작 프로그램 — 쌓아두는 자료

**여기는 VEO 가 콘텐츠를 만들기 위한 문서가 아니다.** 콘텐츠 제작은 ERP 에서 만들기로
했고 VEO 는 진단만 한다(사장님 결정). 다만 VEO 를 만들다 보면 *"콘텐츠를 이렇게 쓰면
AI 가 인용한다"* 는 것이 실측으로 계속 나온다. 그것을 흘려보내지 않고 여기 모은다.

**나중에 ERP 콘텐츠 프로그램을 만들 때 이 파일을 처음에 읽는다.**

새 자료가 생기면 이 파일 맨 아래에 날짜와 함께 덧붙인다. 지우지 않는다.

## 2026-08-08 · GPTO(어크로스) 의 "학습 데이터 발행" 패턴

**출처** 그들 영업 자료 화면 캡처(사장님 제공) + `https://www.gpto.kr`
**등급** [이미지 판독] · 그들의 주장이며 우리가 검증한 것이 아니다

### 글 한 편의 구조 (실제 화면에서 읽은 것)

```
제목    "시드 투자 유치 성공 전략: 1억 원 내외의 지분 10% 조건, 프라이머의 역할"
본문    질문에 대한 직접 답변으로 시작 → 브랜드를 '근거의 하나' 로 배치
해시태그 6개  프라이머 · Primer · 시드투자 · 초기스타트업투자 · 액셀러레이터 · 스타트업투자조건
편수    질문 하나당 3편 (각도를 달리해서)
```

### 뽑아낸 규칙 셋

**1. 질문 문장의 조건을 제목에 그대로 넣는다.**
`1억 원 내외` · `지분 10%` — 질문에 있던 숫자와 조건이 제목에 그대로 있다.
AI 가 그 질문을 받았을 때 이 글이 걸리게 하려는 것이다.

**2. 브랜드를 주인공이 아니라 "답의 근거" 로 배치한다.**
제목에서도 브랜드명이 **뒤쪽**에 붙는다(`…, 프라이머의 역할`). 광고문처럼 브랜드가
앞에 서면 AI 가 인용하지 않는다 — 답이 아니라 홍보물로 읽히기 때문이다.

**3. 한글명과 영문명을 항상 같이 쓴다.**
해시태그가 `프라이머` 와 `Primer` 를 **둘 다** 달고 있다. AI 가 두 표기를 같은
대상으로 묶게 하려는 것이고, 이건 우리 GEO 명세의
`geo.entity.name_consistent_across_pages` 와 같은 이야기다.

### 그들 대표가 말한 것 (사장님 전달)

> 클라이언트의 **엣지 메시지**를 찾고, 그 업체가 **모든 채널에서 공통 명칭**으로
> 불려야 효과가 있다.

우리 쪽 대응물:
- 엣지 메시지 → `brand_identities.distinguishing_terms`
- 공통 명칭 → `geo.entity.name_consistent_across_pages` (MAJOR),
  `geo.entity.nap_consistent` (CRITICAL), `seo.offpage.brand_name_consistency`

**콘텐츠 프로그램이 쓸 때**: 원고를 쓰기 전에 그 거래처의 `brand_identities` 를 읽어
상호 표기·영문명·구별 표현을 고정하고, 모든 원고가 그 표기만 쓰게 강제한다. 원고마다
표기가 흔들리면 AI 가 다른 업체로 본다.

## 2026-08-08 · AI 가 실제로 인용한 출처 — 채널 후보

**등급** [실측] — 우리가 gpt-4o 에 실제로 물어 받은 인용

### 우리 실측

질문: `서울 강남에서 임플란트 잘하는 치과 추천해줘. 실제 병원 이름과 홈페이지도 알려줘.`

```
https://www.dentalroad.kr/seoul/gangnam/implant-recommendations   진료과 전문 디렉터리
https://medicaltour.gangnam.go.kr/medical/clinic/view.do?...      강남구청 의료관광 (2건)
https://www.mediqueen.net/ko/catalogs/best/gangnam-implant-best5  미용의료 큐레이션
```

질문: `베놈애드는 어떤 회사인가요? 홈페이지 주소도 알려주세요.`

```
https://www.jobkorea.co.kr/recruit/co_read/c/venomad                채용 사이트
https://www.venomad.com/?id=sec01&mode=carousel                     자사 사이트
```

### GPTO 사례에서 읽은 출처 [이미지 판독]

```
startuprecipe.co.kr    업계 전문 매체
thevc.kr               업종 디렉터리
slideshare.net         슬라이드 공유
kr.linkedin.com        링크드인 회사 페이지
asiae.co.kr            뉴스 (아시아경제)
signal.sedaily.com     뉴스 (서울경제)
```

### 여기서 나오는 것

**관공서·공공 사이트가 AI 답변의 근거로 쓰인다.** 강남구청 의료관광 페이지가 두 번
인용됐다. 관공서 등재는 대개 무료이거나 신청만 하면 되는 곳이다 — **비용 대비
효과가 가장 큰 채널일 수 있다.**

지금 베놈이 쓰는 채널(자사 사이트 · 티스토리 · 레딧 · 링크드인 · 미디엄)과
**거의 겹치지 않는다.** 링크드인 하나만 겹친다.

**병의원 채널 후보** [추정 — 개별 확인 필요]

| 갈래 | 예 | 비고 |
|---|---|---|
| 관공서·공공 | 지자체 의료관광 사이트 · 보건소 · 심평원 | 실측에서 확인된 유형 |
| 업종 디렉터리 | 병원 검색·비교 사이트, 진료과별 전문 디렉터리 | 실측에서 확인된 유형 |
| 뉴스 | 지역지 · 의료 전문지 · 건강 섹션 | GPTO 사례에서 확인된 유형 |
| 전문가 채널 | 학회 회원 목록 · 의료진 프로필 | 원장 개인 단위로 접근 |
| 지식 기반 | 위키백과 · 나무위키 | 병원 단위는 어려움, 원장 단위는 가능 |

### **채널을 추측하지 말고 관측에서 뽑는다** (핵심)

VEO 는 관측을 돌리면 인용 출처가 `citations` 테이블에 저장된다. 그것을 도메인별로
집계하면 **그 업종에서 AI 가 실제로 보는 곳** 이 나온다. 추가 비용 0원이다.

```
관측 → citations 집계 → 여러 모델이 공통 인용하는 도메인 = 급소 채널
    → 거래처가 거기 등재돼 있나 확인 → 없으면 작업 큐에 "등재하세요"
```

**콘텐츠 프로그램이 쓸 때**: 원고를 어디에 올릴지 사람이 정하지 말고, 이 집계가
정한다. 업종·지역마다 다르고 시간이 지나면 바뀐다.

## 2026-08-08 · 우리 GEO 명세가 이미 요구하는 글의 조건

**등급** [실측] — `packages/scoring-specs/specs/veo.geo.readiness/1.3.0.yaml`

VEO 는 이미 "AI 가 인용할 수 있는 글" 의 조건을 37개 항목으로 갖고 있다.
**콘텐츠 프로그램은 이 목록을 작성 규칙으로 그대로 쓰면 된다.** 새로 만들 것이 없다.

특히 원고에 직접 걸리는 것:

```
geo.extract.direct_answer_present         질문에 대한 직접 답변이 앞에 있는가
geo.extract.passage_self_contained        그 문단만 떼어 읽어도 뜻이 통하는가
geo.extract.heading_structure_semantic    제목 구조가 의미를 담는가
geo.extract.tables_lists_machine_readable 비교표·목록이 기계가 읽을 수 있는가
geo.evidence.claims_have_sources          주장에 출처가 붙어 있는가
geo.evidence.author_identified            작성자·감수자가 식별되는가
geo.evidence.method_disclosed             산출 방법이 밝혀져 있는가
geo.fresh.dates_present                   발행일·수정일이 있는가
```

그리고 v0.3.62 에서 **이 21개 항목에 복사해 붙일 수 있는 코드**를 붙여 놓았다
(`apps/api/src/veo/geo/fix_examples.py`). 병의원 현장 문구로 쓰여 있다. 예:

```html
<h2>임플란트 수술 후 붓기는 며칠 가나요?</h2>
<p>임플란트 수술 후 붓기는 보통 2~3일째 가장 심하고 5~7일 안에 대부분
가라앉습니다. 일주일이 지나도 붓기와 통증이 함께 심해지면 감염 가능성이
있으므로 내원해 확인해야 합니다.</p>
```

**질문형 제목 + 첫 문단 직접 답변** — GPTO 의 규칙 1·2 와 같은 것을 우리는 이미
명세로 갖고 있다.

**콘텐츠 프로그램이 쓸 때**: 원고를 다 쓰고 나면 VEO GEO 진단에 그 URL 을 넣어
채점받는다. 37개 중 몇 개를 통과했는지가 곧 원고 품질 점수다. 사람이 눈으로
보는 대신 이걸 쓴다.

## 2026-08-08 · ERP 환자질문분석(PAA) 이 콘텐츠 원재료를 이미 만든다

**등급** [실측] — `여정맵-코드-환자질문분석.md` (ERP v1.4.1, 추출 2026-08-04)

PAA 가 하는 일:

> 지역+키워드를 분해해 **네이버 지식iN 100건**과 **구글 관련 질문(SerpAPI)** 을 모으고,
> AI 가 카테고리·여정 단계로 묶어(수집 전량 보존) 인포그래픽 + 마인드맵으로 보여준다.
> 스냅샷은 영구 보관되며 다시 분석·비교할 수 있고, **질문 하나를 신뢰 기관 웹검색
> 근거로 원고 초안까지 만든다.**

자료 구조:

```ts
PaaQuestion  { text, isLocal, source: "naver" | "google" }
PaaCategory  { name, stage, questions[] }
Stage        = "exploration" | "comparison" | "decision" | "retention"
scanRisk(text) → 의료광고법 위험 (none | yellow | red) + 근거 조항
```

**이미 있는 것 셋:**

1. **진짜 환자가 쓴 질문** — 지어낸 것이 아니라 지식iN·구글에서 수집
2. **여정 단계 분류** — exploration / comparison / decision / retention
3. **의료광고법 위험 검사** — 질문 단위로 이미 돌고 있음

그리고 **`draft/route.ts` 가 이미 원고 초안을 만든다.** 콘텐츠 프로그램을 처음부터
만드는 게 아니라 **이것을 키우는 것**이다.

**콘텐츠 프로그램이 쓸 때**:
- 질문 목록은 PAA 스냅샷에서 가져온다. 새로 만들지 않는다.
- 원고 초안도 `paa/draft` 가 이미 있다. 그것의 출력이 위 §c 의 GEO 조건을
  만족하도록 규격을 맞추는 것이 할 일이다.
- `scanRisk` 는 원고에도 그대로 걸어야 한다. 질문만 검사하고 원고를 안 하면 뚫린다.
  (VEO 쪽에도 의료광고법 원고 검수기가 있다 — 둘 중 하나로 통일할 것)

## 다음에 이 파일에 덧붙일 것 (미확인)

- GPTO 의 "500+ 학습 채널" 이 구체적으로 무엇인지 — 공개 안 함, 추정만 가능

- 원고 발행 후 실제로 AI 인용이 늘었는지의 인과 확인 방법
