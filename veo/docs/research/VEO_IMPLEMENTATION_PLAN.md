# VEO 구현 실행 계획 요약

**개발사:** VENOM  
**연구·방법론:** VEO-LAB  
**제품:** VEO — SEO·GEO·Naver Keyword Intelligence Platform

## 핵심 구조

- 프론트엔드: Next.js + TypeScript
- 백엔드: FastAPI + Python
- 데이터: PostgreSQL
- 비동기 작업: Redis + Celery
- 웹 수집: HTTP crawler + 필요 시 Playwright
- AI 관측: OpenAI API 등 등록된 provider
- 결과물: S3 호환 저장소
- 실행 환경: Docker

VEO Public과 VEO Console은 같은 분석 엔진을 사용한다. Public은 비로그인 간편 진단이며 범위와 호출량을 제한하고, Console은 조직·프로젝트·경쟁사·이슈·보고서·권한을 관리하는 본 제품이다.

## 개발 순서

### 0단계: 공통 기준 확정

먼저 한 명의 통합 관리자가 저장소와 공통 데이터 형식을 만든다. 사용자, 조직, 프로젝트, 분석 작업, 검사 결과, 증거, 점수, 키워드, 경쟁사, 이슈, 보고서의 형식과 API를 이 단계에서 확정한다.

가장 중요한 것은 점수 규칙이다. 점수마다 방법론 버전, 적용된 항목, 제외된 N/A, 분모, 원자료, 계산 과정, 신뢰도를 남긴다. 이 계약이 테스트를 통과하기 전에는 기능 개발을 병렬로 시작하지 않는다.

### 1단계: 기반 병렬 개발

공통 계약 확정 후 다음을 동시에 개발한다.

| 작업 | 결과 |
|---|---|
| 인증·권한 | 조직 격리, 역할, 프로젝트, 감사 기록 |
| 수집기 | 안전한 URL 수집, Playwright, 원자료 보관 |
| 작업 시스템 | 대기열, 진행률, 재시도, 취소, 부분 성공 |
| Naver 연동 | 공식 API 인증, 검색량과 추세 정규화 |
| 프론트 기반 | Public/Console 경로, 공통 UI, 접근성 |
| 인프라 | Docker, CI, 로그, 지표, 보안 검사 |

### 2단계: 제품 엔진 병렬 개발

- SEO 엔진은 색인, canonical, robots, sitemap, metadata, headings, schema, 링크, 이미지, hreflang, 보안, 모바일, 성능을 증거 기반으로 검사한다.
- GEO Readiness는 JSON-LD 존재 여부만 세지 않고 엔터티 식별, `@id` 연결, sameAs, 저자·발행자·날짜·출처, 인용, 답변 가능성, 접근성을 검증한다.
- GEO Observation은 실제 AI 모델에서 브랜드 언급, 인용, 답변 포함, 경쟁사 점유를 반복 측정한다. Readiness 점수와 절대로 합치지 않는다.
- Keyword Intelligence는 PC/Mobile 월간 검색량, 클릭, CTR, 경쟁도, 광고수, 연관키워드, 추세, 출처와 갱신시각을 제공한다.
- 프론트는 사업자용 요약, 마케터용 비교, 개발자용 수정 근거를 같은 결과에서 역할별로 보여준다.

### 3단계: 통합 기능

- 동일 조건의 경쟁사 비교
- 이슈 배정·상태·재검증·재발 추적
- 방법론 버전 변경과 과거 점수 보존
- 경영진·마케팅·개발자용 보고서
- HTML/PDF/CSV/XLSX 내보내기

### 4단계: 출시 검증

깨끗한 환경에서 회원가입부터 분석, 경쟁사 비교, 수정 후 재검증, 보고서 출력까지 전 과정을 검사한다. 조직 간 데이터 누출, SSRF, 권한 우회, 비밀값 노출, 호출량 제한도 공격 관점에서 검증한다.

출시 전에는 화면의 점수를 원자료와 계산 과정에 직접 대조하며, `TODO`, `FIXME`, 임시 데이터, 하드코딩 점수, 가짜 API 결과가 남아 있지 않은지 검색한다.

## NXT 대비 반드시 보완할 부분

1. SEO와 GEO 모두 단순 항목 존재 여부를 넘어 유효성·정합성·범위·신뢰도를 평가한다.
2. N/A를 0점 처리하지 않고 적용 가능한 분모를 다시 계산한다.
3. GEO 구조 준비 상태와 실제 AI 노출 관측을 분리한다.
4. 점수 배점과 변경 이력을 VEO-LAB 버전으로 공개한다.
5. 모든 문제를 원자료, 영향 URL, 사업 영향, 수정 방법, 재검증 규칙에 연결한다.
6. 경쟁사는 같은 수집 범위와 같은 규칙으로 측정하고 데이터 차이를 경고한다.
7. Naver 수치에는 출처, 갱신시각, PC/Mobile, 결측·억제값 의미를 표시한다.
8. 합법적 출처가 없으면 ‘실시간 인기검색어’로 표현하지 않는다.

## 병렬 작업의 안전장치

- 통합 관리자만 공통 계약, migration, 의존성 잠금 파일을 수정한다.
- 각 작업자는 자신에게 배정된 폴더만 수정한다.
- 계약 변경이 필요하면 직접 수정하지 않고 변경안을 제출한다.
- 각 작업은 테스트 결과와 변경 파일 목록이 없으면 완료로 인정하지 않는다.
- 마지막 검증은 기능 개발자가 아닌 통합 관리자와 별도 검토자가 다시 수행한다.

상세한 작업자별 복사·붙여넣기 프롬프트는 `VEO_PARALLEL_AGENT_PROMPTS.md`, 전체 제품 요구사항은 `VEO_CODEX_DEVELOPMENT_MASTER_PROMPT.md`를 사용한다.
