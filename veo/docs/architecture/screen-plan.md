# 화면 설계 — NXT 참고본과 VEO 기획서 대조

2026-07-29. NXT(넥스트티) 화면 3장을 정밀 분석하고 VEO 기획서와 대조해, 무엇을 가져오고
무엇을 가져오지 않을지 정한 문서다.

기획서 §12.1 은 **"NXT 화면을 복제하지 않는다. VEO 고유 디자인 시스템을 만든다"** 고 못박는다.
그래서 여기서 가져오는 것은 **정보 구조와 사용 흐름**이지 화면 그 자체가 아니다. 색·타이포·
컴포넌트는 `packages/ui` 의 VEO 토큰을 쓴다.

동시에 구현계획 §63 은 **"NXT 대비 반드시 보완할 8가지"** 를 VEO 의 존재 이유로 규정한다.
참고본을 그대로 따라가면 그 8가지를 잃는다. 대조가 필요한 이유가 이것이다.

## 2. 대조 — 가져올 것

기획서가 이미 요구하고 있는데 VEO 화면에 없던 것들이다. 참고본이 **더 낫다.**

| # | 참고본 | 기획서 근거 | VEO 현재 |
| --- | --- | --- | --- |
| ① | 입력 한 칸 + 탭 3개로 시작 | §1.1 `/tools/seo`·`/tools/geo`·`/tools/naver-keyword` | 없음 (빈 탭 10개가 먼저 나옴) |
| ② | 등급표 전체 + 현재 등급 강조 | 명세 `bands` 에 5단계 정의됨 | 등급 이름만 한 줄 |
| ③ | 카테고리를 `0/24` 로 표기 | §6.1 가중치 합 100 | 백분율만 |
| ④ | 개선 할 일에 **+N점** | 채점기가 계산 가능(SEO) | 없음 |
| ⑤ | 수정 대상 코드 박스 | §12.3 Developer view "fix example" | `fix_example` 필드는 있으나 화면 없음 |
| ⑥ | **측정 이력 격자** | §10 점수 버전 관리·과거 점수 보존 | 테이블(`scan_runs`)만 있고 저장 안 함 |
| ⑦ | 항목마다 한 줄 이유 | §5 "모든 결과에 근거를 연결" | 없음 |
| ⑧ | 표 도구(정렬·검색·엑셀·인쇄) | 구현계획 3단계 "HTML/PDF/CSV/XLSX 내보내기" | 없음 |
| ⑨ | 판정 전제를 사람이 고쳐 재분석 | §6.2 N/A 재계산, §7.2 게이트 | 없음 |

## 3. 대조 — 가져오지 않을 것

### 3-1. "실시간 인기 검색어" — **기획서가 금지한다**

> §8.5 공식 근거가 없는 `실시간 인기검색어` 명칭을 사용하지 않는다. 실제 데이터에 따라
> 다음 중 하나를 선택한다. — VEO 최근 조회 키워드 / 최근 24시간 급상승 키워드 /
> 업종별 추천 키워드 / 내부 프로젝트 인기 키워드

네이버는 실시간 검색어를 2021년에 종료했고 공개 API 로 제공하지 않는다. 그 이름을 쓰면
있지도 않은 출처를 있다고 말하는 것이 된다. VEO 는 **`VEO 최근 조회 키워드`** 로 쓰고,
기준 기간·데이터 범위·갱신 시각·비식별화 규칙을 함께 표시한다.

### 3-2. "엔티티 점수 TOP 5" (타사 도메인 공개 순위) — **보류**

남의 사업장 점수를 이름과 함께 공개 순위로 만드는 기능이다. 기획서에 근거가 없고,
§9 경쟁사 비교는 **"같은 수집 범위와 같은 규칙으로 측정하고 데이터 차이를 경고한다"**
는 조건 아래에서만 허용한다. 한 페이지만 훑은 점수로 만든 순위는 그 조건을 만족하지
못한다. 사업적으로 원한다면 별도 결정이 필요하다 — 기술 문제가 아니라 정책 문제다.

### 3-3. 점수 분해가 100 이 되지 않는 표기

참고본의 GEO 카테고리는 `24 + 30 + 15 = 69` 로, 100 이 되지 않는다. VEO 는 §7.1 이
7개 영역 합계 100 을 명시하므로 그대로 쓴다. 분모가 보이지 않는 점수는 §5 위반이다.

### 3-4. 하나의 종합 점수로 뭉치기

§12.2 는 **10가지를 분리**하라고 한다 — SEO 기술 준비도 / Google 준비도 / Naver 준비도 /
검색 성과 / GEO 준비도 / AI 가시성 / 경쟁 SOV / 답변 위험 / 측정 신뢰도 / 키워드 수요·트렌드·기회.
특히 **GEO 준비도와 실제 AI 가시성은 절대 합치지 않는다**(구현계획 §67).

## 4. 참고본에 없는데 VEO 가 해야 하는 것

구현계획 §63~72 "NXT 대비 반드시 보완할 8가지" 가 그대로 화면 요구사항이 된다.

| # | 요구 | 화면에서의 모습 |
| --- | --- | --- |
| 1 | 존재 여부를 넘어 **유효성·정합성·범위·신뢰도** | 항목마다 판정 + 근거 + 신뢰도 |
| 2 | **N/A 를 0점 처리하지 않고 분모 재계산** | `측정 범위` 와 분모를 함께 표시 |
| 3 | GEO 준비도와 실제 AI 노출 **분리** | 카드를 나누고 합산하지 않음 |
| 4 | 배점과 변경 이력을 **VEO-LAB 버전으로 공개** | 채점 기준 버전·체크섬 표시, 버전 화면 |
| 5 | 모든 문제를 **원자료·영향 URL·사업 영향·수정 방법·재검증 규칙**에 연결 | 이슈 카드 5요소 |
| 6 | 경쟁사는 **같은 범위·같은 규칙**으로, 차이는 경고 | 비교 화면에 범위 배지 |
| 7 | 네이버 수치에 **출처·갱신시각·PC/Mobile·결측 의미** | 지표마다 출처 배지 |
| 8 | 근거 없는 인기검색어 명칭 금지 | 3-1 참조 |

**측정 범위(coverage)의 두 가지 성격** — 2026-07-29 확정.

| | 간편 진단 (영업·제안) | 관리 진단 (계약 고객) |
| --- | --- | --- |
| 소유자 권한 항목 | **범위 밖 — 분모에서 제외** | 분모에 포함 |
| 자격증명 없을 때 | 해당 없음 | **측정 불가**(실제 결함) |
| 화면 문구 | "외부 관측 범위에서는 완전한 결과" | "연결이 빠져 있음" |

같은 사이트라도 두 진단은 다르게 말해야 한다. 지금은 구분이 없어 멀쩡한 간편 진단이
측정 범위 65.9% 의 부실한 결과처럼 보인다. `scans.scope` 컬럼이 이 구분의 자리다.

**소유자 권한이 필요한 것과 아닌 것** — 영업 단계에서 무엇을 약속할 수 있는지가 갈린다.

- 우리 자격증명 하나로 **모든 대상**에 적용: PageSpeed Insights, CrUX, 네이버 검색광고,
  데이터랩. 대상 사이트의 협조가 필요 없다.
- **대상의 협조 필요**: Google Search Console, 네이버 서치어드바이저. 우리 **서비스 계정
  하나**를 각 사이트 속성에 사용자로 초대받는 방식이며, 상대의 비밀번호를 받지 않는다.
  `provider_credentials` 는 조직당 한 벌(`UniqueConstraint(organization_id, provider, field)`)
  이라 이 방식이 아니면 여러 고객을 담을 수 없다.

## 5. 업체 관리 — 계정을 만들지 않는다

업체(고객)에게 로그인 계정을 발급하지 않는다. 직원이 **측정 URL 을 저장·관리**하고,
결과를 두 가지 보기로 낸다.

```
업체 추가:  업체명 + 측정 URL  ─ 한 폼
                ↓ 자동 생성
     customers → projects → sites
```

도메인 모델은 이미 있다(`POST /api/customers`, `/api/projects`, `/api/sites`). 사람에게
3단계를 밟게 하지 않고 한 폼에서 받아 내부에서 만든다 — 단계 수는 구현 사정이지
사용자가 알아야 할 일이 아니다.

| 보기 | 대상 | 내용 |
| --- | --- | --- |
| **간소화** | 업체 전달용 | 점수·등급·상위 조치·사업 영향. 기술 세부 없음 |
| **상세** | 직원용 | 47항목·증거·수정 예시·재검증·계산 근거·측정 이력 |

§12.3 의 Business view / Developer view 에 대응한다. **한 원시 결과에서 보기만 다르게**
만들고 계산을 중복하지 않는다 — 화면마다 따로 계산하면 같은 진단의 숫자가 달라진다.
