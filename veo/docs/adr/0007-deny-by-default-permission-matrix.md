# ADR 0007 — 권한은 코드에 있는 단일 행렬로 관리하고, 기본값은 거부다

- 상태: 채택
- 일자: 2026-07-28

## 배경

역할별 권한이 라우터마다 흩어져 있으면 "이 역할이 무엇을 할 수 있는가"에 아무도 답할 수
없다. 권한이 넓어지는 일은 대개 기능을 추가하다가 우연히 일어나며, 그 사실을 아무도
알아채지 못한다.

## 결정

- `veo/authz/permissions.py`의 `ROLE_PERMISSIONS` 하나가 유일한 근거다.
  라우터는 `Depends(require(Permission.X))`만 선언하고 자체 판단을 하지 않는다.
- 기본값은 거부다. 역할이 없으면 권한도 없다. 행렬에 없는 것은 할 수 없다.
- 행렬 자체를 테스트가 고정한다: SUPER_ADMIN 외에 전권을 가진 역할이 없을 것,
  뷰어 역할에 쓰기 권한이 없을 것, 자격증명 관리는 SUPER_ADMIN만일 것,
  점수 명세 발행은 VEO-LAB 역할만일 것.
- **권한을 되읽는 API가 없다.** 자격증명은 저장하고 사용할 뿐 꺼내오지 않으므로
  `credential:read_secret` 같은 권한 자체를 만들지 않았다.
- 프론트엔드는 행렬을 복제하지 않는다. `/auth/me`가 해석된 권한 목록을 내려주고
  화면은 그것만 사용한다. 링크를 숨기는 것은 접근 제어가 아니므로, URL로 직접 진입한
  경우에도 권한 없음 상태를 렌더링한다.

## 결과

- 역할을 넓히려면 행렬을 고쳐야 하고, 그러면 테스트가 실패하며, 누군가 리뷰한다.
- 대가: 새 리소스를 추가할 때마다 권한을 정의하고 행렬에 배치해야 한다. 의도한 마찰이다.
