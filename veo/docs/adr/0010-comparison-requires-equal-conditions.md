# ADR 0010 — 비교는 같은 조건에서만 성립한다

- 상태: 채택
- 일자: 2026-07-28

## 배경

경쟁사 비교는 이 제품에서 자신 있는 거짓말을 만들기 가장 쉬운 자리다.
자사 4페이지와 경쟁사 200페이지를 크롤해 점수를 나란히 놓으면 차트는 그럴듯하게
그려지고, 회의실에 있는 누구도 그게 틀렸다는 걸 알아챌 수 없다.

문제는 의도가 아니라 구조다. 조건이 결과에 붙어 다니지 않으면, 비교하는 코드는
조건이 달랐다는 사실 자체를 알 방법이 없다.

## 결정

- 모든 측정은 `MeasurementConditions`를 함께 저장한다: 명세 id·버전·체크섬,
  수집기 버전, 검사 페이지 수, 언어·지역, 기기, 렌더링 방식, 활성 제공자, 측정 시각.
- 비교는 `assert_comparable()`을 통과해야만 성립한다. 통과하지 못하면 숫자를
  만들지 않고 **거부하고, 왜 거부했는지 한국어로 설명한다.** 설명하는 거부가
  거짓말하는 숫자보다 유용하다.
- 차단 규칙:
  - **방법론(명세 id·버전·체크섬·수집기 버전) 차이는 어떤 경우에도 면제되지 않는다.**
    서로 다른 명세로 계산된 점수는 다른 값이 아니라 다른 단위다.
  - 관측 조건(언어·기기·렌더링) 차이, 활성 제공자 차이는 차단한다.
    한쪽만 Search Console 데이터를 가지고 있으면 같은 조건의 점수가 아니다.
  - 검사 페이지 수가 3배를 넘게 차이 나면 차단한다.
  - 측정 시점이 30일을 넘게 벌어지면 차단한다.
- **면제는 표본 크기 차이 하나뿐**이며, `allow_scope_variance=True`로 명시해야 하고,
  기본값이 될 수 없다. 면제해도 그 차이는 결과에서 사라지지 않는다. 표시된 채로 남아
  독자가 자기 대신 무엇이 받아들여졌는지 볼 수 있게 한다.
- `fingerprint`는 `measured_at`과 `pages_examined`를 제외한다. 몇 분 간격의 두 크롤이
  우연히 다른 페이지 수에 도달했더라도 셋업은 같았고, 그 둘을 묶는 것은 유용하다.
  시간과 표본은 허용 오차를 두고 따로 비교한다.

## 결과

- 비교 API는 거부를 자주 한다. 의도한 것이다. 조건을 맞추는 일이 분석가의 작업이 된다.
- SOV(Share of Voice)는 비교군에 전적으로 의존하므로, 모든 SOV 값은 자기 비교군과
  "비교군이 바뀌면 이 값도 바뀐다"는 안내를 함께 지닌다.
- 분모가 0인 SOV는 0%가 아니라 `데이터 없음`이다. 아무도 아무도 인용하지 않은 것은
  "우리 점유율이 0%"가 아니다.
