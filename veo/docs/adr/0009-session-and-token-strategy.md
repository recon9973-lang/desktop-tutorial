# ADR 0009 — 짧은 JWT + 회전하는 불투명 refresh 토큰

- 상태: 채택
- 일자: 2026-07-28

## 배경

JWT는 폐기할 수 없다. 서명이 유효하고 만료 전이면 서버가 무엇을 알든 통과한다.
반대로 모든 요청에서 세션을 DB 조회하면 상태를 정확히 알 수 있지만 비용이 든다.

## 결정

- **Access token**: JWT HS256, 15분. `sub`, `org`, `roles`, `sid`, `jti`, `iss`, `aud`.
  짧게 두는 것이 폐기 불가 문제에 대한 유일한 현실적 대응이다.
- **Refresh token**: 불투명 난수 256비트. DB에는 **SHA-256만** 저장한다.
  DB 덤프가 곧 유효한 세션이 되지 않게 하기 위해서다.
- **회전**: refresh할 때마다 이전 행을 `ROTATED`로 폐기하고 새 행을 발급한다.
  같은 sign-in에서 나온 행들은 `family_id`를 공유한다.
- **재사용 탐지**: 이미 회전된 refresh 토큰이 다시 제시되면 그 토큰은 탈취된 것이다.
  **패밀리 전체를 폐기**하고 감사 기록을 남긴 뒤, 호출자에게는 평범한 401을 준다.
  탐지 사실을 알려주면 공격자가 다음 시도를 조정한다.
- **역할은 토큰이 아니라 DB에서 읽는다.** 토큰의 `roles` 클레임은 교차 확인용 힌트일 뿐이다.
  권한을 회수했는데 15분간 유효하다면 회수가 아니다.
- **Principal은 sign-in 시점에 조직 하나에 고정된다.** 헤더나 클레임으로 조직을
  바꿀 수 없다. 두 조직에 속한 사용자는 세션을 두 개 갖는다.
- **인증 실패 메시지는 하나다.** 토큰이 없든, 만료됐든, 위조됐든, 세션이 폐기됐든
  401과 같은 문장이다. 구분해 주면 공격자가 위조의 어느 부분을 고칠지 알게 된다.
- 브라우저에서 access token은 **httpOnly·Secure·SameSite=Lax 쿠키**에만 담는다.
  `localStorage`는 XSS 한 번에 전부 내준다.

## 결과

- 권한 회수는 다음 요청에 즉시 반영된다. 세션 폐기는 refresh 시점에 반영된다.
- 남은 위험: 폐기된 세션의 access token은 최대 15분간 유효하다. 즉시 차단이 필요한
  사건(계정 탈취 확정)에는 별도의 거부 목록이 필요하며, Phase 1 범위 밖이다.
