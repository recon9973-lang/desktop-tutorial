# VEO — 이 저장소에서 일할 때

## 먼저 열 것

**`docs/WORKLIST.md`** — 대장이다. 저장소를 뒤지기 전에 여기부터 연다.

```
§1 확정        이미 정해진 것. 여기 있으면 여쭙지 말고 인용한다
§2 기능별 현황  축마다 [코드 / 자료 / 화면] — 지금 어디까지 됐나
§3 날짜별 기록  언제 무엇을 했나 (판 번호와 함께)
§4 남은 것     내가 할 수 있는 것
§5 사장님 몫    돈 · 외부 콘솔 · 로그인 · 사업 판단
```

**무엇을 끝내면 그 자리에서 대장을 고친다.** 커밋과 같은 판에 넣는다.
`tests/ledger/` 가 낡은 대장을 막는다 — 판을 올리고 대장을 안 고치면 시험이 실패한다.

찾는 것이 대장에 없으면 → `docs/CORRECTIONS.md`(내가 틀린 것) → `docs/README.md`(문서
지도) 순서로 본다. 그리고 **찾은 것을 대장에 올린다.**

## 어기면 안 되는 것

| | |
|---|---|
| **측정값** | 잰 그대로 저장한다. 반올림·절삭 없다. 화면 표기만 소수점 두 자리로 **자른다**. 못 잰 값은 `0` 이 아니라 `—` (WORKLIST §1-C) |
| **배포** | `make deploy` 만 쓴다. **초록불이어도 주문 없이 밀지 않는다.** 하루 2회 상한(8월) |
| **이유** | 원문 인용 + 출처를 대거나 `[추정]` 이라고 쓴다. 못 찾으면 이유를 안 붙인다 |
| **`[실측]`** | 실행한 명령과 그 출력이 있을 때만. 눈으로 더한 값은 `[계산]` 이다 |
| **틀린 것** | `docs/CORRECTIONS.md` 에 즉시 적는다 |

## 확인 명령

```bash
make ci-local      # lint · typecheck · 계약 드리프트 · api+worker 전체 시험
make deploy        # 배포 (주문 받고서만)
```

웹은 `apps/web` 에서 `npx vitest run` · `npx tsc --noEmit` · `npx next build`.
**타입체크와 시험이 통과해도 `next build` 는 깨질 수 있다** — 웹을 만졌으면 빌드까지 돌린다.
